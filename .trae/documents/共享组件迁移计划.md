# WEB 端与 Desktop 端组件迁移到 packages/components 计划

## Summary（概要）

将 WEB 端（`apps/web/src/components`）与 Desktop 端（`apps/desktop/src/components`）中**逐字节完全相同**的重复组件，统一收敛到共享包 `@nao-todo/components`（`packages/components`），实现两端复用、消除拷贝。同时按用户要求，将 `packages/components` 现有的扁平单组件目录按功能重新分组（有关联的归组、无关联的保留在一级目录）。

核心发现（已用 `diff` 逐一验证）：**Desktop `src/components` 下的全部 63 个文件与 WEB `src/components` 对应文件 100% 逐字节相同**。Desktop 是 WEB 的严格子集，WEB 仅额外多出 `settings/` 分组。因此这是纯粹的复制粘贴重复，非常适合上提共享。

## Current State Analysis（现状分析）

### 目录对照（apps/web/src/components vs apps/desktop/src/components）

两端共有且完全相同的分组：

- `pomodoro/`：`focus-ring`、`timer`、`focus`、`notes`、`records`、`indicator`（+ 桶文件 `index.ts`）
- `tasks/`：`list`、`table`、`kanban`、`dropdowns`、`smartlists`（+ 桶文件 `index.ts`）

仅 WEB 独有（Desktop 没有）：

- `settings/`：`app-setting`、`password`、`profile`

### 依赖与耦合分级（决定迁移方式）

**A. 零 app 耦合，可原样上提（仅依赖 `@nao-todo/*`、`nue-ui`、`vue`）**

- `tasks/list/*`（`list.vue`、`list-main.vue`、`use-list.ts`、`use-multi-select.ts`、`types.ts`、`list.css`、`index.ts`）
- `tasks/table/*`（`table.vue`、`table-main.vue`、`table-header.vue`、`table-order-button.vue`、`use-table.ts`、`use-column-config.ts`、`use-multi-select.ts`、`column-defaults.ts`、`column-storage.ts`、`column-style.ts`、`types.ts`、`table.css`、`index.ts`）
- `tasks/kanban/*`（`kanban.vue`、`kanban-column.vue`、`kanban-column-item.vue`、`use-kanban.ts`、`use-kanban-column.ts`、`use-kanban-dragger.ts`、`constants.ts`、`types.ts`、`kanban.css`、`index.ts`）
- `tasks/dropdowns/*`（6 个 `.vue` + `use-dropdown-executor.ts`）
- `pomodoro/focus-ring/*`、`pomodoro/notes/*`、`pomodoro/records/*`（纯 props/emits）

**B. 仅依赖 app 内一处工具函数，需先把工具函数上提到 `@nao-todo/infrastructure`**

- `pomodoro/timer/timer.vue` 和 `pomodoro/focus/focus.vue` 依赖 `@/infrastructure/utils/pomodoro` 的 `formatTimeOfDay`、`formatClock`。
  - 该文件为 [pomodoro.ts](file:///home/nathan/Projects/nao-todo/apps/web/src/infrastructure/utils/pomodoro.ts)，两端相同。其中纯格式化函数 `formatMinutes`、`formatTimeOfDay`、`formatClock`、`sendNotification` 无 app 依赖；`buildPomodoroRecord`、`persistPomodoroRecord` 依赖 `@nao-todo/usecases`（可上提但非本次必须）。
  - `timer.vue`/`focus.vue` 还 `import { PomodoroFocusRing } from '@/components/pomodoro'`（组内相对依赖，随组一起迁移即可）。

**C. 有 app 耦合（`@/stores` + `vue-router` / `@/layouts`），需拆分解耦后再上提**

- `pomodoro/indicator/`：
  - [indicator.vue](file:///home/nathan/Projects/nao-todo/apps/desktop/src/components/pomodoro/indicator/indicator.vue) 是纯展示（props/emits + `NaoRouterLink` + `PomodoroFocusRing`）。
  - [use-indicator.ts](file:///home/nathan/Projects/nao-todo/apps/desktop/src/components/pomodoro/indicator/use-indicator.ts) 耦合 `@/stores`（3 个 pomodoro store）与 `vue-router`。
- `tasks/smartlists/`（`project-smart-list.vue`、`tag-smart-list.vue`、`filter-smart-list.vue`）：
  - 组件本身是 `NaoSmartList` 的薄封装，但 `import useProjectDragger from '@/layouts/tasks/aside/use-project-dragger'`——反向依赖了 app 的 layout。
  - [use-project-dragger.ts](file:///home/nathan/Projects/nao-todo/apps/desktop/src/layouts/tasks/aside/use-project-dragger.ts) 是**纯 DOM 拖拽 hook，零 app 依赖**，可直接上提到共享包。

### 消费方（迁移后需改 import 的位置）

WEB 与 Desktop 的 `src/layouts/**` 通过 `@/components/tasks`、`@/components/pomodoro`、`@/components/tasks/dropdowns/*`、`@/components/tasks/smartlists/*`、`@/components/tasks/table/types` 引用这些组件（两端合计约 56 处，已用 Grep 定位）。迁移后统一改为从 `@nao-todo/components` 导入。

### 工程配置现状

- 共享包 `@nao-todo/components`：`package.json` 无 `exports` 字段、`main: index.ts`、`private: true`；采用源码直引（`moduleResolution: bundler`）。深层子路径导入（如 `@nao-todo/components/task-basic-info`）与桶导入均可用。
- 根 `package.json` 的 devDependencies 已声明 `@nao-todo/components: workspace:*` 等 workspace 依赖；两个 app 的 `tsconfig.app.json` 通过 `"include": ["../../packages/**/*"]` 纳入共享包源码，`vite.config.ts` 无需为共享包额外配置 alias（走 workspace node_modules 解析）。
- `@/` alias 在两端均指向各自 `./src`。

## Proposed Changes（具体改动）

> 说明：以下"移动"指把文件从两端 app 复制到共享包并删除两端副本（因两端逐字节相同，合并无冲突）。

### 第 1 步：上提解耦所需的工具/hook 到基础包

1. **`use-project-dragger` → 共享包**
   - 新建 `packages/components/use-project-dragger/index.ts`，内容取自 [use-project-dragger.ts](file:///home/nathan/Projects/nao-todo/apps/desktop/src/layouts/tasks/aside/use-project-dragger.ts)（纯 DOM，无改动）。
   - 在 `packages/components/index.ts` 导出 `useProjectDragger`。
   - 说明：它同时被 app 的 `layouts/tasks/aside/aside.vue`（间接）与 smartlists 使用；上提后 smartlists 不再反向依赖 layout。app 内 `layouts/tasks/aside/use-project-dragger.ts` 可保留或改为 re-export（见第 5 步）。

2. **pomodoro 格式化函数 → `@nao-todo/infrastructure`**
   - 在 `packages/infrastructure/utils/` 新增 `pomodoro.ts`，仅放**纯函数** `formatMinutes`、`formatTimeOfDay`、`formatClock`、`sendNotification`（从 app 版 [pomodoro.ts](file:///home/nathan/Projects/nao-todo/apps/web/src/infrastructure/utils/pomodoro.ts) 抽取）。
   - 在 `packages/infrastructure/utils/index.ts` 导出。
   - app 内的 `src/infrastructure/utils/pomodoro.ts` 保留 `buildPomodoroRecord`/`persistPomodoroRecord`（依赖 usecases 且被 store 使用），并改为从 `@nao-todo/infrastructure` re-export 上述纯函数，避免破坏其它引用点。

### 第 2 步：迁移 tasks 组件到 `packages/components/tasks/`

按用户选择的"分组子目录"结构，将两端相同的 tasks 组件整组迁移：

- `packages/components/tasks/list/`（原样搬运 A 类文件）
- `packages/components/tasks/table/`（原样搬运）
- `packages/components/tasks/kanban/`（原样搬运）
- `packages/components/tasks/dropdowns/`（原样搬运）
- `packages/components/tasks/smartlists/`：搬运后，把 `project-smart-list.vue`/`tag-smart-list.vue` 中的
  `import useProjectDragger from '@/layouts/tasks/aside/use-project-dragger'`
  改为 `import { useProjectDragger } from '@nao-todo/components'`（或相对路径 `../../use-project-dragger`）。
- 新增 `packages/components/tasks/index.ts` 作为该组桶文件（对齐现有 `apps/*/src/components/tasks/index.ts`：导出 `TaskTable`、`TaskKanban`、`TaskList`，并 `export * from './smartlists'`；额外导出 dropdowns 供 layout 使用）。

组内相对 import（如 `./list-main.vue`、`./use-list.ts`、`@nao-todo/components` 的原子组件）保持不变——它们本就来自共享包，可正常解析。

### 第 3 步：迁移 pomodoro 组件到 `packages/components/pomodoro/`

- `packages/components/pomodoro/focus-ring/`、`notes/`、`records/`：原样搬运。
- `packages/components/pomodoro/timer/`、`focus/`：搬运后把 `@/infrastructure/utils/pomodoro` 改为 `@nao-todo/infrastructure`；把 `@/components/pomodoro`（取 `PomodoroFocusRing`）改为组内相对路径 `../focus-ring`。
- `packages/components/pomodoro/indicator/`：
  - `indicator.vue` 搬运（把 `./use-indicator` 依旧从组内引；`../focus-ring` 相对路径保留）。
  - **`use-indicator.ts` 不迁移**——保留在各 app（因耦合 `@/stores` + router）。改为：共享的 `indicator.vue` 通过 **props** 接收展示数据（progress、indicatorColor、phaseLabel、timeDisplay、taskName、isTimerRunning、isFocusRunning）与 **emit `go`** 事件；各 app 在自己的 `use-indicator.ts` 里组装 store 数据后传入。
    - 需要在 app 侧新增一个薄封装（放在 `apps/*/src/components/pomodoro/indicator/` 或 layouts 中）调用 `useIndicator()` 并把结果绑定给共享 `PomodoroIndicator`。
- 新增 `packages/components/pomodoro/index.ts` 桶文件（对齐现有：导出 timer/focus/records/notes/indicator/focus-ring）。

### 第 4 步：更新共享包总导出与目录规整

1. `packages/components/index.ts` 增加：
   - `export * from './tasks'`
   - `export * from './pomodoro'`
   - `export * from './use-project-dragger'`
2. **规整现有扁平组件（用户要求）**：把 `packages/components` 现有的单组件目录按关联归组，无关联的保留在一级目录。建议分组（关联性依据现有 index.ts 导出与命名）：
   - `packages/components/task/`：`task-basic-info`、`task-check-button`、`task-date-info`、`task-date-selector`、`task-delete-button`、`task-priority-info`、`task-project-selector`、`task-remind-setter`、`task-selector`、`task-state-info`、`task-tag-bar`、`task-creator-input`
   - `packages/components/tag/`：`tag-board`、`tag-card`、`tag-color-dot`、`tag-color-selector`、`tag-form`、`tag-node`
   - `packages/components/project/`：`project-archive-button`、`project-board`、`project-card`、`project-delete-button`、`project-form`
   - `packages/components/comment/`：`comment-creator`、`comment-row`
   - 无明显关联的保留在一级目录：`checkbox`、`collapse-button`、`combo-box`、`dialog-wrapper`、`dropdown-div-block`、`empty`、`event-row`、`feature-unimplement`、`inner-dropdown`、`input-button`、`loading`、`loading-error`、`pager`、`router-link`、`rule-hint`、`smart-list`、`switch-button`、`update-indicator`
   - 对应更新 `packages/components/index.ts` 的导出路径为分组子桶（每个分组新增 `index.ts` 再由根 `index.ts` 汇总），**保持对外导出的具名符号不变**（如 `TaskBasicInfo`、`NaoSmartList` 等），以免影响所有现有引用点。
   - 注意：内部有组件深层引用 `@nao-todo/components/xxx` 子路径（如 smartlists 用 `@nao-todo/components/`、task-list 用 `@nao-todo/components` 桶）。分组迁移后凡是**桶导入**（`@nao-todo/components`）不受影响；若存在**深层子路径导入**需同步更新——迁移前用 Grep 核查 `@nao-todo/components/<name>` 形式的深路径引用并逐一改到新分组路径。

### 第 5 步：更新两端 app 的消费方 import 并删除本地副本

1. 删除 `apps/web/src/components/{tasks,pomodoro}` 与 `apps/desktop/src/components/{tasks,pomodoro}` 中已上提的目录（indicator 的 app 侧薄封装除外）。
2. 全量替换消费方 import（已定位约 56 处，含两端 layouts）：
   - `@/components/tasks` → `@nao-todo/components`
   - `@/components/tasks/dropdowns/xxx.vue` → 从 `@nao-todo/components` 具名导入（在 tasks 桶中导出这些 dropdown 组件）
   - `@/components/tasks/table/types` → `@nao-todo/components`（导出 `TableLayoutConfig` 等类型）
   - `@/components/tasks/smartlists/xxx.vue` → `@nao-todo/components`
   - `@/components/pomodoro` → `@nao-todo/components`
   - `@/components/pomodoro/records/row.vue`（WEB collection 用）→ 在 pomodoro 桶导出该 Row 或保留深路径 `@nao-todo/components/pomodoro/records/row.vue`
3. `layouts/tasks/aside/use-project-dragger.ts`：改为 `export { useProjectDragger as default } from '@nao-todo/components'`，或直接把 aside.vue 的引用改为共享包并删除该文件（择一，优先删除并改引用）。
4. app 侧 `pomodoro/indicator` 薄封装接入共享 `PomodoroIndicator`（见第 3 步）。

## Assumptions & Decisions（假设与决策）

1. **两端逐字节相同已验证**：`pomodoro/*` 与 `tasks/*` 全部文件 `diff` 为 IDENTICAL，合并无语义冲突。
2. **迁移范围**（用户选定）：全部迁移并解耦——含 indicator（拆 props/emits）、smartlists（上提 dragger）、timer/focus（上提格式化函数）。
3. **目录结构**（用户选定）：`packages/components` 采用分组子目录；现有扁平组件同步按关联分组，无关联的留在一级目录，且对外导出符号保持不变。
4. **settings 组件不在本次范围**：仅 WEB 存在且深度耦合 `@/stores`/`@/views/*/context`/`useRouter`，非两端复用场景，保持在 WEB。
5. **共享包保持源码直引**：不引入构建产物/`exports` 字段，沿用现有 `moduleResolution: bundler` + tsconfig include 机制。
6. **localStorage 副作用**（table 列配置）与 `sendNotification`（Notification API）在 Electron 渲染进程同样可用，迁移后行为不变。
7. **图片路径**：`list.vue` 等使用 `/images/coffee.webp` 绝对路径；两端 `public/images/` 均已存在同名资源，迁移后仍由各 app 提供，无需改动。

5. `diff` 复核：确认 `apps/web/src/components` 与 `apps/desktop/src/components` 下已迁移目录均已删除，无遗留重复。
