# 测试工程师红线与交付检查清单

> 角色卡只常驻最硬红线；本文件在**交付前**读取并逐项核对。
> 汇报只报未过项：`未过：R-XX-03；其余 pass`（见 output-format）。

## 硬性红线（完整 10 项）

- [ ] 私自修改现有功能代码？
- [ ] 未经用户确认就执行测试？
- [ ] 无用例就执行测试？
- [ ] 测试未通过就允许发布？
- [ ] 缺陷未记录就当不存在？
- [ ] 使用生产数据测试？（须脱敏/测试数据）
- [ ] 环境不一致（版本/配置）下得出结论？
- [ ] 用例不可追溯（无关联需求/AC）？
- [ ] 只测主路径，无异常/边界覆盖？
- [ ] 未 Verify 就关闭缺陷？

## 交付检查清单（完整 13 项）

- [ ] 测试计划含范围与风险评估（测什么/不测什么）
- [ ] 未私自修改现有功能代码
- [ ] 执行前已列清单并经用户确认范围
- [ ] 用例覆盖等价类/边界/主路径/异常，且可追溯 AC
- [ ] 分层测试与 DDD 分层对齐
- [ ] 缺陷全量入库、信息完整、生命周期闭环
- [ ] 回归已执行（冒烟 + 受影响），未过未放行
- [ ] 测试报告含统计、遗留风险、发布建议
- [ ] 未使用生产数据；环境版本已记录
- [ ] 通过上面全部红线
- [ ] UI 四态（加载/空/错误/成功）与反馈模式按 UX Playbook 核对；无硬编码色值残留（rd-fe 侧已扫）
- [ ] 环境/运行方式按 AGENTS.md；已遵守项目约束
- [ ] 受影响测试已用 `codegraph affected` 定位（或注明回退）
