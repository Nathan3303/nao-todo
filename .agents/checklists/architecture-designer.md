# 架构师红线与交付检查清单

> 角色卡只常驻最硬红线；本文件在**评审交付/ADR 归档前**读取并逐项核对。
> 汇报只报未过项：`未过：R-XX-03；其余 pass`（见 output-format）。

## 工作流速查

| 阶段 | 核心任务 | 输出物 |
| :--- | :--- | :--- |
| 需求分析 | 业务/技术需求、NFR 识别 | 需求文档、架构约束清单 |
| 架构设计 | 架构设计、模块划分、选型 | 架构图、技术栈决策记录 |
| 架构评审 | 组织评审、收集反馈 | 评审报告、优化建议 |
| 实施指导 | 技术指导、解难题 | 实施指南、代码规范 |
| 架构演进 | 监控评估、演进规划 | 演进路线图、性能报告 |

## 硬性红线（完整 9 项）

- [ ] 架构设计缺 NFR 分析？
- [ ] 技术选型缺决策依据与风险评估？
- [ ] 架构图缺关键组件和交互关系？
- [ ] 实施计划缺分阶段里程碑？
- [ ] 风险清单缺应对措施？
- [ ] 架构文档缺变更管理流程？
- [ ] 性能指标不可量化/不可监控？
- [ ] NFR 基线缺失或需求模糊时未反问就产出评审方案？（应输出澄清清单索要）
- [ ] 承接实现类派发或直接修改代码？（应回退 PM）

## 交付检查清单（11 项）

- [ ] 业务需求分析完整，NFR 明确
- [ ] 架构设计符合核心原则，不过度设计
- [ ] 技术选型依据充分，风险评估完整
- [ ] 架构图清晰，组件与交互明确
- [ ] 实施计划可行，含里程碑
- [ ] 风险清单完整，措施具体
- [ ] 文档完整，含变更管理
- [ ] 若本次修订**改变既有条款** ⇒ 已附「**连带同步清单（含 Owner）**」（列出**所有持有该结论的文档** + 各自 Owner），并已通知相关 Owner
- [ ] 性能指标可量化可监控
- [ ] 评审已纳入 AGENTS.md 项目约束（输入核对）
- [ ] 影响面评审已用 `codegraph impact/callers`（或注明回退）
