# 交付文档写作规范（写文档前 / 交付前读取）

> 适用：PRD、ADR、评审报告、测试报告、调研报告、发布说明、任务回报（写进 `docs/` 的长文）。
> 不适用：派发消息与回执（格式固定、必须短，见 @.agents/checklists/comm-templates.md）。

## 一、四条原则

1. **默认读者是「接手的人」**：他要的是**结论 / 约束 / 怎么验收 / 证据在哪**，不是你的思考过程。
2. **首屏给结论**：前 20 行内必须有 TL;DR（目标 · 结论 · 影响 · 待办）——只看首屏也能行动。
3. **写决策不写过程，写差异不复述**：与代码 / 上游文档重复的内容一律用指针（`路径#小节`）。
4. **超预算就删，不是加长**：每份文档有长度上限；超了先删「常识 / 过程 / 全量罗列」，仍超才另附文件。

| 文档 | 上限 | 必须留下 | 禁止 |
| :--- | :--- | :--- | :--- |
| PRD | ≤150 行 | 9 模块结论、范围/非范围、AC | 抄竞品原文、贴代码 |
| ADR | ≤60 行 | 决策、对照模式、参考来源 | 大段代码、教程式背景 |
| 评审报告 | ≤60 行 | 可行性、风险、取舍、待拍板点 | 复述 PRD |
| 测试报告 | ≤80 行 | 范围、结果数字、缺陷、风险、建议 | 日志/截图全文 |
| 调研报告 | ≤120 行 | 结论摘要、来源、适配三栏 | 无来源断言 |
| 发布说明 | ≤60 行 | 版本号、**用户可读**行为变化、升级/回滚说明 | 复述提交日志全文、纯编号/类名 |
| 任务回报 | ≤50 行 | 变更清单、门禁数字、未过项、风险 | 复述需求、贴 diff |

**一律下沉**（写进正文就违规）：全部用例（测试）、方案全文与压测数据（ADR）、抓取正文（调研）、背景长叙与竞品原文（PRD）、通过项罗列（报告类）——需要时另存文件给指针。

## 二、通用骨架（每份文档都要）

```text
# <标题>
- 状态：草稿 / 待确认 / 已定稿 · 更新：YYYY-MM-DD · Owner：<角色>
- 指针：上游 PRD / 关联 ADR / 调研报告（路径）
```

- 结尾一行修订：`- 修订：YYYY-MM-DD <一句话>`；**只在结论变化时新增**，不记措辞调整。
- 用表格压缩对比；引用代码用 `path/file.ext:12`，**不贴代码块**（超过 10 行必改引用）。
- **表格要窄**：列数 **≤5**（超了改分条列表）；单元格只放短结论（约 ≤20 字），长内容下沉为列表；**消息/线程里表格 ≤3 列**（否则终端折行错乱）；表内不放代码块。
- 术语首次出现给半句话解释；中文；不写「我们认为 / 如上所述 / 众所周知」。

## 三、PRD（9 模块不删，每格设上限）

> 9 模块是**验收闸门**，不得删；简洁靠「每格 1–3 句 + 允许不适用」实现。

- 首屏 TL;DR（≤5 行）：做什么 · 给谁 · 成功标准 · 不做什么
- 9 模块表格：每格 **≤3 句 / ≤60 字**；不适用项写「不适用：<一行理由>」，**不许留空、不许写废话**
- AC 逐条 Given/When/Then，一条一行
- 推演细节（RICE 打分过程、5 Whys 展开、同类产品调研明细）落 `docs/research/` 或附录，**正文只留结论 + 指针**

## 四、ADR（≤60 行）

```text
背景(≤5 行) → 决策(1–3 句) → 理由(四步法要点，每点一行) → 对照模式表(模式/适用条件/代价/不采纳理由)
→ 参考来源(链接 + 访问日期) → 后果与风险 → 相关指针
```

- 方案细节、压测数据、对比实验**不写进 ADR**：另存文件并在「相关指针」给路径。
- 模板见 @.agents/skills/arch-patterns.md。

## 五、测试报告（≤80 行）

```text
范围 / 不测 → 环境与命令 → 结果（用例数 / 通过 / 失败 / exit code）→ 缺陷表（严重度/复现/影响/状态）
→ 未覆盖与风险 → 发布建议
```

- **用例集单列文件**（如 `docs/reports/<编号>-cases.md`）；报告只放汇总与失败项。
- 通过项不逐条罗列，写 `未过：无` 即可。

## 六、调研报告（≤120 行）

```text
结论摘要(≤5 行) → 清单表(项目 × 纳入 × 依据) → 来源([标题](URL) · 访问 YYYY-MM-DD · 一句话结论)
→ 适配三栏(它解决什么/适用条件/本项目差异) → 未检索到项
```

- 抓取正文**不进正文**；协议与边界见 @.agents/skills/research.md。

## 七、反模式

- 把「过程」当内容：讨论、尝试、失败路径、工具输出。
- 同一内容出现在多处（该用指针）。
- 全量罗列：全部通过项、全部用例、全部日志。
- 用篇幅证明工作量——**文档的价值是让别人少读，不是多读**。
- 宽表（≥6 列或长句单元格）——在终端/消息里会折行错乱，改分条列表。
