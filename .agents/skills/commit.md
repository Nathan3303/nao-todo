# Git 提交规范

## 触发时机

仅在执行 `git commit` 前读取本文件；其他时候不加载。

## 流程

1. `git diff --cached` 与 `git diff --cached --stat` 查看暂存变更
2. `git log --oneline -10` 参考近期提交风格
3. 按格式编写提交消息，执行 `git commit -m "消息"`

## 消息格式

```text
<type>(<scope>): 简短描述（≤50字符）

变更点：

- 具体变更1
- 具体变更2

其他（可选）：

- 依赖/配置/构建等非功能变更
```

## 类型（可扩展）

- feat   新增功能
- fix    修复缺陷
- chore  构建/依赖/配置等杂项
- change 其他（重构、性能等）
- 扩展：refactor（重构）、docs（文档）、test（测试）、style（样式）等

## 规则

- 变更点列出主要逻辑或用户可见变动，描述具体
- 其他仅放配置文件、依赖版本（注明旧→新版本号）等
- 避免重复，已列变更点的不再写其他
- 版本示例：`升级 dayjs 从 1.10.7 到 1.11.5`

## 示例

```text
feat(calendar): 日期时间选择器显示当前选中值

变更点：

- 时间面板不再显示 NaN
- 日期面板显示当前选中日期
- 日期时间面板显示当前选中日期时间

其他：

- 升级 dayjs 从 1.10.7 到 1.11.5
```

## 注意事项

- 提交前确保所有变更已暂存
- 尽量拆分逻辑独立的提交
- 使用中文，简洁准确
- 禁止提交未测试或含调试代码的变更
