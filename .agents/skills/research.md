# 外部调研协议（research）

> 按需读取：需要「外部既有做法」才能决策时（PM 产品形态 / arch 模式选型 / RD 库用法 / qa 测试惯例）。
> 工具：`web_search`、`fetch_content`（pi-web-access 插件；未装则回退"已知常识 + 明确标注"）。

## 一、边界（严格：产品可查、技术禁查）

| 谁 | 可调研 | 不可调研（越界） |
| :--- | :--- | :--- |
| **PM** | 产品形态：同类功能有哪些功能点、实体属性、组织结构、视图与排序筛选、协作权限、生命周期、通知、导入导出、空/错状态、行业惯例与合规 | **任何技术结论**：该用哪个方案/库/中间件、性能量级、限流与排序语义、契约字段语义、跨端影响面 |
| **arch** | 架构模式、一致性/容错方案、协议与规范、同类系统的取舍 | 替 PM 改需求与指标 |
| **RD** | 具体库/API/SDK 用法、报错与版本事实 | 自定架构方案（转 arch） |
| **qa** | 测试策略、工具与业界用例惯例 | 替代 RD 定实现 |

- PM 命中「不可调研」任一项 → **停止检索，转 arch**（见 @.agents/skills/pm-routing.md §二）。
- 不确定是否越界 → **按越界处理**。
- 外部做法一律是**参考与候选**，不是既定前提；**技术前提只能由 arch 以 ADR 定**。

## 二、产品形态调研清单（PM 用，逐项标 有/无/不做）

> 例：需求是「实现一个待办任务应用」时，要系统探索的是**这些**——而不是去查"用什么框架"。

- **功能点集合**：创建/编辑/完成/删除、批量操作、重复任务、子任务、依赖关系
- **实体属性**：优先级、状态、负责人、截止/开始时间、预计耗时、进度、备注与附件
- **组织结构**：标签（多标签）、清单/项目分组、层级、模板、收件箱
- **视图**：列表 / 看板 / 表格 / 日历 / 时间线；排序、筛选、分组、搜索、保存视图
- **协作与权限**：共享、指派、评论、@提醒、角色与可见范围
- **生命周期**：归档、回收站与恢复、软删、历史记录
- **通知提醒**：到期提醒、重复规则、渠道（站内/邮件/推送）
- **数据进出**：导入导出、第三方集成、API/Webhook
- **状态完整性**：空态、加载态、错误态、超限态、离线态
- **惯例与合规**：同类产品的既有交互习惯、无障碍、隐私与数据留存

> 输出：报告内一张表（`项目 × 是否纳入 × 依据/来源`），供 PM 决定 PRD 的「范围 / 非范围」。

## 三、检索纪律（省 token）

1. **先建文件再检索**：先写 `docs/research/YYYY-MM-DD-<主题>.md` 的问题清单与表头——结果有落点，上下文才不留残渣。
2. **只取 3–5 条一手来源**：官方文档 / 规范 / RFC / 一手实现 > 高质量博客 > 二手综述；**拒内容农场与营销页**。
3. **引用格式**（每条来源必带）：`- [标题](URL) · 访问 YYYY-MM-DD · 一句话结论`。
4. **全文只落盘**：抓取内容写进报告文件；线程只回 `≤150 字摘要 + 路径`，**禁止贴正文**。
5. **查不到就写**「未检索到 / 未联网 / 无公开资料」——**禁止凭印象编造引用**（幻觉引用比没查更糟）。

## 四、适配三栏（禁止照搬）

每条外部做法必须给全三栏：

| 它解决什么 | 适用条件 | 本项目差异（采纳 / 改造 / 不采纳 + 理由） |
| :--- | :--- | :--- |

> 「业界都这么做」不是理由：适用条件（规模、团队、合规、既有约束）不成立就得写「不采纳」。

## 五、出口（不替代对方结论权）

- PM → PRD「用户场景 / 业务规则 / 范围」；引用来源，**技术前提留空**待 arch。
- arch → ADR：`参考来源` + `对照过的备选模式（含不采纳理由）`（见 @.agents/skills/arch-patterns.md）。
- 报告统一落盘 `docs/research/`（归档约定见 @.agents/common/intercom-protocol.md「归档约定」）。
- 报告正文按 @.agents/checklists/deliverable-docs.md §六 写：结论摘要 ≤5 行、来源带访问日期、适配三栏、抓取正文不进正文（上限 120 行）。

## 六、反模式

- 把链接当结论；把「X 家这么做」当需求依据。
- 抓取全文贴进消息（污染线程 + 烧 token）。
- 用外部文章推翻用户已定的约束或项目 `AGENTS.md` 的红线。
- PM 用外部调研替代 arch 的技术取舍；RD 用它替代实现判断。
- 无来源、无访问日期的引用。
