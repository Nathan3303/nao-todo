# 测试设计详细规范

## 用例设计方法

- **等价类划分**：有效/无效各取代表值
- **边界值分析**：上点/内点/离点（如金额 0/1/上限/上限+1）
- **判定表**：多条件组合（权限 × 状态 × 输入）
- **场景法**：主路径 + 异常 + 边界
- **错误推测**：并发、超时、断网、重复提交、空值、超长输入

## 反事实守卫（把静态推断升级为实测结论）

当要验证的是「实现/契约的静态推断」而非现成行为时，用**两段式探针**，避免只在单侧证据上下结论：

- **S1 实际链路**：用**真实现 + 真编排**（如真 repo + 真 SyncService）跑端到端；mock 只复现**外部系统**（服务端/网络）的**真源语义**——引源码行号，不复制逻辑；有源码仓时优先临时单测直调真源函数（如 Go converter），测后删除。
- **S2 反事实分支**：独立断言「假设推断成立」时的后果。两段合读才能区分：**命题为假** / **命题为真** / **命题的前置在上游先行被阻断**（最常见误区：推断的上游前提不成立）。
- **守卫化**：S2 保留为**反事实守卫**（当前绿）——修复后它应**转红**，届时改为**正向不变量**（如「往返后必须命中」）并在文件头注明；放 `__tests__/**`，红/绿分列说明。
- **绑定版本**：结论显式绑定被测外部系统版本（commit）；版本一变结论可能翻转（如服务端对齐修法）。

## DDD 分层对齐表

| 层 | 测试方式 | 覆盖内容 |
| :--- | :--- | :--- |
| domain | 纯单测（Vitest / `go test`） | 实体规则、状态流转、不变量、VO |
| application | mock 仓储/端口 | UseCase 编排顺序、端口调用、异常传播 |
| infrastructure | MSW / 集成（内存/真实 DB） | Mapper 双向、HTTP 映射、乐观锁冲突 |
| presentation | VTU / Testing Library | 组件渲染与交互 |
| E2E | Playwright / Cypress | 关键路径、跨模块流程 |

## 缺陷管理

- 生命周期：New → Open → Fixed → Verify → Closed / Reopen
- 严重度：致命 / 严重 / 一般 / 轻微
- 优先级：P0 / P1 / P2 / P3
- 报告要素：标题、环境版本、复现步骤、预期 vs 实际、日志/截图、影响范围
- 不 Verify 不关闭；Reopen 有依据

## 测试报告（≤80 行）

- 结构：范围 / 不测 → 环境与命令 → 结果（用例数/通过/失败/exit code）→ 缺陷表 → 未覆盖与风险 → 发布建议
- **用例集单列文件**（`docs/reports/<编号>-cases.md`）；报告只放汇总与失败项，通过项不罗列（`未过：无` 即可）
- 完整骨架与必写/可省/禁写见 @.agents/checklists/deliverable-docs.md §五

## 自动化与 CI/CD

- 测试左移：早参与需求/用例评审
- 分层自动化：单测/集成每提交必跑；E2E 关键路径 + 发布前冒烟
- 门禁：单测通过率、覆盖率阈值、冒烟用例作为准入
- 可维护性：Page Object / 组件封装；稳定优先于数量
- AI 生成用例：可用于补覆盖，**必须人工评审**后入库

## 性能与安全（按需）

- 性能：并发、响应时间、吞吐、资源；压测类型（负载/压力/稳定性）；基线如 P95<500ms
- 安全：越权、注入、XSS、敏感数据泄露、接口鉴权；按要求启用渗透/扫描

## 误区

- 测试 = 点点点 → 是策略 + 用例工程 + 风险量化
- 用例越多越好 → 覆盖有效性优先
- 自动化万能 → 探索性测试发现未知问题
- 质量只由测试负责 → 产品/研发/测试共同责任
- 无缺陷 = 质量好 → 可能覆盖不足
