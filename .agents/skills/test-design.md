# 测试设计详细规范

## 用例设计方法

- **等价类划分**：有效/无效各取代表值
- **边界值分析**：上点/内点/离点（如金额 0/1/上限/上限+1）
- **判定表**：多条件组合（权限 × 状态 × 输入）
- **场景法**：主路径 + 异常 + 边界
- **错误推测**：并发、超时、断网、重复提交、空值、超长输入

## DDD 分层对齐表

| 层 | 测试方式 | 覆盖内容 |
| :--- | :--- | :--- |
| domain | 纯单测（Vitest / `go test`） | 实体规则、状态流转、不变量、VO |
| application | mock 仓储/端口 | UseCase 编排顺序、端口调用、异常传播 |
| infrastructure | MSW / 集成（内存/真实 DB） | Mapper 双向、HTTP 映射、乐观锁冲突 |
| presentation | VTU / Testing Library | 组件渲染与交互 |
| E2E | Playwright / Cypress | 关键路径、跨模块流程 |

## 缺陷管理

- 生命周期：New → Open → Fixed → Verify → Closed / Reopen
- 严重度：致命 / 严重 / 一般 / 轻微
- 优先级：P0 / P1 / P2 / P3
- 报告要素：标题、环境版本、复现步骤、预期 vs 实际、日志/截图、影响范围
- 不 Verify 不关闭；Reopen 有依据

## 自动化与 CI/CD

- 测试左移：早参与需求/用例评审
- 分层自动化：单测/集成每提交必跑；E2E 关键路径 + 发布前冒烟
- 门禁：单测通过率、覆盖率阈值、冒烟用例作为准入
- 可维护性：Page Object / 组件封装；稳定优先于数量
- AI 生成用例：可用于补覆盖，**必须人工评审**后入库

## 性能与安全（按需）

- 性能：并发、响应时间、吞吐、资源；压测类型（负载/压力/稳定性）；基线如 P95<500ms
- 安全：越权、注入、XSS、敏感数据泄露、接口鉴权；按要求启用渗透/扫描

## 误区

- 测试 = 点点点 → 是策略 + 用例工程 + 风险量化
- 用例越多越好 → 覆盖有效性优先
- 自动化万能 → 探索性测试发现未知问题
- 质量只由测试负责 → 产品/研发/测试共同责任
- 无缺陷 = 质量好 → 可能覆盖不足
