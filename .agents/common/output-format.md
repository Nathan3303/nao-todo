# 输出与沟通规范（通用）

## 语言与风格

- 中文回复。
- 先结论/方案，后细节；关键决策附理由。
- 不堆术语，不写空话。

## 长文落盘（强约束）

- 任意超过 300 字的结构化产出（PRD / 架构方案 / 评审报告 / ADR / 测试报告 / 用例集），**写文件**，不要贴在消息里。
- 消息只回：`路径 + ≤150字摘要 + 结论/阻塞`。
- **引用而非复制**：派发/评审一律给路径（如 `docs/prds/<file>.md#<section>`），禁止把长文全文或附件推进线程——接收方自己读文件，发起方上下文不留副本。
- **正文规范**：PRD / ADR / 报告 / 调研等交付文档统一按 @.agents/checklists/deliverable-docs.md 写（首屏结论、长度上限、必写/可省/禁写三档）——**写文档前读取**。

## 检查清单

- 交付前自查清单。
- 汇报时**只报未过项**：`未过：R-XX-03；其余 pass`。
- 禁止逐条复述全部通过项。

## 回执硬性（红线；模板按需）

> 派发消息模板与两级回执模板（`done(lite)` / `done(full)`）见 @.agents/checklists/comm-templates.md——**派发/回执前读取**，不在常驻展开。

1. 前缀 `[编号] done` 不变（PM 追讨与红线均按 `done` 匹配）；**派发时由 PM 声明级别，未声明默认 `done(lite)`**。
2. 回执即声明已读 `checklists/<role>.md` 并逐项核对（未过项必须列出）——**未核对不回执**。
3. 「测试」必须给**全量门禁精确数字**（命令 + exit code + 文件数/例数/红数或错误数）；只跑子目录或只写「pass」不算回执 —— PM 打回（见 intercom-protocol「终态回执」）。
4. **有阻塞/风险/需决策 → 必须 `done(full)`**（`lite` 不得吞掉需 PM 拍板的事）；详细全文落盘 `docs/reports/<编号>.md`，**禁止**把长报告贴进线程。

## 反模式（禁止）

- 在消息里粘贴角色卡/PRD/输入信封全文。
- 复述需求原文而非结论与差异。
- 把长报告直接 `send` 污染线程历史。
- 汇报时逐条罗列全部通过项。
- 宽表贴进线程（>3 列或长句单元格，终端会折行错乱）——表只用于短结论，长内容下沉文件。
