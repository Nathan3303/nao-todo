# 发版说明写作规范（通用）

> 适用：**任何面向用户交付的仓库**（应用 / 组件库 / CLI 工具…）的每一次发版。
> 触发：**写 release notes 前**（发布执行人）与**验收发布前**（PM）读取。
> 权威单处：本文件。`skills/github-flow.md`、`checklists/`、`templates/` 只给指针，不复制正文。
> 骨架见 @.agents/templates/release-notes.md.example；文档通用写法见 @.agents/checklists/deliverable-docs.md。

## 一、硬约束（必须遵守）

1. **必须有「面向用户的简明版」，且置于正文最前。**
   - GitHub Release 正文 与 仓库 `docs/releases/vX.Y.Z.md` 的**顶部口径一致**（同一份文字、同一版本）。
   - 读者 = **最终用户**，不是开发者；看完前几行就知道「这版对我有什么变化」。
2. **正文 ⛔ 不得出现内部术语 / 编号。** 一律不写：任务或缺陷编号（`DEF-xx` / `Txxx` / `#123`）、提交哈希、文件名与函数名、内部属性名（如 `aria-disabled` / `dirty`）、测试例数与通过率、守卫名、内部模块名。
   - 需要保留 ⇒ 统一移入**末尾「技术细节（可略过）」**段，或**链接仓库文档**（README / CHANGELOG / 详细说明）。
3. **行为变更必须写「用户视角的后果」。**
   - 只写内部机制（改了哪个函数 / 状态）不合格；要写**用户会看到什么、能做什么、不能做什么**。
   - 例：_点过之后按钮会变「已撤销」且不可再点_（✅）—— 而非「按钮加 `aria-disabled`」（⛔）。
4. **口径与落盘一致**：`docs/releases/<version>.md` 是权威落盘；`gh release create --notes-file <该文件>` 与之一同源，禁止两处各写各的。

## 二、建议结构（顺序固定，用不上的段可省）

1. **一句话概括** —— 这版一句话能记住的变化（不可省）。
2. **✨ 更好用了** —— 新能力 / 体验提升。
3. **🐛 修好了** —— 修掉的问题（用户视角现象 → 现在）。
4. **⚠️ 请留意** —— 行为变更 / 需要用户配合的事。
5. **📦 更小更快** —— 体积 / 性能 / 启动等可感知收益。
6. **已知但本期未处理** —— 已知问题与后续计划。
7. **技术细节（可略过）** —— 编号 / 哈希 / 依赖版本 / 门禁数字 / 文档链接。

- **纯内部仓**（无面向用户交付）可省略第 2–5 段的「面向用户」写法，但**结构保留**（仍按「概括 → 变化 → 技术细节」分层）。
- **排版**：本文件与其他文档同受 @.agents/checklists/deliverable-docs.md 「默认不使用表格」约束 —— release notes 正文尤其不要用表格。

## 三、好 / 坏对照

- ✅ **好**：**撤销更好用了** —— 拖动改期后点「撤销」可还原；**点过之后按钮会变成「已撤销」且不可再点**。
- ⛔ **坏**：新增 `calendar.undo.*` i18n 键并接入 `NueMessage` 扩展插槽，成功态置 `aria-disabled`（`T362`）。

完整可套用骨架（含逐段占位与好/坏示例）见 @.agents/templates/release-notes.md.example。

## 四、发布前核对

- [ ] 正文最前有**面向用户的简明版**（用户看得懂）。
- [ ] 正文**无**编号 / 哈希 / 文件名 / 函数名 / 内部属性名 / 测试例数 / 守卫名 / 内部模块名。
- [ ] 行为变更写了**用户视角的后果**（不是内部机制）。
- [ ] 结构完整（一句话 → 变化 → 已知 → 技术细节）；内部信息集中在「技术细节」段。
- [ ] 正文**未使用表格**（改用有序 / 无序列表；见 @.agents/checklists/deliverable-docs.md）。
- [ ] `docs/releases/<version>.md` 与 GitHub Release 正文同源。

## 五、红线

- [ ] 只写内部机制、用户看不懂？
- [ ] 正文里直接出现编号 / 哈希 / 类名 / 属性名 / 测试例数？
- [ ] 没有「面向用户简明版」，或它不在最前？
- [ ] 盘上 release notes 与 Release 正文两处不一致？
