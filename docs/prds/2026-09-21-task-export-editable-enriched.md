## 4. 用户场景

- **画像**：需要把任务（含子任务）带到外部工具/协作者处，并希望子任务信息完整、导出前可裁剪的用户。
- **场景卡**：打开任务详情 → 底部「更多」→ 导出 → 浮层显示可编辑文本 → 按需删改 → 点「复制」→ 粘贴到编辑器；若改坏可点「还原」重来。
- **关键路径**：footer `nue-dropdown`（`export-task`）→ 递归取数（含一级子任务检查项）→ 生成 → `nue-dialog`（`NueTextarea`）→ 复制当前编辑内容。
- **页面状态清单**：加载中（生成期）/ 生成成功 / 取数失败（toast，不开浮层）/ 编辑中 / 已还原 / 复制成功 / 剪贴板不可用。
- **边界数据**：子任务无任何丰富字段；子任务仅有检查项；子任务描述含换行；多层子任务；标签为空。

## 5. 业务规则

### 5.1 根任务输出（不变）

与 TASK-12 一致：`# 名称` + 元信息（状态/优先级/开始/截止/项目/标签/创建/更新，空值逐行省略）+ `## 描述` + `## 检查项` + `## 子任务`。

### 5.2 子任务输出（本单变更）

**一级子任务（直接子任务）= 丰富**：名称行仅「复选框 + 名称」，属性全部走子行；**更深层级 = 精简**。

子任务行：

```text
- [x] 子任务名
```

- 保留复选框：`state === 'done'` → `- [x]`，否则 `- [ ]`（Q3=A）。
- **名称行不含任何属性**（2026-09-21 变更：原「行内括号追加标量」形态废弃，见 §9 Q2′）。

属性子行（各段独立，空则整行/整段省略；顺序固定）：

```text
  - 状态：已完成
  - 优先级：高
  - 开始时间：2026-09-20 09:00
  - 截止时间：2026-09-20 18:00
  - 标签：#重要 #紧急
  - 描述：这是子任务描述
  - 检查项：
    - [x] 检查项一
    - [ ] 检查项二
```

- 顺序固定：状态 → 优先级 → 开始时间 → 截止时间 → 标签 → 描述 → 检查项；**空项整行省略**（不输出空值行）。
- 属性行缩进 2 空格；「检查项」段与「子任务」段的逐项嵌套复选框缩进 4 空格。
- 分隔符统一：**全角冒号、冒号后直接接值**（`- 名称：值`），与根任务元信息 `- 状态：待办` 及既有 `- 描述：…` 同构。
- 时间复用 `formatExportDateTime`（`YYYY-MM-DD HH:mm`）；标签形如 `#名称`，空格连接。
- 「描述」行：描述去空白后非空才输出；**内部换行折叠为空格**（保持单行）。
- 「检查项」段：存在检查项才输出；`- 检查项：` 标签行 + 逐项嵌套复选框（缩进 4 空格）。
- 全部属性为空 → 只输出 `- [ ] 子任务名` 一行。

更深层级（深度 ≥1，即二级及以下）—— 用**标签段**承载，避免与属性行同级混淆：

```text
  - 子任务：
    - [ ] 孙任务
```

- **递归规则（T39 裁决，2026-09-21）**：**每个含子节点的节点各输出一段 `- 子任务：`**（非整棵树只出现一次）。**缩进公式（消除层级命名歧义）**：设节点深度 `d`（一级子任务 `d=0`）——名称行缩进 `4d`；该节点的属性子行与自身 `- 子任务：` 标签段缩进 `4d+2`；其子节点缩进 `4(d+1)`。例：`d=0` → 名称 0 / 属性·标签 2 / 子节点 4；`d=1` → 4 / 6 / 8；`d=2` → 8 / 10 / 12；`d=3` → 12 / 14 / 16。「检查项」段逐项复选框同规则缩进 `4d+4`。更深层级一律精简（**无属性子行**）；受 `MAX_EXPORT_DEPTH = 5` 约束。

完整拼接示例：

```text
## 子任务

- [x] 子任务 1
  - 状态：已完成
  - 优先级：高
  - 开始时间：2026-09-20 09:00
  - 截止时间：2026-09-20 18:00
  - 标签：#重要
  - 描述：子任务描述
  - 检查项：
    - [x] 检查项一
    - [ ] 检查项二
- [ ] 子任务 2
  - 状态：待办
  - 优先级：低
  - 子任务：
    - [ ] 孙任务
```

### 5.3 取数规则

- 一级子任务的检查项：调用**只读取数**（见决策点 D1），逐子任务取回；空则整段省略。
- 一级子任务标签：`task.tags` → `getTag` 解析名称（与根任务一致）。
- 任一取数失败 → 与 TASK-12 一致：toast「导出失败：{error}」且**不开**浮层。
- 递归深度上限 `MAX_EXPORT_DEPTH = 5` 不变；深度上限内 ≥ 二级一律精简。

### 5.4 浮层可编辑规则

- 预览 `<pre>` 改为 `NueTextarea`，`v-model` 绑定本地草稿 `draft`。
- **打开时同步**：`modelValue` 由 false→true 时 `draft = markdown`（props 内容）。
- **编辑期间不覆盖**（Q8=A）：不再监听 `markdown` 覆盖草稿；生成仅在用户主动导出时发生且随后开浮层。
- **复制来源**（Q6=A）：复制按钮复制 `draft`（编辑后文本），不再是 props。
- **还原**（Q7=A）：`draft = props.markdown`（最近一次生成文本），按钮即时生效。
- **不持久化**（Q9=A）：关闭浮层即丢弃草稿；下次打开重新生成。
- 空草稿复制：不额外拦截（保持简单），沿用剪贴板失败提示。

## 9. 决策留痕

- **Q1 字段（用户定）**：一级子任务输出 状态/优先级/开始/截止/标签/描述/检查项；不含项目、创建/更新时间（降噪）。
- **Q2 形态（用户定）**：行内追加标量；描述与检查项因多行/列表语义无法行内，降为子行（`描述：` / `检查项：`）——格式见 §5.2。
- **Q3 复选框（用户定）**：保留 `- [x]`/`- [ ]`。
- **Q4 层级（用户定）**：仅一级丰富，≥ 二级精简。
- **Q5 开关（用户定）**：不加「精简/详细」开关。
- **Q6–Q10（用户定）**：复制以编辑内容为准；提供「还原」；编辑期不覆盖；不持久化；`NueTextarea`。
- **D1（2026-09-21 拍板：采纳 A′）子任务检查项取数**：现有 `TaskCheckItemUseCase.list(taskId)` 会 `store.setCheckItems(...)` 写共享 `TaskCheckItemStore`，若直接用于子任务会**污染当前任务详情的检查项**。
    - **A′（采纳）= 把取数抽成不写 store 的原语，再让既有 `list()` 委托它**：新增 `listByTask(taskId): GoAsync<TaskCheckItemViewObject[]>`（`repo.list` → VO → **归一排序 `sortId ASC, id ASC`**，不触 store）；`list()` 改为 `listByTask()` + 写 store，返回契约与副作用不变（详情页 `use-check-items.ts` 零改动）。相较「并列新增」更优：转换/排序单一真源，避免 `list`/`listByTask` 静默漂移。
    - 方案 A（未采纳，被 A′ 取代）：并列新增只读方法，不重构 `list()`——存在双实现漂移风险。
    - 方案 B（**否决**）：仍调 `list` 事后还原。`setCheckItems` 是**整体替换**（`map.value = new Map(...)`），会清空全部任务缓存；`setCheckItemIds` 直接重指向子任务列表 → 渲染错误内容 + 拖拽排序基准错位。B 只能还原根任务一项，**还原失败即永久脏 store**，无法证明 AC5 的「从未污染」。
    - 方案 C（否决）：不满足用户澄清。
- **D2（2026-09-21 拍板：进入公共导出面）**：`listByTask` 进入 `domain-task` 公共导出面（additive、非破坏）。理由：本单非范围仅禁「改数据结构」，追加只读 API 不属破坏性变更；私有化会导致 `TaskCheckItemUseCase` 类型面隐式扩张，更差。
- **架构实现约束 C1–C3（来自 T32 评审，偏离须回评审）**：C1 导出路径禁止调用任何写型检查项用例；C2 `listByTask` 必须自带归一排序、禁依赖仓储顺序（Go 仓储不排序，Local 仓储按 `sortId` 排序，口径不一致）；C3 旁路读共享 store 数据一律走只读取数路径。
- **行为变化（需回归）**：A′ 落地后 `list()` 在 **Go（在线）仓储**路径下顺序由「服务端顺序」变为 `sortId ASC, id ASC`（Local 路径原本已排序，无变化）。请 rd-fe 确认既有检查项顺序用例并补一条「无序返回 → 顺序稳定」断言。
- **ADR**：`docs/adr/2026-09-21-task-export-readonly-checkitem-fetch.md`。
- **D2 格式冻结（2026-09-21 PM 裁定）**：§5.2 拼接示例作为测试断言基准。**缩进口径以 2/4 为准**（属性子行 2 空格、检查项嵌套 4 空格），与 §5.2 正文及内联示例一致；实现与 T33/T34/T37 测试均按 2/4 落地。该代码块语言已由 `markdown` 改为 `text`，避免被格式化工具重排（详见 §12）。

- **Q2′（2026-09-21 用户变更，修订 Q2）**：原「行内括号追加标量」形态废弃。**子任务名称行只保留「复选框 + 名称」**，状态/优先级/开始/截止/标签/描述/检查项一律改为 `- 名称：值` 属性子行。理由：名称 + 5 项属性的括号长蛇不可读；且与根任务元信息、既有「描述/检查项」子行同构。
- **Q4′（2026-09-21 变更，修订 Q4）**：更深层级由「`- [ ] 孙任务` 同级子行」改为「`- 子任务：` 标签段 + 逐项嵌套复选框（缩进 4）」。理由：属性子行并列后，同级的孙任务会被误读为属性。用户说明：**当前无二级子任务、亦无引入计划**，此项属防御性设计，保留能力但不再作为主路径。 递归口径：每个含子节点的父各一段 `- 子任务：`，每深一级缩进 +4（见 §5.2 递归规则）。
