## 4. 用户场景

- **画像**：在日历三视图间切换的用户。
- **场景卡**：进日历 → 切「日」→ 头部看起来与月/周同款；点左上角开关可收起/展开侧边栏（与月/周一致）。
- **关键路径**：`daily/index.vue` 头部 → 共享样式层 → 侧边栏按钮 → `INDEX_VIEW_CONTEXT_KEY.switchDisplayAside`。
- **页面状态清单**：侧边栏展开（`menu-close`）/ 收起（`menu-open`）/ 日视图加载中 / 空态 / 无 provider 自足回退（单测）。
- **边界数据**：窄屏（头部 `flex-wrap` 生效）；长标题（`min-width` + 居中）。

## 5. 业务规则

### 5.1 样式归属唯一

- 三个视图头部的**排版/布局**规则只允许出现在 `calendar-grid.css`；组件内 `<style>` **不得**再定义 `.day-header` / `.day-title` / `.day-view-toggle` / `.day-view-btn` 的排版属性。
- 标题的**可点变体**（`cursor:pointer` + `:hover` 背景 + `:focus-visible` 描边）**仅** `.cal-title` / `.wk-title`；`.day-title` 为**静态变体**（视觉同排版、无交互暗示）。

### 5.2 头部结构（三视图一致）

- 左组（`gap="2px"`）：**侧边栏开关 → 上一天/月/周 → 标题 → 下一天/月/周**。
- 右组：排序下拉 → 视图切换（`月/周/日`，当前项 `is-active`）→ 分隔线 → 未安排 → 今天。
- **`title` 属性沿用月/周的既有写法**：侧边栏开关在月/周**不带** `title`（保持逐字一致）；日视图同样不带。

### 5.3 侧边栏开关行为

- `isDisplayAside === true` → `icon="menu-close"`；`false` → `icon="menu-open"`。
- 点击 → `switchDisplayAside()`（与月/周同一状态源，收起/展开同一侧边栏）。
- 无 provider（单测/独立挂载）→ 自足回退提供 `isDisplayAside = ref(true)` + `switchDisplayAside = no-op`，**不抛错**。

## 6. NFRs

- 不得引入第二份头部样式（`calendar-grid.css` 为唯一真源）。
- CSS 改动**不得**影响月/周既有视觉（仅追加选择器到既有规则组 + 拆分标题的可点/静态变体）。
- 无 provider 时组件可独立挂载（既有回退约定不破坏）。
- 门禁：`vp test` 全绿、`vp check` 全绿、`guard:ddd` OK、双端 build ✓。

## 9. 决策留痕

- **D1（用户三选一 → 选 b）**：标题采用**静态变体**——视觉与月/周同款，但**不带** `cursor:pointer`/`:hover`/`:focus-visible`，避免"可点却无反应"的误导。否决 (a) 做成下拉（属功能新增）、(c) 点击回今天（语义弱）。
- **D2（用户指示）**：侧边栏收缩按钮**直接抄**月/周元素（逐字一致，含**不带** `title` 属性）。
- **D3（PM）**：数据来源走 `CALENDAR_DAY_CONTEXT_KEY`（组装点转供自 `INDEX_VIEW_CONTEXT_KEY`），而非组件内直接 inject index 上下文——与 C14 既有约定一致，且保住"无 provider 自足回退"的单测能力。
- **D4（PM，未纳入）**：「月视图用 `nue-divider`、周视图用 `.wk-view-sep`」是**既有**不一致（且 `.cal-view-sep` 疑似未被使用）；本单不扩大范围，记入遗留。
