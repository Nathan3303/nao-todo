## 1. 问题证据与 5 Whys

**现象（需求直提）**：详情面板子任务行仅展示 名称+时间内联+描述，子任务标签只能点进子任务详情才能看到；而列表/看板/表格视图均已行内展示标签。

| 层 | 追问 |
| :--- | :--- |
| ① | 子任务行看不到标签 |
| ② | 行布局未预留标签位：名称右侧被时间（开始~截止）占用 |
| ③ | TASK-02 精简行布局时把时间内联名称末尾，标签栏仅服务详情主任务 |
| ④ | 标签是子任务识别/分类的关键信息，多视图已行内展示，子任务行信息层级不一致 |
| ⑤ | **命题：子任务行名称右侧改挂只读标签栏（`TaskTagBar`，clamped=2），时间下移独立行，补齐识别信息且不引入编辑复杂度** |

## 2. 目标指标

| 项 | 口径 |
| :--- | :--- |
| 中间指标 | 有标签的子任务，行内标签可见率 100%（用户手工核验） |
| 成功口径 | 时间信息不丢失（独立行可见）；标签栏不遮挡/不溢出；拖拽/创建/脱离/状态切换零回归 |

## 4. 用户场景

- **画像**：管理含大量子任务的顶层任务的重度用户。
- **场景卡**：打开任务详情 → 子任务列表 → 行内直接识别标签归属（分类/紧急度），时间作为次要信息在独立行，无需逐个点进详情。
- **关键路径**：详情面板 → 子任务区 → 行内名称右侧标签栏（只读）→ 名称下方时间行 → 描述。
- **页面状态清单**：加载（loading）/ 空（无子任务 empty）/ 错误（错误+重试）/ 成功（行=勾选钮+名称行[名称+标签栏+脱离]+时间行+描述）。

## 5. 业务规则

- 有标签（`subTask.tags.length > 0`）→ 渲染只读 small 标签栏，`clamped=2`，溢出 `+N`；无标签 → **不渲染**。
- 时间（`startAt`/`endAt` 任一非空）→ 独立行渲染，位置在名称行下方、描述上方；拼接规则不变（无悬空 `~`）；均空 → 不渲染。
- 名称点击仍切换子任务详情；标签栏只读无交互；脱离按钮默认隐藏、鼠标移入 Item / `focus-within` 时展示（沿用现有 CSS 语义）。
