## TL;DR

- **做什么**：把手机抽屉底部「两个上下堆叠的 40px 图标按钮」改为**一行工具条** —— 左侧「同步状态 = 图标 + 短文字（可带计数）」，右侧「设置齿轮」。
- **给谁**：手机浏览器用户（抽屉宽 256px）。
- **成功标准**：一屏内即可读到同步状态（不点开面板也知道是否同步中 / 待推送 / 失败）；齿轮仍可一键进设置；抽屉省下一行高度；桌面零变化。
- **不做什么**：不改同步面板内容与数据口径 · 不改抽屉宽度/动画 · 不改桌面 rail · 不重做图标体系。
- **为什么做**：现状两个图标按钮**竖排占两行**且**状态只有图标 + 角标圆点**，手机上既读不出含义（只能靠 tooltip，而手机没有 hover）也浪费高度。

## 一、问题证据

- 现状结构（读码）：`aside-v2-drawer.vue` 的 `.nue-div--aside__tools` 为 `flex-direction: column; align-items: center`，内含 ① `#AppAsideDrawerBottomSlot`（同步状态 Teleport 宿主）② 齿轮按钮，两者各 `min-height: var(--nue-box-size-md)`（40px）⇒ **两行 = 至少 80px + gap**。
- 同步触发器（`sync-status-bar.vue`）：`nue-button theme="pure" icon="ntd-sync2"` + 状态类 + 角标伪元素，**无可见文字**；完整状态只在 `aria-label` / tooltip / 展开面板里。手机无 hover ⇒ **状态不可读**。
- 5 Whys：① 手机上读不到状态 ← 触发器只有图标；② 为何只有图标 ← 桌面 rail 只有 70px 宽，放不下文字，抽屉复用了同一份触发器；③ 为何直接复用 ← T521 目标是"补齐能力"，未做形态区分；④ 为何现在要改 ← 用户真机看到"两行图标 + 无信息"；⑤ 根因 ← **能力对等做到了，但"信息密度"没有按容器宽度重新设计**。
- **设计输入（frontend-design 视角，落点而非炫技）**：本组件的容器是 256px 抽屉底部的**工具带**，信息只有两种性质 ——「当前状态（被动）」与「进入设置（主动）」。设计只需让两者在**一行**内各就各位：状态用文字承担语义、图标只做锚点；齿轮靠右作为动作出口，与底部导航图标共用同一垂直轴线。

## 二、目标指标

- **可核指标 1**：手机抽屉工具区高度由「≥2 行」降为 **1 行（40px 行高 + 上下 8px）**。
- **可核指标 2**：**不展开面板**时即可分辨 4 种状态：同步中 / 待推送 N / 失败 N / 正常（上次同步时间或"从未同步"）。
- **可核指标 3**：桌面 / Electron 视觉零变化（像素级 diff 无差异）。
- **口径缺口**：无埋点；靠组件测试 + 用户真机勾选。

## 三、范围 / 非范围

- **范围**
    1. 工具区改**横向一行**：左「同步状态（图标 + 短文字 [+ 计数 chip]）」、右「齿轮」；行高 40px、上下 padding 8px（沿用 `--nue-gap-xs`）。
    2. 状态文字取既有 i18n 键的**最短可用形态**：`sync.syncing` / `sync.pending {count}` / `sync.failed {count}` / `sync.lastSyncAt {time}` / `sync.neverSynced`；**不新增键**。
    3. 状态可辨性：正常 / 进行中 / 异常三态按「颜色 + 符号（图标形态或角标）+ 文字」三重冗余（`AGENTS.md` 三态可辨性），异常态用既有错误色。
    4. 点击区：**状态触发器 ≥40px**；**齿轮点击区按 R4 例外**（≈字形 24px，DESIGN §3 登记），`aria-label` 保留**完整**状态文本。
    5. 抽屉内一行布局不得溢出（256px 与更窄屏）；文字过长时按「状态+计数」优先级收敛（先省略时间细节，不省略状态词）。
- **非范围**
    - **改同步面板（dropdown）内容 / 分区 / 文案** —— 理由：数据口径已定稿（T115b/r7），本单只改入口形态。
    - **桌面 rail 的触发器形态** —— 理由：70px 轨道放不下文字，强行统一会破坏 SHELL-02 已验收形态。
    - **新增 token / 新图标 / 新 i18n 键** —— 理由：`nue-*` 与现有图标集足够；新增须先报 PM。
    - **抽屉宽度 / 动画 / 关闭方式** —— 理由：与本单无关。

## 四、用户场景

- **画像**：手机上边看任务边留意"是不是还没同步上去"的用户。
- **关键路径**：打开抽屉 → **一眼扫到状态**（例如「待推送 2」）→ 需要处理就点状态打开面板 → 或点齿轮进设置。
- **页面状态清单**
    - 加载：同步中 ⇒ 文字「同步中…」+ 图标旋转（复用既有 loading，不新增动效）。
    - 空：从未同步 ⇒ 「从未同步」。
    - 错误：失败 N ⇒ 错误色 + 图标角标 + 「失败 N」。
    - 成功：正常 ⇒ 「上次同步 HH:MM」（窄屏可退化为「已同步」）。

## 五、业务规则

- **不变量 1（信息不减）**：完整状态文本仍在 `aria-label` 与面板内，**视觉精简不等于信息丢失**。
- **不变量 2（一行优先）**：工具区在 256px 与 320px 视口下**不得换行**、不得横向溢出。
- **不变量 3（桌面零变化）**：rail 侧触发器形态、位置、tooltip 一律不动。
- **不变量 4（三态可辨）**：不得只靠颜色区分状态（色盲/去色下仍可辨）。
- **不变量 7（R4 结构）**：同步状态工具带**吸底**（sticky）且不遮挡子页面侧栏最后一项；齿轮在 footer 内，与导航图标同一垂直轴线。
- **不变量 5（token 复用）**：只用既有 `nue-*`（间距 / 字号 `--nue-text-xs` / 色 / 圆角）；不新增。
- **不变量 6（能力不退化）**：齿轮点击仍走 `hostReady` 闸门；焦点归还仍指向当前可见变体齿轮。

## 六、NFRs

- **兼容性**：≤445px 手机浏览器（含 T519 安全区）；桌面 / Electron 零变化。
- **性能**：不新增定时器/监听；状态文字随既有响应式计算派生，无额外轮询。
- **可访问性**：两个控件均可键盘聚焦、`aria-label` 完整、点击区 ≥40px；状态变化不产生 aria-live 轰炸（沿用现状，不加 live region）。
- **安全**：不适用：纯展示层。
- **可维护性**：状态文案映射**单一来源**（一个 computed），两处（视觉文字 / aria-label）共用。

## 七、AC

- **验证接缝**：`apps/web/src/components/sync/__tests__/sync-status-bar.test.ts` + `aside-v2/__tests__/aside-drawer-tools.test.ts`（扩展，不新建基建）。
- **AC1（主路径）**：Given 手机抽屉（≤445px）打开，Then **同步状态工具带吸底一行**（图标 + 短文字）、**齿轮位于 `nue-footer` 与导航同排**且可点；状态触发器 ≥40px，齿轮按 R4 例外；footer 六项（5 导航 + 齿轮）在 256px 抽屉内**不溢出**。
- **AC2（异常/三态）**：Given 同步中 / 待推送 N / 失败 N / 从未同步 四种状态，Then 每种都**在不展开面板时可见**对应文字，且以「颜色 + 符号 + 文字」三重冗余表达。
- **AC3（边界）**：Given 256px 抽屉与 320px 视口，Then 工具区**不换行、不横向溢出**；文字较长时按「状态词优先」收敛，不出现「…」把状态词吃掉。
- **AC4（负向闭环）**：Given 桌面（>445px）与 Electron，Then rail 触发器形态与位置**零变化**；切变体后焦点归还仍指向可见齿轮。
- **AC5（设计一致性）**：只用既有 `nue-*`；字号/间距/圆角与 footer 导航同一体系；不新增 i18n 键；`DESIGN.md` §4.6 若需补一句「工具带一行内：状态在左、动作在右」由 PM 增补。
- **AC6（可自动核）**：① 状态文案映射为单一来源（同一 computed 同时供视觉文字与 aria-label，测试断言两者一致）；② 工具区容器为横向 flex、两子项均满足 40px 下限（源级/运行时断言）；③ 既有 sync/aside 用例全绿。
