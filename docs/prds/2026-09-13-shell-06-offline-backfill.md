## 1. 问题证据与 5 Whys

| ID | 现象 | 根因 | 严重度 |
| :--- | :--- | :--- | :--- |
| **G1** | 离线写入项 `retryCount>=5` 后**永不重推**，联网恢复也不补传 | `sync-service.ts:246` `MAX_PUSH_RETRY=5`；`:599` `continue`；**无重置路径** | Must |
| **G2** | 离线几次编辑即触顶 | 一次网络失败对**整批**脏队列 `markFailed()`（每项 +1） | Must |
| **G3** | 恢复网络后**不自动补传**（仅手动） | 无 `online` 监听/周期退避/前台恢复触发 | Must |
| **G4** | 无本地写上限/暂停可见性 | 无队列上限与暂停态 UI（SHELL-03 L2） | Must |
| **G8** | 触顶的**删除**项永不推送 → 远端数据"复活" | 同 G1（`deletions` 也受跳过） | Must |
| **G11** | 离线期每次写仍发起无效推送，加速触顶 | `setDirtyListener → schedulePush` 无离线判断 | Must |
| G6 | 触顶后每次冷启动 `start()` 恒失败 ⇒ 门恒失败 | G1 衍生 | Should |
| G13 | 会话管理离线 toast 噪声 | 无离线降级态 | Could |

**5 Whys**：① 离线写完恢复网络后数据不上云 → ② 队列项触顶即永久跳过，且无任何"恢复连接"触发 → ③ 重试计数把"网络不可达"当"真实失败"累加，且没有回传触发源 → ④ 同步层缺"离线暂停 / 网络恢复"语义，SHELL-03 只建了 run 边界（成败可判）未建重试生命周期 → ⑤ **命题：为同步队列引入"离线暂停-恢复"语义与回传触发，使推送可自愈且可观测，绝不阻塞本地读写。**

## 2. 目标指标与埋点口径

| 项 | 口径 |
| :--- | :--- |
| 中间指标 | 离线写 N 次 → 联网后**无需手动**，队列在有限时间（≤1 个退避周期）内 `pendingCount/failedCount → 0` |
| 成功口径 | 离线连续 ≥5 次编辑**不触顶**；触顶项可恢复（含删除项）；离线期本地 CRUD 完全不受影响 |
| 埋点 | 不新增远端埋点；以 BC-13…BC-16 + 单测 + QA 实机替代 |

## 3. 范围 / 非范围

| | 内容 |
| :--- | :--- |
| **做 P0** | **R1 回传触发**：启动/解锁（已有 `start()`）+ 前台恢复（`visibilitychange→visible` 节流）+ **条件指数退避定时**（仅当有待推送/失败项：5s→10s→30s→60s→120s 封顶，成功清零）+ `online` 事件即时一次；全部经 `syncService.enqueue` 串行防重入；**`online` 仅作触发/提示，不作鉴权/放行**（沿用 C-22）。**R2 重试语义**：网络类失败 ⇒ **暂停**（**不累加** `retryCount`，仅记 `lastAttemptAt`；网络/前台恢复 ⇒ 清暂停并立即重试）；业务/数据类 ⇒ 计数 + 退避；凭证类（401/403/10041）⇒ 维持现状。**R3 写上限与暂停可见性**：队列超阈值 ⇒ UI 显式「待同步（暂停）」+ 计数 + 「立即重试」；**不阻断本地写**、不丢数据。**R4 触顶可恢复**：`resetFailed(userId)`（或 `nextAttemptAt` 退避）在手动同步/网络恢复/前台恢复/重启时重置，使触顶项重新入列。**R5 不阻塞功能**：本地 CRUD 不等网络；UI 仅消费 `syncStatus` |
| **做 P1** | G6：触顶不再使初始同步门"恒失败"（可离线进入已具备，进一步让门反映"有待回传"而非硬失败）；G13：会话管理离线占位降级 |
| **非范围** | 同步协议/表结构/游标变更；Web 端统一架构（另议）；离线专属常驻大 UI（沿用 SHELL-02 状态轨）；chunk 预缓存；G7（LWW 远端优先）仅为文档口径 |

## 4. 用户场景（画像 + 场景卡 + 关键路径 + 页面状态清单）

- **画像**：飞行/弱网/断网环境下使用桌面端的用户。
- **场景卡**：① 离线连续新建/编辑/勾选多个任务 → 恢复网络 → **自动**上云，无需操作；② 离线删除任务 → 联网后删除正确上报（不"复活"）；③ 长时间离线大量修改 → UI 显示待同步/暂停与计数，本地照常可用；④ 凭证过期 → 不无限重试，走重新登录。
- **关键路径**：本地写 → `markDirty` → 队列 →（触发源）→ push → 成功出队 / 失败分类 → 暂停或退避。
- **页面状态清单**：同步状态 `idle/syncing/paused(离线待回传)/failed(可重试)/ready`；待推送计数可见；本地页面不受同步状态影响。

## 5. 业务规则与不变量

| 规则 | 内容 |
| :--- | :--- |
| R-a 暂停语义 | 网络不可达 ≠ 真实失败；网络类失败**不消耗**重试额度，进入"暂停"，恢复即重试 |
| R-b 数据不丢 | 本地写与队列不受上限阻断；硬上限仅提示，不丢数据、不静默 |
| R-c 可恢复 | 任何"触顶/暂停"状态都必须有恢复路径（自动或手动） |
| R-d 串行与幂等 | 所有推送经 `enqueue` 串行；沿用 SHELL-03 运行边界（beginRun/endRun）与 LWW 快照保护 |
| R-e 安全边界 | `online`/`navigator.onLine` **不得**用于鉴权/放行（C-22）；凭证类失败仍跳登录 |
| R-f 协议冻结 | 不改同步协议/表结构/游标；`SyncRunResult` 等如需扩展仅**纯追加** |
| R-g 不阻塞 | 同步任何状态都不得改变本地页面可用性（AC11 不回退） |

## 6. NFRs

- 定时器**有界**：退避定时仅在有待推送/失败项时存在，成功/清空即停；最长间隔 120s。
- 无新增网络请求类型；不引入请求风暴（G11 修复目标）。
- 日志/状态可观测（复用 `error-observability` 通道与 `syncStatus`）。
- `guard:ddd` 通过；双端构建绿；`vp test` 全绿。
