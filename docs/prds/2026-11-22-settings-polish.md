# PRD：设置面板改版（导航形态 / 账户信息归位 / 密码分区 / 间距治理）

- 状态：待确认（待用户验收设计稿） · Owner：PM
- 更新：2026-11-22
- 指针：用户 2026-11-22 走查四条 · 前序 IA `docs/prds/2026-10-24-settings-ia.md` · 设计稿 `docs/designs/`（待 uiux） · Issue #360
- 优先级：Must（用户直报，观感与信息结构同时影响可用性）

## TL;DR（≤5 行）

- **做什么**：设置对话框整体视觉与信息结构治理 —— 左栏去掉激活左边线改成导航链接观感、账户面板删冗余「更多信息」并把注册时间归位、密码修改升为常驻独立分区、全对话框 padding/gap 统一。
- **给谁**：桌面端与 Web 端使用设置的用户（移动端红线不动）。
- **成功标准**：四条逐项落地 + 用户本人视觉走查通过 + 无信息丢失、无 a11y 回退、无 Web 端零外溢。
- **不做什么**：不把分类改成 URL 路由、不改全站间距台阶、不动移动端。

## 一、问题证据

- 用户 2026-11-22 在设置页走查后直报四条：左栏激活态左侧有一条竖线，与"导航链接"观感不符；账户页「更多信息」分组冗余；密码修改折叠后不易发现；整体 padding/gap 松散、留白过多。
- 5 Whys 摘要：设置面板沿用了「行容器 + 内边距盒」的早期写法 ⇒ 每层各自加 padding ⇒ 累计留白偏大；账户信息被拆成「身份区」与「更多信息」两处 ⇒ 注册时间与身份断联；密码表单按需折叠 ⇒ 可发现性低。

## 二、目标指标

- **主指标**：四条逐条可核（视觉走查勾选 + 结构断言），无一条以"感觉好一点"结案。
- **次指标**：设置对话框内 padding/gap 声明收敛——同一语义只允许一处定义（可核：源码级计数）。
- **反指标**：不得因收紧留白导致可点区 <40px、或文本对比度下降（沿用 `DESIGN.md` 下限）。
- **缺口**：无可用性量化数据（无埋点），以用户走查为终判。

## 三、范围 / 非范围

- **范围**：左栏分类项去激活左边线，改为导航链接观感（字重/颜色表达激活，保留现有 `tablist`/`tab` 语义与键盘操作）。
- **范围**：账户面板删除「更多信息」分组；注册时间移到身份区第三行（昵称、邮箱之后）。
- **范围**：「待注销时间」从「更多信息」迁出，落到危险区（仅待注销状态出现）。
- **范围**：密码修改由折叠改为**常驻独立分区**，且视觉区分度要明显（用户明确指出"目前不够明显"）。
- **范围**：设置对话框内**全部模块**的 padding/gap 梳理，移除冗余空白，保持层级可辨。
- **范围**：`DESIGN.md` 补充「元素设计方式参考现有组件库主题（nue-ui + shadlike）」的口径，使后续新增块有依据。
- **非范围**：分类改成真实 URL 路由（用户选定：只要视觉，不动路由/深链/用例）。
- **非范围**：全站间距台阶改造（本期只到设置对话框 + 文档口径，避免影响任务列表等页面）。
- **非范围**：移动端 `packages/presentation-react` / `apps/mobile`（红线，零改动）。
- **非范围**：更新块（#358）的交互逻辑改动 —— 仅随间距治理被动调整。

## 四、用户场景

- **画像**：日常改主题/提醒/账户信息的用户，设置是高频低注意力场景。
- **场景 A（找东西）**：打开设置 → 左栏一眼看出当前在哪一类（无竖线也能辨）→ 直接点目标分类。
- **场景 B（看自己）**：进账户 → 头像右侧一次看到昵称、邮箱、注册时间，不再需要展开「更多信息」。
- **场景 C（改密码）**：进账户 → 直接看到密码修改分区（不需要先发现可折叠行）。
- **场景 D（离场）**：危险区集中「退出登录 / 注销 / 待注销时间 / 撤销注销」。
- **页面状态清单**：加载 = 头像/资料未就绪（保持既有占位与离线昵称兜底）；空 = 待注销时间不出现时不留空行；错误 = 沿用既有资料加载失败口径；成功 = 四项落地且无空盒。

## 五、业务规则

- **信息只迁移不丢失**：注册时间、待注销时间必须仍可见（后者只在待注销状态出现），不得因删「更多信息」而消失。
- **a11y 不降级**：左栏保持 `role=tablist`/`tab` + `aria-selected` + `↑↓/Home/End` 键盘；密码分区不得丢标签与错误提示的可读性。
- **可点区下限（分层口径）**：控件（按钮/输入/开关）取**组件原生档位**，不低于 36px（`--nue-box-size-df`）；列表/行级可点区 ≥40px。不得为凑 40 自造尺寸（30px 例外的教训）。
- **装饰边界**：块内处于静止态的 1px 边框属装饰（可 <3:1），但**状态边框**（focus/选中/错误）必须 ≥3:1；容器级浅底必须复用既有 `.sd-permission-notice` 三件套，不新造。
- **间距唯一来源**：同一语义的 padding/gap 只允许一处定义（组件级 token 或类），禁止逐块叠加内边距。
- **零外溢**：Web 端与桌面端共用同一套设置面板 ⇒ 改动对两端同时生效且表现一致；移动端不渲染设置对话框的部分保持不动。
- **不新造体系**：所有取值来自 `nue-*` token 与既有类；确需新增须先报 PM。

## 六、NFRs

- **性能**：纯样式与结构改动，不得增加运行时请求或包体（构建产物体积变化 <1%）。
- **安全**：无。
- **兼容**：`zh-CN` / `en-US` 双语文案齐备；离线态（资料缺失）沿用既有兜底。
- **可观测**：无遥测；以用户走查与自动化结构断言为准。
- **缺口**：`DESIGN.md` 中「元素设计方式」的具体条目由 uiux 起草、PM 审定后写入。

## 七、AC

- 验证接缝：设置对话框组件树（左栏 tablist / 四个面板）+ 源级样式断言（padding/gap 唯一来源）—— 待 `qa` 确认（2026-11-22 未确认）。

### 主路径

- AC1：Given 打开设置，When 观察左栏，Then 激活项**无左侧竖线**，靠字重与颜色可辨，且未激活项 hover 有可见反馈。
- AC2：Given 进入账户面板，Then 头像右侧依次显示昵称、邮箱、注册时间；**「更多信息」分组不存在**。
- AC3：Given 账户面板，Then 密码修改以常驻分区呈现（不折叠、无需展开），且与相邻分区有明确视觉分隔。
- AC4：Given 任一分类面板，Then 块内与块间留白遵循统一台阶（同一语义单处定义），无「双层内边距」造成的冗余空白。

### 异常

- AC5：Given 资料未加载完成或离线，When 进入账户面板，Then 注册时间位置不出现空行/空标签，昵称沿用既有离线兜底。
- AC6：Given 用户处于待注销状态，When 进入账户面板，Then 危险区可见「待注销时间」，且「撤销注销」仍可用。

### 边界

- AC7：Given 窄屏（设置对话框窄档），When 打开任一分类，Then 间距收敛后仍无元素溢出/挤压，密码分区与按钮不被截断。
- AC8：Given 英文界面，Then 左栏与账户区文案不折行溢出（长文案不破坏对齐）。

### 负向闭环

- AC9：Given 删除「更多信息」后，`user-info-viewer` 若不再被使用，Then 不得留下死组件/死键（i18n 键与导出清理，或有明确保留理由）。
- AC10：Given 移动端与 `packages/presentation-react`、`apps/mobile`，Then 改动为 0 行（红线自证）。

### 设计一致性

- AC11：Given 改版后的设置面板，Then 元素形态与现有组件库主题一致（按钮/输入/分区沿用既有组件档位，不自造尺寸），且 `DESIGN.md` 有对应口径可查。
- AC12：Given 任一可点元素，Then 控件 ≥36px（组件原生档）、列表/行级命中区 ≥40px；文本对比度 ≥4.5:1、图形/状态边框 ≥3:1；正常 / hover / 激活三态均可辨。

- **③ 左栏激活态**：采用 A（复用既有 `nue-link--route` 四态：激活 `-900` 底 + 白字 + 600）。这正是用户要的「router-link 的样子」且是既有组件行为，不再自造；若走查觉得过重，C 为即时回退（底 `-100` + 字 `-900` + 600）。
