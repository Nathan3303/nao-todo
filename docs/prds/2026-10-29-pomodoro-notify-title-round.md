## 一、问题证据

- **`#1` 番茄通知不受提醒设置约束（用户可感知）**：`packages/presentation/pomodoro/utils/pomodoro.ts` 直接把 `@nao-todo/shared/utils/notification` 的 `sendNotification` 原样 re-export；4 个调用点（专注完成 / 休息即将结束 / 休息结束 / 结束专注）在 `packages/presentation/pomodoro/stores/pomodoro-timer-store.ts` 内**既不读设置、也不传 `silent`**。全模块 grep `reminder` 命中 0。`FEATURES.md` §9 与 §16 已作为已知限制登记（「免打扰与声音开关对它无效」）。
- **`#1` 对照基线已具备**：`packages/shared/reminder/reminder-settings.ts` 提供 `ReminderSettings{ notify, sound, quietHours }` + `readReminderSettings`；`quiet-hours.ts` 提供 `isWithinQuietHours(nowMs, quietHours)`（支持跨天、非法配置不抑制）。任务提醒侧的派发口径见 `apps/web/src/views/index/reminder-notify.ts`：应用内弹窗**恒开**，系统通知受 `notify` 控制，`silent = !sound`。
- **`#2` 页签标题不显示进度**：全仓 `document.title` 命中 **0**；桌面托盘 tooltip 为固定串（`apps/desktop/src/main/tray.ts:78` `tray.setToolTip?.(deps.tooltip ?? 'NaoTodo')`，`CreateTrayDeps` 未暴露可变通道）。⇒ 用户切到别的标签页 / 把窗口收进托盘后，只能靠侧栏 `PomodoroIndicator` 或到点的系统通知得知进度。
- **`#3` 轮次对用户不可见**：`completedRoundCount` 是 `pomodoro-timer-store.ts` 内的**非响应式普通变量**，且未进入 store 的公开返回（末尾 return 只有 `phase/status/remainingSeconds/totalSeconds/isIdle/isRunning` + 动作）⇒ 界面上没有任何「第几轮 / 何时长休」信息，用户设了「4 轮后长休」也无从判断当前处于第几轮。
- **`#3` 附带发现：长休时点 off-by-one（新登记 `DEF-111`，P2，用户可见）**：`completedRoundCount` 在 **break 完成**时 `+1`（`handlePhaseComplete` 的 break 分支），而长休判定 `isLongBreakDue()` 在 **focus 完成**时求值 ⇒ `sessionsUntilLongBreak = 4` 时，长休实际出现在**第 5 次专注结束后**（用户预期第 4 次）。`skip()` 的计数更不一致：跳过 **focus 不计**、跳过 **break 计**。且全仓**无任何覆盖该逻辑的测试**（`packages/presentation/pomodoro/stores/__tests__/pomodoro-timer-lifecycle.test.ts` 仅 54 行，无 `longBreak` 断言）。✅ 该缺陷一旦上线轮次指示器就会**直接暴露给用户**（指示器会与「第 4 轮后长休」的承诺不符）⇒ 必须同批修。

## 二、目标指标

- **通知受控率（`#1`）**：免打扰时段内番茄阶段结束 → **系统通知数 = 0**、**应用内提示出现率 = 100%**（P95 ≤ 1s）；非免打扰时段 → 系统通知照发，`silent` 与「通知声音」开关**逐项一致**（开声音 ⇒ `silent:false`，关声音 ⇒ `silent:true`）。
- **标题即时性（`#2`）**：计时运行中浏览器页签标题**每秒刷新 1 次**（±1s），暂停时显示冻结值，阶段切换（专注↔休息）≤1s 内反映；结束 / 取消 / 离开番茄页返回基线标题**成功率 100%**（不残留旧倒计时）。
- **托盘可见性（`#2`）**：桌面端窗口收进托盘后 tooltip 仍按 1s 粒度刷新；**主进程 IPC 调用 ≤1 次/秒**（不得把 250ms tick 直传）。
- **轮次一致性（`#3`）**：指示器显示的「第 N/M 轮」与引擎实际状态**不一致次数 = 0**；`M=4` 时**第 4 次专注自然结束后进入长休**（达标率 100%，用例级验证）。
- **零回归**：任务提醒（通知开关 / 免打扰 / 去重账本）行为与 `v1.12.16+` 逐字一致 · 移动端 diff = **0** · `#Pomodoro` 布局在 1200px 与 960px 两档下不出现换行溢出 · 无新增 token / 组件。

## 四、用户场景

- **场景 A（免打扰）**：用户在设置里开了免打扰（22:00–08:00），夜里跑一个 25 分钟专注。到点时**不弹会响的系统通知**，屏幕右下角出现一条不打扰的应用内提示「专注完成 · 25 分钟，该休息了」。
- **场景 B（切标签页）**：用户把番茄页留在后台标签页去看文档。页签标题始终显示 `24:59 · 专注`，抬眼看一眼就知道还剩多久，不需要点回来。
- **场景 C（桌面托盘）**：用户把桌面窗口收进托盘。鼠标悬停托盘图标，tooltip 显示 `专注 24:59`；休息中显示 `休息 04:30`。
- **场景 D（轮次）**：用户设「4 轮后长休」。做完第 1 轮看到 ●○○○ +「第 2/4 轮」，做完第 3 轮看到 ●●●○ +「本轮结束后长休」，第 4 轮结束**立即进入长休**（修 `DEF-111` 的预期）。

## 五、业务规则

**通知（`#1`）**

- 判定顺序：① 读设置（失败 ⇒ fail-open：发、不静音）② 免打扰命中 ⇒ 应用内提示，**直接结束**（不发系统通知）③ `notify === false` ⇒ 不发明系统通知，也不弹应用内提示（用户明确关闭了通知；界面上的计时器与侧栏指示器仍在）④ 否则发系统通知，`silent = !sound`。**顺序裁决（`T575` N11 · PM 2026-10-29）**：② 早于 ③ ⇒ 免打扰命中且 `notify === false` 时**仍弹应用内提示** —— 该开关管的是**系统通知**，应用内提示是免打扰的降级通道，不属其管辖；反之未命中免打扰时 `notify === false` **完全静默**（不降级为提示）。
- 应用内提示文案含**阶段 + 时长**，例：「专注完成 · 25 分钟，该休息了」/「休息结束 · 该开始下一轮了」；不使用技术键名。
- 「休息即将结束」的前置提醒同规则处理（免打扰期间同样降级为应用内提示）。
- 通知点击行为不变（聚焦窗口），不新增跳转。

**页签标题（`#2`）**

- 文案格式：运行中 `24:59 · 专注` / `24:59 · 休息` / `24:59 · 长休息`；暂停 `⏸ 24:59 · 专注`；正计时 `12:34 · 正计时`（仅运行/暂停时改写，`idle` 一律回基线）。
- 基线标题 = 应用启动时的 `document.title`，**只记录一次**并在回 idle / 卸载时恢复；不得在每次 tick 重新读取（否则会被自己的旧值污染）。
- 刷新节流：**复用引擎既有 250ms tick 的秒级变化判定**（秒数未变不写 DOM），**不新增定时器**。
- **单一真源（`T574` 裁定 C1/C2）**：页签标题与托盘 tooltip **共用同一个纯函数输出**（⛔ 两端不得各拼一套文案，也不得为 tooltip 另立 i18n 文案）；暂停态统一带 `⏸` 前缀，即 `⏸ 24:59 · 专注`。
- **复位值必为非空（`T574` 裁定 C3）**：`idle` / 结束 / 取消 / 卸载时的复位值统一为 `NaoTodo`（= `apps/web/index.html` 与 `apps/desktop/src/renderer/index.html` 的 `<title>`，亦为 v1.13.0 托盘基线）。⚠️ Electron `setToolTip('')` 语义是**移除** tooltip，故通道载荷恒为**非空** `1..64` 字符。
- 非番茄页不写标题（路由守卫：仅当当前路由属于番茄分区且引擎非 idle 时生效）；离开番茄页（路由变化）若引擎仍在跑，**继续更新**（跨页可见性是本需求的核心价值），结束/取消后恢复。
- 桌面端：同源文案经**窄 IPC 通道**写入托盘 tooltip（通道名与载荷见 ADR / arch 回执）；节流 1s；托盘不可用（`unsupported`）⇒ 静默 no-op，不报错、不影响其它能力。

**轮次（`#3`）**

- 周期定义：一个周期 = `sessionsUntilLongBreak`（设置为 M）次专注；周期结束进入长休。
- **计数点（改）**：仅「**专注自然完成**」计数 `+1`；**跳过专注 / 结束专注 / 取消专注 均不计数**；break / longBreak 完成**不再计数**（原实现的计数点迁移）。
- 长休判定（改）：专注自然完成后，若「本周期已完成数 `>= M`」⇒ 进入长休并把周期计数归零；否则进入短休。
- 指示器展示：圆点总数 = M，实心数 = 本周期已完成数（`focus` / `break` 阶段）；文字标签规则：
    - idle：`共 M 轮一轮长休`（~~**实心固定 0**：idle = 本周期视图未开始，故不展示已完成数~~ ⇒ ⛔ **该口径已被 `docs/prds/2026-10-29-pomodoro-rounds-semantics.md`（`DEF-112`）取代**：实心恒等于已完成轮次）；
    - focus：`第 N/M 轮`（N = 已完成数 + 1）；
    - 当 N === M：追加 `· 本轮结束后长休`；
    - break：`休息中 · 已完成 N/M`；longBreak：`长休息 · 新周期`（实心固定 0 = 新周期开始前）；
    - **实心恒等于「已完成数」，不分阶段、不为 M=1 设特例**（`T575` 裁定 · PM 2026-10-29；与 AC9 对齐）：故 `M=1` 时 idle / focus 显示 ○（0 已完成）、break 显示 ●；文字分别为 `共 1 轮一轮长休` / `第 1/1 轮 · 本轮结束后长休` / `休息中 · 已完成 1/1`。
- 三态可辨：圆点用「实心/空心」区分 + 文字标签兜底（**不得仅靠颜色**，遵守 `AGENTS.md` 界面原则第 4 条）。
- 指示器为**纯展示**，不提供点击跳转/调整；无障碍：容器 `role="img"` + `aria-label` 含文字标签。

## 六、NFRs

- **性能**：标题/tooltip 更新**不新增定时器**，复用既有 tick；主进程 IPC **≤1 次/秒**；`#3` 指示器为纯计算（无副作用），M 上限 10 ⇒ DOM 节点 ≤10。
- **可靠性**：通知层**永不抛**（沿用 `sendNotification` 的布尔返回语义，`NueMessage` 调用失败不得影响引擎阶段流转与记录落库）；设置读取失败 fail-open；托盘通道失败 ⇒ 主进程 try/catch no-op（不得让渲染层崩）。
- **可移植**：Web 无 `desktopAPI` ⇒ 走 no-op 分支，行为零变化；非 Electron 环境不得出现 `window.desktopAPI` 访问异常。
- **平台事实（已知后果，需入发布说明）**：桌面端窗口已收进托盘时，免打扰触发的「应用内提示」**用户看不到**（无窗口）；这是「免打扰即静默」的必然结果，本批**不**为其破例发系统通知。休眠期间不计时不补无意义提示（引擎既有口径不变）。
- **a11y**：指示器 `role="img"` + `aria-label`；圆点装饰性元素 `aria-hidden="true"`。
- **国际化**：新增文案全部走 `packages/shared/locales`（`types.ts` / `zh-CN.ts` / `en-US.ts` 三处齐备）。

## 七、验收标准（AC 五覆盖）

- **AC1（主路径 · `#1`）** Given 通知权限已授予、免打扰未命中、声音开，When 一个专注自然结束，Then 系统通知发出且 `silent === false`，且**不出现**应用内提示。
- **AC2（主路径 · `#1`）** Given 免打扰命中（含跨午夜区间），When 专注结束 / 休息结束 / 休息即将结束任一触发，Then **系统通知调用次数 = 0** 且出现**一条**含阶段与时长的应用内提示。
- **AC3（边界 · `#1`）** Given 通知开关关闭且免打扰未命中，When 专注结束，Then 系统通知 0 次、应用内提示 0 条，且计时引擎照常流转（下一阶段/记录落库不受影响）。
- **AC4（异常 · `#1`）** Given 设置读取抛错（storage 不可用），When 专注结束，Then **照发系统通知且不静音**（fail-open），且无异常冒泡到引擎（阶段流转与记录落库照常）。
- **AC5（主路径 · `#2`）** Given 番茄专注运行中，When 剩余时间变化，Then `document.title` 为 `MM:SS · 专注` 且**每秒最多更新 1 次**；暂停后数值冻结；切换到休息阶段后 ≤1s 变为 `MM:SS · 休息` / `长休息`。
- **AC6（负向闭环 · `#2`）** Given 计时曾运行过，When 用户结束专注 / 取消 / 应用回到 idle，Then `document.title` 恢复为启动基线串（**不残留**倒计时）；且离开番茄页但引擎仍在跑时标题**继续更新**。
- **AC7（主路径 · `#2` 桌面端）** Given 桌面端运行中且托盘可用，When 计时运行 5s，Then 托盘 tooltip 显示阶段 + 剩余时间；**主进程 IPC 调用次数 ≤ 5**（1s 节流生效）；窗口收进托盘后仍持续更新。
- **AC8（异常 · `#2` 桌面端）** Given `desktopAPI` 不存在（Web）或托盘状态为 `unsupported`，When 计时运行，Then 无异常、无控制台错误，其余功能（标题、通知、记录）照常。
- **AC9（主路径 · `#3`）** Given M=4、处于 idle，When 完成第 1 次专注并开始第 2 次，Then 指示器为 ●○○○ + `第 2/4 轮`；完成第 3 次后为 ●●●○ + `本轮结束后长休`；完成第 **4** 次专注后**直接进入长休息**（校验 `DEF-111` 已修）。
- **AC10（边界 · `#3`）** Given M=1，When 完成 1 次专注，Then 进入长休且周期计数归零（下一轮从 ●○○ 重新开始，若 M=4）；M=10 时 DOM 圆点为 10 个且不溢出。
- **AC11（负向闭环 · `#3`）** Given 处在专注阶段，When 用户点「跳过」或「结束专注」（非自然完成），Then 周期计数**不变**、不触发长休、指示器文字与阶段保持一致（不得出现「已完成 N/M」与实际不符）。
- **AC12（设计一致性 · 全批）** 新增 UI 只用既有 `nue-*` token 与 `nue-div`/`nue-text`；圆点三态「实心/空心/文字」可辨（去色后仍可分）；新增文案中英齐备；移动端 `git status --porcelain -- packages/presentation-react apps/mobile` = 0。
