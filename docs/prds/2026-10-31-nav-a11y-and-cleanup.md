# PRD：导航可访问性规避 + 会话边界收敛 + 判据死件清理

> 状态：**待开工确认** · 批次：`B20261031-nav-a11y-cleanup` · 目标版本 `v1.15.2`（PATCH）
> 缺陷来源：`DEF-116`（上游已立 `nue-ui#108`）· `DEF-123` · `DEF-113` · 上一批复验报告 `docs/qa/2026-10-31-T598-session-ux-tail-verify.md`

## 一、问题证据

1. **`DEF-116`**：`nue-link` 的 `route` 形态渲染 `<a class="nue-link">` **无 `href`**（`to` 形态更差，落成 `to="[object Object]"`；`href` 形态丢 SPA 语义）。鼠标点击仍可导航 ⇒ 废掉的是**键盘 Tab / 中键新标签 / 读屏链接语义**。根因 = 模板恒绑 `:href="… ? void 0 : href"`，`undefined` 覆盖 RouterLink 自算值。本仓已规避认证互链 2 处；**仍受影响 11 处静态调用点 + `smart-list` 动态面**（`project-smart-list` / `tag-smart-list` 不传 slot ⇒ 用户自建清单与标签全部无 href，数量随数据增长）。
2. **`DEF-123`**：「会话结束类别」清除点分散在 3 处（`sign-in.vue` 登录成功 / 桌面 `unlock-gate.vue` 登出 / `use-settings-sign-out.ts`）⇒ 新增登出或登录入口必漏清，`DEF-121`（误报「登录已过期」横幅）即此结构导致。
3. **`DEF-113`**：`packages/shared/utils/task-attributes-parser.ts` 的 `parseTaskPriority` 是**第二份三档 switch**（违「判据单一来源」），当前**无调用点**；若未来被接线，`urgent` 会被解析错。

## 二、目标指标

- 侧栏 / 清单 / 标签导航：**Tab 可达、可中键开新标签、读屏识别为链接**（`<a href>` 非空 + 可聚焦）。
- 「会话结束类别」清除点 **收敛为 1 处**；新增登出/登录入口漏清时**有断言可红**。
- 优先级判据**只有一份**实现（`DEF-113` 死件并入单一来源或删除）。

## 三、范围 / 非范围

**范围**

- `DEF-116` 本仓规避：11 处静态调用点 + `smart-list` 动态面 ⇒ 改用原生 `router-link`（保留 `.nue-link` 主题类与 focus 轮廓）或等价可聚焦实现。
- `DEF-123`：新增统一「会话边界」入口（如 `onSessionBoundary({ type: 'sign-in-success' | 'sign-out' })`）承担清除，3 处调用点改指它。
- `DEF-113`：`parseTaskPriority` 并入 `prioritySNMap`/域单一来源，或删除死件（若确无调用点）。

**非范围**

- `nue-ui` 仓库本体改动（上游 `nue-ui#108` 另处理）。
- `DEF-114`（看板按优先级分组接线）—— 需单独 PRD。
- `DEF-115`（移动端 `urgent`）—— 需授权。
- 会话失效判据模型（沿用 ADR D1/D5/D6）。

## 四、用户场景

- **S1 键盘用户**：Tab 能在侧栏「任务 / 日历 / 番茄钟 / 搜索」与自建清单/标签之间移动，Enter 进入。
- **S2 多任务用户**：Ctrl/中键点击清单 ⇒ 在新标签打开（以前点了变空白或无效）。
- **S3 读屏用户**：导航项被识别为链接（有可访问名 + `href`）。
- **S4 已登录用户**：登录成功后再进登录页，**不应**看到上一次的「登录已过期」横幅。
- **S5 未来维护者**：新增一个登出入口而漏清类别 ⇒ 测试**红**（而不是靠人记）。

## 五、业务规则

- **R1 不新造组件范式**：规避优先用原生 `router-link` + 既有 `.nue-link` 主题类；确需新组件先报 PM。
- **R2 可访问性三重证据**：`href` 非空、`tabIndex >= 0`、`focus()` 后 `activeElement` 命中 —— **禁止用 stub 证明框架行为**（项目已发生过的反例）。
- **R3 单一清除点**：「会话结束类别」的清除只能在一处实现；失效路径的「先写 reason 后清理」顺序不得破坏（`DEF-121` 教训）。
- **R4 判据单点**：优先级解析不得存在第二份实现。
- **R5 视觉零变化**：导航项外观（颜色、间距、hover/focus 态）与现状一致，只补链接语义。

## 六、NFRs（业务视角基线）

- 不新增依赖；静态渲染数量不变（不因规避引入额外嵌套导致列表性能回退）。
- 键盘焦点环清晰可见（对比度按 `DESIGN.md`），不依赖颜色单独表意。
- 移动端红线零改动。

## 七、AC

- **AC1（`DEF-116` 主路径）** 11 处静态调用点渲染的 `<a>` **均有非空 `href`**，且等于 `router.resolve(path).href`。
- **AC2（`DEF-116` 边界）** `smart-list` 动态面：**任意条数**（含 0 / 1 / 多）的自建清单与标签项都有 `href`。
- **AC3（`DEF-116` 可访问性）** 各导航项 `tabIndex >= 0`；`focus()` 后 `document.activeElement` 命中该项；有可访问名。
- **AC4（`DEF-116` 负向）** 不存在残留 `to="[object Object]"` 属性；点击仍正常导航（不因改 `router-link` 丢 SPA 行为）。
- **AC5（`DEF-123` 主路径）** 登录成功 / 设置页登出 / 桌面解锁门登出 三条路径都经**同一入口**清除类别（断言：只存在 1 处清除实现 + 三路径各自清空）。
- **AC6（`DEF-123` 异常）** 新增一个「假登出入口」做变体 ⇒ 断言应红（证明结构防复发）。
- **AC7（`DEF-113`）** `parseTaskPriority` 不再存在第二份三档 switch（删除或有调用点且复用单一来源）；若删除，需说明无调用点证据。
- **AC8（红线）** `git status --porcelain -- packages/presentation-react apps/mobile` = 0 行。

## 八、上线闭环

- 顺序：`qa` 用例先行（AC1–AC6 可先写，红基线）→ `rd-fe` 实现 → `qa` 复验（含变异：删 `href` 注入 / 去掉统一清除入口 / 复活第二份 switch 各须转红）→ PM 验收 → RD 合并 → **PATCH `v1.15.2`**。

## 九、变更治理

- 若规避过程中发现**必须**改 `nue-ui` 才能修（而非规避）⇒ 停手报 PM，不在本仓改组件库。
- 若 `smart-list` 的动态面无法在不改公共组件契约的前提下补 `href` ⇒ 先报 PM，评估「改 `smart-list` 契约」是否值得，不得静默留下一半页面无 `href`。
- 视觉若出现任何差异（间距/颜色）⇒ 视为回归，须修回零变化（R5）。
