## 5. 业务规则

### 5.1 新建入口改为「点击刻度标签 → 创建对话框」（Q1/Q7 + T83-C5）

- **移除**：空白点击触发内联新建；日视图**不再渲染** `day-quick-create`。同步清理本单造成的孤儿：`onTrackClick`、`day-quick-create` 节点、`quickCreate*` 状态、`.day-quick-create` 样式、`QuickCreate` import（`quick-create.vue` 组件本体**保留**，月/周在用）。
- **新增**：点击**带文本的刻度标签** → 打开创建对话框：
    ```ts
    // 宿主桥（唯一 payload 构造点）
    onCreateTaskAt(startMin) // 宿主侧与 createTaskOnDay 相邻实现，复用同一 prefillScope() + dialogManager
    // 内部：
    dialogManager.open(TASK_CREATOR_DIALOG_KEY, { startAt, endAt })
    ```
    - `startAt` = `dayjs(anchorKey).startOf('day').add(tickMin, 'minute').toISOString()`；`endAt` = `+ DAY_SNAP_MINUTES`（30 分钟）。**逐字镜像 `createTaskOnDay`**（ISO 格式、同口径）。
    - **落点**：新增 `CalendarDayContext.onCreateTaskAt(startMin)`，宿主侧实现；日视图自足回退实现同一函数（`use-calendar-day.ts` 已注入 context 作兜底）。**禁**日视图直连构造 payload（避免同一功能两套口径）。
- **可点范围与可访问性**（T83 裁决）：
    - 仅**带文本**刻度可点；空文本列**不可点、不参与 tab、不触发 pan**。
    - 原生 **`button`** 语义（唯一新建入口必须键盘可达）：`aria-label="在 14:30 创建任务"` + `title`。
    - DOM：`button` 是 `.day-col-head` 的**孙节点** ⇒ `[data-testid="day-columns"]` 的**直接子节点数仍 === 列数**（冻结契约不受影响）；标签文本仍在 `textContent` ⇒ 「24/48 个有文本」断言口径不变。
    - 标签 `position:absolute; left:0; transform:translateX(-50%)`（**居中于刻度线**，见 §5.6）；**首列 `translateX(0)`、末列 `translateX(-100%)`** 边界保护 ⇒ **点击目标 = 可见标签本身**（消除「点标签左半落到前一列」的错位）。
    - 48 个 tab stop **接受**；若将来嫌噪，另立单做 roving tabindex，**不得**在本单降级为 `tabindex="-1"`。
- **依据（T83 复核）**：`creator.vue:51` 的 `open(createTaskOptions)` 按 `key in states` 白名单预填（含 `startAt`/`endAt`，`if (!presetVal) return` ⇒ ISO 字符串安全）；**单例确认**：`useDialogManager()` 每次 `new`，但全 Web 应用**只有 1 个调用点** `index-view.ts:66`，经 `INDEX_VIEW_CONTEXT_KEY` provide；`dialog-adapter.vue`（注册处）与 `calendar-view.ts` 注入同一 key ⇒ **同一实例**；`daily/index.vue` 已 inject 该 context ⇒ **零新增管道**。
- **`n` 快捷键（用户默认采纳 PM 建议）**：一并接到同一 `TASK_CREATOR_DIALOG_KEY`（payload 用当前选中日 / 默认时段），消除「文档称快速新建、实际无效」的割裂。
- **登记（T83-C10）**：`snapMinutes(…, 'floor')` 因 D5 被取代而在生产路径**失去唯一消费者**（仅剩单测）⇒ **已退役模式**，保留纯函数与用例，不删除。

### 5.3 名称贴边（sticky）与裁切提示（Q3=A / Q10=A + **T83-C1 修正设计**）

> ⚠️ **原方案（PM 初稿 `position: sticky; left: 0`）被 T83 证伪**：`task-bar.vue` 的 `.cal-item` 有 `overflow: hidden` ⇒ **它自身即最近 scrollport** ⇒ sticky 偏移恒为 0（名称完全不动）；且 `.cal-item-text { flex: 1 }` ⇒ 名称宽 ≈ 条宽 ⇒ 无可滑动余量。

**修正设计（T83-C1）**

```css
/* task-bar.vue：opt-in prop（stickyLabel?: boolean，默认 false ⇒ 月/周零变化） */
.cal-item.is-sticky-label {
    overflow: visible;
    clip-path: inset(0);
} /* 剪裁等价，但不建 scrollport */
.cal-item.is-sticky-label .cal-item-text {
    position: sticky;
    left: 0;
    flex: 0 1 auto;
    width: max-content;
    max-width: 100%; /* 收缩到内容宽 ⇒ 产生滑动余量 */
    overflow: hidden;
    text-overflow: ellipsis;
}
```

- 为何可行：scrollport = `.day-body`（唯一）⇒ `left: 0` 贴**视口左缘** ✓；包含块 = `.cal-item` 内容盒 ⇒ **钳制在条内** ✓；条滚出后名称随条消失 ✓ —— **零 JS/测量**。
- 用 `clip-path: inset(0)` 而非删除剪裁：**`clip-path` 不建立 scroll container**（也不建立包含块），视觉剪裁等价（`.cal-item` 无圆角；`::before` 优先级色条 / hover 背景 / 下拉菜单裁剪语义与 `overflow:hidden` 一致）。
- **月/周可证零变化**：整块 CSS 由 `is-sticky-label` 门控，prop 默认 `false` ⇒ 月/周 DOM/CSS 逐字节不变（比 `:deep()` 覆盖更安全）。
- **硬约束（须进新 ADR C9 并遵守）**：`.cal-item-text → .day-body` 之间**不得存在任何 scroll container** ⇒ **禁止**在 `.day-seg`/`.cal-lanes`/`.day-grid`/`.day-scroll`/`.cal-item` 上新增 `overflow(≠visible)`、`contain(≠none)`、`transform`/`filter` 而不重新验证本特性。`.day-axis-bg`（无子节点）**可**加 `contain: paint`。
- **登记为约束的必然结果（写入 AC3 文案，防验收误判）**：可滑动余量 = **条宽 − 名称宽**；**名称宽 ≥ 条宽时为 0** ⇒ 名称随条滚出，**非缺陷**。
- **裁切提示（Q10=A + T83-C7）**：左右缘各一层**渐隐遮罩**，置于**滚动容器之外** —— 新增 `.day-body-wrap`（`position: relative`）包住 `.day-body` + 两个绝对定位遮罩，`pointer-events: none`；仅当该侧确有可滚动内容时显示（`scrollLeft`/`maxScroll` 驱动，rAF 合并）。**禁**计数徽标；**禁**把遮罩放进 `.day-body`。

### 5.4 左右缘拉伸与手柄可见性不变量（Q4 / Q6 + **T83-C2/C3**）

**两侧手柄恒在（用户 2026-09-22 裁决，取代 T83 原不变量）**

> 任务条**左右缘各一个手柄**，**不做 `isStart` / `isEnd` 门控**（续接段也不移除任何一侧能力）。**左拉改 `startAt`（`endAt` 不变）；右拉改 `endAt`（`startAt` 不变）。**

- 用户原话：「不用移除，左侧也需要同样的功能，左侧拖拉是改动开始时间，右侧拖拉是改动结束时间。」
- **被取代**：T83 的「左手柄 ⟺ `isStart`、右手柄 ⟺ `isEnd`」（当时给 (i) 同单禁止 / (ii) 挂账两案；用户选择**第三种：两侧恒在、完全对称**）。
- **⚠️ 已知可接受（用户明确要求）**：跨日任务的**续接段**两侧手柄，改动落在**相邻日**（左拉改前一天 `startAt`、右拉改次日 `endAt`），**当前视图不可见** ⇒ 条不延伸、拖动看似「没反应」，直至改动跨越 `00:00`/`24:00` 才显现；**写回与撤销 toast 仍正常发生**。这是「两侧恒在」的必然代价，**非缺陷**。
- **TASK-16 C13（真实值锚）仍是硬约束**：两侧手柄拖动原点必须是**真实 `startAt`/`endAt`**，**禁**用裁剪后的 `00:00`/`24:00` 反推（否则跨日任务每拖一次就漂移）。
- **不夹取（r2 明确）**：写回值**不得夹取到可见日边界** —— 左拉续接段允许 `newStart` 早于当天 `00:00`、右拉续接段允许 `newEnd` 晚于当天 `24:00`；计算式 = `真实锚点 + Δ`，**禁**以 `[0, 1440]` 夹取（TASK-16 D2「离开视图不夹取」）。

**写回约束（T83-C3）**

1. **新增第三种手势**（如 `gesture='resize-start'`），**不得**复用「时长不变」的 move 分支；写回 `{ startAt: newStart, endAt: 真实 endAt 不变 }` ⇒ **时长改变**（与右缘同族）。
2. 锚点 = 真实 `startAt` + Δ（C13）；`Δ = (clientX − originX) ÷ perMin`。
3. 吸附 `round` + 最短 `DAY_SNAP_MINUTES`：钳制 `newStart ≤ realEnd − DAY_SNAP_MINUTES`（领域不变量由**该钳制**保证，不依赖领域报错）。
4. 写回链路仍走 `useCalendarSchedule` + U2 撤销内核（**TASK-16 C9 不变**）；失败回退同右缘。
5. 手柄 DOM：`.day-task-resize--start`（`left: -3px`），与右缘同规格；注意不被 `.cal-item::before` 遮挡（`.day-seg` 内 `z-index: 3` 已高于条）。
6. 遵守 TASK-16 D2（离开视图不夹取）：`newStartMin` 由 `clientX ∈ [rect.left, rect.right]` 天然限界。

**✅ 已拍板（用户 2026-09-22）**：**两侧手柄恒在、完全对称**（既不禁止左侧、也不禁止右侧）；T83 原不变量与 (i)/(ii) 两案均被取代，见上。

### 5.5 空白拖拽横向平移（Q5 + **T83-C4**）

- **阈值 = `DRAG_THRESHOLD_PX`（5px，单一阈值，复用 `use-drag-schedule.ts:15`）** —— **不另设 4px**（否则「同样小位移，条上算点击、空白处算平移」不可解释）。
- 仅横向：`scrollLeft = startScrollLeft − (clientX − startX)`；纵向不变；未超阈值 ⇒ 不滚动。
- **目标排除清单（零抢占）**：pan 挂 `.day-body` **冒泡相**，首行 `if (target.closest('.cal-item, .day-seg, .day-task-resize, .day-cols-head, .day-allday-lane')) return`；条上由 `useDragSchedule` 独占（只「不处理」，**不** `stopPropagation`/`preventDefault` ⇒ 顺序无关）；**列头必须显式排除**（解决「从刻度标签起拖既 pan 又开对话框」）。
- `setPointerCapture` 于 `.day-body` + 结束释放（无需 window 监听，卸载即释放）；**禁**在 `pointermove` 读布局（起始一次性读取除外）。
- `.day-body.is-panning { cursor: grabbing; user-select: none }`；`.day-axis-track` 的 `cursor: pointer` **改为 `grab`**。
- **不**并入/泛化 `useDragSchedule`（TASK-16 C8 禁第三套任务拖拽会话壳；pan 是不同关注点）⇒ 新建极小 `daily/use-day-pan.ts`，仅复用 `DRAG_THRESHOLD_PX` 与阈值/取消/卸载形状。

### 5.6 刻度进一步细分（Q4=A / Q8=A + **T83 数值与层级裁决**）

- **×4 档 10 分钟 → 5 分钟**：列数 **288**；`30 % 5 === 0`（I1 ✓）；`MIN_SPAN_MIN = 30` ⇒ 最小条宽 **6 列**；标签仍 **48 个**（规则分支无需改动，每 6 列一个标签）。
- **标签相对刻度线水平居中**（`translateX(-50%)`，首末列边界保护）。
- **格线四级 + 嵌套链规则**：`60 / 30 / 10 / 5`（透明度随粒度变细单调递减）；**集合 = 当前粒度 ⊕ 嵌套上级（至 60min）**，相邻层级整除：30min 档 = `60/30`（**与 ×1/×1.5 现状视觉等价**）、15min 档 = `60/30/15`、5min 档 = `60/30/10/5`。以**档位修饰类**（`.day-col-lines--30/--15/--5`）驱动 ⇒ AC6 可做**结构断言**；仍**全部 CSS 渐变**（禁 `列数 × N` DOM）。
- **列宽下限优先**：`总宽 = max(k × 容器宽, 列数 × 20px)` ⇒ 1200px 容器下 ×4 取 5760px（**等效 4.8×**），列宽 20px。
- **ADR r2 已落盘**（本单触发）：D1 矩阵 ×4 行更新、**I2 → I2′（≥20px）降级**（唯一性推导在 I2′ 下**仍成立**，代价已登记）、D1.2 格线四级、**C2 枚举 `{30,15,10}` → `{30,15,5}`**、**C6 列头节点数 ×4 = 288**、**D2 登记 100px → 120px** + 分工说明。
- **分工说明（防验收误判）**：细格线管**读数**，吸附管**写入**（TASK-16 C2「显示路径连续不吸附」）；5min 格线 + 恒定 30min 吸附 = 6 条线中 1 条可吸附，**不是矛盾**。
- **实现注意**：`daily/day-zoom.ts` 的 `DayAxisSpec.columnMinutes: 30|15|10` **须同步为 `30|15|5`**（类型层不得再允许已退役的 10min）。
