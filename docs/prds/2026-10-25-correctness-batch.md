## TL;DR

- **做什么**：修三处「用户一看就发现」的正确性 / 体验问题 —— 优先级排序变字母序、深链被"上次访问路由"顶掉、设置里两处无障碍欠账。
- **给谁**：用列表排序、用分享/刷新深链、用读屏或键盘操作设置的用户。
- **成功标准**：优先级排序符合「高→中→低」；带目标地址的链接打开后**停在该地址**；设置左栏可被读屏正确播报、可用方向键切换。
- **不做什么**：不动提醒 / 同步 / 番茄 / 视图结构；不修「桌面刷新掉登录」（`DEF-45`，已转观察，需再现取证）。
- **为什么做**：三条都是**低成本高可感**的错误；a11y 两条是上一批（`T533`）明确留下的欠账。

## 一、问题证据

- **`DEF-11`（P2）优先级排序为字母序**：桌面 / 首页列表按 `priority` 排序时按字符串比较（`high` / `low` / `medium`）⇒ 呈现为「高 → 低 → 中」，与用户心智「高 → 中 → 低」不符；同一查询在服务端/本地排序口径不一致时还会出现两端口径不同。
- **`DEF-59`（P3）深链被覆盖**：冷加载带 `hash` 的 URL（如分享出的 `#/tasks/all/kanban/t1`）会被「上次访问路由」（`LAST_VISITED_ROUTE`）覆盖 ⇒ 打开后跳到上次的位置，18 处引用该键。产品口径此前未定，故长期挂账。
- **设置 a11y 欠账（`DEF-82` + `tablist`）**：① 共享改密表单三个输入只有 `placeholder`（`nue-input` 不透传 attrs 到内层 input）⇒ 读屏与表单自动填充拿不到持久标签；② 设置左栏 `role=tablist` 未关联 `tabpanel`（无 `aria-controls`）、方向键不切换分类 ⇒ 键盘/读屏用户只能 Tab 逐个过。
- **5 Whys（本批共性）**：这些小错能长期存在 ← 都属"功能能跑但语义不对"，没有自动化断言盯着；无断言 ← 断言只覆盖主路径可见结果，不覆盖**语义正确性**（排序语义 / 地址优先级 / 可访问名）⇒ 本批要求把这三类语义以断言固定下来。

## 二、目标指标

- **指标 1（排序语义）**：`priority` 升/降序排序在**两端口径一致**，且升序 = 低→中→高、降序 = 高→中→低（可核：给定混合数据断言序列）。
- **指标 2（深链）**：带目标路由的冷加载 URL 打开后，最终路由 = URL 指定路由；无目标路由时才回落「上次访问」。
- **指标 3（a11y）**：改密表单每个输入有**非空可访问名**；设置左栏 `tab` 与 `tabpanel` 一一关联，方向键（上/下）可切分类，`Home`/`End` 跳到首/末。
- **指标 4（零行为回归）**：提醒、同步、番茄、视图结构行为不变；既有用例零改动（除 a11y 与排序的新增断言）。
- **口径缺口**：无埋点；靠用例 + 用户真机（读屏为可选）。

## 三、范围 / 非范围

**范围**

1. **`DEF-11` 排序语义**：把 `priority` 排序改为**语义序**（`high > medium > low`，缺省/无值排最后），升序取反；**统一排序实现**（服务端与本地两端口径一致，或明确只改客户端并记录口径）。
2. **`DEF-59` 深链优先**：加载时**URL 显式路由优先**，仅当 URL 无目标（如 `/`）时才用 `LAST_VISITED_ROUTE` 回落；写入「上次访问」的逻辑保留（在确定最终路由后再写）。
3. **a11y 收尾**：
    1. 共享改密表单：三个输入补**程序化标签**（`aria-label` 或 `<label for>`），且**不改动** `nue-input` 组件本身（照既有 `autocomplete` 手法经 `innerInputRef` 设置，或在外层用 `<label for>` 包裹）。
    2. 设置左栏：`role=tablist` 的每个 tab 与对应面板建立 `aria-controls` / `id` 关联，面板 `role=tabpanel` + `aria-labelledby`；`↑/↓`（或 `←/→`，随现行布局方向）切分类，`Home`/`End` 跳首末；焦点跟随。
4. **口径留痕**：在缺陷池把 `DEF-11` / `DEF-59` / `DEF-82` 置为已闭环；`DEF-45` 保持「转观察」并写明再现任据（三步取证）。

**非范围**

- **`DEF-45` 桌面 `Ctrl+R` 刷新掉登录** —— 理由：用户 2026-09-30 复现未成功、已转观察；本批不占施工位，再现时按「token 是否仍在 / Console 报错 / 首个失败请求」三步取证后再定。
- **同步口径批（`DEF-46` / `DEF-47` / `DEF-44`）** —— 理由：需先定「清单排序/图标是否跨端同步」，属规则决定，另批。
- **窄屏抽屉同步状态（`DEF-30`）** —— 理由：需先修订原 ADR 口径。
- **托盘常驻 / 多设备只提醒一次 / PWA 推送** —— 理由：独立批次（送达完整性）。
- **移动端同类缺陷（`DEF-18` / `DEF-38`）** —— 理由：用户已裁定不修 + 红线目录。
- **排序 UI 改造 / 新排序字段** —— 理由：本批只修语义错误，不加能力。

## 四、用户场景

- **画像**：在列表里按优先级排查待办的用户；把某个视图链接收藏/分享的用户；用键盘或读屏操作设置的用户。
- **关键路径**：点「优先级」排序 → 看到「高 → 中 → 低」；打开收藏的链接 → 直接落在那个视图与任务详情；设置里用 `Tab` 进左栏后按 `↓` 切到「提醒」。
- **页面状态清单**：排序（升/降两态）· 深链（有目标 / 无目标）· 设置左栏（鼠标 / 键盘 / 读屏）。

## 五、业务规则

- **R1 排序语义单一来源**：`priority` 的**序**由一处映射（高=0/中=1/低=2，无值=最后）定义，服务端与客户端共用同一口径；禁止字符串比较。
- **R2 无值排序**：未设置优先级恒排最后（升序与降序都最后）。
- **R3 地址优先级**：**URL 显式路由 > 上次访问路由 > 默认（任务页）**；「上次访问」只在确定为默认入口时写入，避免自我强化。
- **R4 可访问名来源**：输入的可访问名来自**持久标签**（`aria-label` / `<label for>`），不得依赖 `placeholder`。
- **R5 tab 语义完整**：每个 `tab` 必有 `aria-controls` 指向存在的 `tabpanel`；面板 `aria-labelledby` 指回 `tab`；键盘切换后焦点与 `aria-selected` 同步。
- **R6 只读不改契约**：不改任务/清单/同步的数据字段与接口；排序只改**比较口径**。

## 六、NFRs

- **兼容性**：Web + 桌面同代码；移动端零改动（红线）。
- **性能**：排序为内存比较，不新增请求；深链判断在路由初始化一次，无额外往返。
- **可访问性**：改密表单三输入可访问名非空；左栏 tab/tabpanel 关联完整、键盘可达；焦点可见。
- **可维护性**：排序映射单一来源 + 用例锁定；深链规则写进注释与用例；禁止在各处重复实现「上次路由」判断。

## 七、AC

- **验证接缝**：既有用例面 —— 任务列表/排序用例（`packages/presentation/task/...` 与本地仓储 list 用例）+ 路由初始化用例（`apps/web/src/views/index/__tests__`）+ 设置对话框用例（`settings/dialog/__tests__`）+ 改密表单用例（`packages/presentation-identity`）；**新增断言挂在既有文件**，不新建测试框架。
- **AC1（主路径·排序）**：Given 混含 高/中/低/无值 的任务，When 按 `priority` 降序，Then 序列为 高→中→低→无值；升序为 无值→低→中→高。
- **AC2（边界·排序）**：Given 同优先级多项，Then 以既有默认次序（创建时间）稳定排列，不抖动；Given 全部无值，Then 保持原序。
- **AC3（一致性·排序）**：Given 同一查询，Then **两端口径一致**（服务端与本地返回同一序；若服务端不在本批改动范围，需在 PRD/缺陷池明确记录「仅客户端」口径与理由）。
- **AC4（主路径·深链）**：Given 冷加载 `#/tasks/all/kanban/t1`，Then 最终路由为该视图且详情打开；Given 无目标（`#/`），Then 回落到上次访问。
- **AC5（负向·深链）**：Given 深链目标非法（不存在的 `viewType` / 无效 `taskId`），Then 走既有回退（任务页）且**不报错**；写回「上次访问」的值必须是**最终**路由。
- **AC6（a11y·改密表单）**：Given 打开密码修改，Then 三个输入的可访问名非空且互不相同；断言用真实组件（非 stub）。
- **AC7（a11y·左栏 tab）**：Given 设置左栏，Then 4 个 `tab` 均有 `aria-controls` 且目标存在；`↑/↓` 与 `Home/End` 可切换并同步 `aria-selected` 与焦点；窄屏分段件不因此改变行为。
- **AC8（设计一致性/回归）**：Given 全仓，Then 提醒/同步/番茄/视图结构行为零变化（既有用例零改动）；移动端红线 0；不新增 `nue-*` token。
