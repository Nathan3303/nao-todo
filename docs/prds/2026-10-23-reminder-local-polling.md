# 2026-10-23 任务提醒改本地轮询（Web + 桌面统一）PRD

> **状态**：待开工确认（v1.0，2026-10-23）· **Issue**：[#232](https://github.com/Nathan3303/nao-todo/issues/232) · **批次**：`v1.12.15`（PATCH）+ 跨仓 `nao-todo-server` 一处开关
> **来源（成熟度）**：grill 两轮结论（2026-10-23）+ 架构回执 `docs/reports/T526-arch-review.md` + 接缝经 QA 确认（`T525`）⇒ 走 pm-to-spec 综合路径，不重复盘问。
> **指针**：ADR 提议 `docs/adr/2026-10-23-reminder-local-judgment.md`（arch 出，待 PRD 落定后终签）。
> **硬约束**：移动端红线目录零改动 · 不新增弹窗动作 · 单一判定实现（禁双源双提醒）。

## TL;DR

- **做什么**：把任务提醒的「到期判定」从服务端 SSE 推送搬到本机轮询，Web 与桌面共用一份实现。
- **给谁**：会关标签页、网络不稳、会离线使用 Web / 桌面的用户。
- **成功标准**：断网也能按时弹；同一条提醒在同浏览器 / 刷新 / 重开后**恰好 1 次**；关着应用期间到期的，重开后补弹一次。
- **不做什么**：不动弹窗动作集（确认 + 稍后）· 不做聚合列表 · 不动移动端 · 本批不删服务端 SSE 路由。
- **为什么做**：SSE 断线即静默漏提醒；且关闭期间到期的提醒会被服务端 cron 抹掉痕迹 ⇒ 重开无补弹。

## 一、问题证据

- **现状（读码）**：Web `apps/web/src/views/index/reminder-sse.ts` 连 `/sse/reminders?token=`，`error` 只关闭连接 ⇒ 标签页开久后**静默漏提醒**。
- **补弹不可达（arch 实证）**：服务端 cron 每分钟 `ProcessReminders` 会清空一次性提醒的 `remind_at`、推进重复提醒，该字段又同步回本机 ⇒ 关闭期间到期的条目在上云后 ≤60s **失去「已到期」痕迹**。
- **两端不一致**：桌面已有本地扫描，但去重账是**内存 Set** ⇒ 刷新 / 多标签重复弹；且**漏弹子任务**、**会弹已完成任务**（与 ADR D1 口径不一致）。
- **5 Whys**：提醒不可靠 ← 判定权在服务端；为何在服务端 ← 早期客户端没有本地数据；为何现在可移 ← 离线阶段一已让本机有完整任务数据；根因 ← **应用已本地优先，提醒判定仍留在服务端**。

## 二、目标指标

- **指标 1（离线）**：断网状态下到期提醒照常弹出，该路径 **0 次网络请求**。
- **指标 2（唯一性）**：同一条提醒（`taskId@remindAt`）在同浏览器多标签 / 刷新 / 重开后**恰好 1 次**。
- **指标 3（准时）**：可见标签页延迟 **≤10s**（有精确定时的 ≤1s）；隐藏态不承诺；回前台 **≤2s** 补扫；冷启动补弹 **≤30s**。
- **指标 4（单实现）**：全仓仅一份提醒判定实现，桌面独立扫描器下线。
- **口径缺口**：无埋点；靠引擎/组件测试 + 用户真机勾选。

## 三、范围 / 非范围

**范围**

1. Web 下线 SSE 提醒通道（模块 + `use-sse.ts` + `VITE_DISABLE_SSE` 相关引用清零）。
2. 桌面下线自有扫描器与独立弹窗装配，改用同一引擎（经 webapp 复用同壳）。
3. 判定口径：只读本机已同步任务；排 deleted / archived / givenUp / done；**不过滤子任务**。
4. 重复提醒 daily/weekly 由本机在弹出后推进下一次（monthly 仅历史兼容、不续期）。
5. 展示前**落账**（键 `taskId@remindAt`），跨标签互斥、跨重开持久。
6. 错过（关闭 / 隐藏期间到期）的条目在重开 / 回前台补弹，同一条只补一次。
7. 系统通知点击 = 聚焦 + 打开该任务详情；弹窗内点任务名 = 打开详情（现为空实现）。
8. 跨仓：停用服务端提醒 cron 的字段改写（一处开关，不删代码、可回滚）。

**非范围**

- **移动端 App**（`packages/presentation-react` / `apps/mobile`）—— 红线，不随 Web / 桌面需求改动。
- **删除服务端 `/sse/reminders` 路由** —— 客户端不再连即空转；与 cron 代码清理合并下一批跨仓清理。
- **弹窗新增动作（完成 / 自定义稍后）** —— 用户裁定保持「确认 + 稍后」，只强化跳详情。
- **聚合列表视图** —— 用户裁定多条同期仍逐条弹 + `n/total` 进度。
- **免打扰时段 / 提示音 / 角标** —— 本次未提出，避免范围膨胀。
- **多设备之间只提醒一次** —— 口径为「同浏览器一次」，多设备各自提醒。
- **月重复续期** —— 设置 UI 已隐藏该选项，仅兼容历史数据展示。

## 四、用户场景

- **画像**：把任务留在浏览器标签或桌面端、网络时好时坏、偶尔完全离线的用户。
- **关键路径**：设提醒 → 关掉或放着 → 到点（可离线、可在后台）→ 回到应用看到提醒 → 确认 / 稍后 → 需要时直接打开任务详情。
- **页面状态清单**：准时弹出 · 重开后补弹 · 无到期项 · 队列 `n/total` · 通知权限被拒（只弹应用内）。

## 五、业务规则

- **R1 判定权在本机**：到期 = 本机任务 `remindAt ≤ now` 且状态活跃（非删除 / 归档 / 放弃 / 完成）。
- **R2 同一条只一次**：键 = `taskId@remindAt`；跨标签 / 刷新 / 重开均成立。
- **R3 稍后即新条目**：Snooze 改写 `remindAt` ⇒ 键变 ⇒ 到点再弹一次。
- **R4 重复提醒**：daily/weekly 弹出后推进到下一次；仅活跃任务继续。
- **R5 子任务**：与顶层任务同口径提醒（对齐服务端现状）。
- **R6 未操作不复弹**：弹过即视为已提醒（无论是否点确认）。
- **R7 不丢**：隐藏 / 关闭期间的到期项在恢复可见或重开后补弹（受 R2 约束）。
- **R8 时钟**：以本机时间为准；系统回拨不得导致同键重复弹。
- **R9 只提醒本机有数据的任务**：未同步到本机的任务不提醒（用户已接受）。

## 六、NFRs

- **性能**：轮询不得造成可感知卡顿或耗电；不得每轮全表解密（技术口径见 ADR §NFR，arch 终签）。
- **可用性**：本地库不可读 / 桌面未解锁 ⇒ 不崩、不误弹，恢复后补扫。
- **兼容性**：Web（含手机浏览器）+ 桌面两端同语义；桌面解锁后补扫。
- **隐私安全**：提醒内容仅本地展示，不新增出站请求与数据外发。
- **可访问性**：通知权限被拒时仍以应用内弹窗承载，信息不减。
- **可维护性**：单一实现、单一去重键，禁两套判定并存。

## 七、AC

- **验证接缝**：`packages/shared/reminder/` 的引擎工厂 `createReminderEngine(deps)` + 纯核心 `collectDueReminders(tasks, now, claim)`（QA 已确认 2026-10-23，`[T525]` 回执）。
- **AC1（主路径）**：Given 本机有 `remindAt` 到期的活跃任务，When 引擎运行，Then 应用内弹窗 + 系统通知各 1 次，载荷含 `taskId/taskName/description`。
- **AC2（离线）**：Given 断网，When 到期，Then 照常提醒；断言该路径 **0 次网络 / EventSource 调用**。
- **AC3（负向闭环·唯一性）**：Given 同一条到期项，When 多标签同开 / 刷新 / 重开，Then 全部场景合计**恰好 1 次**（展示前落账 + 互斥）。
- **AC4（负向闭环·补弹）**：Given 关闭或隐藏期间到期，When 重开 / 回到前台，Then 补弹 1 次（可见 ≤2s、冷启动 ≤30s）；再重开不再弹。
- **AC5（边界·准时）**：Given 可见标签页，Then 延迟 ≤10s（有精确定时的 ≤1s）；隐藏态不承诺、回前台补偿。
- **AC6（异常与降级）**：Given 本地库读失败，Then 静默不崩、不落账、下轮可补；Given 通知权限被拒，Then 仅应用内弹窗、不抛错。
- **AC7（边界·过滤）**：Given done / 归档 / 放弃 / 删除任务到期，Then 不弹；Given 子任务到期，Then 弹。
- **AC8（边界·稍后与重复）**：Given 稍后 N 分钟，Then 到点再弹 1 次；Given daily/weekly，Then 弹后推进下一次并在下次到期再弹。
- **AC9（主路径延伸·跳转）**：Given 点系统通知，Then 聚焦并打开该任务详情；Given 点弹窗内任务名，Then 打开详情（当前为空实现，须实现）。
- **AC10（设计一致性）**：Given 全仓，Then 仅一份判定实现（SSE 模块删除、桌面旧扫描器下线、`VITE_DISABLE_SSE` 清零）；弹窗仍用 `TASK_REMINDER_DIALOG_KEY`，通知标题 = 动作语义、正文 = 任务名；移动端红线 0。
- **AC11（跨仓）**：Given 服务端，Then 提醒 cron 的字段改写已停用（开关可回滚）；`/sse/reminders` 保留、无客户端连接。

## 八、上线闭环

- **验证**：RD 自测受影响面（web / desktop / shared）→ PM 读码核 AC → 用户真机勾选（清单落 `docs/reports/`）。
- **监控**：不适用：无埋点，靠测试 + 用户真机回报。
- **灰度**：不适用：开关只有服务端一处；服务端先关开关、客户端随后上。
- **回滚**：客户端 revert 单 squash 提交；服务端把开关恢复原值。
- **发布**：`v1.12.15`（PATCH）+ 服务端同批；发布说明写明「重复提醒续期与补弹改由客户端负责」。
