# TASK-01 子任务创建继承父任务清单与时间窗（endAt 锚定继承 + 快照语义）交付归档

> 日期：2026-09-10（交付终签日）｜范围：`packages/presentation`（web + desktop 共用面）｜发布：`v1.4.1`
> 配套：ADR [`2026-09-10-task-01-subtask-inherit.md`](../adr/2026-09-10-task-01-subtask-inherit.md)（r3）

---

## 1. 背景与 5 Whys

**触发**：在「已排期 + 已归清单」的父任务下新增子任务，子任务**丢失清单归属与时间窗**（落到收集箱 + 当天），用户需逐个重设。

| 层级 | 追问                                          | 结论                                                                              |
| :--- | :-------------------------------------------- | :-------------------------------------------------------------------------------- |
| 1    | 为什么子任务没有清单/时间窗？                 | 子任务创建走 `createSubTask`，payload 硬编码 `projectId: null` + `endAt: now`     |
| 2    | 为什么硬编码？                                | 创建入口只收「名称」一个参数，未读取父任务上下文                                  |
| 3    | 为什么没读父上下文？                          | 子任务创建是"快速输入"路径，历史实现选择用默认值                                  |
| 4    | 为什么默认值是"收集箱 + 今天"而非父任务的值？ | 无继承需求定义 ⇒ 未定义"子任务是否应继承父任务清单与时间窗"                       |
| 5    | 为什么现在才暴露？                            | 排期/归清单能力（CAL 系列）先于子任务创建体验；父任务有窗口后，"子任务空窗"才可见 |

---

## 2. 目标与埋点口径

- **目标**：在父任务创建子任务时，子任务**自动获得与父任务一致的清单归属与时间窗**，无需二次设置；父任务后续修改**不回写**已存在的子任务。
- **埋点**：**不新增任何埋点/遥测**（决策 D4）；验收以「父子字段相等」+「快照不变」+「既有桶计数不变」为客观判据。
- **零契约变更**：不改后端、不改同步协议/表结构/游标（约束 C-T8）。

---

## 3. 规则（两段式权威口径）

```
① 若父任务 endAt 有效 ⇒ endAt 一定继承；startAt =（有效 且 start ≤ end）? 父 startAt : null
② 否则（endAt 缺失/无效）⇒ startAt = endAt = null（未安排）
```

- **锚点 = `endAt`**：本域"未安排"谓词、日历格子、逾期判定均以 `endAt` 为准。
- **"无效/倒置"只作用于 `startAt`**（视同缺失 ⇒ `null`），**禁止**因此丢弃有效 `endAt`（约束 C-T11）。
- `projectId` **原样拷贝**；`''`/`null` 均等价于收集箱。
- **快照语义**：拷贝发生在**创建时刻**；父任务此后修改时间窗/清单，**不回写**已存在的子任务（禁级联，C-T5）。

## 6. 约束清单（C-T1…C-T11，逐条对应 ADR §8）

- **C-T1** 继承范围仅三字段｜**C-T2** 值快照（禁重算；**适用范围仅客户端拷贝**，跨表示法以秒级瞬时比较）｜**C-T3** `startAt`/`endAt` 必须显式 `null`（禁 `undefined`）｜**C-T4** 父 VO 不可得 ⇒ 兜底不抛错
- **C-T5** 禁级联｜**C-T6** 单一实现 + 第二入口显式登记不一致｜**C-T7** 父 VO 只取 `task-details.ts` 的 `task` ref｜**C-T8** 零 API/契约变更
- **C-T9**（r2）移动端**不继承**须在 ADR/PRD/验收显式声明，移动端不得声称"继承"｜**C-T10**（r2）`fillStartAt()` 保持**零调用**（不得新增调用点）｜**C-T11**（r2）`endAt` 有效则必定继承

## 10. 遗留项

1. **`DEF-SYNC-04`（服务端，P1，待立单）**：`nao-todo-server/domain/task/valueobjects/createTask.go:49-61 FillStartAt()` 在客户端**已提供 `startAt`** 且 `endAt` 非空时用 `time.Now()` **覆盖**；`repoImpl.go:127` 覆盖分支亦命中 ⇒ **每次被接受的推送都会重刷 `startAt`**（父子各取自身写入时刻 ⇒ 相差数秒）。用户可见影响：显式设置的开始时间被丢弃且随每次编辑漂移；`endAt < now` 时产出 `startAt > endAt`（客户端 `updateSchedule` 会拒绝该组合）。**修复口径**：`startAt` 已提供时不得覆盖 + 服务端往返回归（秒级瞬时不变）。**不并入"离线写入边界"批次**。
2. **移动端未覆盖（D7-a=B）**：`packages/presentation-react/src/logic/compose-task-usecase.ts:129` 同源实现**未修改** ⇒ 手机端新建子任务仍为「收集箱 + 当天」。**已知且显式接受**；**不得**在验收/文案中声称移动端"继承"。B-5 已命中 ⇒ **下次触碰子任务创建默认值必须直接升级为 application 层默认解析**，不得逐端修。
3. **死代码登记**（不删，仅登记）：`CreateTaskValueObject.fillStartAt()`（`create-task.ts:98`，零调用；C-T10 禁止新增调用点）｜`taskDetailsStore.taskDetails` / `setTaskDetails`（C-T7 禁止使用）｜`LocalUserRepoImpl`｜`NueAside` `v-model:displayed`。
4. **纯表示法与语义差异的判定口径**：跨表示法（`Z`+毫秒 ↔ `+08:00` 秒级）以**秒级瞬时相等**判定，不算快照破坏；只有**语义性重写**才记数据变更。
