## 1. 问题证据与 5 Whys

**现象（用户直提）**：导出浮层只有一种输出、且**取数失败时浮层根本不出现**——`footer/index.vue` 是「点菜单 → 先取数 → 成功才开框」，失败只弹 toast，用户无法在框内重试；同时导出用途已分化为「纯文本二次编辑 / 程序处理 / 视觉分享」三类，单一 Markdown 无法覆盖。

| 层  | 追问                                                                                                                              |
| :-- | :-------------------------------------------------------------------------------------------------------------------------------- |
| ①   | 用户把任务带出应用后的用途不同：编辑文本、喂给程序、贴到文档/聊天里给人看                                                         |
| ②   | 现有导出只有一条 Markdown 渲染链，`export-dialog.vue` 只认一个 `markdown` prop                                                    |
| ③   | 取数与渲染被焊死在「点菜单 → 取数 → 开框」的固定顺序里，失败路径**从 UI 上整体消失**（无浮层、无重试、须重走菜单）                |
| ④   | **命题**：把「取数」与「渲染」解耦为「开框 → 框内 LoadingError → 一次取数 → 三格式纯函数渲染」，并新增 JSON / HTML 账单两个渲染器 |

**需求①的定性**：与 TASK-13 已交付内容字面重复，用户明确为**现状基线描述**（Q1=baseline）⇒ 本单增量 = ②JSON + ③LoadingError + ④HTML；**Markdown 输出格式零变更**，不触碰 TASK-13 §5.2 冻结基准。

## 4. 用户场景

- **画像**：需要把任务（含子任务）带出 nao-todo、且用途分化的用户：写文档 / 交给脚本处理 / 贴进聊天与文档给人看。
- **场景卡**：打开任务详情 → 底部「更多」→ 导出 → 浮层**立即出现并显示加载态** → 加载完成默认展示可编辑 Markdown → 按用途切到 JSON（只读结构化）或 HTML（账单单据预览）→ 点「复制」带走。
- **关键路径**：footer `nue-dropdown`（`export-task`）→ `exportVisible = true`（**立即开框**）→ 对话框 `watch(modelValue)` false→true 触发 `startExport()` → 递归取数（含一级子任务检查项，只读，不写 store）→ 组装 `ExportTaskNode` → 三渲染器纯函数派生 → 框内按格式展示 → 复制。
- **页面状态清单**（LoadingError 三态 + 交互态）：

| 状态          | 表现                                                                      |
| :------------ | :------------------------------------------------------------------------ |
| 打开即加载    | 框内 `loading-error loading`（文案 `task.details.export.loading`）        |
| 加载成功      | 默认 Markdown：`NueTextarea` 可编辑；顶部格式分段控件可用                 |
| 加载失败      | 框内 `loading-error error`（错误文案 + 「重试」按钮）**且**保留失败 toast |
| 重试中        | 回到加载态（「重试」防重入：进行中不可重复点）                            |
| 格式切换      | **零加载**（本地重渲染）；JSON/HTML 期间「还原」按钮不显示                |
| Markdown 编辑 | 编辑期不被 props 覆盖；切走再切回**保留**草稿                             |
| 已还原        | 文本回到最近一次生成的 Markdown                                           |
| 复制成功      | toast `copySuccess`                                                       |
| 剪贴板不可用  | toast `copyFailed`                                                        |

- **边界数据**：子任务无任何丰富字段；仅有检查项；描述含换行与 HTML 特殊字符（`<` `&` `"`）；多层子任务（至 5 层）；标签为空；任务处于「已放弃」；检查项/子任务数为 0；超长描述。

## 5. 业务规则

### 5.1 取数与状态机（本单核心变更）

- **流程反转**：`footer/index.vue` 的 `export-task` 分支**不再 `await exportTask()`**，直接 `exportVisible.value = true`；取数由对话框打开触发。
- `use-export-task.ts` 暴露 `status: 'idle' | 'loading' | 'error' | 'ready'`；`startExport()`（打开时触发）与 `retry()`（按钮触发）共用同一实现：置 `loading` → 取数 → 成功 `ready` / 失败 `error` + toast `task.details.export.failed`。
- **重试防重入**：`status === 'loading'` 时忽略重复触发。
- **取数结果缓存**：一次成功取数得到 `ExportTaskNode` 树并缓存；**格式切换不重新取数**（`status` 保持 `ready`）。
- 失败语义沿用 TASK-13：任一取数失败即整体失败（返回 `null`），不展示半成品。`error` 文案取 `unwrapError(err)`，空则回退 `task.error.loadFailed`。
- 关框（`true→false`）重置为 `idle` 并清空缓存；下次打开重新取数（不持久化）。

### 5.2 格式选择与可编辑性

| 格式     | 展示                                             | 可编辑              | 复制内容                                     | 「还原」 |
| :------- | :----------------------------------------------- | :------------------ | :------------------------------------------- | :------- |
| Markdown | `NueTextarea`（沿用 TASK-13）                    | ✅ 本地草稿 `draft` | **编辑后草稿**                               | 显示     |
| JSON     | 只读 `<pre>`（等宽、可滚动）                     | ❌                  | JSON 文本（`generateTaskJson` 输出）         | 隐藏     |
| HTML     | `iframe[sandbox=""]` + `:srcdoc`（只读渲染预览） | ❌                  | 完整 HTML 文档源码（含 `<style>`，非富文本） | 隐藏     |

- 格式选择器放 `#content` **顶部**（**不占用 `#header`**——`nue-dialog` 未占用 header 时自带右上角关闭按钮，TASK-13 已据此移除 footer「关闭」；占用 header 会连带移除关闭入口）。
- 默认 Markdown；**不持久化**所选格式；关框后下次打开回默认。
- **新增 props 全部必须有默认值**：`format` 默认 `'markdown'`、`status` 默认 `'ready'`、`json` / `html` / `errorMessage` 默认 `''`。⇒ 旧挂载契约 `{ modelValue, markdown }` 继续有效（`export-dialog.test.ts` 零变更、必须全绿）；`markdown` prop **保留**（不改名、不删除）。
- 切换格式**不重置** `draft`（切走再切回保留编辑结果）。
- 三格式共用同一 `ExportTaskNode` 树，**不重复取数**（见 §5.1）。

### 5.3 JSON 输出契约（`generateTaskJson(root, exportedAt)` → string）

纯函数、无 Vue/i18n 依赖；**固定 schema 全量输出**（不因空值省略键，便于机器稳定消费）。

```json
{
    "formatVersion": 1,
    "exportedAt": "2026-09-23T02:30:00.000Z",
    "task": {
        "id": "a1b2c3d4-0000-0000-0000-000000000000",
        "name": "示例任务",
        "state": "in-progress",
        "stateLabel": "进行中",
        "priority": "high",
        "priorityLabel": "高",
        "isGivenUp": false,
        "startAt": "2026-09-20T01:00:00.000Z",
        "endAt": "2026-09-20T10:00:00.000Z",
        "projectId": "p-1",
        "projectName": "工作",
        "tagIds": ["t-1"],
        "tagNames": ["重要"],
        "createdAt": "2026-09-19T02:00:00.000Z",
        "updatedAt": "2026-09-19T03:00:00.000Z",
        "description": "原始描述\n保留换行",
        "checkItems": [{ "name": "检查项一", "isDone": true }],
        "subTasks": []
    }
}
```

- **口径（Q7=A）**：既保留**原始枚举值**（`state` / `priority` / `isGivenUp` / `projectId` / `tagIds`）供程序消费，也附**本地化文案**（`stateLabel` / `priorityLabel` / `projectName` / `tagNames`）供人读。`stateLabel` 沿用既有 `resolveStateLabel`（「已放弃」优先于领域状态）。
- **空值语义**：标量与时间无值 → `null`（**空字符串归一为 `null`**，避免 `""`/`null` 两种空态）；数组无值 → `[]`。
- **时间**：原样 ISO 字符串（不做 `YYYY-MM-DD HH:mm` 格式化——那是 Markdown/HTML 的展示口径）。
- **`description` 保留原始换行**（机器口径不折叠）。
- **递归字段名 `subTasks`**（与 Markdown/HTML 的「子任务」段一致；源字段 `children` 是内部命名）。
- 缩进 2 空格；`JSON.stringify(payload, null, 2)`；末尾换行。
- **不敏感于 locale**：仅 `stateLabel`/`priorityLabel`/`projectName`/`tagNames` 随语言变化。

### 5.4 HTML 输出契约（`generateTaskHtml(root, labels, generatedAt)` → string）

纯函数、无 Vue/i18n 依赖；输出**完整 HTML 文档**（`<!DOCTYPE html>` + `<head>` + `<style>` + `<body>`），**自包含**：无外部资源、无脚本、无网络请求。

- **固定浅色（纸质单据）**：`<meta name="color-scheme" content="light">` + `color-scheme: light`，**不跟随暗色模式**——保证「预览所见 = 复制源码所得」（Q5=A 的 iframe 沙箱内渲染结果与外部粘贴结果一致）。
- **样式自包含**：所有样式写在文档内 `<style>` 块，颜色/尺寸用**字面值**（不引用 `--nue-*` 变量，外部环境无这些变量）。规格见 §14。
- **转义**：所有插值文本经统一转义（`&` `&amp;` / `<` `&lt;` / `>` `&gt;` / `"` `&quot;` / `'` `&#39;`），覆盖任务名、子任务名、检查项名、描述、标签名、项目名、状态/优先级文案。
- **描述保留换行**（`white-space: pre-wrap`）。
- **空值处理**：空字段/空检查项/空子任务**对应段落整段省略**（与 Markdown 一致），不留空标题。
- **合计段（本格式独有）**：新增派生信息——`检查项 x/y`、`子任务 x/y`（`y` 为**全层级**子任务总数）；`y === 0` 的组整行省略；两组皆无 → 整段省略。全部完成时给出完成态标记（规格见 §14）。
    - **边界澄清（2026-09-23，裁定 C；防误读）**：**判定条件是「对象数 `y`」，不是「完成数 `x`」** ⇒ `x = 0` 且 `y > 0` **必须输出 `0/y`**（例：1 个未完成检查项、无子任务 → 输出 `检查项 0/1`，且**不得**出现 `0/0`）。即「有可计之物」才决定行是否出现；`0/y` 是**合法读数**而非空总计。反向断言（`not.toContain('0/y')`）为**过度断言**，不得作为规格依据。
- **递归深度**沿用 `MAX_EXPORT_DEPTH = 5`；层级用缩进 + 左侧虚线导轨表达，**不嵌套卡片**。
- `generatedAt` 由调用方传入已格式化字符串（保持纯函数可测）；`html lang` 随 locale 取 `zh-CN` / `en-US`。

### 5.5 沿用规则与显式差异

| 规则               | Markdown（不变）                       | JSON                           | HTML                 |
| :----------------- | :------------------------------------- | :----------------------------- | :------------------- |
| 深度上限           | `MAX_EXPORT_DEPTH = 5`                 | 同                             | 同                   |
| 空段省略           | 整段省略                               | 不省略，输出 `null`/`[]`       | 整段省略             |
| 描述换行           | **折叠为单行**（单行语法）             | **保留**                       | **保留**（pre-wrap） |
| 一级子任务丰富字段 | 状态/优先级/开始/截止/标签/描述/检查项 | 全字段（含 id/项目/创建/更新） | 同 JSON 展示口径     |

> 描述换行的差异是**刻意**的：Markdown 的 `- 描述：值` 是单行子行语法，折叠是格式约束；HTML/JSON 无此约束，折叠反而丢信息。

## 6. NFRs

- **纯度**：`generateTaskJson` / `generateTaskHtml` 与 `generateTaskMarkdown` 同构——纯函数，无 Vue / 无 i18n / 无 I/O，**文案由调用方注入**；`generatedAt` / `exportedAt` 亦注入 ⇒ 全部可确定性单测。
- **可测的接缝**：iframe 只做 `:srcdoc` 绑定这一件事，组件测试断言 `srcdoc` 属性 === 纯函数输出（jsdom 不渲染 iframe 内部，故渲染正确性必须由纯函数单测保证）。
- **安全**：`iframe sandbox=""`（禁脚本/禁同源，最严）；生成器转义覆盖五字符；单测含注入载荷（`<img src=x onerror=...>`、`</style><script>`、`&`、裸 `'`/`"`）断言输出中不存在可执行片段。
- **无外部请求**：HTML 文档不得含 `src=` / `href=` / `@import` / `url(` 外部指向（单测断言）。
- **性能**：取数次数与格式数解耦（恒为 1 次任务树递归取数）；三渲染器仅字符串拼接，无额外 I/O。长文本（>10k 字描述）不得卡顿——JSON/HTML 视图容器 `overflow: auto`。
- **布局稳定**：内容区容器设 `min-height: min(60vh, 32rem)`（与 TASK-13 预览区等高）⇒ 加载态→内容态**高度不跳变**。
- **可访问性**：格式选择器为可聚焦按钮组（键盘可达）；iframe 带 `title`；LoadingError 文案可读。
- **兼容性**：不改服务端契约、不改数据结构、不改领域导出面；`ExportTaskNode` 扩展为前端本地类型 additive 变更（Markdown 渲染器不读新字段 ⇒ 输出零变化）。
- **门禁**：`vp check` + `vp test --run` + `pnpm run guard:ddd` + `pnpm run desktop:build` + `vp run webapp build` 全绿；移动端红线零改动。

- **账单母语的对应关系**：项目名 = 抬头；任务名 = 单据标题；元信息 = 交易信息；检查项/子任务 = 明细行；完成度 = **合计**；撕口 = 分享边界；脚注 = 开具时间。

### 14.3 版式与对齐

- 单列、**左对齐**（单据不是海报）；`max-width: 30rem`（≈480px，小票宽度）居中；`padding: 2rem 1.75rem`。
- 标签在左、**数值右对齐**（账单惯例，也是本格式与 Markdown 的关键差异）：用两列网格 `grid-template-columns: max-content 1fr`，数值列 `text-align: right`。
- 层级**只用字号 + 字重 + 分割线**表达（灰阶系统里颜色无法承载层级）。任务名 `1.5rem/700`；段标题 `0.75rem/600` + 字距 `0.08em`；明细 `0.875rem`；脚注 `0.75rem`。
- 缩进单位 `1.25rem`；层级导轨为左侧 `1px dashed #D8D8D8` 竖线。

### 14.5 合计计量条（本设计的记忆点）

- 结构：`track`（`height: 6px`，`background: #E8E8E8`）+ `fill`（`background: #1A1A1A`，`width: <完成率>%`）。
- 旁列分数 `x/y` 用等宽数字，右对齐。
- **纯 CSS 实现**，不依赖 `■/□` 字形（跨平台字形宽度不一致会导致计量条错位）。
- 全部完成（`x === y && y > 0`）时，在分数右侧追加完成标记（实心方框 + 文案 `task.details.export.heading.*` 之外不新增文案）。
- `y === 0` 的组整行省略；两组皆无 → 整个合计段（含段标题）省略。
- **`x === 0` 且 `y > 0` 时仍输出 `0/y`**（判定条件是对象数 `y`，不是完成数 `x`）——例：仅 1 个未完成检查项 ⇒ 输出 `检查项 0/1`；`0/0` 永不出现。

### 14.6 自评与修订（两遍法的第二遍）

| 原草稿                                   | 判定                                                                                       | 修订                                                                 |
| :--------------------------------------- | :----------------------------------------------------------------------------------------- | :------------------------------------------------------------------- |
| 「细线 + 零圆角 + 板式列」组合           | 是 AI 生成设计的常见默认（broadsheet 套路）——但**本单 brief 明确要求账单风格，brief 优先** | 保留；但把唯一「响亮」额度全部让给合计计量条，其余保持克制           |
| 每段都加「01 / 02 / 03」式序号           | 内容不是序列，编号无语义                                                                   | **删除**（按技能规约：结构装置必须承载信息）                         |
| 元信息用 `状态 · 优先级 · 时间` 中点连接 | 中点是通用 AI 痕迹，且账单母语本就是「左右两列对账」                                       | **改为右对齐两列**，全面弃用中点连接                                 |
| 加「条形码式等宽 ID 块」                 | 纯装饰，且没有编码语义                                                                     | **删除**（出门前摘掉一件配饰）；单据号由「短 ID + 开具时间」一行承载 |
| 段标题用全大写 + 字距                    | 技能规约列为默认痕迹——但中文无大小写，英文侧用**小字 + 字距**即可，不上全大写              | 保留小字 + `0.08em`；英文文案用句首大写，**不全大写**                |
| 完成态用绿色                             | 引入色相即打破纯灰阶系统，且黑白打印/色觉障碍下失效                                        | **改为实心/描边方框**                                                |
| 撕口纯装饰                               | 撕口可承载「分享边界」语义                                                                 | 保留，置于脚注之上作为信息分组装置                                   |

### 14.7 质量底线

- 无动画（纸是静态的）；`prefers-reduced-motion` 无关。
- 语义标签：`<article>` + `<h1>` 任务名 + `<section>` 分段 + `<ul>/<li>` 明细 ⇒ 复制到别处仍保留结构语义。
- 文本对比度：主文字 `#1A1A1A` / 纸白 `#FFFFFF` ≈ 17:1；次级 `#6B6B6B` ≈ 5.7:1（达 AA 正文）；弱化 `#9A9A9A` **仅用于未完成明细的名称**，不上正文。
- 长内容：描述与明细列允许自然换行，不得横向溢出（`overflow-wrap: anywhere` 于名称/标签）。
- 窄屏（≤480px）：`max-width: 30rem` 自然降为 100%，两列网格的数值列可换行（`min-width: 0`）。
