# PRD：登录体验收尾批（W3 提示 + `DEF-119` + `DEF-117` + `DEF-116`）

> 状态：**待开工确认** · 批次：`B20261031-session-ux-tail` · 范围：web + desktop（移动端红线不动，`lynx.ts` 除外需授权）
> 上游依据：ADR `docs/adr/2026-10-31-credential-coherence.md`（D5 提示形态 · D1 判据 · D6 头拼接）+ 缺陷池 `DEF-92/116/117/119`

## 一、问题证据

1. **`DEF-92`（P2，W3）**：到期 / 被顶号时*静默*回登录页 —— 用户不知道自己在哪、为什么被踢。ADR D5 已定：类别**本地推断**（JWT `exp` 已过 ⇒ 过期；未过 ⇒ 他处登录），提示形态 = **登录页顶部横幅**（模态已否决）。
2. **`DEF-119`（P2，用户 2026-10-31 真机）**：Web 改密 ⇒ 服务端撤销其它设备会话（SEC-03）⇒ 桌面 `Ctrl+R` 刷新检入得 **`10022`** ⇒ 只显示「验证未完成，请重试」。文案不说明原因、默认动作（重试）在该场景**无效**，用户误以为应用故障。
3. **`DEF-117`（P3）**：`persistence-go/**` **61 处**内联 `` `Bearer ${…}` ``、**5 处** `=== 10041` 字面量（`preference-sync.ts` ×4、`lynx.ts` ×1）未走单点；已用冻结计数棘轮焊死（新增即红），本批清偿并归零。
4. **`DEF-116`（P3）**：`nue-ui` 1.13.0 的 `nue-link route="…"` 渲染 `<a class="nue-link">` **无 `href`** ⇒ 认证互链可点性不可保证（`T589` AC8 侧发现）。

## 二、目标指标

- 会话结束时**用户能看懂发生了什么**：到期 / 被顶号各一句人话 + 可关闭（`DEF-92`）。
- 改密后在他端刷新：文案**说明原因**并给出**有效动作**（重新登录），重试降为次要（`DEF-119`）。
- `Bearer` 拼接与凭证码比较**只剩单点**（棘轮常量归零或仅留 `lynx.ts` 1 处并注明授权缺口）。
- `DEF-116` 影响面**有清单 + 规避结论**，组件是否已修有上游结论。

## 三、范围 / 非范围

**范围**

- **W3**：`sessionStorage` 记 reason（按 `local-storage-policy.ts` 的 `USER_SCOPED_STORAGE_KEYS` 登记）· 登录页顶部横幅（zh/en）· 跨标签广播（复用既有 `applyRemoteSignOut` 等价形态）· `session-end.ts` 注释「四路复用」表述修正（实际 3 路 + 广播 1 路）。
- **`DEF-119`（方案 A）**：`check-in.vue` 的 `10022` 分支分类 —— token 未过期 ⇒ 判「密码可能在其它设备修改 / 会话已被撤销」⇒ 文案给原因 + **主按钮「重新登录」**；并发检入（短时多次）**保留「重试」为主**，两者都要在。
- **`DEF-117`**：61 处改 `buildAuthHeaders(...)`（或请求器统一注入）；5 处改 `isCredentialCode` / `decideSessionEnd`；**每改一处同步下调棘轮**，正常路径归零；`lynx.ts` 1 处**保持并注明**（需移动端授权）。
- **`DEF-116`**：核查 `nue-link` 各形态（`route` / `to` / `href`）、列出受影响页面清单、给本仓规避方案；上游问题单独立项说明（不在本仓改组件库）。

**非范围**：服务端错误码细分（已裁定不做）· 移动端产品代码（`presentation-react` / `apps/mobile`）· `nue-ui` 仓库本体改动 · 新的凭证判据模型（沿用 D1）。

## 四、用户场景

- **S1 会话 7 天到期**：刷新/任意请求撞 `10041` ⇒ 回登录页，顶部横幅写「登录已过期，请重新登录」。
- **S2 被顶号 / 他端登出**：⇒ 横幅写「你的账号已在其它设备登录」。
- **S3 改密后他端刷新（`DEF-119`）**：⇒ 检入页说明「密码可能已在其它设备修改」，主按钮「重新登录」。
- **S4 并发检入**（同一设备双击/快速刷新）：⇒ 仍以「重试」为主，文案不夸大为「密码被改」。
- **S5 多标签**：一个标签登出/失效 ⇒ 其它标签同步回登录页并显示同一横幅。

## 五、业务规则

- **R1 文案说人话**：禁技术键名/错误码；中英同步；每条给「发生了什么 + 下一步」。
- **R2 判据单一**：类别推断只用 D1 的单点实现（`credential-codes` + `exp` 解析），不在页面里另写判断。
- **R3 不误导**：不确定原因时用「可能」而非断言；「重新登录」与「重试」的主次必须与真实概率一致。
- **R4 提示可关闭、不阻断**：横幅可关闭、不遮挡表单、不自动消失（可手动关）。
- **R5 无新增 secret/明文落到日志**；`sessionStorage` 只存**类别枚举**，不存 token/密码。
- **R6 单点不回退**：本批不得重新引入第二处凭证判据或 `Bearer` 拼接。

## 六、NFRs（业务视角基线）

- 不新增运行时依赖；不改服务端与移动端契约；离线可进入能力不回退。
- 横幅与检入失败态需满足对比度下限（`DESIGN.md`），文字 + 图标不单靠颜色。
- 跨标签广播不得造成「多标签互相回环跳转」。

## 七、AC

- **AC1（`DEF-92` 主路径）**：JWT `exp` 已过 ⇒ 会话结束 ⇒ 登录页出现**过期**横幅（文案断言）。
- **AC2（`DEF-92` 主路径）**：JWT 未过期但服务端判 `10041/10042` ⇒ 出现**他处登录**横幅。
- **AC3（`DEF-92` 异常）**：reason 缺失/脏值 ⇒ 回退到**通用**一句（不显示空白/不乱断言）。
- **AC4（`DEF-92` 边界）**：横幅**可关闭**且关闭后不复发；刷新页面 reason 仍可读（`sessionStorage`）但**登出即清**。
- **AC5（`DEF-92` 跨标签）**：标签 A 登出 ⇒ 标签 B 回登录页且显示同一横幅；**无回环**（A/B 各只导航一次）。
- **AC6（`DEF-119` 主路径）**：`10022` + token 未过期 ⇒ 文案含「密码」/「其它设备」语义，**主按钮 = 重新登录**，次按钮 = 重试。
- **AC7（`DEF-119` 异常/边界）**：短时并发检入仍以**重试**为主；`10022` + token 已过期 ⇒ 走过期语义（不报「密码被改」）。
- **AC8（`DEF-117`）**：`persistence-go` 与 `shared/requester`（`lynx.ts` 除外）**0 处**内联 `` `Bearer ${…}` ``；`=== 10041` 字面量 **0 处**；棘轮常量同步归零（`lynx.ts` 单列并可注明「待移动端授权」）。
- **AC9（`DEF-117` 回归）**：清偿后同步相关用例 0 红；`def6-mirror-e2e` / `t326` 等 e2e 语义不变。
- **AC10（`DEF-116`）**：给出受影响页面清单 + 规避结论；若采用原生 `router-link`/`a[href]` 规避，需有**可访问名与可聚焦**断言。
- **AC11（设计一致性）**：横幅与失败态沿用既有 `nue-*` token，不新造色值；浅/暗可读。
- **AC12（红线）**：`git status --porcelain -- packages/presentation-react apps/mobile` = **0 行**。
