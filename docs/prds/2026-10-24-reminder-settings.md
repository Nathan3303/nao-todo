> **指针**：上一批 PRD `docs/prds/2026-10-23-reminder-local-polling.md`（其「免打扰 / 提示音」非范围**由本单接管**）。
> **硬约束**：移动端红线零改动 · 单一引擎实现（禁双端各写一套）· 不开 PWA/Web Push · 不做多设备「只提醒一次」· 不做桌面托盘常驻。

## TL;DR

- **做什么**：给已能可靠到点的提醒补上「设置区（通知 / 声音 / 免打扰）· 免打扰静默排队 · 弹窗一键完成 · 清单名与原定时间 · 权限引导」。
- **给谁**：桌面端与手机浏览器两端都在用的用户（当前提醒功能面偏薄）。
- **成功标准**：能不被打扰（免打扰时段内零弹窗、零通知、提醒不丢，结束后补一次）；能一键完成；一眼看到是哪个清单、原定几点；手机端不再"开了通知却收不到"却毫无解释。
- **不做什么**：不做 PWA/Web Push、不承诺手机系统通知、不做多设备只提醒一次、不做桌面托盘常驻、不做「最近错过」列表。
- **为什么做**：提醒可靠性已解决（`v1.12.15`），但「什么时候别打扰我 / 我想怎么被提醒 / 我没法只靠网页发通知」这些**日常手感与预期校准**还缺。

## 一、问题证据

- **无法关闭**：全仓无提醒设置项（i18n 无 `notification` / 免打扰键）⇒ 用户只能靠「关掉浏览器」来停止打扰。
- **通知非全函数（R1，arch 实锤）**：`packages/shared/utils/notification.ts` 的 `new Notification(...)` **无 try/catch**；Android Chrome 存在 `Notification` 对象但构造抛错 ⇒ 引擎已 claim 未 consume ⇒ **该条永久不再提醒**。
- **手机发不了系统通知（R2）**：iPhone Safari 普通标签页无该 API；Android Chrome 需 Service Worker ⇒ 现状「有通知开关也无从解释」。
- **信息不足**：弹窗只有任务名 + 描述，看不出清单与原定时间；用户点进详情又打断节奏。
- **弹窗动作只有「确认 / 稍后」**：完成任务要「点任务名 → 进详情 → 改状态」三步（用户 2026-10-24 裁定补「完成」）。
- **5 Whys**：打扰不可控 ← 无设置项；无设置项 ← 提醒长期由服务端推送、客户端只做展示；现在为何要补 ← 判定已下移本机，提醒成了**客户端能力**，就该有客户端设置与预期说明。

## 二、目标指标

- **指标 1（免打扰不丢）**：免打扰时段内到点提醒 **0 次弹窗 / 0 次通知 / 0 条落账**；时段结束后（或下次打开 / 回前台）**每条恰好补弹 1 次**。
- **指标 2（可控）**：设置区三项改动**即时生效**且跨设备一致（同账号另一浏览器拉取后生效）。
- **指标 3（少一步）**：完成任务从「3 步」降为「弹窗内 1 次点击」。
- **指标 4（不再静默失败）**：通知不可用（拒绝 / 不支持 / 构造失败）时**提醒照常以应用内形式出现**，且用户被明确告知一次。
- **口径缺口**：无埋点；靠引擎/组件测试 + 用户真机勾选。

## 三、范围 / 非范围

**范围**

1. 设置区（并入既有「应用设置」区块，**不新增第 4 个 Tab**）：**通知开关**（只管系统通知）· **声音开关**（系统通知自带声音，用 `silent` 控制）· **免打扰**（单段时段，可跨天，默认关闭）。
2. 免打扰 = **静默排队**：引擎前置抑制门（在 `claim` 之前），时段内零副作用；结束后由既有 10s 轮询 / 可见性补扫**逐条补弹**（不新增触发器）。
3. 弹窗新增「**完成**」（用户裁定，替代原「跳过本次」方案）：点击即把任务标记完成并出队；后续重复提醒因「已完成被过滤」自然停止。
4. 弹窗补「**清单名 + 原定提醒时间**」：提醒事件携带 `projectId` / `remindAt`（原定时刻），清单名由装配层注入（弹窗不引 router / 仓储）；补弹时标注「原定 …」。
5. **权限引导**：三态（已允许 / 已拒绝 / 不支持）判定 + **一次性设备级提示** + 设置区常驻状态；**索权改到设置区用户手势**触发（启动自动索权会被浏览器忽略）。
6. **设置跨设备同步**：复用偏好快照 `preferences.reminder = { notify, sound, quietHours }`（服务端零改动），本地身份级单键 + 既有偏好队列。
7. **R1 修复**：通知适配层**永不抛**（能力探测 + try/catch + 降级标记），保证「通知失败 ≠ 提醒丢失」。

**非范围**

- **PWA / Web Push** —— 用户 2026-10-24 裁定 A：本批只做应用内 + 引导，推送另立项（iPhone 需先「添加到主屏幕」）。
- **手机端系统通知承诺** —— 同上，发版说明须写清手机端以应用内为准。
- **多设备只提醒一次（账号级）** —— 需账号级已提醒状态与服务端配合，另立项。
- **桌面托盘常驻 / 开机自启** —— 另一块「送达」短板，另立项。
- **「最近错过的提醒」列表** —— 本批不做（补弹已覆盖），如需另立项。
- **一次性提醒的「取消提醒」入口** —— 详情页日期选择器已有清空入口，本批不重复建设。
- **每日多时段免打扰** —— 架构裁示单段（`[start,end)`，可跨天）够用；多段留待有真实诉求。

## 四、用户场景

- **画像**：白天在电脑前、晚上也用手机看任务；晚上 22 点后不想被弹窗和通知吵。
- **关键路径**：设置里开免打扰 22:00–08:00 → 期间到点的提醒静默排队 → 第二天早上打开应用，逐条补弹（标「原定 07:30」）→ 点「完成」直接勾掉，或点任务名看详情。
- **页面状态清单**：设置区三项（开 / 关 / 不可用）· 免打扰生效中（设置区显示"现在处于免打扰"）· 通知被拒（常驻提示 + 一次性说明）· 补弹（带「原定」）· 完成失败（提示 + 留在队列）。

## 五、业务规则

- **R1 免打扰区间**：`[start, end)` 半开区间，允许跨天（如 22:00–08:00）；**含起点、不含终点**（08:00:00 整即放行）；`start === end` 视为关闭；缺失 / 非法（`25:00`、倒序）**fail-open**（该段忽略、不抛错）。
- **R2 抑制门位置**：必须在 `claim` **之前**（时段内不落账、不通知、不消费）⇒ 提醒不丢；禁止把门放在 `notify` 内。
- **R3 补弹**：结束（或下次打开 / 回前台）后由既有轮询触发，按 `remindAt` 升序逐条补，每条恰好 1 次；重复提醒的 `remindAt` 在补弹前**不得被推进**。
- **R4 完成动作**：仅表示「任务完成」（写任务状态），不是「我知道了」；完成后出队；任务已被他人完成 / 归档 / 删除时按现有只读口径静默处理。
- **R5 通知开关**：关闭后**不弹系统通知**，应用内弹窗与引擎判定**照常**（不影响「只提醒一次」）。
- **R6 声音开关**：只影响系统通知是否发声；应用内不动。
- **R7 权限**：`denied` / `unsupported` 时**绝不阻断**应用内提醒；一次性提示按**设备级**记录（不入账号同步）。
- **R8 设置同步**：本地优先（先写本地再入偏好队列）；远端失败不阻塞 UI、不覆盖本地；旧快照缺 `reminder` 字段取默认（= 与 `v1.12.15` 行为一致）。
- **R9 时钟**：免打扰按**设备本地墙钟**判定，时间基准沿用已校准 `now()`（`Date.now() + getServerTimeOffset()`）。

## 六、NFRs

- **性能**：每轮扫描读一次设置（O(1)，10s 一次），不做额外定时器；免打扰不新增轮询。
- **健壮性**：通知适配层**永不抛**；设置读取失败取默认且不阻断提醒；存储不可用时退化（沿用既有账本降级口径）。
- **兼容性**：Web（含手机浏览器）+ 桌面同一实现；iPhone Safari 以应用内为准（明示）。
- **隐私**：设置随账号同步（不含任何设备指纹）；权限 ack 只存本机。
- **可维护性**：免打扰判定抽**纯函数**（可测、无 DOM）；单段模型；与引擎解耦（端口注入）。
- **可访问性**：设置项有可读标签与状态文字（不只靠颜色）；开关可用键盘操作。

## 七、AC

- **验证接缝**：`createReminderEngine`（新增可选端口 `isSuppressed(nowMs)`）+ 纯函数 `isWithinQuietHours(nowMs, range)` / `normalizeQuietHours`（`packages/shared/reminder`）+ 偏好快照三处适配（`buildUserConfigSnapshot` / `isSnapshotEmpty` / `applyUserConfigSnapshot`）+ UI 薄用例（QA 已确认 2026-10-24，`[T531]` 回执）。
- **AC1（主路径·设置区）**：Given 打开设置 → 应用设置，Then 见到「提醒」小节三项（通知 / 声音 / 免打扰），默认值 = 通知开 / 声音开 / 免打扰关；改动立即生效且重开保留。
- **AC2（主路径·通知开关）**：Given 关闭通知开关，When 提醒到点，Then **无系统通知**，应用内弹窗照常，且该条不被重复提醒。
- **AC3（主路径·声音）**：Given 关闭声音开关，Then 系统通知静音（`silent`），应用内表现不变。
- **AC4（负向闭环·免打扰不丢）**：Given 处于免打扰时段，When 提醒到点，Then **0 弹窗 / 0 通知 / 0 落账 / 0 消费**（账本无新键、`remindAt` 未变）。
- **AC5（主路径·补弹）**：Given 免打扰期间到点 N 条，When 时段结束（或下次打开 / 回前台），Then 按 `remindAt` 升序**逐条补弹，每条恰好 1 次**；再重开不再弹。
- **AC6（边界·区间）**：Given 22:00–08:00，Then 22:00:00 起静默、23:59 / 00:00 / 07:59:59 静默、**08:00:00 整放行**；`start === end` = 关闭；非法 / 缺失配置 fail-open 且不抛错。
- **AC7（主路径·完成）**：Given 弹窗显示到期任务，When 点「完成」，Then 任务状态变为已完成并出队；该任务后续重复提醒不再打扰；完成失败时给提示并**保留在队列**。
- **AC8（主路径·信息）**：Given 弹窗弹出，Then 显示**清单名**与**原定提醒时刻**（补弹时标注「原定 …」）；弹窗层不引 router / 仓储（清单名经装配层注入）。
- **AC9（异常·权限引导）**：Given 通知被拒或浏览器不支持，Then 应用内提醒照常；**一次性**设备级说明只出现一次（重开不再出现）+ 设置区常驻状态；索权只在用户点击设置区相关控件时发起。
- **AC10（异常·通知永不抛）**：Given 通知构造抛错（如 Android Chrome 页面通知），Then 引擎仍完成 notify→consume，应用内弹窗正常，**该条不丢且不重复**。
- **AC11（主路径·同步）**：Given 在 A 设备改三项设置，When B 设备（同账号）拉取偏好，Then 三项一致；远端失败时本地值保留且 UI 不报错；旧快照缺字段取默认。
- **AC12（设计一致性/回归）**：Given 全仓，Then 两端共用同一引擎实现（结构断言）、移动端红线 0、i18n zh/en 键齐备（含类型）、既有提醒 AC（`v1.12.15`）用例零回归。
