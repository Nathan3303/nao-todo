## 3. 改动口径

### 3.1 时间内联（`开始 <相对日期> ~ 结束 <相对日期>` 移至名称末尾）

- **文案/格式不变**：`t('task.details.startedAt'/'dueAt')` + `parse2RelativeDate`；**仅非空才显示**；`~` 拼接规则不变。
- **布局判据（裁决：α + 时间相对上限）**：
    - 时间元素：`flex: 0 0 auto`（宽度**随内容、不收缩**）+ `max-width`（相对上限，建议 CSS 变量、默认 `60%`）+ `overflow: hidden; white-space: nowrap; text-overflow: ellipsis`；
    - 名称元素：`flex: 1 1 auto; min-width: 0` + `overflow: hidden; white-space: nowrap; text-overflow: ellipsis`（**先被截断**）；
    - 脱离按钮：`flex: none`。
- **稳定性理由（形式化）**：行内**可收缩项只有名称一个**（且可收缩到 0）⇒ 时间（≤ 上限）+ 按钮（固定）**必然放得下** ⇒ 不挤出按钮、也不存在"谁先收缩"的隐式比例分配。
- **否决项**：β（标题与时间都 `flex: 0 1 auto` ⇒ 按比例收缩）**不可验收**（时间可被截成不可读片段，无稳定下限）；纯 α（无上限）在极端文案下会把名称挤没。
- 实现自由：可用 `nue-text :clamped` 或原生 CSS，但必须满足 §5 的 AC ②③。

### 3.2 移除编辑按钮 ⇒ 删除整套行内改名机制

- 该按钮是行内改名的**唯一入口** ⇒ 移除后 `editingId` / `editingName` / `startEditName` / `submitEditName` / `cancelEditName` + 模板 editing 分支（`nue-input`）+ check/clear 按钮 + **仅其使用的 CSS** 全部不可达 ⇒ **一并删除**（不留不可达分支）。
- **能力不丢**：**改名唯一入口收敛为"点击名称 → 该子任务详情页标题"**（`main/index.vue:127-133`，`theme="pure,name"` → `updateTaskName`（`:56`）→ `updateTaskDetails(id, { name })`）。

### 3.3 脱离父任务按钮移至名称末尾

- 独立 `subtask-row__actions` 列**整体消失**（该列已无其它内容）。
- 交互**保持不变**：hover / focus-within 才可见（`opacity` 切换）+ `flex: none` 预留位（避免行内跳动）；确认弹窗与 `detachSubTask` 调用链不变。

### 3.4 点击口径（防误触，**必须显式实现**）

- **导航点击保持在名称元素**（`@click="switchTaskDetails"` **不移到行容器/title-line**）⇒ 无需 `.stop`，且点击"脱离父任务"**不会**同时进入详情。
- **时间元素不设独立交互**（点击时间不导航、无 hover 样式）；`title` 属性除外（见 §5 AC ④）。

## 5. 验收标准（AC，逐条可验）

| ID  | 断言                                                                                                           |
| :-- | :------------------------------------------------------------------------------------------------------------- |
| AC① | 时间文案出现在**名称同一行、名称之后**；文案与格式与改动前**完全一致**（相对日期、`~` 拼接、仅非空显示）       |
| AC② | 常规文案 ⇒ 时间**完整显示**、名称完整；空间不足（窄容器 / 长名称）⇒ **名称呈省略号截断、时间仍完整**           |
| AC③ | 极端时间文案或极窄行 ⇒ 时间被截断为**省略号**且**不超过行宽上限**；**不得硬裁切**、**不得挤出脱离按钮**        |
| AC④ | 时间被截断时，**全文可由 `title` 取得**（`title` = 完整展示文案，不做绝对时间转换）                            |
| AC⑤ | **编辑按钮已消失**，且**改名路径可用**：点击名称 → 该子任务详情 → 标题改名往返成功（**只演"按钮消失"不算过**） |
| AC⑥ | 点击"脱离父任务"按钮**不触发**详情导航；点击时间**不导航**；点击名称仍正常进入详情                             |
| AC⑦ | 父任务详情面板中：无描述的子任务**不渲染 meta 行**；有描述的子任务描述仍在第二行                               |
| AC⑧ | 完成勾选 / 脱离父任务 / 子任务创建输入条 **行为与改动前一致**（脱离后从列表移除 + 顶层列表刷新）               |

## 7. 非目标与已知接受

1. **跨端动作集不相交**（web 脱离 / mobile 删除）+ 时间仅 web 展示 ⇒ **登记遗留、另单收敛**；移动端不得声称与 web 一致。
2. 时间整体截断时**可能切在 `~` 中间**（如 `开始 3 天前 ~ 结…`）⇒ **属预期**（AC③ 只断言"省略号 + 不超上限 + 不挤出按钮"）；不拆分为分段不可收缩 `span`（成本 > 收益）。
3. 名称被截断后**无 tooltip**（全文可由"点击名称 → 详情页"取得）⇒ 接受。
4. `TaskHandler` 零调用壳方法（`updateTaskName`（本单后新增零调用）、`updateTaskDescription`、`updateTaskEndAt`、`giveUp`）⇒ **登记死代码**，另立 API 清理单批量评估，不在本单删。
5. **与 `DEF-STORE-01` 的已知交互（本单不修，**保持观察**）**：Pinia 任务多副本机制确实存在 —— `TasksStore.tasks` 与 `TaskDetailsStore.tasks` 为两个独立 `useMapperStoreBase` Map，四视图各绑两个 use case、跨 store 无同步（**代码事实，架构已核到行**）。且**两副本同 id 同时在场是必然**：打开子任务详情会经 `TaskUseCase.get` 末尾 `addTask` 写进**列表 store**（`domain-task/src/application/usecases/task.ts:74-84`），而父任务的子任务列表由 `subTaskUseCase` 写进**详情 store**（`tasks-view.ts:52/65` + `use-subtasks.ts:38-45`）⇒ 任一侧后续写入必然让另一侧陈旧。**但“用户可见的陈旧”目前属未复现（而非否定）**：QA 探针差异 0/10 且**前置条件未满足**（未断言两副本同 id 同时在场；且该轮步骤②未产生任何写入，日历未开启）⇒ **暂不定级、不据此判本单任何缺陷**；排查顺序仍：**先比两 store 副本，再怀疑行布局**。⇒ 立单时写互引行（可追溯性）：`关联：TASK-02 ADR §3（时间内联 ⇒ 若成立则由不可见变为可见）+ TASK-01 ADR 遗留登记（写侧：子任务写入不落列表 store）+ README 遗留登记「DEF-STORE-01」行`。
6. **验收事实口径：详情抽屉内容宽固定 ~404px**（缩窄视口仅在抽屉自身下限后再压缩）⇒ 行内时间占 ~218px 后，**名称可用 ≈ 138px ≈ 10 个中文字**；因此“常规名称完整”**仅短名可达成** —— 这是 α+上限 判据的**必然结果**（非缺陷），且**不降上限**（降上限会切掉尾部“截止 <时间>”，那是本域锚点）。**裁决留痕：用户 2026-09-11 明确确认「时间上限保持 60%」。** 若日后需给名称腾空间 ⇒ 走“**压缩时间文案**”另单（i18n 一处，不丢信息）。

## 9. 冻结协议 v2（本单起生效，因 pre-commit 钩子排版归一）

**背景**：仓库钩子（`vite.config.ts:17-19` `staged:{'*':'vp check --fix'}`）会对暂存文件做排版归一 ⇒ **提交后字节 ≠ 作者交付时的 hash**（v1.4.1 批已有 5 文件被归一，经证明为纯排版、零改字）。

| 步  | 动作                                                                                             |
| :-- | :----------------------------------------------------------------------------------------------- |
| 1   | **作者声明"内容冻结"** 并给出内容 hash（仅供**证明**用，不再作为字节校验基准）                   |
| 2   | RD 提交（钩子归一）；**不得**绕过钩子、**不得**手工重排版                                        |
| 3   | RD 报 **`git show HEAD:<file> \| sha256sum`** = **字节冻结 hash**（PM 以此为准并记录）+ 归一证明 |

**归一判定（可放行 = 纯排版）**：① 任意空白变化（缩进/换行/行尾/CRLF/trailing newline）；② **Markdown 表格分隔行与表头区的 `:`/`-`/对齐填充**增删；③ 反引号内文本不变。

**必须停手报 PM**：任何**正文/表格内容单元格**的字符增删改（含数字、标点、`C-R*`/`U-R*` 编号、`file:line` 引用），或**表格行数/单元数变化**。

**证明方式（两项同时成立）**：
① **先剔除表格分隔行**（`grep -vE '^\|[[:space:]:|-]+\|$'`）→ 再**逐行去空白**（`sed 's/[[:space:]]//g'` 或整体 `tr -d '[:space:]'`）→ 逐字比较一致；
② **结构计数**一致：`## ` 标题数 / 列表项数 / **非分隔行行数** / **内容行 `|` 计数（排除分隔行）**。

> ⚠️ **两个已踩过的坑（勿再犯）**：
>
> 1. **必须先剔除分隔行** —— 分隔行的 `-`/`:` 是**非空白字符**，对齐填充会改变它们（实测：ADR 去空白字符数 6043 → 6417，差 374 **全是分隔行 `-`**；README 5164 → 5177）⇒ 否则会把**合法归一误判为漂移**；
> 2. `grep -E` 中 **`\s` 不是合法转义**（**GNU grep 的 BRE/ERE 都不认 `\s`**，`grep -E '\s'` 实际匹配字母 `s`；仅 `grep -P` 认）⇒ 排除分隔行**必须**用 `[[:space:]:|-]`；处理 CRLF 时**先 `tr -d '\r'`** —— **CRLF 行尾的 `\r` 会使 `$` 锚定失败**（`|` 后还有 `\r`）。**推荐写法**：`tr -d '\r' < f \| grep -vE '^\|[[:space:]:|-]+\|$'`（或 `sed -E '/^\|[[:space:]:|-]+\|$/d'`，同样需先去掉 `\r`）。

**归一实测（TASK-02 批，已核）= 无漂移**：ADR 仅 **3 处**分隔行、README 仅 **1 处**分隔行对齐填充；非分隔行行数两侧一致（**98/98**、**52/52**），逐行去空白 `diff` 仅命中这些分隔行。

**基准时效**：作者报 hash（内容冻结）即视为**基准生效**；此后**不得再改盘** —— 若确需修改 ⇒ **必须重报新 hash**（否则 PM 会按旧基准判出**假差异**，并可能误判 RD 未按冻结版提交）。
**另**：**提交时钩子归一属预期**（见上）；**字节冻结 hash 由 RD 提交后回报**（`git show HEAD:<file> \| sha256sum`），PM 一律以**字节冻结 hash** 为权威。

**证据口径（读回真相，因 `DEF-STORE-01` 观察项）**：冒烟的“读回断言”**真相优先取服务端读回**（HTTP 路径）；Pinia 双副本仅作辅助。`qaKit` **宜**跑**副本一致性探针**（同一 id 同时读 `TasksStore` 与 `TaskDetailsStore`，比较 `endAt/startAt/projectId/state`），**有差异 ⇒ 登记 + 告警 + 报告单列差异行**；⚠️ **探针必须先断言“两副本同 id 同时在场”**（`presentInTasksStore` / `presentInDetailsStore`）—— 否则 0 差异属**空集比较、无信息量**；并须在“两副本均在场**之后**发生一次写入”才算有效轮次。首轮实测差异 0/10（**前置未满足**，仅作记录）。

> ⚠️ **不得**用“取信息最全副本”**静默抹平**差异 —— 这条原则**不依赖于 `DEF-STORE-01` 是否成立**（它守的是“证据不得掩盖可疑差异”）；即使当前探针未命中，也不把该读法当作唯一真相源。
