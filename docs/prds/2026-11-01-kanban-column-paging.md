# 2026-11-01 看板列内独立分页 PRD（`DEF-126`）

> **状态**：**PRD 定稿，待开工确认**（用户 2026-11-01 定口径：`limit=20` · 结尾文案「没有更多了」· 刷新与排序/筛选变化时重置回第一页；方案 **B = 每列独立分页**）。
> **Issue**：[#309](https://github.com/Nathan3303/nao-todo/issues/309)· **批次**：`v1.16.2`（PATCH）· **分支**：`fix/<issue-id>-kanban-column-paging`
> **依据**：用户 2026-11-01 报障「看板列滚动加载更多失效，只能加载第一页」，并选定方案 B。
> **缺陷**：`DEF-126`（P2，**既有缺陷、非本批回归**）

## TL;DR

- **做什么**：看板**每列各自分页** —— 列内滚到底加载该列的下一页（每页 20 条），加载完显示「没有更多了」；分组 / 筛选 / 排序 / 刷新时各列回到第一页。
- **给谁**：任务页 / 普通清单页 / 标签页的**看板视图**用户（三处同一实现）。
- **成功标准**：看板不再是「全列合计只有前 20 条」；每列能看到该列**全部**任务；列头数字给出该列总数；离线仍可用（本地优先，零服务端契约改动）。
- **不做什么**：不改列表 / 表格视图的分页（两者现状正常）· 不改服务端契约与同步协议 · 不做「整块看板全局分页」· 不改拖拽写路径 · 不动移动端红线目录。
- **为什么做**：现状看板首屏 = **全部列合计 ≤20 条**（页面适配器只 `loadFirstPage`，列内 `loadMore` 是空函数），实测 65 条数据时「待办 20 / 正在进行 0 / 已完成 0」两列**假空** ⇒ 用户以为任务丢了。

## 一、问题证据

- **代码事实**（`T618` 取证）：`use-kanban-column.ts` 的 `loadMore = async () => {}`（空函数）、`states.isDone` 恒 `true` ⇒ `kanban-column.vue` 的 `<nue-infinite-scroll :disabled="states.isDone">` **恒禁用**；页面侧 `use-kanban-view-adapter.ts` 只调 `taskLoader.loadFirstPage(true)`，**未接** `loadNextPage`（列表适配器 `use-list-view-adapter.ts` 才有 `handleNextPage`）。
- **量化**（`T618` 实测）：默认 `pagination.limit = 20`。45 条数据 ⇒ 看板可见 20、不可见 25（55.6%）；65 条（45 todo + 10 doing + 10 done）⇒ 看板「待办 20 / 正在进行 0 / 已完成 0」，不可见 45（69.2%）；按用户库 188 条外推 ⇒ 不可见 **≥168（89.4%）**。
- **起点**：`b55dd5b2`（2026-04-14「实现看板视图功能」）把列内 `loadMore` 换成空函数 + `isDone: true`，后续 `8a39bad8` / `b51ea6ed` 照搬；`git tag --contains b55dd5b2` = **58 = 全部 tag** ⇒ **已发布版本从未有过可用的看板分页**（历史上有过的分页实现只存在于两条未发布的 `temp 暂存` 提交里）。
- **5 Whys**：① 为什么看不到全部任务 ← 看板首屏只取 20 条；② 为什么只有 20 ← 适配器只调 `loadFirstPage`；③ 为什么触底不补 ← 列内 `loadMore` 是空函数且 `isDone` 恒真；④ 为什么一直是空函数 ← 2026-04 那次「实现看板视图」把列从「自带 loader」改成「吃父级传入的 tasks」，loader 能力被摘掉但接口留了桩，之后 58 个版本无人回归验证；⑤ 根因 ← **能力迁移只做了数据来源，没做分页能力的对等迁移，且无回归断言**。
- **为什么选 B（用户 2026-11-01 定）**：本项目业务域为**本地优先 + 远端同步**（`binding.ts` 业务 7 域全部 `newLocalXxxRepository()`，读写走本地 Dexie，写经 `syncTracker.markDirty` 入队回传）⇒ 「每列各自查本地」成本低、**零服务端契约改动**、与用户心智一致（「这一列还有没有更多」）。用户体验上，全局分页会让「某列早已看完、另一列还有很多」时反复触底空转。

## 二、目标指标

- **可核指标 1**：任一列触底 ⇒ 该列追加下一页（20 条），其它列不受影响（列内条数单调增，不重复、不丢）。
- **可核指标 2**：每列加载完全部任务后显示文案「**没有更多了**」，且不再触发请求。
- **可核指标 3**：列头数字 = **该列任务总数**（不是已加载数）—— 用户能看出「这列一共多少、还有多少没看到」。
- **可核指标 4**：本地优先不变 —— 分页查询走本地仓储；**零**新增服务端请求类型 / 零同步协议变更（可用「断网时照常翻页」作为反证）。
- **口径缺口**：无埋点；靠组件测试 + 用户走查。

## 三、范围 / 非范围

- **范围**
    1. **列内独立分页**：每列各自持有 `page / limit(20) / isDone / total`，触底加载该列下一页；列条件 = 当前 `groupBy` 对应的字段（`state` 分组 ⇒ `state=<列>`；`priority` 分组 ⇒ `priority=<列>`，与 `DEF-114` 的「列与写字段一致」同口径）。
    2. **结尾文案**：该列到底 ⇒ 显示「没有更多了」（既有 `nue-infinite-scroll` 的 disable 区文案可复用），到底后不再发请求。
    3. **重置规则**：**刷新（`RefreshData`）· 排序变化 · 筛选变化 · 分组切换** ⇒ 各列重置回第 1 页（已加载页清空）。
    4. **列头计数**：显示该列**总数**（来自分页 `total`）。
    5. **空态与加载态**：列内首次加载显示 loading；0 条显示既有「无待办任务」空态；错误显示既有错误态 + 重试。
    6. **拖拽一致性**：跨列拖拽成功后，源列与目标列的卡片与计数即时正确（写路径不变）。
    7. **三处一致**：内置清单 / 普通清单 / 标签页看板行为一致（同一实现）。
- **非范围**
    - **列表 / 表格视图分页** —— 理由：现状正常（列表 `handleNextPage`、表格有分页器），改动无收益。
    - **服务端契约 / 同步协议** —— 理由：本地优先架构下分页在本地完成；动契约属另一层风险。
    - **整块看板「全局分页」** —— 理由：用户已选 B。
    - **拖拽写路径与载荷键集合** —— 理由：`DEF-114` 已锁（`{priority}` / `{state}` 各自唯一），本单零触碰。
    - **移动端 `apps/mobile` / `packages/presentation-react`** —— 项目红线。
    - **新增 token / i18n 键？** —— 「没有更多了」若既有文案可覆盖则复用；确实需要新增中文文案时**允许新增 1 个 i18n 键**（中英同步），不得硬编码中文字符串。

## 四、用户场景

- **画像**：在「按状态」看板里扫今天要做的（待办列很长）、已完成列只有几条的用户；以及在「按优先级」看板里只看「紧急」列的用户。
- **关键路径**：进入看板 → 待办列滚到底 → 追加 20 条 → 继续滚 → …… → 显示「没有更多了」；期间切到「按优先级」⇒ 各列回到第一页重新按优先级分列。
- **页面状态清单**
    - 首次加载：列内 loading；数据回来后显示第 1 页 20 条 + 列头总数。
    - 触底加载中：列底 loading 指示；不打断已有卡片。
    - 到底：列底「没有更多了」，不再请求。
    - 0 条：既有空态文案。
    - 断网：照常翻页（本地仓储），无错误提示。
    - 筛选到 3 条：各列重置后只显示这 3 条，列头数字 = 3。
    - 拖拽跨列：目标列 +1、源列 -1，立即反映。

## 五、业务规则

- **R-A（用户已定）**：每列每页 **20 条**（`limit = 20`）。
- **R-B（用户已定）**：到底显示文案「**没有更多了**」。
- **R-C（用户已定）**：**刷新 / 排序变化 / 筛选变化 / 分组切换** ⇒ 各列重置回第 1 页。
- **R-D（PM 裁定，可否决）**：列头数字显示**该列总数**（不是已加载数）—— 与「还有多少没看到」的心智一致；若你更想看「已加载数」，一句话改。
- **R-E（PM 裁定）**：分页**必须走本地仓储**（`taskUseCase.list` 走本地 Dexie），不得新增服务端查询参数或同步字段；断网可用是验收反证。
- **R-F（一致性）**：列条件与写路径同源 —— `state` 分组用 `state` 过滤、`priority` 分组用 `priority` 过滤（与 `DEF-114` R2 一致），不得交叉。
- **R-G（单一来源）**：三处页面共用一份实现；禁止在三个菜单/页面各写一套分页逻辑。
- **R-H（文案不硬编码）**：中文文案走 i18n（可新增 1 键，中英同步）；不得在组件里写死中文。

## 六、NFRs

- **离线优先**：分页查询纯本地；断网、只读态下照常翻页。
- **性能**：单次翻页只查一列（不是全部列一起重查）；列内追加不重渲染其它列。
- **兼容**：桌面端与 Web 同一份实现（桌面经 `@` 别名复用 web 源码）。
- **可测**：分页状态（page / loaded / isDone / total）在组件层可断言；重置规则有独立用例；「到底不再请求」用请求计数断言。
- **无障碍**：列内加载与到底提示对读屏可感知（既有 `nue-infinite-scroll` 的 bar 语义沿用即可，不新增自绘）。

## 七、验收标准（AC）

- **AC1（主路径）**：`Given` 某列有 45 条任务，`When` 该列滚到底，`Then` 追加 20 条（共 40），再滚到底追加 5 条（共 45）并显示「没有更多了」。
- **AC2（列间隔离）**：`Given` 待办列 45 条 / 已完成列 3 条，`When` 待办列触底加载，`Then` 已完成列卡片与页码**不变**。
- **AC3（列头计数）**：`Given` 待办列 45 条仅加载 20 条，`Then` 列头显示 **45**（总数，R-D）。
- **AC4（到底不再请求）**：`Given` 某列已加载完，`When` 继续滚动，`Then` 不再发起查询（查询次数断言 = 0 增量），文案为「没有更多了」。
- **AC5（重置 · 刷新）**：`Given` 某列已加载 3 页，`When` 触发 `RefreshData`，`Then` 各列回到第 1 页（20 条）。
- **AC6（重置 · 筛选 / 排序 / 分组）**：`Given` 已加载多页，`When` 改筛选、改排序、切分组，`Then` 各列均回到第 1 页，且列条件按新分组取字段（`state` / `priority`）。
- **AC7（离线反证）**：`Given` 断网（或只读态），`When` 列内触底，`Then` 照常翻页、无错误提示、无服务端请求（R-E）。
- **AC8（拖拽一致）**：`Given` 两列各有数据，`When` 跨列拖拽一条，`Then` 源列 -1、目标列 +1 且计数即时正确；写载荷仍为 `{priority}` / `{state}` 各自唯一（既有断言保持）。
- **AC9（边界）**：`Given` 0 条 / 恰好 20 条 / 21 条，`Then` 空态正常、恰好 20 条时到底即显示「没有更多了」、21 条时第 2 页 1 条。
- **AC10（三处一致）**：`Given` 内置清单 / 普通清单 / 标签页，`Then` 分页行为一致（同一实现，非三份复制）。
