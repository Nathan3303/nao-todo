## 1. 问题证据（5 Whys）

| 层       | 内容                                                                                                         |
| :------- | :----------------------------------------------------------------------------------------------------------- |
| 现象     | 用户**登出后再登录**，**内建清单的视图偏好**（如 all / today / tomorrow 各自的视图设置）**丢失**，需重新设置 |
| Why1     | 登出执行**清库**（T106 语义），偏好被清                                                                      |
| Why2     | 偏好**只存本地**（`localStorage` / `IndexedDB`），**无服务端副本**                                           |
| Why3     | 服务端**无对应持久化**（`UserConfig` 仅 `Appearance` 一字段）                                                |
| Why4     | 偏好从未被纳入「用户设置」同步范围                                                                           |
| **根因** | **偏好缺少「服务端持久化 + 登出后可恢复」的闭环**                                                            |

## 2. 目标指标

| 指标                      | 目标                   | 埋点              |
| :------------------------ | :--------------------- | :---------------- |
| 登出→重登后偏好自动恢复率 | **100%**               | 恢复成功/失败计数 |
| 恢复耗时（P95）           | **< 2s**（不阻塞进入） | 从启动到偏好就绪  |
| 偏好丢失工单              | **0**                  | —                 |

## 5. 业务规则 + 落点（PM 读码确认）

| 偏好             | 现状落点                                                                                                                               | 键 / 形态                                                                                                                 | 登出后                                |
| :--------------- | :------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------ | :------------------------------------ |
| **内建清单偏好** | `packages/infrastructure/src/built-in/project/repoImpl.ts` → **localStorage**                                                          | **`${userId}/${builtInId}`**（**已含 userId ⇒ 天然用户级**）                                                              | ❌ 被清（**用户痛点**）               |
| **普通清单偏好** | `packages/domain-project/src/domain/entities/project-preference.ts` → **IndexedDB `projectPreferences` 表**（`local-database.ts:257`） | `ProjectPreferenceEntity`（**`ViewType` / `GetOptions` / `Columns`**）                                                    | ❌ 被清（业务表）                     |
| **侧边栏宽度**   | `packages/shared/hooks/use-aside-width.ts` → localStorage                                                                              | `ASIDE_WIDTH`（**在「身份级必清」名单内**）                                                                               | ❌ 被清                               |
| **日历偏好**     | `apps/web/src/views/index/calendar/calendar-view.ts` → localStorage                                                                    | `CALENDAR_WEEKSTART`（**设备级白名单 ⇒ 保留**）· `CALENDAR_POMODORO_BADGE` · `CALENDAR_DAY_ZOOM`（**不在白名单 ⇒ 被清**） | ⚠️ **一半留一半丢**（**现状不一致**） |

**业务规则**：

1. **归属 = 用户级**（用户裁定：「清但能从服务端拉回，属于用户设置属性」）⇒ **不采用设备级保留**（避免切换账号串号）。
2. **本地优先 + 服务端兜底**：两端一致 —— **本地保存**，**本地丢失后从服务端同步**（用户裁定 Q4）。
3. **冲突语义**：待 arch 定（默认建议：**后写覆盖**，必要时带时间戳）。
