> **依据**：用户 2026-10-22 原话「在移动端浏览器中浏览 Web 端时，AppAsideV2 会应用 Float 变体，本次版本中的 Float 变体没有展示同步状态组件和设置按钮（以及设置对话框），把他们加上」+ PM 读码（`apps/web/src/components/app/aside-v2/`）。

## TL;DR

- **做什么**：手机（视口 ≤445px，Float 变体 = 抽屉）里补上**同步状态**与**设置入口**：抽屉内容区底部新增「工具区」（同步状态在齿轮上方），并让设置对话框在手机上**可用且不挤**。
- **给谁**：用手机浏览器访问 Web 端的用户（当前版本里抽屉既无同步状态也无设置入口，等于功能缺失）。
- **成功标准**：抽屉内可见同步状态 + 齿轮，点齿轮能打开设置且三区可切换；桌面 rail 视觉零变化；切变体无重复实例 / 无残留。
- **不做什么**：不重做抽屉形态（宽度 / 动画 / 关闭方式不变）· 不改桌面 rail 布局与同步状态语义 · 不改同步面板内容与状态口径。
- **为什么做**：`SyncStatusBar` 靠 `.aside-rail-bottom-slot` 注入点渲染，而该注入点**只由桌面 `aside-v2.vue` 绑定** ⇒ 抽屉在屏时 `railBottomHost` 恒为 `null`，**整块不渲染**；齿轮与 `<app-settings-dialog />` 亦只存在于桌面 rail ⇒ 手机上**设置功能完全不可达**（`settings/dialog/state.ts` 原文即标注「移动端抽屉设置入口另议（本任务不动）」，本次即补此项）。

## 一、问题证据

- **变体判定**：`aside-v2/adapter.vue` —— `responsiveFlag <= responsiveTypes.MOBILE(0)` ⇒ `<aside-v2-drawer>`。阈值来自 `packages/shared/hooks/use-responsive-flag.ts:5` 的 `responsiveWidths = [445, …]` ⇒ **视口 ≤445px 走抽屉**。
- **同步状态为何没有**：`sync/sync-status-bar.vue:223` 是 `<Teleport v-if="railBottomHost" :to="railBottomHost">`；`rail-host.ts` 的 `railBottomHost` **仅**由 `aside-v2.vue` 中 `#AppAsideRailBottomSlot` 的 ref 绑定 ⇒ 抽屉在屏时恒 `null` ⇒ 组件整体不渲染（不是样式问题）。
- **齿轮与对话框为何没有**：`aside-v2-drawer.vue` 只有 header（头像/昵称）、content（`#SubPageAsideTeleportSlot`）、footer（5 个导航图标）；**无齿轮按钮、无 `<app-settings-dialog />`**。
- **宿主闸门**：`settings/dialog/state.ts` 的 `openSettingsDialog()` 有 `hostReady` 前置（宿主未挂载则静默不打开）⇒ 要让手机能开设置，抽屉必须挂载对话框实例，且 `unbindSettingsDialogHost()` 卸载时 `open` 复位。
- **桌面形态不适用手机**：`settings/dialog/index.vue` 左栏固定 `width: 12rem`（192px）+ 右侧内容 ⇒ 390px 屏上右栏仅 ~180px；`themes/dialog.css` 仅在 **≤400px** 转贴底抽屉 ⇒ **401–445px 区间**无任何适配（会出现横向挤压 / 裁切）。
- **5 Whys**：① 手机上没同步状态、没设置 ← 抽屉未绑注入点、未挂对话框；② 为何未做 ← `SHELL-01/02` 落地时只做了桌面 rail，抽屉明确标注「另议」；③ 为何能上线 ← 当时 Web 端以桌面为主，手机浏览器非验收面；④ 为何现在暴露 ← `T519` 修好手机视口后，手机端开始被真实使用；⑤ 根因 ← **变体之间的能力不对等**（Float 变体被视为"临时收纳"，未纳入与 rail 同等的功能基线）。

## 二、目标指标

- **可核指标 1**：手机（≤445px）抽屉内**同步状态与齿轮均可见**（当前：两者均不存在，可见率 0%）。
- **可核指标 2**：手机上从齿轮能**打开设置对话框**并完成三区（个人资料 / 修改密码 / 应用设置）切换与关闭（当前：入口不存在 ⇒ 0%）。
- **可核指标 3**：桌面（>445px）与 Electron 的 rail 视觉**零变化**（宿主、位置、同步状态语义不变）。
- **口径缺口**：无前端埋点/RUM，指标靠**组件测试 + 用户真机勾选**，无线上统计。

## 三、范围 / 非范围

- **范围**
    1. 抽屉 content 区底部新增**工具区**：同步状态（在齿轮**上方**，延续 SHELL-02 语义）+ 齿轮按钮（直开设置对话框）。
    2. 注入点机制支持**两种变体**（同一时刻仅一个宿主）：抽屉在屏时同步状态渲染到抽屉工具区；切回桌面时回到 rail 注入点。
    3. 抽屉内挂载设置对话框实例，`hostReady` / `unbind` 语义保持（宿主不在屏不得打开；卸载兜底关闭）。
    4. 设置对话框**手机窄屏适配**：≤445px 下三区入口由左栏纵排改为**横向 / 顶部可容纳**的形态，内容占满宽度、无横向溢出与文字裁切（具体机制由 RD 选，见 AC3）。
    5. 齿轮 a11y：沿用 `aria-label` / `title`（`nav.settings`），对话框关闭后焦点归还**当前可见**的齿轮。
    6. 组件测试：宿主绑定/解绑、变体互斥（同时刻仅 1 个对话框实例）、窄屏形态断言。
    7. `DESIGN.md` 补一条「抽屉工具区与变体能力对等」约定（若确需成文）。
- **非范围**

    - **桌面 rail 布局与同步状态位置** —— 理由：SHELL-02 已定稿，本次只做"补齐抽屉"，不动已验收形态。
    - **同步面板内容 / 状态口径 / 冲突入口** —— 理由：仅换住宿主，逻辑零改动。
    - **手机端底部导航栏（bottom nav）等更大改造** —— 理由：用户明确只要"把这两样加上"。
    - **`packages/presentation-react` / `apps/mobile`** —— 理由：移动端红线。

## 四、用户场景

- **画像**：用手机浏览器访问 Web 端（≤445px），点开左上抽屉找功能。
- **关键路径**：打开抽屉 → 看当前同步状态（是否已同步 / 失败）→ 点齿轮 → 改个人资料 / 密码 / 应用设置 → 关闭回到列表。
- **页面状态清单**
    - 加载：抽屉打开瞬间同步状态未就绪 ⇒ 需有占位/既有加载语义，不得空白跳动。
    - 空：同步状态无数据时按现有降级显示（不新增文案）。
    - 错误：同步失败 / 覆盖度不足 ⇒ 抽屉内仍以「颜色 + 符号 + 文字」三重冗余可辨（`AGENTS.md` 三态可辨性）。
    - 成功：工具区两件套可见可用；对话框三区可切换、可关闭、不裁切。

## 五、业务规则

- **不变量 1（能力对等）**：Float 变体与 rail 变体的「同步状态 + 设置入口」能力**必须一致**；变体差异只允许在**摆放位置**，不允许在**有无**。
- **不变量 2（单一宿主）**：任一时刻**最多一个**同步状态宿主、**最多一个**设置对话框实例；切变体时宿主改绑，不得两处同时渲染或残留孤儿节点。
- **不变量 3（宿主闸门不放松）**：`openSettingsDialog()` 仍受 `hostReady` 约束 —— 宿主（当前变体）未挂载时不得打开，也不得在切变体后"补弹出"。
- **不变量 4（桌面零变化）**：>445px 与 Electron 的 rail 视觉、同步状态位置与语义不得变化。
- **不变量 5（语义顺序）**：工具区内同步状态在齿轮**上方**（SHELL-02 既定关系）。
- **不变量 6（不改契约）**：不改 `useResponsiveAside` 阈值、不改同步数据口径、不动服务端。

## 六、NFRs

- **兼容性**：手机浏览器 ≤445px（含 T519 已落地的安全区 `env()`，工具区不得被手势条遮挡）；401–445px 与 ≤400px 两档均需通过；桌面 Chrome/Safari 与 Electron 零变化。

- **可维护性**：注入点与对话框宿主逻辑**单一来源**（不得在两个变体里各写一套状态机）。
