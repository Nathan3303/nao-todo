## TL;DR

- **做什么**：让桌面端**关掉窗口也继续提醒** —— 关窗口收进托盘常驻、默认开机自启，并修掉「常驻两天就被踢回登录页」的会话缺口。
- **给谁**：把 NaoTodo 当日常任务工具的桌面用户（笔记本合盖 / 关窗口后仍希望按时收到提醒的人）。
- **成功标准**：关掉窗口后到点的提醒**照常弹出系统通知**；重启电脑后**无需手动打开**即可继续提醒；连续常驻 **≥48 小时不被强制回登录页**。
- **不做什么**：不做多设备「只提醒一次」、不做 PWA / Web Push、不做自动更新、不动移动端、不做托盘内直接操作任务。
- **为什么现在做**：`FEATURES.md` §16 明确登记「桌面托盘常驻 / 开机自启 = ❌，关掉窗口即退出（macOS 除外）」⇒ **桌面端「不漏提醒」至今不成立**，是本产品最核心承诺（提醒）的最后一块空洞；且 `DEF-15` 会让「常驻」在 48 小时后自毁，必须同批修。

## 一、问题证据

- **关窗口即退出（产品事实）**：`FEATURES.md` §16「❌ 桌面托盘常驻 / 开机自启 —— 关掉窗口即退出（macOS 除外），因此桌面端只有开着窗口才提醒」。读码定位：`apps/desktop/src` 内 `Tray` / `setLoginItemSettings` **0 命中**，仅有 `apps/desktop/src/main/index.ts:66` 的 `window-all-closed` 处理 ⇒ 缺口真实存在，非文档滞后。
- **提醒能力已具备、只差「活着」**：`v1.12.15` 起提醒**判定在本机**（本地轮询 + `taskId@remindAt` 去重账本），`v1.12.16` 起有免打扰与系统通知开关 ⇒ **进程活着就能提醒**；因此「关窗口即退出」是当前唯一阻断点。
- **`DEF-15`（P2，待派单）常驻 >48h 被强制回登录页**：客户端 checkin **仅冷启动触发**（`check-in.vue:37` 为唯一触发点），JWT **48h**、会话 **7 天绝对期（不滚动）** ⇒ 与是否活跃无关；7 天后连 checkin 都失败，只能重新输密码。
- **`DEF-14`（P2，待派单）服务端会话行膨胀**：`(user_id, device_id)` 唯一索引 upsert，但 **`device_id` 为空时不参与去重**；服务端 cron 无过期会话清理 ⇒ dev 库实测 **61 行 / 11 用户**，12 行 `device_id` 为空，单用户最多 **19 行（17 行已过期）**。
- **关联**：桌面端已有单实例锁（`DEF-7` 已修，`apps/desktop/src/main/single-instance.ts`）⇒ 开机自启 + 手动启动必须靠它收口，本次要纳入验收。

## 二、目标指标

- **送达率（核心）**：窗口关闭（收进托盘）期间到点的提醒，**系统通知发出率 = 100%**（以本机提醒账本为准，不含用户手动关通知/免打扰时段的正常抑制）。
- **送达率（核心）**：**进程存活且系统未休眠**时，窗口关闭（收进托盘）期间到点的提醒，**系统通知发出率 = 100%**（以本机提醒账本为准，不含用户手动关通知/免打扰时段的正常抑制）。**休眠 / 关机期间不承诺送达**：唤醒后 ≤10s 内补弹（未操作则按既有口径只补一次，`RV3`）。实测指标见 `T1`（`docs/reports/T543-arch-review.md` §三）。
- **常驻存活**：**常驻 = 进程持续运行**；连续常驻 **≥48h 不掉登录**（本批必达）；**≥7 天**不被强制登出 —— **本批不承诺**（见 §五 D2）。**补充口径**：关机 / 休眠累计超过 48h 导致 JWT 过期 ⇒ 需重新登录属预期行为（`RV10`）。
- **开机自启成功率**：设置开启后，**下一次系统重启**即自动进入常驻态（自启失败或需系统批准必须可见，不得谎报已开启）。
- **会话表健康**：同一设备重复登录**不新增行**；过期会话可被清理任务回收，且**活跃会话删除数 = 0**（跨仓验收）。
- **零回归**：**Web 端行为零变化**、移动端红线 0、提醒去重/免打扰语义与 `v1.12.15`/`v1.12.16` 逐字一致。

## 三、范围 / 非范围

**范围内**

- 托盘常驻：关窗口 = **三平台统一**收进托盘继续运行（**不再销毁窗口**）；托盘图标 + 菜单（打开主窗口 / 退出）。
- 开机自启：默认开启、设置里可关；自启时**静默启动到托盘**（不弹主窗口）；托盘不可用 / 可能不可见时**改为正常显示窗口**。
- 会话续期（客户端）：常驻期间周期静默 checkin + 网络恢复后补续 + **失败不清凭证**。
- 客户端保住设备标识（`DEF-14` 关联项：设备标识不得被本地清理误删）。
- 服务端过期会话清理 + 空设备标识策略 + 同设备重复登录不新增行（跨仓）。
- 设置区：开机自启开关 + 当前常驻状态可见（文案说人话）。
- 托盘不可用环境 / 自启被系统禁止的**可见降级**。
- 首次「收进托盘」的一次性提示（避免用户以为程序崩了）。

**非范围**

- 多设备只提醒一次、PWA / Web Push、手机端系统通知（各为独立批次）。
- 自动更新、安装包签名/公证（`DEF-75` 已按 B 档定案）。
- 托盘内直接操作任务 / 未读数角标 / 快捷暂停提醒。
- 移动端（红线）、Web 端**行为变更**（门控代码允许，见头部硬约束）。
- 7 天绝对期是否放开（见 D2，本批只做「到期可见提示」）。
- `DEF-45`（桌面 `Ctrl+R` 刷新掉登录，已转观察，需再现取证）。

## 四、用户场景

- **主场景（关窗口后提醒）**：用户上午打开 NaoTodo 安排任务，随手关掉窗口（以为只是收起）⇒ 下午 15:00 的提醒照常以系统通知弹出 ⇒ 点通知，窗口恢复并停在该任务详情。
- **主场景（开机自启）**：用户晚上关机，第二天开机后什么都不做 ⇒ 提醒依旧按时到达，不需要记得「先打开 NaoTodo」。
- **主场景（长时间不关）**：用户连续一周不关机、不关窗口 ⇒ 不需要每天重新登录。
- **异常（托盘不可用）**：托盘构造失败 ⇒ 关窗口仍按旧行为退出，设置区/关闭提示明确告知「当前环境不支持托盘常驻」。
- **异常（托盘存在但不可见）**：如 GNOME 无 AppIndicator 扩展 ⇒ 仍常驻，状态显示「已开启（可能不显示托盘图标）」，并提供设置页「退出 NaoTodo」，避免无退出路径。
- **异常（自启被系统拒绝）**：系统策略或权限阻止自启 ⇒ 设置区显示「开机自启未生效」并可重试。
- **边界（到期）**：会话满 7 天绝对期 ⇒ 应用给出明确的「需要重新登录」提示（而不是静默不再提醒）。

## 五、业务规则

- **D0 用户已拍板（2026-10-25，四项全按推荐）**：① 关窗口 = **收进托盘**继续运行（托盘菜单里才有「退出」）② 开机自启**默认开启**，设置里可关 ③ 会话续期 = **客户端定时续期 + 服务端会话清理同批** ④ 批次形态 = **本批只做本需求**，一个版本发一次。
- **D1 设置落点（已确认 2026-10-25）**：放进设置「**提醒**」分类下的「桌面常驻」子块（理由：目的是「不漏提醒」，与提醒设置同源，不新开第 5 类）。
- **D2 会话 7 天绝对期（已确认 2026-10-25）**：**本批维持不变**（改它属安全姿态变更，须单独立项评估），仅要求「到期有明确可见提示」；常驻存活承诺只到 48h 以上、7 天以内。
- **D3 托盘菜单动作（已确认 2026-10-25，`RV5` 补充）**：托盘菜单仅两项 —— 「打开 NaoTodo」「退出」；不加任务操作、不加未读角标。**补充**：设置页「桌面常驻」块内另提供「退出 NaoTodo」（不属托盘菜单，用于托盘不可见时的退出路径）。
- **D4 自启启动形态（已确认 2026-10-25，`RV11` 补充）**：静默启动到托盘，**不弹主窗口**；**托盘不可用 / 可能不可见时，自启正常显示窗口**（否则应用完全不可见）。
- **R1 退出语义唯一**：真退出只经托盘菜单「退出」（托盘不可见时用设置页「退出 NaoTodo」，`RV5`）；退出后不再提醒（须在菜单项与首次提示里说明）。
- **R2 提醒语义零变化**：去重键 `taskId@remindAt`、免打扰 `[start,end)`、系统通知/声音开关、权限三态、子任务提醒、已完成/归档/放弃不提醒 —— 全部保持既有口径。
- **R3 降级不静默**：托盘不可用 / 自启被拒 / 通知权限缺失，一律**可见**（设置区状态 + 必要的关闭提示），禁止「显示已开启但实际没生效」。
- **R4 凭证安全**：续期失败（网络类）**不得清凭证**；仅明确的凭证失效才走重新登录（与 `DEF-5` / `DEF-33` 既有判据一致）。
- **R5 平台差异（`P1` 裁定 = A，2026-10-25）**：**三平台统一「关窗 → 隐藏 + 进程不退出」**（含 macOS；mac 当前的「关窗仍销毁窗口 ⇒ 提醒引擎停止」不再保留）。该变更属 macOS 用户可见行为变更，**须写入发布说明**。
- **R6 设备标识稳定**：设备标识必须跨重启、跨本地清理保留（关联 `DEF-14`），否则会话行会继续膨胀。

## 六、NFRs

- **可靠性**：常驻进程不得因窗口隐藏而停止提醒扫描；单实例保证自启 + 手动启动不产生第二个实例。
- **后台行为**：只能影响提醒的**时效**（既有口径：可见 ≤10s / 回前台 ≤2s / 冷启动 ≤30s），不得引入「窗口隐藏时不提醒」的新抑制。
- **安全**：续期不延长到「永不需要重新认证」；凭证清理判据不放宽（R4）。
- **可观测**：自启/托盘/续期三处状态在设置区可见（用户视角），不依赖日志。
- **平台矩阵**：Windows / Linux / macOS 三平台行为差异必须显式登记（含降级路径）。
- **性能**：常驻不应带来可感知的 CPU/内存增量（验收以用户体感 + qa 抽样为准，具体阈值由 arch 定）。
- **可维护性**：托盘/自启属平台能力，落点应由 arch 明确（本 PRD 不指定实现位置）。
- **NFR 归口（已回执）**：`T543` 已把上述基线转译为 **`T1`–`T7` 可度量指标**（时效 / 资源 / 续期 / 清理 / 判定 / 单实例 / 依赖与包体），含度量方法与可行性，见 `docs/reports/T543-arch-review.md` §三；实现期以 `T*` 为验收口径，阈值不达标 ⇒ 回评审复议。
- **已知代价（须回归）**：隐藏态仍绘制（`T2` 抽样）；`backgroundThrottling:false` 使 `visibilityState` 不再反映真实可见性 ⇒ 依赖「隐藏即停」的既有逻辑（番茄 tick / 同步触发）在桌面端不再暂停（`R7`，AC12）。

## 七、AC（Given–When–Then，五覆盖）

**主路径**

- **AC1**：Given 应用已登录且窗口打开（三平台一致），When 用户点窗口关闭，Then 进程不退出、主窗口**隐藏（不销毁）**、托盘图标存在；再次点击托盘「打开 NaoTodo」/ Dock 或任务栏图标 / 再次启动应用，窗口按原状态恢复（首次提示见 AC14）。
- **AC2**：Given 应用处于托盘常驻态，When 用户从托盘菜单（或设置页「桌面常驻」块内）选「退出」，Then 进程结束、托盘图标消失、此后不再发提醒（重启应用后才恢复）。
- **AC3（核心）**：Given 窗口已收进托盘、**进程存活且系统未休眠**，When 到点触发一条提醒，Then 系统通知照常弹出且**仅一次**（去重口径不变）；点击通知后窗口恢复并停在该任务详情。**休眠 / 关机期间不承诺送达**，唤醒后 ≤10s 补弹（未操作则只补一次）。
- **AC4**：Given 开机自启默认开启（= 写入「开机启动」意图），When 用户重启系统，Then 应用自动进入常驻态且**不弹主窗口**（托盘不可用 / 可能不可见时改为显示窗口）；在设置里关闭后重启则不自启。「写入成功」≠「已生效」，生效以系统回读为准（见 AC10）。
- **AC6**：Given 应用连续常驻（常驻 = 进程持续运行），When 超过 48 小时且期间未长时间关机 / 休眠，Then 用户仍处于登录态、提醒照常；**关机 / 休眠累计 >48h 导致过期 ⇒ 需重新登录属预期**（见 AC8）。

**边界**

- **AC5**：Given 自启与手动启动同时发生，When 用户手动打开应用，Then 不出现第二个实例，已有窗口被恢复/聚焦。
- **AC8**：Given 会话达到 7 天绝对期，When 用户此时使用应用（**含窗口隐藏态**），Then **隐藏时先发系统通知**「登录已过期，请重新登录」，打开后给对话框与登录引导（不得静默不再提醒）；重新登录后提醒恢复（`RV6`）。

**异常 / 降级**

- **AC9（拆两态，`RV4`）**：① Given 托盘**构造失败**，When 用户关闭窗口，Then 按既有行为退出，设置区显示「当前环境不支持托盘常驻」；② Given 托盘**构造成功但可能不可见**（如 GNOME 无 AppIndicator），When 用户常驻，Then 仍常驻，状态显示「已开启（可能不显示托盘图标）」并给出设置页「退出 NaoTodo」，**不得让用户无退出路径**。
- **AC10**：Given 系统策略 / 权限阻止自启或需用户批准（macOS 13+ `requires-approval`、Windows 任务管理器禁用），When 用户在设置中开启自启，Then 设置区显示「未生效 / 需系统批准」并提供重试，**不得显示为已开启**（`RV7`）。
- **AC11**：Given 续期时网络不可用，When 续期失败，Then 凭证不被清除、用户保持登录态，网络恢复后自动补续。

**负向闭环**

- **AC12**：Given 本批改动完成，Then 三平台关窗语义统一为「隐藏 + 进程不退」（**macOS 属行为变更，须写入发布说明**）；**Web 端行为零变化**（新增能力一律 `desktopAPI` 门控）；`packages/presentation-react` 与 `apps/mobile` 零改动（红线 0）；提醒去重 / 免打扰 / 权限三态语义不回归；`backgroundThrottling:false` 的副作用（隐藏态不再暂停：番茄 tick / 同步触发）已回归（`R7`）。

**设计一致性**

- **AC13**：Given 用户打开设置，Then「桌面常驻」子块位置符合 D1，内含**开机自启开关 + 常驻状态四态（已开启 / 可能不可见 / 需系统批准 / 不支持）+「退出 NaoTodo」**，文案**无内部术语**（说人话），状态**颜色 + 符号 + 文字三重可辨**；窄屏 ≤445px 布局与既有设置一致；托盘图标在浅色 / 深色 / 高 DPI 下可辨识（用户视觉验收）。
- **AC14（首次提示，`RV8`）**：Given 用户首次点关闭且托盘可用，When 窗口被收进托盘，Then 显示**一次性**系统通知「NaoTodo 仍在后台运行，提醒照常；要退出请用托盘菜单」；再次关闭不重复提示；标记持久化在 `userData`（不写 `localStorage`，不动 K10 白名单）。

**跨仓**
