## 1. 背景与 5 Whys

### 1.1 触发（用户实测）：离线冷启动白屏

| #   | 问题                       | 答案                                      | 证据                                                                                                                                                                 |
| :-- | :------------------------- | :---------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 后端不可达时启动为何白屏？ | 解锁门两个模板分支都不匹配 ⇒ 渲染空       | `unlock-gate.vue`：仅 `v-if="checking"` / `v-else-if="profile"`，**无 `v-else`**                                                                                     |
| 2   | 为何 `profile` 为 null？   | 冷启动拉 profile 失败                     | 后端不可达 ⇒ `loadUserProfile()` 返回 `[null, err]`                                                                                                                  |
| 3   | 为何失败"悄无声息"？       | **不抛异常、也不打日志**                  | `loadUserProfile()` 返回**元组**（`usecase.ts:43-53`，不 reject）；请求器把断网**归一化为 resolve**（`axios.ts:72-108`）⇒ 原 `try/catch + console.warn` **永不触发** |
| 4   | 为何没有兜底？             | 模板链未穷尽，且 `profile` 被当作就绪条件 | 同 1；`profile` 仅内存（`user-store.ts:16`，不持久化）⇒ 离线必缺失                                                                                                   |
| 5   | 为何此前未被发现？         | 三个门/壳从未按"失败组合 → 终态"验证过    | 同类扫描：`AppRoot` ✅ 有兜底、`index.vue` ✅、`initial-sync-gate` ⚠️（依赖全局态）、`LoadingError` ⚠️（`v-else` 落空）、`aside-v2` ❌（壳耦合）                     |

### 1.2 第二层（修好解锁门仍进不去）

- `aside-v2.vue:59` `<nue-div v-if="profile">` 门住**整个轨道**（导航 + 齿轮 + SHELL-02 注入点）⇒ 离线进去也没导航。
- 「离线进入」只切 AppRoot 分支、**不改路由**；而 auth 守卫（`views/auth/routes.ts`）把"有 JWT 但未认证"强制推入 `auth-checkin` ⇒ 检入离线必败 ⇒ `check-in.vue` `replace('/auth/signin')` ⇒ **登录页死路**（BC-5 实测 FAIL）。

### 1.3 第三层：同步状态无"运行边界"（同族缺陷）

| 编号               | 缺陷                                                                                                             | 证据                                                                                                                                                                   |
| :----------------- | :--------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **DEF-SYNC-01**    | 拉取阶段失败被同一次运行的推送阶段清空                                                                           | `sync-status.ts:51` `markSyncing(){set({lastError:null})}` × `sync-service.ts:339`(pull)/`:507`(push)；`manualSync()=pullAll→pushAll` ⇒ 原始症状「面板失败态永不可见」 |
| **DEF-SYNC-02**    | 队列项全 `retryCount≥5`（`pushBody`/`deletions` 皆空）时**不 markSynced** ⇒ `syncing` 永久 true + 假成功进主界面 | `sync-service.ts:537-540` vs 空队列路径 `:511-514`；`listDirty` 不按 retryCount 过滤（`sync-tracker.ts:74-78`）                                                        |
| **DEF-SYNC-03**    | `markSynced()` **无条件**写 `lastSyncAt`，失败也推进                                                             | `sync-status.ts:55-64` vs 字段文档"上次**成功**同步"                                                                                                                   |
| **F-5**            | `LoadingError` 的 `v-else` 落 default slot，调用方不填即空白                                                     | `loading-error.vue:17-34` + `initial-sync-gate` 未提供 default slot                                                                                                    |
| **F-6**            | 壳耦合（见 1.2）                                                                                                 | `aside-v2.vue:59`                                                                                                                                                      |
| **DEF-OFFLINE-01** | 解锁门无 `v-else` 兜底（见 1.1）                                                                                 | `unlock-gate.vue:100-103`                                                                                                                                              |

**共同根因**（架构原话）：同步状态是"可被任意阶段中途读写的**全局可变状态**，缺**运行边界**" ⇒ 失败既会被抹掉，也会被伪造。

## 2. 目标指标与埋点口径

- **北极星**：沿用先例（"任务完成/当日计划完整率"，V1 裁决），本单为可用性缺陷修复，**不拆新指标**。

## 4. 优先级与选型留痕

**战略筛子**：① 无正式北极星，沿用先例（通过）② 壁垒 2/5 ③ 不做则离线场景**应用不可用 + 白屏无逃生**（数据信任） ⇒ **Must**。

> ¹ 归一化基准（全部桌面端用户，离线为确定性触发场景）｜² Impact 3（数据信任 + 误导性"成功"）｜³ 实施前置信度｜⁴ 人日（含 QA；W2 1.0 → +BC-7 0.5 → +W1/F-6 0.75 → +DEF-01 0.75 → +DEF-02 0.25，取整 3.5）

**偏离说明（留痕）**：RICE 上 B 最高（最便宜），但它只修初始门 ⇒ 用户"手动同步失败"永远不可见，属治标。采用 D 的理由：**同族缺陷共享同一根因（缺运行边界 + 门/壳非总函数）**，分单修会重复踩坑；且 F-6 不修则"离线可用"主线在冷启动路径上不成立。

**用户裁决的两处**：① 离线可用性边界 = **A**（本单只做"显式终态 + 可前进含离线进入"，离线**写入**边界另立）② 离线身份呈现 = **B'**（**缓存昵称 + 首字母头像 + 离线标识**，替代架构建议的"纯占位"）—— 架构复核为"有条件可行"，条件落成 C-15…C-21。
