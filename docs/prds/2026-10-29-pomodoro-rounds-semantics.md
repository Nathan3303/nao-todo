## 一、问题证据

- **`DEF-112`（P2，用户实测发现）**：用户在第 3 轮点「结束专注」后，界面显示 **四个空圈**（看起来轮次被清零），但再点「开始」又变成 **第 4/4 轮**。同一状态两处互相矛盾。
- **根因是需求口径错，不是引擎错**：引擎侧 `resetToIdle()` 刻意**不清零** `completedRounds`（代码注释明写「计数点 = 专注自然完成，休息结束 / 取消 / 结束专注都不得抹掉本周期已完成的轮次」）；但 `resolveRoundIndicator()` 的 `idle` 分支**无条件返回 `filled: 0`**。该 `filled: 0` 来自上一批 PM 的「验收补正 D11」，即**PM 判错**，非 RD 实现问题。
- **对照业界形态（§九）**：主流做法把「中止本次」「跳过本次」「清空本组」视为**三个不同权重的动作**；前两者不计数，清空本组是**独立入口 + 二次确认**。本项目当前**只有前两者**（`结束专注` / `跳过`），缺第三个，于是「想重新开始一个周期」没有正当出口 —— 这才是语义被误读的深层原因。
- **现状可复用面**：`completedRounds` 已在 store 公开（`ref<number>`）；指示器已是纯展示 + 纯函数视图模型；`NueConfirm` / `NueMessage` 为全站既有能力；i18n 已有 `pomodoro.rounds.*` 命名空间。

## 二、目标指标

- **显示与状态一致（核心）**：`idle` 态圆点实心数与引擎 `completedRounds` **不一致次数 = 0**；「结束专注」前后**不出现数值跳变**（结束前 ●●●○ → 结束后仍 ●●●○）。
- **语义可读（核心）**：`idle` 文案能让人一句话答出「本周期已完成几轮、还要几轮长休」；新入口文案让人一眼明白「清空的是本周期进度，不是专注记录」。
- **误操作 = 0**：重置入口**必须二次确认**；运行中/暂停中**无该入口**（不能悄悄把正在计的一轮清掉）。
- **零回归**：`longBreak` 仍显示新周期（0 实心）；`focus` / `break` 的文案与实心规则不变；上一批 AC9/AC11 用例仍绿（除本批明确修正的 `idle` 组）。
- **可达性**：键盘可 Tab 到入口并 Enter/Space 触发；指示器 `aria-label` 与可见文案同源。
- **零波动**：入口出现/消失**不推动计时器与笔记区位置**（无布局跳动）。

## 四、用户场景

- **场景 A（你遇到的）**：做完 3 轮，第 4 轮暂停后点「结束专注」。指示器**保持 ●●●○**、文案「本周期已完成 3 轮 · 再 1 轮长休」，不会出现假的四连空圈；再点开始仍是「第 4/4 轮」，**全程无跳变**。
- **场景 B（想要重开一组）**：上午做完了 2 轮，午休后换了新任务，想从 1/4 重新开始。`idle` 态圆点旁出现「重新开始本周期」入口 → 点它 → 确认框说明「将清空本周期已完成的 2 轮（今天的专注记录不受影响）」→ 确认 → 圆点回 ○○○○、文案回中性、toast「本周期已重新开始」。
- **场景 C（防误触）**：用户只是好奇点了入口但还没确认 → 取消 ⇒ **计数、记录、文案全部不变**，没有任何副作用提示。

## 五、业务规则

**计数（不变，仅重申作为验收基线）**

- 自然完成专注 ⇒ `+1` 轮；跳过专注 / 结束专注 / 取消 ⇒ **不计数**；跳过休息 ⇒ 不计数；长休结束 ⇒ 周期归零。

**显示（本批修正点）**

- `filled`（实心数）= **本周期已完成轮数**，恒等，**不分阶段**（这是唯一规则）。
- `idle` 文案三档：
    - 已完成 = 0：`共 M 轮一轮长休`（中性，不暗示进度）
    - 0 < 已完成 < M：`本周期已完成 N 轮 · 再 X 轮长休`（**X = M − N**）
    - 已完成 = M（仅在 `autoRest=false` 的短暂态可能出现，实现需先归零 ⇒ 不出现该档，用用例守住）
- `focus` 文案：`第 N/M 轮` +（当 N = M）`· 本轮结束后长休`（沿用，不变）。
- `break`：`休息中 · 已完成 N/M`（沿用）· `longBreak`：`长休息 · 新周期`，实心 0（沿用）。

**「重新开始本周期」入口**

- **可见条件**：`phase === 'idle'` **且** `completedRounds > 0`。其余情况**不渲染**（不是 disabled —— 避免留下「按不动的按钮」噪声）。
- **位置**：轮次指示器同一行的**行尾**，小号 ghost 文字按钮；与圆点/文案同一视觉组。
- **确认**：点击后 `NueConfirm`，标题「重新开始本周期？」，正文「本周期已完成的 N 轮会被清空，**今天的专注记录不受影响**。」，确认按钮「重新开始」，取消按钮「取消」（危险动作走 `destructive` 主题）。
- **效果**：确认 ⇒ `completedRounds = 0` → 指示器即时回 ○○○○ + 中性文案 → `NueMessage.success('本周期已重新开始')`。**不触碰** 计时引擎阶段、当前任务/模板选择、笔记、任何记录。
- **取消 / 关闭**：零副作用（无 toast、无状态变化）。

**无障碍与文案**

- 指示器容器 `role="img"` + `aria-label` 与可见文案**同源**（含进度信息，不只念「轮次」）。
- 入口为原生可聚焦按钮（`NueButton`），`title` 与 `aria-label` 同文；键盘 Enter/Space 触发；确认弹窗 Esc = 取消。
- 所有新文案走 i18n：`pomodoro.rounds.*` 命名空间下新增（中英 + `types.ts` 三处齐备）。

## 七、验收标准（AC 五覆盖）

- **AC1（主路径 · 显示）** Given 本周期已完成 3 轮（M=4）且当前 `idle`，When 渲染指示器，Then 实心 **3** 个、文案为 `本周期已完成 3 轮 · 再 1 轮长休`。
- **AC2（主路径 · 无跳变）** Given 正在进行第 4 轮（显示 ●●●○ / `第 4/4 轮`），When 先暂停再点「结束专注」，Then 指示器**仍为 ●●●○**（**不得**变成四个空圈），文案回到 idle 档；再点开始 ⇒ `第 4/4 轮`（与结束前一致）。
- **AC3（边界 · 0 轮）** Given 本周期完成 0 轮且 `idle`，Then 实心 0、文案 `共 M 轮一轮长休`、**无**「重新开始本周期」入口。
- **AC4（边界 · 长休）** Given 进入长休，Then 实心 0、文案 `长休息 · 新周期`（**回归项**：不得因本批修正而显示旧周期进度）。
- **AC5（主路径 · 重置入口）** Given `idle` 且已完成 2 轮，When 点击「重新开始本周期」并确认，Then 计数归零、指示器回 ○○○○ + 中性文案、出现「本周期已重新开始」提示，**且已完成记录的条数/内容不变**。
- **AC6（负向闭环 · 取消）** Given 同上，When 在确认框点「取消」或按 Esc，Then 计数不变、无提示、无记录变化、入口仍在。
- **AC7（边界 · 不可用态）** Given 处于 `focus` / `break` / `longBreak` 或 `idle` 且 0 轮，Then 「重新开始本周期」**不渲染**（`queryByText` 为 null），且无键盘可达路径触发它。
- **AC8（异常/幂等）** Given 已完成 1 轮，When 连续两次确认重置，Then 第二次不产生额外副作用（计数仍 0、不弹第二次成功提示之外的异常、不抛错）。
- **AC9（无障碍）** Given 用键盘浏览番茄页，Then 入口可 Tab 聚焦、Enter 触发确认、Esc 取消；指示器 `aria-label` 含与可见文案一致的进度表述。
- **AC10（设计一致性）** 新增 UI 只用既有 `nue-*` token；960px 与 720px 两档下指示器行**不换行、不溢出**、入口出现/消失**不推动**计时器位置；新增文案中英齐备；移动端 `git status --porcelain -- packages/presentation-react apps/mobile` = 0。
