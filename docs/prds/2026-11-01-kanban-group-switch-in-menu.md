# 2026-11-01 看板分组切换移入右上角菜单 PRD

> **状态**：**PRD 定稿，待开工确认**（用户 2026-11-01 定口径 A/A/A/A + 「仅看板视图时条件渲染」）· **Issue**：[#306](https://github.com/Nathan3303/nao-todo/issues/306)· **批次**：`v1.16.1`（PATCH）· **分支**：`feat/<issue-id>-kanban-group-in-menu`
> **依据**：用户 2026-11-01 原话「关于 1 切换控件位置，你能把这个切换组件安排进右上角的菜单中的视图条目下方吗？即紧贴看板视图下方」+「另外需要条件渲染，当前视图为看板视图时才显示」。
> **用户已定 4 口径**：① 形态 = 内嵌分段控件一行（按状态 | 按优先级）；② 原位置 = 完全移除；③ 范围 = 三处右上角菜单都加；④ 时机 = 先走查完 `v1.16.0` 再改（改完发 `v1.16.1`）。

## TL;DR

- **做什么**：把看板「按状态 / 按优先级」分组切换从**看板内容区顶部那一行**搬到**右上角「视图」菜单**里，位置紧贴「看板视图」项正下方，且**仅在当前视图为看板时渲染**。
- **给谁**：任务页 / 清单页 / 标签页看板视图的使用者（桌面与 Web 窄屏同享同一菜单）。
- **成功标准**：分组切换不再占用内容区垂直空间；入口在「切视图」的地方一次找得到；切到表格 / 列表时菜单里不出现该分段；键盘可完成全部操作；三处菜单行为一致。
- **不做什么**：不改分组列集合与顺序 · 不改拖拽写路径与载荷语义 · 不做分组选择持久化 · 不改菜单其它条目 · 不新增 token / i18n 键 · 不动移动端红线目录。
- **为什么做**：现状把「切哪个视图」与「看板内部怎么分组」拆在两处，且分组那一行**常驻占用内容区顶部一整行**（看板本就列多、垂直空间紧张）；把两者收进同一菜单，入口语义更顺（"我在看哪种视图/怎么分组"是一次心智操作），内容区回到纯列。

## 一、问题证据

- **现状位置（读码）**：分组切换在 `packages/presentation/task/components/kanban/kanban.vue` 的 `nue-header.kanban-toolbar`（`segmented-switch`，两段「按状态 / 按优先级」），位于列区之上、常驻占一行。
- **入口割裂**：右上角菜单 `operation-dropdown.vue`（三处：`tasks/built-in-project`、`tasks/project`、`tasks/tag`）里已有「视图切换」（表格 / 看板 / 列表），而"看板内部怎么分组"却在页面另一处 —— 同一个心智动作（决定看什么）被拆成两个入口。
- **状态归属（读码）**：`currentGroupBy` 住在看板组件内部 `useKanban`（`packages/presentation/task/components/kanban/use-kanban.ts`），通过 `TASK_KANBAN_CONTEXT_KEY` 提供给列。控件一旦搬到 web 菜单，控件与状态**跨了层** ⇒ 必须把状态上提（见 §5 R-D）。
- **5 Whys**：① 为什么用户要求搬 —— 分组那行占内容区空间且入口离"切视图"太远；② 为什么当初放在内容区 —— `DEF-114` 修「看板分组真正接线」时把控件与列区放在同一组件内最省事；③ 为什么现在不合适 —— 接线修完后（`v1.16.0`）分组已是稳定能力，属"设置一次、长期有效"的性质，不需要常驻可见；④ 为什么进菜单更好 —— 菜单里已有"视图"这一同类概念，分组是视图的修饰；⑤ 根因 —— **控件位置按"实现便利"而非"信息层级"决定**（常驻控件 vs 设置项的层级错配）。
- **设计输入（frontend-design 视角）**：这一行不是数据展示，而是**视图的设置项**；设置项不该占据内容区黄金空间，应归入"视图"这一设置容器。搬动本身不改变信息，只改变层级 —— 因此验收重点是**零信息丢失 + 零视觉回归**，而非新造观感。

## 二、目标指标

- **可核指标 1**：看板视图下，内容区顶部**不再有分组行**（DOM 中 `kanban-toolbar` 分组容器不存在），列头之上无空白占位（列区顶部间距与列表重建前的边距一致，且不高于原「列头行」）。
- **可核指标 2**：菜单内「视图切换」块中，分段与「看板视图」项的**垂直间距 ≤ 一个条目内间距**（视觉上属同一条目组）。
- **可核指标 3**：非看板视图（表格 / 列表）下，菜单 DOM 中**不存在**该分段（不是 `v-show` 隐藏）。
- **可核指标 4**：键盘独立完成「开菜单 → 聚焦分段 → 切到按优先级 → 关菜单」全流程，无鼠标。
- **口径缺口**：无埋点；靠组件测试 + 用户勾选清单。

## 三、范围 / 非范围

- **范围**
    1. **移除**：`kanban.vue` 的 `nue-header.kanban-toolbar` 整块（分组分段 + 其容器与样式），看板只保留列区。
    2. **新增**：三处 `operation-dropdown.vue` 的「视图切换」块内，在「看板视图」`inner-dropdown-option` **正下方**渲染一行 `segmented-switch`（`按状态 | 按优先级`），复用 `packages/shared/components/segmented-switch`（`DESIGN.md §4.5` 单一来源件，调用方第 5–7 处）。
    3. **条件渲染**：仅当当前视图为看板（`preference.viewType === 'kanban'`）时渲染；切到表格 / 列表后**不渲染**（DOM 不存在）。
    4. **状态上提**：分组状态与列集合改为「单一来源、三处页面共用同一份实现」；看板列仍由 `TASK_KANBAN_CONTEXT_KEY` 供给，列组件语义不变。
    5. **文案**：复用既有 i18n 键（`task.kanban.groupByState` / `groupByPriority` / `groupByLabel`），中英文同步，不新增键。
    6. **交互**：菜单内切换分组后看板列**即时**更新；菜单的既有打开 / 关闭行为不回归。
    7. **焦点归还（补一处）**：`nue-dropdown` 关闭时**不**把焦点还给触发器 ⇒ 在 `TaskOperationsDropdown` 加一处「打开时记 `document.activeElement`，关闭时 `.focus()` 回触发器」（全仓唯一实现，不在 3 处菜单复制）。
    8. **落地顺序（`T611` 建议，PM 采纳）**：① 状态上提（只加组合式函数 + 3 行 provide，**不动 DOM**，零可见变化、可独立验收与回滚）→ ② 控件搬家（包装件 + 三处菜单插入 + 删 toolbar 块与死 CSS）→ ③ 焦点归还。

## 四、用户场景

- **画像**：在任务页看板上按优先级看"哪些紧急还没动"的用户；以及按状态看"今天做完了什么"的用户。
- **关键路径（改后）**：进入任务页（看板视图）→ 右上角菜单 →「视图切换」块 → 看到「看板视图」下方「按状态 | 按优先级」→ 切到「按优先级」→ 关菜单 → 4 列（紧急 / 高 / 中 / 低）。
- **页面状态清单**
    - 看板视图：分段出现，当前值高亮（滑块 + 字重 + 字色三重）。
    - 表格 / 列表视图：分段**不出现**，菜单其余条目与现在完全一致。
    - 菜单打开中切换分组：列区即时更新，菜单不关闭（见 R-A），用户可直接对比两档后再关菜单。
    - 刷新 / 重新进入：回到「按状态」（R7 不变）。
    - 空看板（0 任务）：4 列仍显示空列与列头，分段仍可用。
    - 只读 / 离线：分段可用（纯本地状态，不写库、不发请求）。

## 五、业务规则

- **R-A（PM 裁定；2026-11-01 经 `T611` 实证后订正措辞）**：**菜单内点击分段后菜单保持展开**，看板列即时更新。理由：分段是"状态控件"而非"命令项"，用户常在两档间来回对比。证据：`nue-ui` 的 `dropdown-item.vue:11` 默认 `closeWhenExecuted: false`、`dropdown.vue:233` `if (!props.closeWhenExecuted) return` ⇒ **现有菜单项点击后本来就不关闭**（原写法"其它命令项仍按现行为关闭"与实现不符，已更正）⇒ 本单**不引入**任何关闭行为。**D3（PM 决策）= 切视图后也不显式关闭菜单**（现状即如此，改动超范围）。
- **R-B（位置）**：分段必须落在「视图切换」块内、紧跟「看板视图」条目**下方**，与三条视图条目同属一组；不放到「视图操作」块，不加分隔线。
- **R-C（不持久化）**：沿用 `v1.16.0` `R7` —— 分组选择不写任何偏好存储，刷新 / 重新进入回「按状态」；localStorage / sessionStorage 零写入。
- **R-D（单一来源）**：分组状态与列集合**只允许一份实现**（三处页面共用），禁止三处各存一份、禁止 web 与 presentation 各持有副本；看板列组件仍只从上下文取分组（`TASK_KANBAN_CONTEXT_KEY`），拖拽写路径零改动。
- **R-E（无障碍）**：分段在菜单内必须键盘可达 —— `Tab` 可进入、段间可切换（方向键或 Tab）、`Enter`/`Space` 激活、焦点环可见；`aria-label` 保留（`task.kanban.groupByLabel`）；菜单 `Esc` 关闭且**焦点归还原触发器**（见 §三 范围 7，`nue-dropdown` 原生不提供，须补；`T611` 实测：弹层打开时 `NueOverlay` 自动 `focus()` ⇒ 「Tab 进入分段」免费可得，缺的只是关闭时的归还）。
- **R-F（视觉零回归）**：分段尺寸与菜单条目高对齐、不挤压条目、不溢出（窄至 320px）；暗色与浅色下选中态均为「滑块 + 字重 + 字色」三重冗余，去色后可辨（项目红线 §4）。
- **R-H（菜单内尺寸档，2026-11-01 用户走查反馈后追加）**：分段在菜单内必须**与菜单条目同档** —— 段高 = `--nue-box-size-sm`（**32px**，=「看板视图」条目高）、字号 = `--nue-text-xs`（**12px**，= 菜单项字号）。原 `size="md"` 段高 **40px** 比菜单条目（32px）高 8px ⇒ 在菜单里「突兀、抢层级」⇒ 改为新增第三档 **`size="inline"`**（差异写在共享件内部，调用方零 CSS 覆盖，符合 `DESIGN §4.5` 三轴不变量）；`sm`（28px，日历/设置在用）与 `md` 保持不变。**实测口径更正（`T615`，2026-11-01）**：PM 原判「字号继承 ≈16px、需减小」**有误** —— 分段按钮走 `nue-button--small`，主题本就给 `--nue-text-xs`（**12px**，与菜单项相同），headless Chromium 实测三档字号**均为 12px** ⇒ **实际改动只有段高 40 → 32px**；`font-size: var(--nue-text-xs)` 是**显式锁定**（防主题改 small 档时漂移），视觉上幂等。**点击区 32px < `DESIGN §3` 的 40px 页面级底线 ⇒ 按「菜单内嵌控件跟随条目高度」登记例外**（菜单项本身即 32px）。
- **R-G（信息不丢失）**：搬动只迁移位置，不删信息 —— 原看板顶部那一行若含其它元素（除分段外），一并核查并归位或删除并说明。

## 六、NFRs

- **无障碍**：焦点环对比度 ≥3:1；分段 `role="group"` + 每段 `aria-pressed`（共享件既有语义不变）；菜单内不产生双焦点陷阱。
- **性能**：零新增请求；菜单打开不触发额外渲染风暴（切分组只重排列，不重新拉数据）。
- **兼容**：桌面（Electron）与 Web 行为一致；窄屏 Web（≤445px）菜单可用、不溢出。
- **可维护**：`segmented-switch` **直接调用点保持 4 处不变**（自证命令 `grep -rn "<segmented-switch" --include=*.vue apps packages \| grep -v __tests__ \| wc -l` = 4）—— 变化只是第 4 处由 `kanban.vue` 直用改为 `KanbanGroupSwitch` 包装件内用，而该包装件被三处菜单共用 ⇒ 不产生第二份分段实现、不复制逻辑。（原写「4 → 7」有误，`T611` 提「4 → 5」亦不准，按实测订正为 **4 → 4**。）
- **可测**：分组状态单一来源有断言（三处页面共用同一实现）；条件渲染用"DOM 不存在"断言；`R7` 用"零写入"断言。

## 七、验收标准（AC）

- **AC1（主路径）**：`Given` 看板视图、`When` 打开右上角菜单，`Then` 「看板视图」正下方出现一行两段「按状态 / 按优先级」，默认高亮「按状态」；点「按优先级」`Then` 列区变 4 列（紧急 / 高 / 中 / 低），列头与内容正确。
- **AC2（条件渲染 · 负向）**：`Given` 当前视图为表格或列表，`When` 打开菜单，`Then` 菜单 DOM 中**不存在**该分段（不是隐藏）；切回看板后重新出现。
- **AC3（原位置移除）**：`Given` 看板视图，`Then` 内容区顶部不存在分组行，列区上方无空白占位，页面无布局跳动。
- **AC4（三处一致）**：`Given` 内置清单 / 普通清单 / 标签页，`When` 分别打开菜单，`Then` 三处位置、形态、行为一致（同一实现，非三份复制）。
- **AC5（语义回归 · 不可放宽）**：`Given` 按优先级分组，`When` 中途拖拽卡片，`Then` 写入载荷**只有** `priority`；按状态分组时**只有** `state`（既有断言原样保留并通过）。
- **AC6（不持久化）**：`Given` 已切到「按优先级」，`When` 刷新或重新进入页面，`Then` 回到「按状态」；全程偏好存储零写入。
- **AC7（菜单交互）**：`Given` 菜单展开，`When` 点击分段切档，`Then` 列区即时更新且菜单**不关闭**（R-A）；`Esc` 或点外部 `Then` 关闭且焦点回到触发器；菜单关闭后分组保持（本次会话内）。
- **AC8（键盘）**：`Given` 仅键盘，`When` 依次 `Tab` 到菜单触发器 → 打开 → 聚焦分段 → 切到「按优先级」→ `Esc` 关闭，`Then` 全流程可达且焦点可见；无鼠标操作。
- **AC9（视觉 / 暗色 / 窄屏）**：`Given` 浅色与暗色、320px 与桌面宽度，`Then` 分段不挤压条目、不裁字、不溢出；选中态在去色后仍可辨（滑块位置 + 字重）。**（R-H）** 且分段**段高与「看板视图」菜单条目一致 = 32px**（字号两边本就同为 12px），不与菜单条目争夺视觉层级。
- **AC10（边界）**：`Given` 0 任务空看板 / 只读态 / 断网，`When` 在菜单内切分组，`Then` 列头与空态正常、分组可切、无写入、无错误提示。
