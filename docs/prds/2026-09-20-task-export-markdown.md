## 1. 问题证据与 5 Whys

**现象（用户直提）**：任务数据仅能在应用内查看，无法带走 / 分享 / 二次加工。

| 层  | 追问                                                                |
| :-- | :------------------------------------------------------------------ |
| ①   | 用户需要把任务（含子任务）内容带到应用外                            |
| ②   | 无任何导出能力（仓库无剪贴板封装、无导出逻辑）                      |
| ③   | 任务数据分散在多个 store（详情 vo / 子任务 / 检查项 / 标签 / 项目） |
| ④   | **命题：提供「导出为 Markdown 文本 + 一键复制」能力**               |

## 4. 用户场景

- **场景卡**：打开任务详情 → 底部「更多」→ 导出 → 浮层显示完整 Markdown → 点「复制」→ 粘贴到任意编辑器/笔记。
- **关键路径**：详情面板 footer `nue-dropdown`（`export-task`）→ 递归取数 → 生成 → `nue-dialog` → 剪贴板。
- **页面状态清单**：有/无描述；有/无检查项；有/无子任务；多层子任务；取数失败；剪贴板不可用。

## 5. 业务规则

- **输出结构**：`# 任务名` + 元信息列表（状态/优先级/开始/截止/项目/标签/创建/更新）+ `## 描述` + `## 检查项`（`- [x]`/`- [ ]`）+ `## 子任务`（层级缩进 2 空格/层，复选框反映 done）。
- **空段整段省略**（无空标题）：描述空白、无检查项、无子任务 → 对应段落不输出。
- **空值逐行省略**：开始/截止/项目/标签为空则对应元信息行省略。
- **递归**：逐层 `subTaskUseCase.list({ parentTaskId, page, limit })` 按 `pagination.maxPage` 分页取尽；视图对象经 `TaskDetailsStore` 取回并按 `sortId`/`id` 排序。
- **深度上限**：`MAX_EXPORT_DEPTH = 5`（防自引用/异常数据无限递归）。
- **失败处理**：取数失败 → toast「导出失败：{error}」且**不开**浮层；复制失败/剪贴板不可用 → 错误提示（不静默）。
- **入口交互**：菜单 `close-when-executed`（点击即关）；生成期无 loading 指示（用户确认）；成功才开浮层。

## 6. NFRs

- 生成器为**纯函数**（零 Vue 依赖，i18n 文案由调用方注入 → 可单测、可跨端复用）。
- 浮层长文本可滚动（`<pre>` + `overflow: auto`）。
- 门禁：vp check + vitest 716 + `guard:ddd` + 双端 build ✓。

## 9. 决策留痕

- **入口位置（Q1）**：初版置于 header（T21）→ 用户实测后要求移入 footer「更多」菜单（T22）——与同类操作（收藏/评论/复制任务/移动）同组，header 只留日期与关闭。
- **输出方式（Q2）**：预览浮层（而非直写剪贴板）——可核对内容，并规避非 HTTPS/权限下剪贴板 API 失败。
- **子任务层级（Q3）**：递归全部层级（逐层分页），并加 5 层深度上限防环。
- **字段范围（Q4）**：必需字段 + 创建/更新时间；**不含评论与专注记录**（噪声大）。
- **图标冲突**：菜单内「复制任务」已用 `files`，导出改用 `share`（T22）。
- **浮层组件**：`nue-dialog`（自身 teleport，挂载位置不影响行为）；T22 移除已无调用方的 `loading` prop。
- **生成器解耦**：`export-markdown.ts` 纯函数（i18n labels 由调用方注入），`use-export-task.ts` 负责取数与剪贴板（均可单测）。
- **用户样式**：footer `border-top` 由外层 `details.vue` 的 `> .nue-footer` 移入 footer 组件自身（内聚；经核实 `details-main` 内部的进度 `nue-footer` 不受影响）。
