# 2026-10-22 SmartList 标题宽度溢出（可用空间未被用满）PRD

> **状态**：**✅ 已交付并合并（`79d31286`，PR [#229](https://github.com/Nathan3303/nao-todo/pull/229)，2026-10-22）** · **Issue**：[#226](https://github.com/Nathan3303/nao-todo/issues/226) · **批次**：`v1.12.14`（PATCH）
> **依据**：用户 2026-10-22 原话「侧边栏中的 SmartList 的标题宽度太小，在移动端的浏览器中浏览时出现溢出隐藏（其实还有很多空间）」+ 裁定 **A = 用满可用宽度，真不够才省略**（桌面同步受益）。
> **硬约束**：不改 `NaoSmartList` 的对外 props / 事件 / 插槽 · 不改清单数据与排序 · 移动端红线目录零改动。

## TL;DR

- **做什么**：让 SmartList 表头的**标题区吃满可用宽度**（= 容器宽 − 右侧操作按钮），只有**真正放不下**时才单行省略，并给出 `title` 全文提示。
- **给谁**：手机抽屉（256px）与桌面侧栏（窄）里看清单的用户。
- **成功标准**：常见清单名（中文 ≤10 字 / 英文 ≤24 字符）在 256px 抽屉内**完整显示**；真放不下时省略号出现在**文字末尾**（而非整块被裁），且长按/悬停可读全名。
- **不做什么**：不把标题改多行 · 不动右侧操作按钮（管理/新增）的既有位置与样式 · 不改折叠头交互。
- **为什么做**：现状标题框**没有被允许增长到可用宽度**（表头是两个 `flex: none` 子项 + `justify-content: space-between`），名称稍长就先被裁；而右侧操作区旁仍有空白 ⇒ 用户看到「明明有地方却显示不全」。

## 一、问题证据

- 组件结构（`packages/shared/components/smart-list/smart-list.vue`）：`nue-collapse-item` 的 `#header` 内为 ① `nue-button theme="pure"`（箭头图标 + `.nue-div--title`（名称 + 计数））② `.nue-div--actions`（管理 / 新增两个 pure 按钮）。
- 主题约束（读码）：`.nue-collapse-item__header{display:flex; justify-content:space-between; align-items:center}`；`.nue-div{flex:none; width:fit-content}`；`.nue-button{--nue-button-flex:none}` ⇒ **表头两个子项都是"不伸缩、按内容定宽"**，宽度总和超过容器时只能溢出；而祖先链上有 `overflow-x: hidden`（`#SubPageAsideTeleportSlot` / `.nue-div--aside-wrapper`）⇒ 溢出**被裁剪**而非换行 ⇒ 表现为"标题被吃掉一段、右侧还有空白"。
- 影响面：`apps/web/src/components/calendar/aside/aside.vue` 两处（清单 / 标签两个 SmartList）· 其余使用 SmartList 的页面同理（桌面窄窗亦受影响）。
- 5 Whys：① 标题被裁 ← 标题区宽度被"内容定宽"决定后未参与分配；② 为何不参与分配 ← 表头子项都是 `flex: none`，没有"吃剩余空间"的成员；③ 为何这样写 ← 表头最初只承载短名称 + 两个图标按钮，未考虑长名称；④ 为何现在暴露 ← 手机抽屉（256px）成为真实使用面（T521 后可进设置、侧栏被真用）；⑤ 根因 ← **表头缺少"可伸缩的内容区"这一职责划分**（标题应占剩余、动作固定）。
- **待实测项（RD 必须先量后改）**：① 表头各子项的实际 `clientWidth` 与容器宽；② 标题文字被裁的**真实来源**（是 `.nue-text` 的 `text-overflow` 生效，还是祖先 `overflow-x: hidden` 直接裁边）；③ 省略号是否会出现（若被祖先裁边则**不会有省略号**，只有硬切）。以上三项必须以真实组件（不 stub `nue-collapse-item` / `nue-button`）的实测数据写进回执。

## 二、目标指标

- **可核指标 1**：256px 抽屉内，中文 ≤10 字 / 英文 ≤24 字符的清单名**完整显示率 100%**（用真实最长名称实测，非估算）。
- **可核指标 2**：真放不下时，省略号**出现在文字末尾**（`text-overflow: ellipsis` 生效），且列出「被裁标记」不再出现"硬切"。
- **可核指标 3**：桌面侧栏与既有布局**无回归**（表头高度、操作按钮位置、折叠交互不变）。
- **口径缺口**：无埋点；靠实测宽度数字 + 用户真机勾选。

## 三、范围 / 非范围

- **范围**
    1. 表头职责划分：标题区 = **可伸缩**（占剩余宽度，`min-width: 0`），动作区 = **固定内容宽**。
    2. 标题单行 + `text-overflow: ellipsis`；真溢出时给 `title`（或既有 tooltip）全文。
    3. 计数（count）随标题同行，且**不被省略**（标题省略时计数仍在，或整体省略但不吞计数 —— 二者择一，由 RD 依据实测选，需在回执说明）。
    4. 复用/扩展既有测试：`smart-list` 及使用方（calendar aside）相关用例，覆盖「长名称不硬切」「动作按钮不被挤压」。
- **非范围**
    - **多行标题** —— 理由：用户选 A（单行 + 真不够才省略）；两行会改变表头高度与列表密度。
    - **改操作按钮的数量/位置/图标** —— 理由：与溢出无关，改动会牵连 `slot name="actions"` 的三处调用方。
    - **改折叠交互 / 拖拽** —— 理由：不在症状范围内。
    - **`NaoSmartList` 对外 API** —— 理由：跨包公共组件，改 API 需另立 ADR。
    - **移动端红线目录** —— 理由：`packages/presentation-react` / `apps/mobile` 不随 Web 改动。

## 四、用户场景

- **画像**：清单名较长的用户（如「2026 Q4 产品迭代待办」），在手机抽屉里扫清单。
- **关键路径**：打开抽屉 → 找清单 → 需要**一眼看清名称**（不是猜）。
- **页面状态清单**
    - 加载：不适用（同步数据，随既有加载态）。
    - 空：无清单 ⇒ 既有空态文案，不变。
    - 错误：不适用。
    - 成功：长名称完整显示；极长名称末尾省略 + 可读全文。

## 五、业务规则

- **不变量 1（空间优先给标题）**：标题吃满「容器宽 − 动作区宽 − 箭头图标宽」，不得预留空白。
- **不变量 2（动作区不被挤压）**：管理/新增按钮宽度与点击区不变（≥ 既有尺寸），不因长标题而缩水或被推出。
- **不变量 3（省略语义正确）**：省略只发生在**文字末尾**，并同时提供全文（`title`）；不得"硬切"（无省略号的裁边）。
- **不变量 4（计数不丢）**：计数为信息的一部分，不得因省略而消失。
- **不变量 5（桌面无回归）**：表头高度、左对齐基线、折叠/拖拽行为不变。
- **不变量 6（不改公共 API）**：`NaoSmartList` 的 props/emits/slots 不变。

## 六、NFRs

- **兼容性**：256px 抽屉 / 320px 视口 / 桌面侧栏三档均通过；桌面 / Electron 除"标题更宽"外无其它变化。
- **性能**：纯 CSS 布局调整，零 JS 监听。
- **可访问性**：全文可通过 `title` 或既有 tooltip 获取；折叠头仍可键盘操作。
- **安全**：不适用。
- **可维护性**：修复落在 `packages/shared/components/smart-list/smart-list.css`（单一来源），**不得**在使用方各自打补丁。

## 七、AC

- **验证接缝**：`packages/shared/components/smart-list` 及 `apps/web/src/components/calendar/aside/__tests__`（扩展，不新建基建）。
- **AC1（主路径）**：Given 256px 抽屉 + 10 字中文清单名，Then 标题完整显示、无省略号、右侧动作按钮位置不变。
- **AC2（异常 · 长名）**：Given 名称长度使「标题 + 动作」超出容器，Then 省略号出现在文字末尾、动作按钮未被压缩、`title` 可读全文。
- **AC3（边界）**：Given 计数为三位数与最宽动作区组合，Then 标题仍吃到剩余宽度，且不出现横向滚动条 / 硬切。
- **AC4（负向闭环）**：Given 桌面（>445px）与 Electron，Then 表头高度、基线、折叠与拖拽行为**零变化**；无清单时空态不变。
- **AC5（设计一致性）**：字号/颜色/间距沿用既有 `nue-*`；不新增 token；不改变左对齐与图标间隔。
- **AC6（可自动核 + 实测证据）**：① 回执须含**真实组件实测**的宽度数字（容器宽 / 标题框宽 / 动作区宽）与「修复前被裁的是文字还是边」的判定；② 测试断言：标题容器具备可伸缩与 `min-width: 0`、`text-overflow: ellipsis` 生效、动作区 `flex: none`；③ 使用方（calendar aside）相关用例全绿。
