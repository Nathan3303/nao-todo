## TL;DR

- **做什么**：给日视图时间轴补上 **00:00 与 24:00 的可见边界**，并修好**首 / 末刻度文本的落位**（首标签不悬空、末标签后不留无标注段）。
- **给谁**：日历「日」视图用户（web + 桌面端）。
- **成功标准**：×1…×4 五档 × {触 20px 下限列宽, 宽屏列宽} 下，两端边界可见、首末标签不裁切、无 >30min 的无标注段；**内部格线与全部交互零变化**；用户视觉勾选通过。
- **不做什么**：不改几何公式 / 格线链 / 档位阶梯 / 两端 fade 行为 / 周视图与月视图 / 移动端。
- **为什么做**：轴起点**根本没线**（渐变周期从透明起笔），终点线**与容器右边缘重合**被读作「被裁的边」；末标签停在 `23:30`，其后 6 列（触下限时 120px）无任何标注 ⇒ 用户看不出「这一天从哪到哪」。

## 1. 问题证据

- **现状 A（起点无线）**：格线由 `.day-col-lines` 的 `repeating-linear-gradient` 绘制，**线画在每个周期的末端**（`calc(100% / 24 - 1px)` → `calc(100% / 24)`）⇒ **x = 0 恒为 transparent**；48 / 144 / 288 各层同理。首标签 `00:00` 绝对定位在列 0 左边缘（`.is-first-tick` 把 `translateX(-50%)` 改为 `0`）⇒ **有线可依的前提不存在，标签悬在轴起点**。
- **现状 B（末标签后空一截）**：列头标签只在 `minutes % 30 === 0` 的列生成（30min 档仅整点 `HH`，细档整点 + 半点 `HH:MM`）⇒ 末标签是 **`23:30`（列 282 / 288）**；24:00 处那条线恰好压在 `.day-scroll` 的 100% 处、而 `.day-body` 是 `overflow-x: hidden` ⇒ 视觉上等同「容器右边框被切掉」，**不被读作轴端点**；`23:30 → 24:00` 共 6 列（触下限时 120px）**无任何刻度或标注**。
- **用户复现路径**：档位拉到 ×4（5min / 列，288 列）+ 窗口较窄（列宽触 `MIN_DAY_COLUMN_PX = 20px` 下限，总宽 = 288 × 20 = 5760px）⇒ 两端缺陷最显眼。×1 档同样存在（同一套渐变与标签规则），只是列稀疏、不易察觉。
- **5 Whys**：
    1. 为什么首端没有线 ⇒ 渐变以 transparent 起笔，线只画在周期末端，端点被排除在「网格」之外。
    2. 为什么当初没在端点补线 ⇒ 模型按「24 小时等分网格」设计，**端点被默认交给容器边框**（`overflow-x: hidden` 下即不可见）。
    3. 为什么末标签停在 23:30 ⇒ 标签生成规则只有「整点 / 半点」两型，**没有「轴端点」这一型**。
    4. 为什么值得修 ⇒ 端点是用户判断「这一天从哪到哪」的唯一锚；缺锚比缺内部格线更影响可用性（用户已直接报障）。
    5. **根因** ⇒ 网格模型（`build-day-grid.ts`）只描述「内部刻度」，**未描述「轴端点」这一独立语义** ⇒ 端点无数据、无类名、无样式。
- **影响面**：仅「日」视图时间轴的视觉与端点标注；无功能/数据/性能影响。

## 2. 目标指标

- **中间指标**：端点边界线 **2 条**（00:00 / 24:00）在「5 档 × 2 种列宽」共 10 种组合下均可见；端标签 **2 个**（首 / 末）无裁切；轴上 **无 >30min 的无标注段**。
- **成功口径**：`vp check` **0 error** · 受影响面测试全绿 + 批末全仓 `vp test` **0 红** · 5 个守卫 **rc0** · 双端 build **rc0** · 移动端 diff **0** · **用户视觉勾选通过**。
- **业务量化指标**：不适用（视觉缺陷修复，无可独立度量的业务量；用户报障即需求触发器）。

## 4. 用户场景

- 作为**放大看早间安排**的用户：日视图拉到 ×4（5min 粒度），我要一眼确认「这一天从 00:00 到 24:00」的起止，两端不能被截断感糊掉。
- 作为**默认档位**用户：×1 档看当天任务，端点同样不应「悬空」或「少半个标签」。
- 作为**窄窗口**用户：窗口窄到列宽触 20px 下限（总宽 5760px），横向平移到位移两端时，00:00 / 24:00 的边界与端标签必须清晰可见。
- 作为**键盘 / 读屏**用户：端标签若可点，须可 Tab 可达、有明确可读名称（不出现「24 点创建任务」这类歧义文案）。

## 5. 业务规则

- **R1 端点语义**：00:00 与 24:00 是时间轴的**物理端点**，须有**独立于内部格线**的可见边界；不得依赖「贴容器边缘」充当端点。**（T518-R2 修订：粗细与内部小时线一致 = `1px`，靠「颜色更深」区分而非加粗 —— 用户 2026-10-21 裁定「边界线不要这么粗，与正常刻度线一致即可，并且保持颜色」）**
- **R2 端标签落位**：首标签（`00:00`）左对齐于轴起点、不裁切；末标签标注 **`24:00`**（×1 / ×1.5 档沿用当前 `HH` 型式 ⇒ `24`）右对齐于轴终点、不裁切；中间标签（整点 / 半点）型式与档位对应关系**维持现状**。**（T518-R2 修订：两个端标签**不带左右内边距**，文字**紧贴**轴左端 / 右端 —— 用户 2026-10-21 裁定「00 和 24 这两个刻度就不要 padding 了，紧贴左和右」；中间标签仍保留既有 `0 6px` 内边距）**
- **R3 决议 D1（✅ 用户 2026-10-21 裁定：显示端标签）**：轴末端**显示 `24:00` 端标签**，而非「只加线不加标签」—— 理由：用户症状明确把「末标签后面空一截」当作问题，只加线仍留 120px 无标注段，未闭环。
- **R4 整像素**：新增线 / 标签须落在整像素（与 D3′ 同口径），不得引入子像素抗锯齿导致「线消失 / 闪烁」。
- **R5 单一来源**：端点样式复用既有 `--cal-*` token，**不新增 token / 色板**；端点实现**限定在日视图作用域**，不得让周视图继承（避免隐性扩散）。
- **R6 端点数据化**：端点语义进 `build-day-grid.ts` 模型（端点索引 / 端标签文本），**不在 CSS 里硬编码魔数**，以便后续周视图复用评估。
- **R7 内部标签一律居中（T518-R1，2026-10-21 用户验收裁定）**：所有**内部**刻度标签以刻度线为中心（`translateX(-50%)`）；**轴末端的对齐保护由端标签唯一承担** ⇒ 撤销 `.is-last-tick` 的右对齐保护（类名 / CSS 规则 / 断言一并移除），否则末内部标签（×1 = `23`，×2+ = `23:30`）会右偏到自己的刻度线左侧，与其余标签不一致。**首端的 `.is-first-tick` 保留**（首列居中会向左裁掉一半，该保护仍必要）。
- **R8 当前时间标注（T518-R3，用户 2026-10-21 追加）**：**当前时间线顶端显示当前时刻 `HH:MM`**（线 / 圆点 / 文本**同色**；**T518-R6 换色：`--nue-error-color-60`（红）→ `--cal-fg`（中性深灰）**，用户 2026-10-21 裁定「不要红色，换一个」）（纯文字，**不新增底色 / 气泡**，既有顶部圆点保留）；恒 `HH:MM` 两位补零、**不随档位简化**；贴在线顶端、随内容横向滚动（**不 sticky**）；**非今天不渲染**（跟随既有 `v-if`）；沿用既有 **30 秒**时基，**不得新增第二个定时器**；`pointer-events: none`（不拦截任务条 / 拖拽 / pan）。**（T518-R5c 数值口径，2026-10-21 arch 评审后定）** 带高 `24 → 26px`：文本盒高 = `0.65rem × 1.5 = 0.975 × 根字号`，而仓内**没有** `html { font-size }`（`:root` 只定义 `--nue-primary-font-size` 变量，与 `rem` 无关）⇒ 实际根字号 = 浏览器默认值、**用户可改**。24px 时 `textTop = 16 − 0.975·root ≥ 0` ⇒ 根字号只允许 **+2.5%**（17px 即破，而测试按 16 硬推仍绿 ⇒ **静默失守**）；26px ⇒ 容忍根字号 **≤ 18.46px（+15%）**。**不采纳**「带高用 `calc(0.975rem + …)` 随根字号缩放」：会引入**子像素带高** ⇒ 泳道与任务条边缘抗锯齿抖动，违反整像素口径；**不采纳**把 `font-size` 改 px（伤可访问性缩放）。**残留上限（如实登记）**：根字号 ≥20px（+25%）仍会越带，此时应重估带高。**（T518-R5 修订）** 文本承载方式 = **恒 1 个真实文本节点**（R11 的视口贴边需测文本宽度，`attr()` 伪元素无法测宽）⇒ 原「零 DOM / `content: attr(data-now)`」表述作废；节点数**恒定 1 个、不随列数增长**（NFR 口径不变）。
- **R9 当前时刻文本的专用间隔带（T518-R4，用户 2026-10-21 追加）**：泳道区**上方**留出一条**恒定**间隔带（**取 26px**；推导见下方「R5c 数值口径」）；当前时刻文本**只在该带内**横向移动（跟随线位置），**不得压住任何任务条内容**；任务条与拖拽 / 缩放的命中几何**整体下移该高度**（相对泳道的相对关系不变）；该带**恒定存在**（不随「今天 / 非今天」切换），避免切换日期时任务条整体跳动。
- **R10 圆点与线同轴心（T518-R4）**：`.day-now-line::before` 实心圆点**恒与线水平同轴心**（撤销 R3 为防裁切加的 `is-near-start` / `is-near-end` 水平位移）；代价 = 时间线贴轴起点 / 终点（约 ±5min 且滚到端点）时圆点有 **≤3px** 被 `overflow-x: hidden` 裁切 —— 用户 2026-10-21 明确**「保持垂直对齐」优先于「完全不被裁」**。
- **R11 时刻文本定位与间隔带空白（T518-R5，用户 2026-10-21 追加）**：① 文本**水平居中于 now-line**、**垂直位于线头正上方**（即落在间隔带内，线身在带内不绘制，从带底起）；② **视口贴边**：当「居中」会使文本越出**当前可见区域（视口）**的左右边缘时，文本改为**贴住该侧可视边缘**（不居中、不裁切）—— 注意这是**视口**语义，与 R8/AC6b 的「轴端点」语义是两回事，两者可能同时生效；③ 横向滚动 / 档位切换 / 切日 / 窗口 resize 时实时跟随，**不得抖动**；**禁在滚动 / 拖拽帧内读布局**（文本宽度须缓存 + rAF 批处理，沿用 `use-day-viewport` 既有纪律）；④ **间隔带内保持空白**：内部格线（`.day-axis-bg`）让出带高（`top: var(--day-now-band)`，**日视图限定**），带内除「时刻文本 + now-line 头部圆点」外不绘制内容；**端点边界线保留贯穿**（它属轴的框，不是刻度线）。
- **R12 全天泳道置顶（T518-R7，用户 2026-10-21 手工调整后纳入）**：`.day-scroll` 子节点顺序改为 **全天泳道 → divider → 列头 → 网格**（原为 列头 → 全天泳道 → divider → 网格）⇒ 全天任务在**最上方**优先可见，列头紧随其下。**「全天」文字标签移除**（信息不丢失论证：泳道位置 + 只读条自身已表达「全天」，去掉标签避免置顶后重复占位；**保留** `data-allday-reason` 与 `title-suffix` 的可访问性原因说明）。
- **R13 间隔带精细数值（T518-R7）**：带高 **26 → 24px**、文本 `line-height: 1.5 → 1.3`、文本**允许** `padding: 0 var(--nue-padding-sm)`（横向呼吸；横向宽度须计入视口贴边测量）。**为何不采纳用户试的 16px**：几何硬约束 = `文本盒(0.65rem×1.3 = 0.845×根字号) + 圆点 7 + 间隙 1 ≤ 带高` ⇒ 16px **装不下**（20.52 > 16）；21/22px 虽装得下但根字号容忍上限仅 **+3.6%**（＝退回 arch 指出的「假绿」区）；`8 + 0.845×16×1.15 = 23.55` ⇒ **24px 是保住「根字号 +15% 以上」的最紧值**（实测上限 **18.93px / +18%**）。
- **R14 扩展到 18px（T518-R8，用户 2026-10-21：「更紧一点，18px ?」）**：带高 **24 → 18px**，并**把圆点移出带外**：`.day-now-line::before` 的 `top: -7px → 0`（圆点**完全落在泳道顶部、与线头重合**），文本 `bottom: calc(100% + 8px) → calc(100% + 1px)` ⇒ 文本盒 `[3.48, 17]`、圆点 `[18, 25]`、**间隙 1px**。**为什么必须移圆点**：`文本 13.52 + 圆点 7 = 20.52 > 18` ⇒ 两者不可能同处 18px 带内（要么圆点溢出带外、要么文本被挤）。**收益（非妥协）**：根字号容忍上限 `(18−1)/0.845 = 20.12px（+25.7%）`，**优于 24px 时的 +18.3%** —— 因为带内不再需要容纳圆点。**AC8d 口径随之调整**：带内**只有文本**；圆点属于「线头标记」、位于带下泳道顶部（仍与线水平同轴心，R10 不变），且**不得遮挡任务条文字**（7px 圆点、仅在轴顶端，由用户视觉勾选确认）。
- **R15 文本靠拢列头（T518-R9，用户 2026-10-21：「时间文本能够贴着列头的近一点，这样没有阅读问题」）**：文本由**底对齐**改为**顶对齐**（`.day-now-label` 的 `bottom: calc(100% + 1px)` → **`top: 0`**）⇒ 文本盒 `[0, 13.52]`，与上方列头的视觉距离 = **仅 `.day-scroll` 的 8px flex gap**（原为 8 + 3.48 = 11.48px）。带高仍 **18px**（圆点在 `[18,25]`，文本↔圆点间隙 4.48px）。**附带收益**：根字号容忍上限由 `(18−1)/0.845 = 20.12px（+25.7%）` 升至 **`18/0.845 = 21.30px（+33.1%）`**（顶对齐后文本只受带上缘约束，不再被底边偏移挤压）。
- **R16 用户终版微调（T518-R10，用户 2026-10-21 手工调整并交付）**：① `--day-now-band: 18 → 12px`（**只用于** `.day-axis-bg` 与 `.day-grid .cal-lanes` 的偏移，即「带内无格线」+ 泳道下移 12px；now-line 不再消费该变量）；② `.day-now-line { top: 2px; bottom: 0 }` ⇒ 线从网格顶下 **2px** 起贯穿到底（**不再让出整条带**）；③ `.day-now-line::before { top: 0 }` ⇒ 圆点 `[2, 9]`（在带上半部、与线头重合）；④ `.day-now-label { top: -10px; line-height: 1 }` ⇒ 文本盒 **`[-10, 0.4]`**（顶出网格 10px，落在列头下方 8px flex gap 与列头底部空白内，**视觉紧贴列头**），与圆点间隙 **1.6px**；⑤ 根字号上限 = `(2 − (−10)) / 0.65 = 18.46px（+15.4%）`。**契约口径变更（取代 R11/R14/R15 相关表述）**：文本**不再位于带内**（在带上方的网格外区域）；圆点**不在带下**（在带上部）；「线身让出带」作废 —— 现语义为「**文本在线头正上方，线头（圆点）与线贯穿带与泳道**」。

## 6. NFRs

- **性能**：**零 DOM 增量随列数放大**（禁 288×N DOM；端点线用 CSS / 伪元素）；**禁**在 `pointermove` 或滚动帧内读布局（沿用 `use-day-viewport` 现纪律）。
- **a11y**：`.day-col-label` 仍为原生 `button`（键盘可达）；端标签若沿用点击新建入口，须有 `aria-label` / `title` 且语义正确（`24:00` 的文案由 RD 拟定、PM 复核，避免歧义）。
- **一致性**：图形（线）对比度 **≥3:1** 对 `--cal-bg`（`DESIGN.md` 下限）；文本 ≥4.5:1；不依赖颜色单一通道（本次不涉及三态语义）。**（T518-R6）** 当前时刻线取 `--cal-fg`（= `--nue-primary-text-color` = `primary-color-800`；浅色 hsl(0,0%,20%) ≈ **12.6:1**、深色模式自动升为 l80 ≈ **10:1**）⇒ 两模式均远超 3:1（图形）与 4.5:1（文本，同一 token 用于文本）。
- **可维护性**：端点语义以数据/类名承载，落在 `__tests__/` 可断言的位置（结构断言 + 行为断言各一组）。
- **回归面**：内部格线 / 任务条 / 拖拽 / pan / 档位持久化 / 新建入口**逐项零变化**（由 AC4 钉死）。
