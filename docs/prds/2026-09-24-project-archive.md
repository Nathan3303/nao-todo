# 2026-09-24 清单归档 PRD（归档 = 收起但可找回；闭环 = 查看 / 恢复 / 单任务脱归档）

> **状态**：**待用户确认开工**（本 PRD 已含用户 12 条口径；技术口径待 arch 评审 ⇒ 见 §12）。
> **依据**：现状核查报告 `docs/reports/2026-09-24-project-archive-status.md`（`T174` 探针，**commit `ce272bc3`**）+ 用户 2026-09-24 逐条决策（ask_me 7 项 + 追加 2 条规则）+ 业界对照（§10）。
> **硬约束**：**不丢失数据**（归档绝不删数据）· **不丢失功能**（阶段一/二零回归）· **移动端零改动**。

## 1. 问题证据（5 Whys）

| 层       | 内容                                                                                                                                                     |
| :------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 现象     | **清单无归档可用**：web/desktop 无归档入口（菜单项被注释）；即便触发，`archive()` 实为 `delete()`                                                        |
| Why1     | 归档的**数据骨架早已铺好**（`Project.archivedAt` + 本地库字段 + 同步字段双向闭环 + 服务端 `Archive`/`Unarchive` API 与**双向级联**），但 UI/闭环从未接线 |
| Why2     | 归档入口被注释掉、`archive/unarchive` 方法体写成 `delete` 占位 ⇒ **半成品**（探针定性：「骨架齐备、闭环缺失、核心实现是错的」）                          |
| Why3     | 无「已归档清单」查看/恢复入口 ⇒ 即使用户能归档也**找不回**（`unarchive` 目前**仅服务端 API 可达**，i18n/组件/store action 全是死件）                     |
| **根因** | **缺少「归档 = 收起但可找回」的完整用户闭环**，且**缺少「归档清单内任务如何处置」的可见性规则**（客户端无级联 ⇒ 离线归档后任务仍留在日历/看板）          |

## 3. 范围 / 非范围

**范围（本批）**

1. **入口**：清单头部操作菜单 + **清单右键菜单**（两处一致）⇒「归档清单」；**二次确认**（提示「该清单内 N 个任务将一并归档」）
2. **归档语义**：整清单归档 ⇒ 清单从活动区收起；**任务随清单一起隐藏/恢复**（客户端**同级联** + 服务端既有级联；离线一致）
3. **查看与恢复**：侧栏清单区底部**「已归档」入口** ⇒ 面板列出已归档清单（名称 / 任务数 / 归档时间）⇒ **「取消归档」** ⇒ 清单**回侧栏原位**、该清单仍归档的任务**全部恢复**
4. **归档清单内只读**：禁止新建/编辑/删除/改期/移动/番茄等**一切变更**；**唯一例外 = 逐条「取消归档」**（见 5）
5. **单任务脱归档（用户追加规则）**：归档清单内可对**单条任务**「取消归档」⇒ 因清单仍归档，该任务**归属「收集箱」（写 `projectId = 'inbox'`）** + **可见提醒**（中英）；若清单已恢复 ⇒ 该任务回到原清单（**不改** `projectId`）
6. **可见性**：归档清单与归档任务在上述 **7 处全部排除**；**搜索默认排除**，并提供**显式开关「包含已归档」**（开时命中并带「已归档」标识）
7. **禁归档内建清单**：收集箱等内建清单**不可归档**（入口不出现或禁用 + 兜底拒绝）

**非范围（本批不做，显式登记）**

- **单任务归档入口** —— **用户 2026-09-24 决定：本批不做**。理由：与既有「完成 / 放弃 / 删除」三态语义重叠；业界「单条归档」主要见于卡片/工单类（Trello/Jira），个人任务类（Todoist/Things）用「完成 + 清单归档」即可。**重估判据**：实际反复出现「想收起单条任务但不想标完成/放弃/删除」，或单个清单长期混着「活跃 / 搁置」两批任务 ⇒ 单独立项（届时复用本批的任务级可见性改造，边际成本最低）。**替代**：先由既有「**放弃**」承担「不做了」；若「放弃 ≠ 归档（留着以后可能做）」的语义差确实存在 ⇒ 即为重估信号。
- **自动归档**（按时间/完成率等策略）· **归档统计/报表** · 归档清单的**永久删除**（仍走现有「删除清单」）
- **批量**取消归档（面板内可后续增强）· **移动端任何改动**（红线）
- **字段级/复杂恢复**（如把归档任务恢复到指定清单）

## 5. 业务规则

1. **归档 ≠ 删除**：归档只置 `archivedAt`，**绝不**写 `deletedAt`；删除仍走现有「删除清单」流程。
2. **级联**：清单归档 ⇒ 其下任务一并归档（客户端本地级联 + 服务端既有级联，双端一致）；清单恢复 ⇒ 其下**仍处于归档状态**的任务一并恢复。
3. **只读**：清单处于归档态 ⇒ 其下任务**只读**（禁一切变更）；**允许**的唯一动作 = 单任务「取消归档」。
4. **单任务脱归档的归属（用户规则）**：任务取消归档时若**其清单仍归档** ⇒ 任务改为**归属收集箱**并**提醒用户**；若清单已恢复 ⇒ 任务回到原清单。（⚠️ **收集箱表示 = 写 `'inbox'`（禁 `''`）** —— 见 §12 评审结论 Q4；字段写法 = `archivedAt = null` + `projectId = 'inbox'` + `updatedAt`（同事务 + `markDirty`））
5. **可见性**：归档清单/任务在 7 处默认排除；搜索默认排除 + 显式「包含已归档」开关。
6. **复位**：取消归档后清单回侧栏**原位**（保留 `sortId`；⚠️ **如实口径**：归档期间若发生过排序重建，「回原位」= **最近位置**、非像素级原位 —— §12 Q6 / ADR PA-10）；任务恢复后回到原清单原位置。
7. **二次确认**：归档前列出「N 个任务将一并归档」（**N 口径 = 「未归档且未删除」计数，不得用 `taskCount`** —— §12 Q2）；取消 = 不归档（无副作用）。
8. **内建清单不可归档**（收集箱等）。

## 6. NFRs（业务视角）

- **数据完整性**：归档/恢复**不得**产生静默丢失；离线窗口内级联必须一致（不得出现「清单收起但任务仍可见」）。
- **可观测**：单任务脱归档 ⇒ 收集箱 + **可见提醒**；批量归档 ⇒ 确认框内数量可见。
- **性能**：归档/恢复为本地优先写（即时），不得因归档查询拖慢列表（7 处过滤须为既有查询的谓词扩展，不引入全表扫描）。
- **一致性**：web/desktop 同组件同逻辑；移动端零改动。
- **可回归**：阶段一（离线镜像/迁移门/清库/明文姿态/状态展示）与阶段二（OCC/冲突 UX/多标签/偏好）**零回归**。

## 12. 架构评审结论（`T175`，arch，ADR `docs/adr/2026-09-24-project-archive.md` r1）—— 六项已裁定

> 评审结论：**⏳ 有条件可行**（**阻塞项 1** = `DEF-36` 前置修复）。以下为逐项裁定（原文见 ADR §2–§7）。

| #             | 结论                                                                                                                                                                                                                                                                                                                                                                             |
| :------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q1 客户端级联 | **必做**：任务仓储新增 `archiveByProjectId` / `unarchiveByProjectId`（批量），**清单 + 任务同一 Dexie `rw` 事务** + 逐任务 `markDirty`；只改需变状态的行。代价 = N 本地写 + N 队列项，但走既有 `/sync/push` 批量、不建新通道                                                                                                                                                     |
| Q2 可见性     | **单一杠杆 L1**：本地任务仓储 `list()` **默认排除归档**（未传 `isArchived` 视同 `false`）⇒ 一举覆盖清单视图 + **内置视图（8 个 `getTasksOptions` 全无该谓词）**；②搜索另加「包含已归档」开关 + 结果标识；`taskCount` 口径不变但**二次确认 N 另算**                                                                                                                               |
| Q3 三态边界   | **归档 = `archivedAt`** · **停用/删除 = `deactivedAt`**（服务端权威，7 天后 purge）· **墓碑 = `deletedAt`**（仅同步/清库，不作业务判定）。客户端「已删除」判据收敛为 **`deletedAt` ∪ `deactivedAt` 任一非空**；`ProjectEntity.isDeactived()`（未来时间判据、**0 调用方**、系用户域语义误移植）**废弃**                                                                           |
| Q4 收集箱表示 | **写 `'inbox'`（禁 `''`）**：本地按**字面 `'inbox'`** 过滤（写 `''` 会当场「任务消失」）；服务端对二者等价归一为隐式桶 `userId`（CAL-03）。**单任务脱归档** = `archivedAt=null` + `projectId='inbox'` + `updatedAt`（同事务）；**不得**因脱归档改清单 `archivedAt`                                                                                                               |
| Q5 `DEF-12`   | **②`Sort` 无白名单（注入面）同批修（必做）**；**①`ByTaskArchived(false)` 空操作同批修，但只修显式 `false` 分支 ⇒ `archived_at IS NULL`**，**（用户 `DP-1=(b)` 裁定）同时改「未传 `isArchived`」的服务端默认 ⇒ 排除归档**（移动端可见结果变化，**须随发布说明登记**）。已核实 `/sync/pull` 不经该谓词                                                                             |
| Q6 只读与复位 | 路由**复用**清单视图 + **数据驱动归档态守卫**（判据 = 任务 `archivedAt` 非空，**用例层**拦截 ⇒ URL 直达也写不了）；**新增独立错误码 `ARCHIVED_READONLY`**（**不复用** `OFFLINE_READONLY`，语义/根因不同）；「已归档」入口 = 侧栏底部 + **复用 `project-manager` 弹窗新增 `archived` tab**（零新组件、两端同 UI）；`resortWithRebuild` **保持只对活动项重建**，恢复时碰撞按锚归一 |
