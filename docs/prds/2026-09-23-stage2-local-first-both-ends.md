# 2026-09-23 阶段二 PRD 草案（两端同构 local-first + 同步 + 服务端冲突解决）

> **状态**：**草案 v0.1**（PM 起草，用户已定方向；**待 arch 架构评审转译技术指标**）
> **用户方向（2026-09-23 原话）**：「**产品整体**……**Web 端和 Desktop 端都是读写本地**，然后**同步服务进行同步**，与后端**解决更新冲突**……**Desktop 端就只是为 Web 端套了一层桌面端的壳**而已。」
> **硬约束（用户强调）**：**不要丢失功能**。

## 1. 问题证据（5 Whys）

| 层       | 内容                                                                                     |
| :------- | :--------------------------------------------------------------------------------------- |
| 现象     | **两端架构分裂**：desktop 读写本地 + 回传；**web 只读镜像 + 写路径远端直连**（离线禁写） |
| Why1     | 阶段一为「最小风险」选了 web 只读（C-59），desktop 保持既有 local-first                  |
| Why2     | 分裂导致**同一产品两端行为不同**（web 离线不能写、desktop 能写）                         |
| Why3     | **web 的 IndexedDB 只用于读镜像**，未用于写 ⇒ 架构能力浪费                               |
| Why4     | 两端各维护一套写路径语义 ⇒ **同步/冲突逻辑无法统一**                                     |
| **根因** | **缺少「两端同构 local-first + 统一同步 + 服务端冲突解决」的终态架构**                   |

## 2. 目标指标

| 指标           | 目标         | 说明                                             |
| :------------- | :----------- | :----------------------------------------------- |
| **功能不丢失** | **100%**     | 阶段一/历史功能**零回归**（硬约束）              |
| 两端行为一致   | **100%**     | web 与 desktop 对同一操作产生**一致结果**        |
| 离线可用（写） | **两端均可** | 离线可增删改，联网自动回传                       |
| 数据不丢       | **0 丢失**   | 冲突必须**可解**且**可观测**，不得静默覆盖丢数据 |
| 冲突可解率     | **100%**     | 每条冲突有确定结论（不卡死、不丢）               |

## 3. 范围 / 非范围

|          | 内容                                                                                                                                                                                                                                                                                                                                                    |
| :------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **做**   | ① **web 业务写路径切本地**（25 个写入口，清单以 `docs/reports/2026-09-23-DEF-PROBE-P1-offline-probes.md` §3.3 为唯一真源）② **回传机制**（本地改动 → 服务端）③ **服务端冲突解决**（策略由 arch 定）④ **两端一致**（web / desktop 同构）⑤ **迁移**（存量 web 只读数据 / 离线镜像 → 新语义）⑥ **偏好面复用**（`TASK-26` 已验证的「本地优先 + 同步」机制） |
| **不做** | ❌ **移动端**（红线）· ❌ 服务端会话模型改造（除非冲突解决必需）· ❌ 重写 UI                                                                                                                                                                                                                                                                            |
| **依赖** | `TASK-26`（偏好面本地优先 + 同步）**先行落地**，作为机制验证 ✓                                                                                                                                                                                                                                                                                          |

## 4. 用户场景

| 场景                                | 期望                                       |
| :---------------------------------- | :----------------------------------------- |
| web 离线新增/编辑任务               | **本地成功**、界面即时生效、联网后自动回传 |
| web 与 desktop 同时改同一任务       | **服务端给出一致结论**（不丢数据、可观测） |
| web 在线改任务                      | 本地优先 + 回传（**不再**远端直连写）      |
| 网络异常 / 回传失败                 | 不阻塞使用；**可见提示**；重试             |
| 阶段一功能（离线读镜像 / 只读提示） | **不得回退**（离线仍能读）✓                |

## 5. 业务规则

1. **本地优先**：两端**所有写**先落本地，再回传 ✓
2. **离线可写**：两端离线均可写 ✓（撤销 C-59 的 web 离线禁写）
3. **冲突由服务端解决**：客户端不做合并决策（或仅做无损提示）✓
4. **不丢功能**：阶段一的「离线可读镜像 / 迁移门 / 清库 / 明文姿态」等**全部保留** ✓
5. **可观测**：冲突、回传失败、重试均有计数与可见提示 ✓

## 6. NFRs（**业务视角基线**，技术指标由 arch 转译）

| 维度           | 基线                                             |
| :------------- | :----------------------------------------------- |
| **数据完整性** | **冲突不得导致静默丢数据**；每条冲突有确定结论   |
| 可用性         | 离线可写；网络异常不阻塞                         |
| 一致性         | 两端同构；同一操作结果一致                       |
| 性能           | 本地写**即时**（不等待网络）；回传不阻塞 UI      |
| 可观测         | 冲突/失败/重试计数 + 可见提示                    |
| 安全           | 沿用阶段一（明文姿态 / 清库 / 会话）**不得削弱** |
