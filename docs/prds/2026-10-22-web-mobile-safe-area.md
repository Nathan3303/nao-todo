# 2026-10-22 Web 端移动浏览器视口与安全区修复 PRD

> **状态**：**已开工（用户 2026-10-22 确认，D1–D4 全按推荐项裁定）** —— 派发 `rd-fe`。**Issue**：[#217](https://github.com/Nathan3303/nao-todo/issues/217)（仅摘要 + 指针）· **分支** `feat/217-web-mobile-safe-area`。
> **依据**：用户 2026-10-22 报障原话（「用手机浏览器浏览 NaoTodo Web 端时会出现显示不全，主要体现为手机顶部刘海遮盖以及浏览器底部超越视口。我怀疑是 css 属性值的问题，比如 100vh 或 100vw，我记得有一个 css 属性值可以覆盖手机端的安全区域，看下能不能通过 theme 的形式将修改落到覆盖组件级别中」）+ PM 澄清四问（设备 = iPhone Safari 普通标签页；主症状 = **底部最后一行被浏览器地址栏盖住且无法滚到底**；范围 = **只做安全区/视口修复**；派发 = 走完整流程）+ 读码。
> **硬约束**：**移动端零改动**（`packages/presentation-react` / `apps/mobile`）· 桌面端与 Electron **视觉零变化** · 不新增 `nue-*` token · C 端界面原则（`AGENTS.md` / `DESIGN.md`）· 不改业务逻辑与契约。

## TL;DR

- **做什么**：修 Web 端在**手机浏览器**里的视口与安全区基线 —— 外壳高度不再被浏览器地址栏遮住、内容能滚到底，刘海 / 手势条区域留出安全边。
- **给谁**：用手机浏览器访问 NaoTodo Web 的用户（当前 iPhone Safari 为已确证场景）。
- **成功标准**：iPhone Safari（地址栏**可见**与**收起**两态）下末行内容可完整看到且可滚到底；桌面端 / Electron 视觉零变化；防回归测试落地。
- **不做什么**：不做手机窄屏布局重排（另开需求）；不碰移动端两个红线目录；不改业务与后端。
- **为什么做**：外壳高度按「工具栏收起时的大视口」算（`100vh`），可视区比它矮 ⇒ 底部被地址栏吃掉；而 `html{overflow:hidden}` 让这段溢出**无法用滚动补偿** ⇒ 「看不到 + 滚不到」。

## 一、问题证据

- **用户复现**：iPhone · Safari 普通标签页（非主屏独立窗口）⇒ 任务列表**最后一行被地址栏盖住**，且页面**滚不动**，无法把末行拉进可视区；用户另报顶部刘海区域可能遮盖。
- **视口基混用（读码）**：主题 reset `nue-ui-theme-shadlike/dist/global/html-reset.css` 给 `.nue-html` 定 `height:100vh / width:100vw`，并由 `#app{height:100%}` 链下来；项目补丁 `apps/web/src/themes/variables.css:13-15` 只把 `body` 改成 `100dvw / 100dvh`。⇒ **`html` 用大视口、`body` 用动态视口**，两者不同基；移动端 `vh` 取「工具栏收起」高度，比当前可视区高 ⇒ 外壳底部落在地址栏之下。
- **无法滚动补偿**：`html` 同时是 `overflow:hidden`（主题 reset）⇒ 溢出部分既不可见也不可滚；内部滚动容器只覆盖到「大视口」底部 ⇒ 用户感知为「最后一行永远够不到」。
- **安全区拿不到**：`apps/web/index.html:5` 的 viewport meta **缺 `viewport-fit=cover`** ⇒ iOS Safari 下 `env(safe-area-inset-*)` 恒为 `0`，任何纯 CSS 安全区方案在此为空转。
- **窄屏抽屉无底部安全边**：`apps/web/src/themes/dialog.css:23-38` 在 `max-width:400px` 下把弹窗变贴底抽屉（`margin-top:auto` + 无底 padding）⇒ 底部按钮压在 home indicator 上。
- **5 Whys**：① 末行被遮 ← 外壳高度按大视口算；② 为何按大视口 ← `html` 的 `100vh` 没跟 `body` 一起改成动态视口；③ 为何没被发现 ← 桌面 / Electron 上 `vh == dvh`，两基等价，**只在移动浏览器暴露**；④ 为何移动浏览器不在验收面 ← 全范围门禁无移动视口用例（仓库无 e2e / Playwright 基建），视觉走查按分工交给用户；⑤ 为何无该用例 ← Web 端「手机浏览器」是长尾入口（移动主战场是 `apps/mobile`），从未建立视口基线约束。
- **同类根因**（同一 `100vh` 口径）：`apps/web/src/components/initial-pull-gate.vue:51` 与 `apps/web/src/views/index/index.vue:22` 的加载态 `height="100vh"`。

## 二、目标指标

- **北极星拆解**：Web 端可用性 → 「移动浏览器首屏完整可读」→ 本次只取最硬的一格：**末屏可达性**。
- **可核指标**：iPhone Safari（地址栏可见 / 收起两态）下，列表最后一行**可见率 100%**（现状：地址栏可见态 **0%**，且无法通过滚动补偿）。
- **回归指标**：桌面端 / Electron 外壳与弹窗尺寸**零变化**（`env()` 解析为 0 ⇒ 数值与改动前一致）。
- **口径缺口（如实记录）**：项目无前端埋点 / RUM，指标只能靠**可视断言 + 用户真机勾选**，不做线上统计。

## 三、范围 / 非范围

- **范围**
    1. viewport meta 补 `viewport-fit=cover`（安全区能取到值的前提）。
    2. 视口基归一：`html` / `body` / `#app` 三者同一基（动态视口优先、静态视口兜底），并去掉 `100dvw` 这类「含滚动条宽度」的写法。
    3. 新增主题级安全区补丁文件（四向 `env(safe-area-inset-*)`，全带 `0px` 兜底），按既有 `apps/web/src/themes/*.css` 惯例在 `themes/index.ts` 引入。
    4. 窄屏抽屉式弹窗底部补安全边（覆盖组件级，`themes/dialog.css`）。
    5. 收敛残留 `100vh` 加载态（`initial-pull-gate.vue` / `views/index/index.vue`）。
    6. 源级防回归测试（沿用 `apps/web/src/themes/__tests__/button-overrides.test.ts` 的 `?raw` 断言手法）。
    7. `DESIGN.md` 增「安全区与视口基线」一节；`AGENTS.md` 加一条指针。
- **非范围**
    - **手机窄屏布局重排**（70px 固定侧栏 / 桌面信息密度）—— 理由：用户明确裁定「只做安全区/视口修复」，重排是独立需求、会显著放大改动面与验收面。
    - **`packages/presentation-react` / `apps/mobile`** —— 理由：移动端红线，不随 Web / 桌面需求改动。
    - **`packages/presentation-identity` 全屏遮罩里的 `100vw/100vh`** —— 理由：定位在 `position:fixed` 覆盖层，与外壳尺寸无关；且跨端共用、改它会把面扩到身份域。
    - **引入 `visualViewport` 监听 / 虚拟键盘适配** —— 理由：无此症状证据，纯 CSS 已能覆盖；加 JS 监听会引入 resize 抖动与性能面。
    - **引入 e2e / Playwright 基建** —— 理由：本批不新建测试基建，接缝复用既有源级断言。

## 四、用户场景

- **画像**：临时用手机浏览器打开自己 NaoTodo 的用户（不想装 App / 借他人设备查看 / 从聊天链接点开），典型是一次性、短会话、竖屏。
- **关键路径**：打开 Web 端 → 登录（或已登录）→ 进入任务列表 → **向下滚到列表末尾核对 / 勾选最后一条** → 需要能够完整看到并点到末行。
- **页面状态清单**
    - 加载：首屏加载态**同样**不得超出可视区（现状 `100vh`，横跨整个外壳）。
    - 空：空态文案居中，不得被地址栏切掉下半行。
    - 错误：加载失败提示（`nue-empty`）同样需落在安全区内。
    - 成功：列表末行完整可见、可点；抽屉式弹窗底部按钮不压手势条。

## 五、业务规则

- **不变量 1（单一视口基）**：`html` / `body` / `#app` 三者高度基**必须一致**；不得出现「父用静态视口、子用动态视口」的混基。
- **不变量 2（安全区内缩）**：刘海 / 圆角 / 手势条区域**不得承载可交互元素**；内缩量取 `env(safe-area-inset-*)`，无安全区环境为 `0`。
- **不变量 3（桌面零变化）**：桌面浏览器与 Electron 上安全区值恒为 `0` ⇒ 任何新增 padding / 尺寸不得产生非零效果。
- **不变量 4（可用性优先于观感）**：当「动态视口」不被支持时，**宁可让内容可滚**，也不得回到「被裁且不可滚」。
- **不变量 5（不改契约）**：不触碰领域 / 基础设施 / 服务端；不改任何组件对外 props（加载态高度从 `100vh` 改为相对父级属于适配修正，不改 props 语义）。

## 六、NFRs

- **兼容性基线**：iOS Safari ≥ 15（动态视口 15.4+ 起支持；15.0–15.3 走静态视口兜底，**不得比现状更差**：内容可滚到底）；iOS Safari ≥ 16、Android Chrome 均须通过；桌面 Chrome / Edge / Safari、Electron 零变化。
- **性能**：纯 CSS，零 JS 监听、零重排循环；不新增请求。
- **可访问性**：安全区内缩后，正文对比度与点击区尺寸不降（点击区下限 40px 沿用 `AGENTS.md`）。
- **安全**：不适用：纯展示层样式与 meta，不涉凭证 / 数据面。
- **可维护性**：安全区补丁集中在**一个**主题文件内，禁止散落到各组件 `<style>`；新增 token 一律禁止。

## 七、AC

- **验证接缝**：`apps/web/src/themes/__tests__/safe-area.test.ts`（源级 `?raw` 断言，沿用 `button-overrides.test.ts` 既有接缝）—— **降级说明**：qa 会话当前未在跑，本批不新建测试基建、不设 QA 用例面；接缝由 rd-fe 自测、PM 核对源文本。若用户要求 QA 复核接缝，在开工确认卡勾选后 PM 再 `ensure qa`。
- **AC1（主路径）**：Given iPhone Safari 打开 Web 端且地址栏处于**可见**态，When 滚动任务列表到底，Then 最后一行完整可见、不被地址栏遮挡，且滚动到底时列表**无残余不可达高度**。
- **AC2（异常 · 降级）**：Given 环境不支持动态视口（模拟 `100dvh` 声明被丢弃），When 打开同一列表并滚动到底，Then 外壳退回静态视口兜底，且末行**仍可通过内部滚动到达**（禁止「被裁且不可滚」）。
- **AC3（边界 · 刘海 / 横屏）**：Given `viewport-fit=cover` 生效且设备有刘海或横屏圆角遮挡，When 打开主界面与抽屉式弹窗，Then 顶部、左右、底部均按 `env(safe-area-inset-*)` 内缩，无文字、按钮、图标落入遮挡区。
- **AC4（负向闭环 · 桌面回归）**：Given 桌面浏览器与 Electron（安全区值恒为 `0`），When 打开同一页面与弹窗，Then 外壳尺寸、弹窗位置与改动前**逐项一致**（视觉零变化），且 `vp check` / 全范围门禁全绿。
- **AC5（设计一致性）**：Given 窄屏（≤400px）抽屉式弹窗，When 打开并触达底部按钮，Then 底部留白 ≥ `env(safe-area-inset-bottom)`，视觉与既有 `nue-*` 间距体系一致；`DESIGN.md` 已增「安全区与视口基线」一节并被 `AGENTS.md` 指针引用。
- **AC6（防回归 · 可自动核）**：Given 仓库源文本，When 运行新增源级测试，Then 断言：① `apps/web/index.html` 的 viewport meta 含 `viewport-fit=cover`；② 安全区补丁文件含四向 `env(safe-area-inset-*)` 且带 `0px` 兜底、并已被 `themes/index.ts` 引入；③ Web 主题入口与新增补丁内**不含** `100dvw`、不含裸 `100vh`（白名单 = 兜底声明行，需显式列明）。④ 全仓 `apps/web/src` 内 `100vh` 残留计数 = 0。
