## 1. 问题证据与 5 Whys

| 现象 | 证据 |
| :--- | :--- |
| 搜索状态不可保持/不可分享 | SEA-03 遗留 P2；`entry.vue` 的 `keyword` 与四维筛选全为组件内存态，刷新/返回即丢，`/search` 无 query 深链 |
| 重复回找零复用 | SEA-02 遗留 P2（搜索历史）；每次回找需重新输入 |
| 找回误删/误弃任务无路径 | `use-search.ts` 查询固定 `isDeleted:false/isGivenUp:false`，`searchTasks` 纯层亦硬排除三类 |
| 结果不可解释 | 命中备注时行内无任何"命中来源"提示 |
| 多语言不一致 | `entry.vue` / `search-filter-bar.vue` 文案硬编码中文，其余界面统一 `t()` |

**5 Whys（贯穿）**：① 搜索是"回找旧任务"的核心路径却不可复用/不可保持 → ② 状态只活在内存、无历史、无深链 → ③ 从未建立状态外化与范围配置 → ④ 早期按 MVP 交付，遗留项被标 P2 未回收 → ⑤ **命题：把搜索状态外化为可恢复、可分享、可复用的形态，并补齐范围与语言一致性。**

## 4. 用户场景（画像 + 场景卡 + 关键路径 + 页面状态清单）

- **画像**：任务量较大、常用搜索回找旧任务的 web/desktop 用户。
- **场景卡**：① 找到某任务后把链接发给未来的自己（收藏/分享）；② 刷新页面后继续上次搜索；③ 重复搜索同一关键词，用历史一键复用；④ 误删任务后用开关搜出并恢复；⑤ 英文界面下使用搜索。
- **关键路径**：进入 `/search` → （有 query）还原关键词/筛选 → 输入/选择 → 结果 → 点行开详情 → 返回（状态保持）→ 点历史复用。
- **页面状态清单**：加载=沿用现状；空词=`nue-empty` + **最近搜索**（无历史时仅引导文案，不显示空标题）；无结果=沿用现双清入口；错误=沿用现重试；成功=结果列表（含状态/命中来源标识）。

## 5. 业务规则与不变量

| 规则 | 内容 |
| :--- | :--- |
| 状态真源 | **本地状态为真源**（SEA-04-DEF-02 修正）：URL 仅挂载时导入 + 状态/路由变化时导出（含对账再导出）；不为关键词/筛选另建 localStorage（历史除外） |
| 写回方式 | 使用 `router.replace`（不污染后退栈）；空值不写入 query（URL 干净） |
| 编码 | 数组维度以 `,` 连接；收件箱哨兵 `projectId=''` 编码为 `inbox` token（解析回 `''`）；ID 为 nanoid（URL 安全） |
| 默认口径 | 未开开关时保持现状排除 `deleted/archived/given-up`；开关开启后仅纳入 `deleted/given-up`，`archived` 恒排除 |
| 历史 | 记录时机=**点击结果进入详情时**（代表有效回找）；≤10 条、去重置顶、`trim`；localStorage 读写 try/catch 容错 |
| 既有不变量 | `taskId` path param 语义不变；打开详情仍 `push`、返回保持 query；子任务补拉/限流退避/5000 上限/四维 OR-AND 语义不变 |
| 颜色纪律 | 仅 shadlike 令牌（标签色点为用户数据豁免） |

## 6. NFRs

- 双主题令牌自适应；无字面量色。
- URL 长度可控（ID 集合省略空值；正常量级 < 1KB）。
- localStorage 异常（禁用/损坏）不阻断搜索，降级为无历史。
- 键盘可达性不回归（结果行 Enter/Esc、筛选触发器 `aria-expanded` 保持）。
- 门禁：`vp check` + `vitest`（纯层新增单测）+ `webapp`/`desktopapp` 构建绿；EOL 纪律。

## 13. 验收与数据结果

**门禁（rd-fe 每子项提交前实测）**：`vp check` 目标文件 pass / exit=0；`vp test --run` T1 60文件/552例 → T2 61/559 → T3 61/562 → T4 61/562 全绿；webapp/desktopapp 双端构建 4 次均 ✓。

**单测覆盖（rd-fe）**：AC1/2 query 往返 + replace；AC3/4 历史 LRU/去重/上限/清除/存储不可用；AC5 descriptionOnlyHit；AC6 includeExcluded 且 archived 恒排除；AC7 excluded 往返；AC9 非法值/空 query/空历史/损坏 JSON；AC8 两文件模板/脚本无硬编码中文；AC10 URL 写回保留 taskId params。

**未覆盖**：AC1/2/6 的真实浏览器端到端（需登录 + 后端）→ 用户手动冒烟。

**缺陷 SEA-04-DEF-01（用户冒烟发现，24h 内补单）**：点击搜索结果项后搜索关键词/筛选被清空。
- 根因：`index-view.ts` 的 `showTaskDetails` 用 `router.push({ name, params: { taskId } })` 未携带 `query` → 下钻后 query 丢失 → `use-search.ts` 的 `watch(route.query)` 还原为空状态。
- 修复（用户裁定方案 A，最小改动）：下钻时保留当前 query（抽纯函数 `task-details-location.ts`，`index-view.ts` 改为调用）；深链/刷新/前进后退语义不变。
- 回归单测 3 例（携带 query 下钻不丢 / 无 query 视图行为不变 / 空 name 不影响 taskId）；`vp test` 62 文件 565 例全绿；双端构建 ✓。

**用户终签**：✅ 通过（用户手动复验 DEF-01/02 修复后全量冒烟通过，2026-09-13）；不启用 QA。

**缺陷 SEA-04-DEF-02（用户复验发现，24h 内补单；改用 B 方案）**：关闭详情面板后搜索文本同样被清空。
- 根因：`closeDetails` / `switchTaskDetails`（packages/.../task-details/task-details.ts）与 `float-details.vue` after-close 均为“只带 params 不带 query”的 push → URL 丢 query → `watch(route.query)` 反向导入为空状态。DEF-01（A 方案）只堵了“打开”一处，暴露了“每个详情导航都需记得带 query”的脆弱性。
- 修复（用户裁定 B 方案）：**本地状态为真源**——移除 `watch(route.query)` 反向导入；保留挂载期一次性 URL 导入（深链/刷新不变）；保留状态→URL `replace` 导出；新增路由 query 变化时的**对账再导出**（仅 `search` 路由，本地≠query 才回写，绝不反向清空）；不改包内详情导航（避免跨包 DDD 越界）。
- 新增纯函数 `needsSearchQueryReExport` + 3 例单测；`vp test` 62 文件 568 例全绿；双端构建 ✓。
- 注：DEF-01 的“下钻保留 query”仍保留（无冲突，属正确行为）。
