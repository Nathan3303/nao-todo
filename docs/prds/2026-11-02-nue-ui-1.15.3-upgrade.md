- **做什么**：把 `nue-ui 1.13.0 → 1.15.3` + `nue-ui-theme-shadlike 0.13.28 → 0.13.30`（两处 `package.json` 同步），**并回退本仓为绕过 `DEF-116` 而自建的 `NaoRouterLink` 包装**——上游 `#108` 已修，规避代码不应长期滞留。
- **给谁**：全部 Web / 桌面端用户；尤其键盘与读屏用户（链接语义、开关语义、清除键可达性）。

## 一、问题证据

- **上游已修（读上游仓库源码 + 发版说明）**：`v1.15.3` 三单 —— `NueLink` 路由形态补齐 `href`（`route`/`to` 形态渲染真链接，`to` 不再以未声明属性落 DOM）· `NueAvatar` 在 `src` 变化时复位错误态并重试 · `NueSwitch` 支持默认插槽即开关文案。
- **本仓规避实况**：`packages/shared/components/router-link/`（`NaoRouterLink`，用 `resolveDynamicComponent('router-link')` 渲染原生链接并复刻 `.nue-link` 主题类）；**8 个文件 import、11 处模板调用点**（`app/aside` · `app/float-aside` · `app/aside-v2` · `app/aside-v2-drawer` · `pomodoro/aside` ×4 · `tasks/aside` ×2 · `presentation/pomodoro/indicator` · `shared/components/smart-list`）。
- **版本落后**：`1.13.0 → 1.15.3` 跨两个 minor，期间 4 项会作用于本仓的行为/结构变更 —— ① `1.14.0` a11y 补齐（`NueSwitch` 补 `role="switch"`/`aria-checked`/键盘激活、`NueInput` 新增 `inputAttrs`、clear/eye 图标按钮补 `role`/`tabindex`/`aria-label`）② `1.15.0` message 关闭键可达 + `NueTextarea` 补 `inputAttrs` + **`NueSelect`/`NueDatePicker` 清除按钮移出 `nue-button`（DOM 结构变化）** ③ `1.15.1` date-picker 西半球时区显示错一天 ④ `1.15.2` date-only 值统一按 `00:00` 解释（原面板取当前时刻）。
- **配套约束**：`nue-ui-theme-shadlike 0.13.30` 新增 `select.css` / `date-picker.css` / `message.css`（共约 143 行，配合上面第 ② 项的新结构）⇒ **主题必须与核心包同批升**，否则新结构没有样式。
- **5 Whys（为什么现在做）**：① 为什么升 —— 上游修了我们自己挂的缺陷单；② 为什么本仓要跟 —— 规避代码是临时手段，长期保留会与上游实现分叉；③ 为什么会分叉 —— 我们复刻了 `.nue-link` 全部主题类与 DOM 结构，上游任何链接改动都要手工同步；④ 为什么之前不升 —— 缺陷未修，升了也解决不了 `href` 缺失；⑤ 根因 —— **上游缺陷驱动的本仓权宜实现缺少「上游修复后回收」的到期闭环**（本轮补上：`DEF-116` 到期日 = 本批关闭）。
- **设计输入**：本批是**依赖升级 + 规避回收**，不是视觉改版；验收重点是「外观零变化、可访问性只增不减」，而不是新造观感。

## 四、用户场景

- **场景卡（键盘用户）**：Tab 从页面顶部进入侧栏 → 焦点依次落在每个导航项上（可见焦点环）→ Enter 跳转 → 右键可「在新标签页打开」。
- **场景卡（自建清单/标签）**：用户新建 3 个清单与 2 个标签 → 侧栏列表项同样是真链接（数量随数据增长，非固定 11 处）。
- **场景卡（头像 404 后恢复）**：登录态过期导致头像 404 → 重新登录 → 同一页面头像**无需刷新**即恢复显示。
- **场景卡（日期选择）**：任务卡片设置「开始/截止时间」（`datetime`）→ 回填与保存值语义与升级前一致；只选日期时时刻口径按上游统一为 `00:00`，不得因此**改写**我们传给后端的值。
- **场景卡（下拉清除）**：`nue-select` 中已选项 → 用清除键清除 → 值清空且可键盘完成。
- **关键路径**：切分支装依赖 → 真实挂载断言 → 全仓门禁 → 本地 dev 走查。

## 五、业务规则

- **R-A（回退口径）**：导航一律回到 `<nue-link route="…">`；**不允许**保留 `NaoRouterLink` 作为"过渡包装"（双份实现正是本批要消除的东西）。
- **R-B（外观不变）**：11 处调用点的类名与视觉结果与回退前一致（`.nue-link` / `.nue-link--route` / `--route-icon` / `--actived` 全套）；唯一允许的差异 = 上游内部 DOM 细节（如空 `.nue-link__content`）且该差异不得产生可视变化。
- **R-C（可访问性只增不减）**：`href` 可解析、可聚焦、有焦点环、有可访问名；**若上游 `nue-link` 未提供焦点环**，须在共用层补一次（禁止每处调用点各写一份）。
- **R-D（日期口径）**：`date-only` 值一律按 `00:00` 解释是**展示/回填口径**；**不得**因升级改变我们写入任务/后端的时间值语义。若实测发现 4 处 `datetime` 调用传的是 date-only 串且依赖「补当前时刻」，须先报 PM 再由 PM 决定是改调用方还是改口径。
- **R-E（选择器结构变动）**：`nue-select` / `nue-date-picker` 的清除控件成为触发区同级的原生 `<button>` ⇒ 功能断言（清除生效、`disabled` 跟随、键盘可达）必须实测；本仓样式若依赖旧嵌套结构须按新结构修正，不得用 `!important` 硬压。
- **R-F（版本一致性）**：核心包与主题包同批升级；`apps/desktop` 与根**不得出现版本漂移**（桌面端打包用的是自己的 `node_modules`）。
- **R-G（范围守门）**：升级过程中发现与本单无关的既有缺陷 ⇒ **登记缺陷池，不在本单修**。
- **R-H（类名映射写法，`T628` C3）**：`nue-link` 的类名**只能由 `theme` 产生** —— `parseTheme` 按**逗号**切分字符串（空格不切），`iconLink` / `size` 在 `nue-link` 上**不存在 / 未实现**（`size` 是死 prop，传了静默无效）。⇒ 图标型入口必须写 `:theme="{ route: true, 'route-icon': true }"`（对象语法，与原包装件历史写法一致），并在用例中断言 `nue-link--route-icon` 类存在。
- **R-I（焦点环单点，`T628` C1/C4）**：焦点环补在 **`apps/web/src/themes/link.css`**（`@/themes` 同时被 web 与 desktop renderer 引入 ⇒ 一处覆盖两端），声明与现口径逐字一致；**必须先于回退落地**（否则出现无环空窗）；本批**只加不删**（`tasks/aside` / `sign-in` / `sign-up` 的既有重复实现保留）。
- **R-J（`switch` 去双实现，`T628` C2）**：5 处自建 a11y 与上游新增能力重复 ⇒ 同批拆除，`aria-label` 保留；`search-filter-bar` 的断言**不许改**，靠产品侧拆除变绿。
- **R-K（`newTaskId` 追认，`T628` D1）**：**有条件接受** —— C-1 语义固定为命令通道且禁 `update:newTaskId` 回写 · C-2 前提「每次新增 id 唯一」（若将来同值重复须改 `{id, seq}`）· C-3 广播前 `getTask` 必须可取（否则静默丢弃）· C-4 不得当第二数据源。四条须写入 JSDoc 与用例头注。
- **R-L（身份页互链规避挂账，`T628` D4）**：`packages/presentation-identity` 的 `sign-in.vue` / `sign-up.vue` 仍是原生 `<router-link class="nue-link">`（同 `DEF-116` 家族），**本批不回收**（当前无用户可见缺陷，回收会把身份页互链纳入回归面）；登记挂账，**到期 2026-12-31**，届时与 `DEF-128` 一并评估。

- **构建与体积**：Web 与桌面产物 build 均 exit 0；核心包升级后首屏体积增量 <1%（超出须说明来源）。
- **依赖面**：不新增运行时依赖；`pnpm-lock.yaml` 只允许 `nue-ui` / `nue-ui-theme-shadlike` 及其传递依赖变化。
- **不只做**：性能/安全 —— 理由：本批不涉及数据面与网络契约。

## 七、AC（验收标准）

- **AC1（依赖）** 根与 `apps/desktop` 的 `nue-ui` = `1.15.3`、`nue-ui-theme-shadlike` = `0.13.30`；`pnpm-lock.yaml` 一致；`git diff` 中无其它包的版本变更。
- **AC2（主路径）** 11 处导航入口真实挂载（真实 router + 真实 `nue-link`）后，渲染出的 `<a>` **均有非空 `href`** 且 `= router.resolve(path).href`。
- **AC3（边界）** `smart-list` 动态面：任意条数（0 / 1 / 多）的自建清单与标签项均有 `href`。
- **AC4（可访问性，`T628` 改口径）** 三证并列：① **运行期** 各导航项 `tabIndex >= 0`、`focus()` 后 `document.activeElement` 命中该项、有可访问名；② **源级** `apps/web/src/themes/link.css` 内存在 `.nue-link:focus-visible` 且含 `outline: 2px solid var(--nue-primary-color-600)` 与 `outline-offset: 2px`（`?raw` glob 断言，参照 `button-overrides.test.ts` 的 `sourceOf()` 防伪）；③ **用户走查**「Tab 到侧栏导航项可见 2px 环」。**⛔ 不得声称 jsdom 能验证 `:focus-visible` 计算样式**（jsdom 无级联、伪类不匹配）。
- **AC5（负向）** 不存在 `to="[object Object]"` 属性残留；点击仍走 SPA 导航（不因改回 `nue-link` 变成整页刷新）。
