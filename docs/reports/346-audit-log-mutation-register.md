## 二、为什么原判会「以为不可杀」（根因，供后续复用）

三条都栽在**同一个思维陷阱**：用「结果为 0 条」的断言去验「实现有没有走偏」，而**上游还有一道筛子**会先兜住：

| 变异                   | 被谁"无意中"兜住                                                                                   | 正确判据                                                                                          |
| :--------------------- | :------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------ |
| #3 删实体层归一        | **记录层预筛**：记录完全一致时根本进不到实体层（`inbox` 场景只有在「记录真有差异」时才会到实体层） | 让**记录真变**（改 `description`）再断言 `fields` 恰为那 1 个字段 —— 未归一会**多出** `projectId` |
| #11 删记录层预筛       | **实体层精筛**：即使进到实体层，未变化行仍会算出 0 条差异 ⇒ 行为等价                               | 断言**可观测的代价**（解密次数 = 0）——它是「预筛存在」的唯一可观测面                              |
| #10 `hasMore` `>`→`>=` | 分页用例只有 7 条（第二页 2 条 < 页大小）⇒ 边界不可见                                              | 造**恰好一页**（5 条）的边界数据                                                                  |

## 四、维护约定

1. **新增写入点 / 新增筛子（预筛、归一、判等）时**，必须同步评估：是否需要「可观测代价」型断言（如解密次数、查询是否走索引），
   否则同类变异会再次「行为等价 ⇒ 不可杀」。
2. **新增分页 / 限幅 / 防抖** 类行为，必须补**边界值**用例（恰好一页 / 恰好达上限 / 恰好到防抖窗口）。
3. 变异执行后**必须**逐字节还原（`sha256sum -c`），并在回执里给出「红例名 + 还原结果」；⛔ 不接受「文件红数」作为 kill 证据。
4. 本表与 `docs/reports/346-audit-log-final-verify.md` §2 互为索引：本表是**唯一清单**，复验报告只记当次实测。
