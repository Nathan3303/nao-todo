# 缺陷池（Defect Pool）

> **性质**：**缺陷的单一权威登记源**（PM 维护）。任何来源发现的缺陷（QA 实机 / 架构评审 / PM 勘察 / 用户反馈）**先登记入池**，再决定是否立单、何时派单。
> **与既有登记的关系**：`docs/adr/README.md` §遗留登记（跨篇）是 **ADR 期**登记（编号 `DEF-<域>-NN`）—— **保留原位不迁移**（历史留痕）；**自 2026-09-23 起，新缺陷一律入本池**。
> **编号规则**：`DEF-N` 产品/纪事级，延续既有 `DEF-1…DEF-4` 序列。`OFF-N` 是 WEB-OFFLINE 勘察期别名（指 `docs/prds/2026-09-23-web-offline-recon.md`）。
> **状态机**：`已登记待派单` → `已派单` → `已回执待验收` → `已闭环` ｜ `已驳回` ｜ `转需求`。
> **严重度**：P1 = 门禁交付 / 数据正确性 / 安全；P2 = 功能语义错误、可绕过；P3 = 观感或口径偏差。

## 二、逐条明细

### DEF-5（OFF-1）离线检入清 JWT —— **P1**

| 项           | 内容                                                                                                                                                        |
| :----------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **机制**     | `AuthUseCase.checkIn` 在**任何错误（含网络类）**时执行 `authStore.clearAuthData()` → `clearUserData()` → **`localStorage.clear()`**                         |
| **症状链**   | web 离线刷新 → 门 B（`routes.ts` `beforeEnter`）拦下 → 走 checkin → 网络失败 → **JWT 被销毁** → 重试读到空 token → 落登录页（离线无法登录）= **彻底进不去** |
| **影响**     | web 离线**完全不可用**；且说明 SHELL-05 C-24「网络类不跳 signin」的意图在 usecase 层被 `clearAuthData()` 反噬                                               |
| **证据**     | arch A3 §0.2（读码确认；Z2 待实测补充）。原报告 `/tmp/WEB-OFFLINE-A3-offline-boundaries.md`（已沉淀至 recon 文档）                                          |
| **建议处置** | 区分**网络类**与**凭证类**失败：网络类**不得** `clearAuthData`；凭证类（401/403/10041）保持现状                                                             |
| **验收要点** | ① 断网冷启动/刷新后 **JWT 仍在**且可走离线进入；② 凭证类失败仍清认证；③ 不能把「网络抖动」变成「强制重新登录」                                              |

### DEF-6（OFF-2 / C5）本地镜像完整性缺口 —— **P1**

| 项           | 内容                                                                                                                                                                                                                                                                                                                                                           |
| :----------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **机制**     | `PULL_LIMIT = 200`/表、排序 `updated_at ASC`（**最旧先拉**）、`ListSync` 用 `.Unscoped()`（墓碑也占窗口）、`pullAllInner()` **单轮无续拉**；拉取触发点**仅 3 处**（`start()` / `pullAll()` / `manualSync()`）；而 `online` + `visibilitychange` 走的 `resumeBackfill()` **只 push 不 pull**，且 `scheduleBackfillTick` 在 `countDirty === 0` 时**直接 return** |
| **影响**     | 大账号下本地副本以「**最旧优先、≤200 行/表/每次启动**」填充且**无自动补全** ⇒ **desktop 可能读不到最新任务**。dev 库全表 **189 行 < 200**，**恰好掩盖了它**                                                                                                                                                                                                    |
| **证据**     | arch A1/A2/A3（读码 + 推断）；**运行时确证待 V1 探针**                                                                                                                                                                                                                                                                                                         |
| **建议处置** | 连续拉取（循环至无更多数据）；`resumeBackfill` 补 pull；触发点补全                                                                                                                                                                                                                                                                                             |
| **验收要点** | ① >200 行账号：启动 1 次后 `tasks.count()` **不应**停在 200（V1）；② 本地必须包含**最新**任务 id                                                                                                                                                                                                                                                               |
| **关联**     | **WEB-OFFLINE 阶段一硬前置**；**V1 探针需 >200 行账号**（现状 189 行会给出**假阴性**，必须先造数）                                                                                                                                                                                                                                                             |

### DEF-7（OFF-3）desktop 未启用单实例锁 —— P2（明文姿态下 P1）

| 项           | 内容                                                                                                                                                                                                                                           |
| :----------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **机制**     | `requestSingleInstanceLock` **实测未启用**（A2 G9）                                                                                                                                                                                            |
| **影响**     | 桌面可多开 ⇒ 多写者：① pull 游标 RMW ② 重复 push（`schedulePush` 每标签各排）③ 暂停/退避态互相覆盖 ④ **迁移并发**（先完成者删 `key-bundle`、后到者失败）⑤ **「登出复活」**（标签 A 清库、标签 B 内存 store 写回 ⇒ 明文复活）⑥ 双实例双倍首同步 |
| **建议处置** | desktop 加单实例锁（**一行配置、收益最大**）；web 用 `BroadcastChannel` 广播 logout 让其他标签清 store 并跳登录（同时解 ⑤）；迁移/同步用 Web Locks 选主                                                                                        |
| **验收要点** | 双开被拒绝；多标签登出后任一标签均无残留明文                                                                                                                                                                                                   |

### DEF-8（OFF-4）全仓零 CSP —— P2（明文姿态下 P1）

| 项           | 内容                                                                                                                                                                                                                                                                                                                                                         |
| :----------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **机制**     | `securityHeaders()` 仅 `X-Frame-Options` / `X-CTO` / `X-XSS-Protection`(已废弃) / `Referrer-Policy`；**无 CSP**                                                                                                                                                                                                                                              |
| **约束**     | ① desktop 生产走 **`file://`**（`win.loadFile`）⇒ 无响应头 ⇒ **CSP 只能靠 `<meta>`**；且 Chromium 下 `file://` 的 localStorage/IndexedDB 归属「file 协议」大类 ⇒ 同 profile 下其它本地 HTML 也可能触及同源存储；② **SPA 不由 `nao-todo-server` 托管** ⇒ CSP 需落**静态托管侧**；③ API 是**另一个 origin**（`VITE_BASE_URL`）+ `withCredentials`（带 cookie） |
| **影响**     | 明文姿态下 **origin 独占性即机密性边界** ⇒ CSP 从「建议」升为「必须」                                                                                                                                                                                                                                                                                        |
| **建议处置** | 托管侧响应头 CSP + desktop `<meta>` CSP；移除已废弃的 `X-XSS-Protection`；第三方资源按域白名单                                                                                                                                                                                                                                                               |
| **验收要点** | 两端均存在生效 CSP；无 `unsafe-eval`；加载/交互无 CSP 违规报错                                                                                                                                                                                                                                                                                               |

### DEF-9（OFF-5）`getCurrentUserId() ?? ''` 兜底 + `localSession` 内存态 —— P1（明文姿态下）

| 项           | 内容                                                                                                                |
| :----------- | :------------------------------------------------------------------------------------------------------------------ |
| **机制**     | `getCurrentUserId()` 以 `?? ''` 兜底；`localSession.currentUserId` 是**内存态**（刷新即 null），且 **web 无重建点** |
| **影响**     | 明文落盘下**极易跨用户读到明文**；`?? ''` 使「无用户」与「用户空串」不可区分                                        |
| **建议处置** | `userId` 隔离改为**硬失败**（null/空一律拒绝库操作）；web 启动时从 JWT 重建 session                                 |
| **验收要点** | 无/空 userId 时库操作被拒绝并可见；跨账号切换不串数据                                                               |

### DEF-10（OFF-6）`checkAndCleanExpired` 唯一生产调用点在被退役的门上 —— P1（门退役即触发）

| 项           | 内容                                                                                                                                                                                                                                 |
| :----------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **机制**     | 已存在「按用户事务清空全部本地数据」原语 `deletionService.checkAndCleanExpired()`（事务清 11 业务表 + `meta(key-bundle)` + `deletionSchedules` + `syncQueue` + `syncCursor`，已单测）；但其**唯一生产调用点在 `unlock-gate.vue:75`** |
| **影响**     | 退役解锁门时若不迁走该调用 ⇒ **注销到期清理永久不触发**（**静默失效、无报错**）                                                                                                                                                      |
| **建议处置** | 门退役时同步把调用迁到新启动路径（并入 WEB-OFFLINE 门退役顺序步骤 5）                                                                                                                                                                |
| **验收要点** | 门退役后，注销宽限期到期仍触发本地清理（有可观测断言）                                                                                                                                                                               |

### DEF-11（OFF-7）`priority` 排序为字母序 —— P2

| 项           | 内容                                                                                                                                   |
| :----------- | :------------------------------------------------------------------------------------------------------------------------------------- |
| **机制**     | local 仓通用排序对字符串用 `String(a).localeCompare(String(b))` ⇒ `priority` 取值 `low`/`medium`/`high` 时 `asc` = `high, low, medium` |
| **影响**     | desktop / index list 的「按优先级排序」**语义错误**（两个方向都不是优先级序）                                                          |
| **证据**     | arch A2 §B（读码 + node 实测）                                                                                                         |
| **建议处置** | 比较器加 **rank 映射**（`low 0 / medium 1 / high 2`，服务端另存在 `urgent 4` ⇒ 应含 `urgent 3`）；**或**前端 rank 排序                 |
| **验收要点** | `asc`/`desc` 两端均为语义序；含 `urgent` 时的兜底与用例                                                                                |

### DEF-12（OFF-8）服务端 `isArchived` 空操作 + `sort` 无白名单 —— P2 / **P1（安全）**

| 子项                              | 内容                                                                                                                                                                           |
| :-------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **① `isArchived=false` 是空操作** | 归档任务**漏入 web 结果**（数据可见性错误）。建议：修过滤语义。验收：归档任务不出现在默认列表                                                                                  |
| **② `sort` 无白名单**             | `ORDER BY ToSnakeCase(field) direction` 原样拼接、**无白名单** ⇒ **SQL 注入面**（arch 建议另开安全 ticket）。建议：字段与方向**双向白名单**。验收：非法 field/direction 被拒绝 |
| **证据**                          | arch A1 §A / A2 §C（读码 + 实测）                                                                                                                                              |

### DEF-13（OFF-9）`pendingCount` 滞后 —— P3

| 项           | 内容                                                                                                        |
| :----------- | :---------------------------------------------------------------------------------------------------------- |
| **机制**     | `syncStatus.pendingCount` **只在一次同步运行的 `endRun()` 时刷新** ⇒ 写完 2s 内、或从未跑过同步时是**旧值** |
| **影响**     | 任何「未同步数量」UI 可能显示旧值；**登出清库护栏若读它会误判**（漏判/误判未同步数据）                      |
| **建议处置** | 权威口径统一用 `syncTracker.countDirty(userId)`；UI 明确刷新时机                                            |
| **验收要点** | 写入后立即读到的数量与 `countDirty` 一致                                                                    |
