## 二、走查清单（请逐项勾选，✅ 通过 / ❌ 不通过并记下现象）

### ① 同一条、同一字段：覆盖要看得见（AC1，核心）

- [ ] **测什么**：我在 B 端编辑描述时，A 端改了同一条描述并保存；我随后在 B 端保存，B 端能否看到「我的修改已覆盖云端」。
- **怎么操作**：
    1. 两端打开**同一条任务**的详情，确认两端描述一致。
    2. **先在 B 端**点进描述框，随便改几个字（**先不要保存**，让编辑框保持"正在编辑"）。
    3. 到 **A 端**把同一条的描述改成别的内容，保存。
    4. 回到 **B 端**，保持刚才的输入，点保存。
    5. 打开同步/冲突面板，找到这条任务。
- **预期结果**：
    - 面板**新增 1 条**，类型显示「**我的修改已覆盖云端**」。
    - 点开能看到两侧内容，标签是「**云端当时的版本**」/「**我的当前版本**」，内容分别是 A 端保存的那版 / 我在 B 端保存的这版。
    - 文案里**没有**英文键名、`stale`、`revision`、记录 ID 之类的技术词（记录 ID 可出现在次要位置，但主信息必须是名称与内容）。
    - 内容可以复制：用鼠标选中「云端当时的版本 / 我的当前版本」的文字即可复制（**本版该记录没有「复制」按钮**，见文末观察项）。
- **对应 AC**：AC1。

### ② 各改各的字段：不要打扰我（AC5）

- [ ] **测什么**：两端改的是**不同字段**（例：A 端改描述，B 端改任务名称），保存后面板不应新增记录。
- **怎么操作**：重复 ① 的步骤，但让 A 端改**描述**、B 端改**名称**（B 端同样先输入后保存）。
- **预期结果**：冲突面板**没有新增**记录；两端各自保存成功，列表/详情显示正确。
- **对应 AC**：AC5（零误报）。

### ③ 那条记录上不应出现「用云端的」（AC9 / 决策 D6）

- [ ] **测什么**：① 产生的「我的修改已覆盖云端」记录上，**不应有**「**用云端的**」按钮（即"保留服务端版本"）。
- **怎么操作**：打开 ① 的那条记录，看底部动作区。
- **预期结果**：
    - 底部**没有**「用云端的」按钮（该动作对这类记录拿不回云端内容，会误导）。
    - 仍能看到「**保留我的修改**」与「**关闭**」。
    - 其它类型的记录（如「云端有更新，需要你选择」）上仍正常出现「用云端的」——如果你手头有这类旧记录，可顺手确认它没被误删。
- **对应 AC**：AC9 / R-8 / D6。

### ④ 外观与前一批一致（C 端观感）

- [ ] **测什么**：新增记录的外观是否与上一批冲突面板一致，不像"后台管理台"。
- **怎么操作**：对比 ① 的记录与既有记录，检查布局、字号、按钮层级、点击高度、深色/浅色主题。
- **预期结果**：卡片/分区留白一致；主按钮（保留我的修改）突出、次按钮弱化；条目点击区不局促；无表格式生硬排版；无内部术语。
- **对应 AC**：AC9（零新 kind / 零新文案 / 不自绘状态）。

### ⑤（可选，建议一起看）改回原值，但云端被我覆盖过（AC1b）

- [ ] **测什么**：我先把描述改了一个值、又改回原来的值再保存，而这期间远端把同一描述改成了别的值——这仍然是一次真实覆盖，要记 1 条。
- **怎么操作**：B 端开始编辑描述（改成 X）→ A 端把描述改成 Y 并保存 → B 端把描述**改回最初的值**再保存 → 看面板。
- **预期结果**：**新增 1 条**「我的修改已覆盖云端」，显示云端当时的版本是 Y、我的当前版本是最初的值。
- **对应 AC**：AC1b。
