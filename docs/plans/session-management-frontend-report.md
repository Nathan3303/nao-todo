# 会话多端管理 —— 前端落地方案

## 1. 变更背景

服务端已完成「会话与登录端绑定」改造，由「一用户一会话」升级为「一用户多会话（多设备登录）」，并新增三组接口供用户管理自己的登录会话：

1. 查看现存会话列表；
2. 下线某个指定会话（踢下线单台设备）；
3. 一键退出其他全部设备。

前端需要配合两件事：

- 登录/请求时携带**设备 ID（deviceId）**，用于把会话绑定到具体登录端；
- 新增「登录设备 / 会话管理」界面，调用上述接口并做好 token 失效兜底。

> 说明：本报告描述的是后端已就绪的契约。服务端新增的 CORS 白名单已包含 `X-Device-Id` 请求头，前端无需再处理跨域放行。

## 2. 新接口契约

三个接口都挂在 `/api` 下，需要登录态（`Authorization: Bearer <jwt>`，与现有接口一致）。所有响应均为 **HTTP 200 + JSON**（项目统一风格，不要用 HTTP 状态码判断成败）。

### 2.1 获取会话列表

```text
GET /api/user/sessions
Authorization: Bearer <jwt>
```

成功响应：

```json
{
    "code": 10130,
    "message": "获取会话列表成功",
    "data": [
        {
            "id": "734112563728736256",
            "deviceId": "3f2c9a1e-8d4b-4c6a-9e0f-1234567890ab",
            "deviceType": "Chrome",
            "ip4": "120.229.1.2",
            "region": "广东·深圳",
            "createdAt": "2025-01-02T10:00:00+08:00",
            "updatedAt": "2025-01-03T18:20:00+08:00",
            "current": true
        },
        {
            "id": "734112563728736257",
            "deviceId": "",
            "deviceType": "iOS",
            "ip4": "183.6.3.4",
            "region": "广东·广州",
            "createdAt": "2025-01-01T09:00:00+08:00",
            "updatedAt": "2025-01-01T09:00:00+08:00",
            "current": false
        }
    ]
}
```

字段说明：

| 字段         | 类型   | 说明                                                                                        |
| ------------ | ------ | ------------------------------------------------------------------------------------------- |
| `id`         | string | 会话 ID（雪花 ID，字符串），下线单条时用                                                    |
| `deviceId`   | string | 设备 ID；老客户端/未携带时为**空串**                                                        |
| `deviceType` | string | 设备/浏览器类型：`Chrome` `iOS` `Android` `WeChat` `Alipay` `Safari` `Firefox` `Unknown` 等 |
| `ip4`        | string | 登录端 IPv4 地址                                                                            |
| `region`     | string | IP 归属地（如 `广东·深圳`）；内网/解析失败为 `未知` 或 `UnknownRegion`                      |
| `createdAt`  | string | 登录时间（RFC3339）                                                                         |
| `updatedAt`  | string | 最近活跃时间（登录或 CheckIn 换发 token 时更新，RFC3339）                                   |
| `current`    | bool   | 是否为「本次请求所在」的会话，即当前设备                                                    |

失败响应：

| code    | 场景                                 |
| ------- | ------------------------------------ |
| `10131` | 未登录（中间件已拦截，一般不会触发） |
| `10132` | 获取失败，`error` 字段含原因         |

### 2.2 下线单个会话

```
DELETE /api/user/sessions/:sessionId
Authorization: Bearer <jwt>
```

- `:sessionId` 为列表项里的 `id`。

成功响应：

```json
{ "code": 10140, "message": "下线成功" }
```

失败响应：

| code    | 场景                                            |
| ------- | ----------------------------------------------- |
| `10141` | 会话 ID 无效（非正整数）                        |
| `10142` | 会话不存在或已下线（已被删除 / 不属于当前用户） |
| `10143` | 下线失败，`error` 字段含原因                    |

### 2.3 退出其他全部设备

```
DELETE /api/user/sessions
Authorization: Bearer <jwt>
```

- 无路径参数；删除当前用户**除当前 token 外**的全部会话，当前设备保持登录。

成功响应：

```json
{ "code": 10150, "message": "已退出其他全部设备" }
```

失败响应：

| code    | 场景                         |
| ------- | ---------------------------- |
| `10151` | 未登录（一般不会触发）       |
| `10152` | 退出失败，`error` 字段含原因 |

## 3. deviceId 协议

### 3.1 是什么

客户端为「当前安装/浏览器」生成的一个**稳定随机 ID**，用于把会话与具体登录端绑定。服务端只存储、不生成。

### 3.2 传递方式

请求头：

```
X-Device-Id: 3f2c9a1e-8d4b-4c6a-9e0f-1234567890ab
```

- **字符串，长度 ≤ 64**（超长会被服务端截断）。
- **可选**：不携带也能登录（退化为「每次登录新增一条会话」，见 §4）。

### 3.3 何时携带

- **必须**在 `/api/auth/signin` 请求带上（会话绑定发生在登录这一刻）。
- 建议在**所有 `/api` 请求**统一带上（实现最简单，且未来设备级策略可直接复用）。服务端中间件对每个请求都会读取该头，目前仅登录建会话时消费。

### 3.4 生成与持久化（推荐）

```ts
// deviceId.ts
const KEY = 'nao.deviceId'

export function getDeviceId(): string {
    let id = localStorage.getItem(KEY)
    if (!id) {
        // 优先用原生 UUID；也可用雪花字符串，只要能持久且唯一即可
        id = crypto.randomUUID()
        localStorage.setItem(KEY, id)
    }
    return id
}
```

要点：

1. **首次访问即生成并持久化**（在登录之前就要有值），不要等登录成功后再生成。
2. **登出不要清除** `deviceId`——同一个浏览器/设备应始终保持同一个 ID，才能实现「同设备重复登录覆盖旧会话」。
3. 换设备（不同浏览器 / 卸载重装 / 清空站点数据）会得到新 ID，属正常现象：旧设备会话仍保留在列表里，可由用户手动下线。

## 4. 行为语义（前端需理解）

| 场景                              | 服务端行为                                                                          |
| --------------------------------- | ----------------------------------------------------------------------------------- |
| 同一 `userId + deviceId` 再次登录 | **覆盖**该设备旧会话，旧 token 立即失效（旧端下次请求会拿到 `code:10041` 凭证失效） |
| 不同 `deviceId` 登录              | 各自保留一条会话                                                                    |
| 未携带 `deviceId` 登录            | 每次登录**新增**一条会话（列表里 `deviceId` 为空串，可能多条）                      |
| 下线某个会话                      | 该会话 token 立即失效；若下线的正是当前会话，则当前端等于被登出                     |
| 退出其他全部设备                  | 当前设备保留，其余全部被踢下线                                                      |
| 会话过期（7 天硬上限）            | 列表不再展示；被踢/过期端后续请求返回 `code:10041`                                  |

> 关键结论：**重复登录会顶掉同设备的旧登录态**。如果前端在「已登录」状态下再次触发 signin（例如自动重登），请确认这是预期行为；否则应在已有登录态时跳过 signin。

## 5. 前端落地要点

### 5.1 HTTP 客户端注入 deviceId

在统一的请求封装（axios/fetch 实例）中全局注入请求头：

```ts
// 请求拦截器
config.headers['X-Device-Id'] = getDeviceId()
```

确保 **signin 请求也会带上**（signin 用的实例也要走同一拦截器）。

### 5.2 会话管理界面

1. 进入页面时调用 `GET /api/user/sessions` 拉取列表；
2. 按 `deviceType` 映射图标/文案，展示 `region`、`ip4`、`createdAt`、`updatedAt`；
3. 用 `current === true` 高亮「当前设备」，且对当前项**隐藏或禁用**单条下线按钮（或提示「当前设备请使用退出登录」）；
4. 「下线」按钮调用 `DELETE /api/user/sessions/:id`，成功后从本地列表移除该项；
5. 「退出其他全部设备」按钮调用 `DELETE /api/user/sessions`，成功后列表仅保留 `current` 项。

### 5.3 deviceType 展示映射（示例）

```ts
const DEVICE_LABEL: Record<string, string> = {
    Chrome: 'Chrome 浏览器',
    Safari: 'Safari 浏览器',
    Firefox: 'Firefox 浏览器',
    iOS: 'iOS 设备',
    Android: 'Android 设备',
    WeChat: '微信内置浏览器',
    Alipay: '支付宝内置浏览器',
    Unknown: '未知设备'
}
```

### 5.4 凭证失效兜底（重要）

被下线/被顶掉的设备，后续任何请求会收到：

```json
{ "code": 10041, "message": "用户凭证验证失败" }
```

前端全局拦截器需把 `code === 10041` 视为「登录态失效」：清空本地 token 与登录态，跳转登录页（或提示重新登录）。这与现有凭证失效处理一致，但**现在多了一个触发来源：被其他设备下线 / 被同设备重复登录顶掉**。

### 5.5 时间与 IP 展示

- 时间字段为 RFC3339，直接 `new Date(createdAt)` 解析后按本地时区格式化。
- `ip4` 为原始 IPv4 文本；如需脱敏（如 `120.229.*.*`）在前端处理即可，后端不做脱敏。

## 6. 边界与注意事项

1. **列表不分页**：当前返回该用户全部未过期会话，数量通常很小，前端直接整体渲染即可。
2. **`deviceId` 为空串**：列表项 `deviceId` 可能是空串（老客户端），展示时需兜底（如显示「未知设备」），不要因空值报错。
3. **下线的并发一致性**：若两个端同时下线同一会话，后到的一方可能收到 `10142`（会话不存在），前端把它当作「已下线成功」即可，刷新列表。
4. **退出其他设备后**：本地列表应刷新；若列表请求因缓存/时序暂未同步，以刷新后的结果为准。
5. **不要在前端比较 deviceId 来判断自己**：一律以服务端返回的 `current` 字段为准（它按「当前请求的 token」精确匹配）。
6. **SSE/EventSource 也受影响**：被下线的设备，其 SSE 会话校验同样失效，前端 SSE 断开后按既有重连逻辑处理即可（重连会因 `10041` 失败而触发登出）。

## 7. 前端自测清单

- [ ] 首次登录（无 deviceId）能正常登录，请求头自动携带 `X-Device-Id`
- [ ] 登录后刷新/重新登录同设备，能正常登录且旧登录态被顶掉（旧端后续请求返回 `10041`）
- [ ] 「会话管理」页面能列出全部会话，当前设备有「当前」标识
- [ ] 点击某条「下线」后，该条从列表消失；被下线的另一台设备随后请求失败并跳登录
- [ ] 点击「退出其他全部设备」后，列表只剩当前设备；其他设备失效
- [ ] 在另一台设备登录（不同 deviceId），两端都能同时在线，列表各出现一条
- [ ] 清除浏览器站点数据后重新登录，列表出现一条新会话（旧会话仍在，可手动下线）
- [ ] 未登录状态访问会话接口，得到 `10041` 并跳登录
- [ ] 下线一个已被删除的会话（返回 `10142`）前端不报错、刷新列表
