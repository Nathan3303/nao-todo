## 2. 判定口径（可观测断言载体）

| 观察面         | 断言载体（实现落地后）                                                                                                                                                                                                                                         |
| :------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本地写         | 内建偏好 `localStorage[`${email}/${builtInId}`]`；普通清单偏好 `IndexedDB.projectPreferences`（key `${userId}:${projectId}`）；侧边栏 `localStorage['ASIDE_WIDTH']`；日历 `localStorage['CALENDAR_WEEKSTART'\|'CALENDAR_POMODORO_BADGE'\|'CALENDAR_DAY_ZOOM']` |
| 偏好队列       | `IndexedDB.meta` 单记录 `${userId}:preference-queue`（**不 bump Dexie version、不加索引**）；项去重键：`{kind:'projectPreference', projectId}` / `{kind:'userConfig'}`                                                                                         |
| 回传（设置面） | `PUT /user/config`，body 含**全量快照** `preferences = {version:1, builtInProjectPreferences, asideWidth, calendar}`                                                                                                                                           |
| 回传（按行）   | `POST /projects/:projectId/preference`（**复数 `projects`**），body `{viewType, getTasksOptions, columns}`                                                                                                                                                     |
| 拉取           | `GET /user/config` 响应含 `updatedAt`（服务端权威时间）；普通清单偏好 `GET /projects/:id/preference` 响应含 `updatedAt`                                                                                                                                        |
| 冲突判据       | 仅 `user_configs.updated_at` / 服务端行 `updated_at`；**客户端时间戳不作判据**（负向断言）                                                                                                                                                                     |
| 业务不变量     | `syncTracker.countDirty(userId)` / `syncStatus.pendingCount` 在偏好写前后**不变**；`syncQueue` 无偏好项；无 `markDirty` 调用                                                                                                                                   |
| 离线闸门       | `withReadOnlyGuard` 清单不含偏好写入口；离线调用偏好写**不返回** `OFFLINE_READONLY`、**不弹** `NueMessage.warn`                                                                                                                                                |
| 可观测         | 偏好同步成功/失败计数 + 失败可见（同步状态面）；不静默                                                                                                                                                                                                         |

## 8. 对 AC / 契约的疑问（**须 PM 确认，⛔ 未自行改 AC**）

### Q-1（口径疑问）：派单信封 AC1–AC6 与 TASK-26 PRD v0.3 §7 AC1–AC6 **不一致**

- PM [T132] 信封列的 AC1–AC6 与 **TASK-27（阶段二）PRD §7 AC1–AC6 逐字同构**（仅「任务」→「偏好」）：
    - 信封 AC1 = 在线本地写+回传 · AC2 = 离线本地+自动回传 · AC3 = 两端同改 ⇒ 服务端确定结论 · AC4 = 失败/冲突 ⇒ 不阻塞+可见+重试 · AC5 = 两端一致+阶段一零回归+移动端 0 · AC6 = 契约自洽。
- TASK-26 PRD v0.3 §7 的 AC1–AC6 为**用户可见**口径：AC1 登出重登恢复 · AC2 换设备/本地被清从服务端恢复 · AC3 离线本地生效+联网同步 · AC4 服务端不可达不阻断+可见提示 · AC5 一致性/清库 · AC6 契约。
- **两套并不等价**：例如「登出→重登偏好恢复」（PRD AC1，用户痛点根因）在信封 AC 中**没有直接对应**；而信封 AC1/AC3（在线写路径/冲突）在 PRD AC 中亦无直接条目。
- **本用例文档的处理**：以**信封口径**为主轴展开（AC1–AC6），并在 §3 标注与 PRD §7 的对应；**契约面**统一收敛到 §4（同时满足两套的 AC6）。**请 PM 确认**：
    1. 本批验收以**哪一套**为权威？（建议：**两套并行** —— 信封口径作为实现期技术验收，PRD §7 作为用户终验；本 QA 验收报告将同时出两份覆盖矩阵）
    2. 若仅取其一，请指定；**在确认前，本 QA 不擅自合并/改写 AC**。
- **补充**：PRD §7 AC1 措辞「偏好自动恢复（**本地**）」与 §5「登出后偏好被清」存在张力（清库后本地已无值，恢复只能来自服务端拉取）。请确认 AC1 的真实判据是否为「重登后偏好恢复为登出前值（**来源为服务端**），且恢复不阻塞进入」。

### Q-2（登记，非阻塞）：R-5 内建偏好键用 email

ADR 明确本批**不改键**（避免迁移），但会遗留「改邮箱 ⇒ 偏好丢失/串号」。本用例 **PSYNC-AC1-01 不判红**（按 ADR 登记为遗留项），请在缺陷池登记或确认后续单。

### Q-3（登记，非阻塞）：R-14 `tagPreference`

本批**不得声称「偏好面全部一致」**。`tagPreference` 仍被 web 离线闸门拦截（DP-5 后续单）。本用例以 **PSYNC-INV-10 负向登记**，验收报告将显式列出该未一致项。
