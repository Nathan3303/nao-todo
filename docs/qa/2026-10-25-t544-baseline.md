## 四、改前基线（T2 已采；T1 阻塞）

### 4.1 方法与环境

```text
pnpm run desktop:build                                    # 产物 out/main|preload|renderer
node scripts/qa/desktop-idle-sample.mjs --seconds 60 --warmup 25 --runs 3 --label pre-change
```

- 采样器（本单新增，可直接复用于**改后对照**）：`scripts/qa/desktop-idle-sample.mjs`
- 口径：**进程树求和**（主进程 + zygote + renderer + GPU + utility，实测 6 进程）；CPU 用
  `/proc/<pid>/stat` 的 `utime+stime` **增量**（`ps %cpu` 是生命周期均值，不可用），RSS 用 `statm` 常驻页；
  每轮独立临时 `--user-data-dir`（不碰真实用户数据），`--no-sandbox`。
- 机器：Linux（Wayland，Electron 43.4.1），后端 `localhost:3302` 存活，**未登录**（全新 userData ⇒ 登录页）。
- ⚠️ **状态偏差（必读）**：本次只能测「**未登录 + 可见**」；登录态会额外跑提醒引擎 10s 轮询与同步，
  数值会更高。⇒ 改后对照**必须同状态**（同样全新 userData），否则不可比。

### 4.2 数值（3 轮 × 60s，1s 采样）

| 轮次             | CPU 均值（全窗口累计） | CPU 逐秒 median / p95 / max | RSS median（进程树求和） |
| :--------------- | ---------------------: | :-------------------------: | -----------------------: |
| 1                |                 0.148% |      0 / 0.99% / 4.95%      |                 668.7 MB |
| 2                |                 0.165% |      0 / 0.99% / 4.95%      |                 733.8 MB |
| 3                |                 0.198% |      0 / 0.99% / 3.96%      |                 736.4 MB |
| **汇总（中位）** |             **0.165%** |        **0 / 0.99%**        |             **733.8 MB** |

- **T2 阈值对照口径**（评审 §三）：隐藏空闲 CPU **中位 ≤1.5%**、p95 **≤5%**、RSS **≤ B×1.3**。
  以本次 `B = 733.8 MB` ⇒ **改后 RSS 上限 ≈ 954 MB**。
- 备注：RSS 为 6 进程 RSS **求和**（共享页被重复计入），故绝对值偏大；**只用于同口径前后对照**。
  GPU 进程报 `--ozone-platform=wayland 与 Vulkan 不兼容`（环境告警，非本需求引入）⇒ 前后对照不要改启动参数。

### 4.3 T1（提醒时效）——**本机阻塞，需补测**

- 阻塞原因：本机**无 QA 账号凭据**（`NAO_QA_EMAIL` / `NAO_QA_PASSWORD` 未配置），应用停在登录页 ⇒
  提醒引擎不运行，无法产生 `remindAt → notify` 样本。
- 影响：T1（`p100 ≤11s` / `p50 ≤1.5s`）**改前数值缺失**。补救仍可行（代码可从 `main` 检出重建），
  执行步骤（有凭据时 5 分钟内可完成）：

```text

git worktree add /tmp/t544-pre origin/main && cd /tmp/t544-pre && pnpm install && pnpm run desktop:build
```

- 说明：「**隐藏态**时效基线在改前不存在」（关窗即退出），T1 的改后判定应以「改前可见态」为参照 + 10s 轮询上限。

## 五、`AC7` 验收探针 SQL 口径（给 `T546`，本单不写代码测试）

```sql
-- ① 部署前摸底（只读）
SELECT COUNT(*) AS total FROM user_sessions;
SELECT COUNT(*) AS active FROM user_sessions WHERE expired_at > NOW() AND deleted_at IS NULL;
SELECT COUNT(*) AS reclaim_expired FROM user_sessions WHERE expired_at < NOW() - INTERVAL 7 DAY;
SELECT COUNT(*) AS reclaim_revoked FROM user_sessions WHERE deleted_at IS NOT NULL AND deleted_at < NOW() - INTERVAL 1 DAY;

-- ② 临时 SESSION_CLEANUP_RUN_ON_START=true 重启 → 日志应有一行
--    session_cleanup removed_expired=<reclaim_expired> removed_revoked=<reclaim_revoked>（无 token）

-- ③ 复跑 ① 并断言（硬判据）
--    total 减少量 = reclaim_expired + reclaim_revoked
--    active 数值 **完全不变**（活跃删除数 = 0）
-- ④ 恢复 SESSION_CLEANUP_RUN_ON_START=false 重启
```

- 客户端侧另一半（AC7）：同设备登录两次 ⇒ 该用户行数不变；`X-Device-Id` 非空；登出后 `nao.deviceId` 仍在（既有 K10 用例覆盖）。

## 七、发现的 PRD / 实现口径疑点（请 PM 裁定）

1. **`resume` / `online` 是否在「距上次成功 <12h」也续期**：T3 字面「触发补集」= 是（只受 ≥5min 去抖），
   本单用例按字面写。若实现选「仅失败后补续」更保守 ⇒ 需改用例（`renewal` 的 resume/online 两条）。
2. **启动触发与既有冷启动 checkin 重复**：`check-in.vue:37` 已是冷启动唯一触发点，本单要求 `scheduler.start()`
   也续期一次 ⇒ 可能双请求。若实现选择「复用冷启动结果、仅安排 12h 周期」，需调整该条用例。
3. **`unconfirmed`（GNOME）时自启是否显示窗口**：RV11/P4 说「不可用/可能不可见 ⇒ 显示窗口」，D4 说「静默到托盘」；
   本单断言 `unconfirmed ⇒ 显示窗口`（避免应用完全不可见）。若 PM 认为仍应静默，需改用例。
4. **`unsupported` + macOS 的 `window-all-closed`**：PRD 未明说；本单按既有 macOS 语义断言「不退出」（AC12 零回归）。
5. **AC1「托盘图标存在」**：自动化只断言「`Tray` 构造成功 + 菜单挂载」，图标**真实可见性**只能用户验收。
6. **AC13 的「四态文案无内部术语 + 三重可辨 + 窄屏布局」**：本单只测 IPC 数据面，UI 呈现全部走用户验收；
   若 PM 要求文案键做自动化（如禁 `tray`/`deviceId` 等词），请另派一条（属 i18n 文本级断言，成本低）。
