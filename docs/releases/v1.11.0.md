# v1.11.0（2026-09-24）

本版本完成**阶段二 2B：冲突精细化** —— 把上一版的「冲突只计数、不处理」升级为**两端一致的冲突可见 / 可对比 / 可恢复**（OCC 乐观并发控制），并补齐**多标签协调**与**偏好面收口**。web 与 desktop 行为一致，**移动端零改动**。

## 亮点

### 1. 冲突可见、可对比、可恢复（OCC）

- 服务端在推送回执里逐条给出结论：`applied` / `noop` / **`stale`（版本已被他端改过，未写入）** / `conflict` / `skipped` / `error`；**服务端始终保留权威版本，本地改动不丢**。
- 状态面板「冲突 N」入口 → **冲突列表** → **只读对比**（服务端版本 vs 你的版本）→ 两个显式动作：**「保留服务端版本」** 或 **「以我的版本重试」**（以最新版本为基准重推，不会死循环）。
- 不再有「静默丢数据」：此前 `error` 回执会被误出队（本地改动无声丢失），本版**不出队并退避重试**。

### 2. 多标签不再互相覆盖

- 同一账号开多个标签页时，推送加**单主锁**：未拿到锁的标签**安静跳过**（不发请求、不消耗重试、队列保留），由持锁标签完成本轮推送。
- 冲突记录（journal）的写入改为**原子读-改-写**，恢复动作与后台推送并发也不会丢记录。

### 3. 偏好面两端一致（含标签偏好）

- 普通清单偏好与**标签偏好**都改为「本地优先 + 同步 + 服务端权威」，web 与 desktop 同构；换设备 / 清缓存 / 重登后可从服务端恢复。
- **偏好读取更快**：本地有数据时**立即返回、不发网络请求**；与远端的对账改在启动 / 联网 / 回到前台时后台完成。
- 偏好数据仍与业务同步队列**互不干扰**（不会污染业务的待同步计数）。

### 4. 顺带修复：web 上旧版本加密数据不可读（DEF-35）

- 仅影响「同一地址曾被桌面端使用过」的历史数据：本版在启动时**一次性自愈**（清掉读不出的本地密文副本 → 从服务端重新拉全量 → 明确告知），**无需手动清数据**；密钥包（`key-bundle`）**不删**（同地址的桌面端可能仍需要）。

## 行为变更（请留意）

- **离线期间的冲突会变得「可见」**：如果你在离线时基于较旧的数据改动了某条任务，而联网前该任务已被别处修改，推送时会得到 `stale`，并出现在**冲突列表**里等你选择。**这不是数据丢失**（本地改动仍在），但**你可能比之前看到更多「冲突 N」** —— 这是「冲突可解」取代「静默覆盖」的设计结果。

## 兼容与数据

- **无需数据迁移**：本地数据库版本未变（Dexie 不 bump）；服务端为**纯追加**改动（无表结构变更、无新错误码）⇒ 客户端与服务端可分别回退。
- **服务端**：跨仓 `nao-todo-server`（`54e843d` / `ac72a37`，`arch/go-ddd`）—— 建议与服务端**同批部署**；服务端先行部署对旧客户端**完全无影响**。
- **移动端**：零改动（红线守住）。

## 已知限制（不阻塞发布，均已登记）

- 冲突 journal 的 `stale` / `conflict` / `skipped` 条目**不含「败方内容快照」**；`noop` / `stale` 含快照。上限由 50 提升到 200，超出后**最旧记录会被折叠丢弃**（列表内会有「已折叠/丢弃」提示）。
- 「标签偏好」的保存接口暂不回服务端 `updatedAt` ⇒ 推送成功后基准时间由**下次对账**刷新（内容等价，多一次请求）。
- 状态面板只显示「已达上限」形式的折叠提示；「更早已丢弃」的提示仅出现在展开的冲突列表内。
- 本版**不做**：字段级合并（只按整条取服务端或你的版本）、版本向量、服务端 `version` 列、跨标签 leader 选举。
- 桌面端 / 移动端本地库不做自动清理（既有行为，未变）。
- 服务端集成测试需串行执行（`-p 1`）—— 既有测试基建限制，非本版引入。
