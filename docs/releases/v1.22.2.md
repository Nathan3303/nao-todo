# v1.22.2 —— 走查修复：搜索筛选、归档只读与几处细节

## 一句话

修的是你走查时点出来的几处别扭：搜索栏「截止日」那颗按钮在窄窗口下会变空、选了日期就不显示文字；归档任务在详情里看不出"已经归档、不能改"；还有两处对齐与留白。功能逻辑没有变化。

## ✨ 更好用了

- **搜索的「截止日」筛选会显示完整范围**：跨年份时会带上年份，例如「截止日：2025年11月1日 至 2026年9月8日」，鼠标悬停还能看到全文。以前只显示月日，跨年时看着像"起点晚于终点"。
- **筛选的「截止日」面板改成了任务详情里那种样式**：以前是「标签在左、输入框在右」的一行挤两个日期；现在跟任务详情面板里的日期选择一个模子 —— 起、止各占一行，标签在日期上方，日期没有边框像纯文字，行与行之间用细线分开，最下面是「包含无截止日」开关（文字在左、开关在右，整行都能点）。
- **归档任务现在一眼能看出是只读的**：详情顶部有明确说明，整块变灰，编辑入口全部关闭（名称、描述、状态、优先级、标签、日期、检查项、评论、子任务都不能改），只保留「取消归档」「变更历史」「导出」。

## 🐛 修好了

- **窗口变窄时「截止日」变成一个空白小胶囊**：以前按钮会被压到几乎没有宽度、文字随之消失；现在按钮不再被压扁，空间不够时换行。
- **选完日期后按钮突然变空白**：日期选择器给出的是带时间的格式，导致日期文案计算抛错、整颗按钮渲染中断。现在会先规整日期，并对异常兜底，脏值也不会让控件消失。
- **变更历史展开内容左边多缩一截**：现在与弹窗标题对齐。
- **窄窗口下设置页「关于与更新」的内容贴着卡片边缘**：已补足内边距。

## ⚠️ 请留意

- **归档任务是只读的**：想继续编辑，需要先在任务详情的「更多」里「取消归档」。
- **搜索仍然默认只显示 50 条**：底部「显示更多」可以继续加载，这是刻意设计（避免一次渲染过多）。
- **没有任何数据格式或同步行为变化**。

## 📦 更小更快

- 本次没有体积变化。

## 技术细节（可略过）

- **搜索筛选（#398 / PR #399 · #400 · #401）**：
    - `.filter-trigger` 由「可收缩 + `max-width: 220px`」改为 `flex: none` + `18rem` 上限；「不收缩 / 文本可省略 / 宽度上限」抽成单一来源 `apps/web/src/components/search/filter-trigger.css`，排序与截止日两个独立 SFC 共用（此前父级 scoped 规则根本作用不到它们），空间不足时换行而非压扁。
    - 截止日值的来源不统一：`nue-date-picker` 输出 ISO（`2025-11-01T00:00:00.000Z`），经 `split('-').map(Number)` 得 `NaN` ⇒ `Intl.DateTimeFormat().format(Invalid Date)` 抛 `RangeError`；该函数在**渲染期**执行 ⇒ 整颗触发器渲染中断（只剩注释、宽度塌成 padding）。修法为输入侧 `dateKeyOfIso` 规整成 `YYYY-MM-DD`、展示侧 `shortLabel` 容错回退（PR #400）。
    - 年份规则：两端年份不同或任一端非当年 ⇒ 带年份；文案走 i18n `date.monthDay` / `date.yearMonthDay`，不使用 `Intl` 自由格式（与项目 `2025年11月1日` 风格不一致），也不复用 `packages/shared/utils/relative-date-parser.ts`（其输出带 `HH:mm` 且为相对措辞，会随当前时间漂移，不适合做筛选条件摘要）。
    - 面板排版（PR #401 → **#403 定稿**）：先试「标签定宽 + 控件 flex」的横排，用户走查判定「样式不对」⇒ 改为**逐值复刻**任务详情面板的 `task-date-selector`（全局样式块，同因 Teleport 到 body）：每行「标签在上（`padding: 0 var(--nue-padding-xs)` / `--nue-primary-color-400`）+ 控件全宽（`border: none` / `box-shadow: none` / `padding-block: 0`）」、行间 `nue-divider`、定宽 `14rem`、`gap: var(--nue-padding-xs)`；开关行取提醒设置器的取值（`padding: 0 var(--nue-padding-xs)` / `height: var(--nue-box-size-xs)` / `space-between` / 文字左、开关右）。**去掉 `theme="menu"`** —— 菜单主题自带 `padding: 2px 0` 且把分隔线缩到 `calc(100% - .5rem)`，与参考件「父容器 4px 内边距 + 分隔线通栏」冲突。Chromium 同页渲染参考件对照 **8/8 计算值相等**（224px / `4px 0` / 8px / 4px / `rgb(153,153,153)` / 8px / 0px / none）；左缘数值证明 `labelPaddingLeft = btnPaddingLeft = 8px`、`labelLeft = btnLeft = 37px`。清除键沿用 DEF-129 让位式 `padding-right: calc(var(--nue-padding-xs) + 1rem + var(--nue-padding-xs))`（实测与日历图标间距 11px、不重叠）。**有意偏差（已登记）**：标签 `rgb(153,153,153)` ≈ **2.8:1**，沿用既有面板故低于 `DESIGN.md` 4.5:1 口径 —— 全站日期选择器同此底子，登记缺陷池待统一调整；动作区分隔线随动作区出现（无值时整组隐藏，避免底部悬空线）。
