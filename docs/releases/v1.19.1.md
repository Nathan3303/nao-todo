# v1.19.1 —— 刷新失败不再打断输入，更多字段的覆盖也会留痕

## 一句话

两件小事：一侧网络抖动时，**子任务列表和「新增子任务」输入框不再被整块清掉**；**优先级、状态、星标、标签、父任务、开始时间**被另一台设备改过、而你保存覆盖掉时，冲突面板**也会留下记录**了（以前只有名称/描述会留）。

## ✨ 更好用了

- **子任务区刷新失败不再打断你**：以前网络抖一下，子任务列表会换成错误提示，"新增子任务"的输入框也消失（正在打字就白打了）。现在**列表留着、输入框留着**，旁边给一条非阻塞提示（会自己重试）。真正第一次加载就失败时，仍然是正常的错误状态。
- **更多字段的覆盖看得见了**：现在改**优先级 / 状态 / 星标 / 标签 / 父任务 / 开始时间**时，如果另一端也改过同一个字段、而你保存覆盖了它，冲突面板会记一条（可查看两版、可复制）。判定基准取的是**你开始操作那一刻**的值 —— 后台每 30 秒自动刷新不会把基准悄悄推走。

## 🐛 修好了

- **提示条有时会显示内部痕迹**：这条不是新 bug，是本批给"错误提示"补的一道永久护栏 —— 断言可见文案必须是完整人话（含「刷新失败 + 原因 + 正在显示上次加载的内容」），且不含 `Error:`、`ECONN`、`[object Object]`、`code:` 这类内部痕迹。
- **测试侧两处会误报的地方**（不影响你使用，但会误导我们排查）：到期提醒的用例改为用数据库自己的时钟造数（本机时区不同会误判）；集成测试固定单进程跑（多包并行会互相清库）。服务端已独立修好并部署合入。

## ⚠️ 请留意

- **`t663` 的那条断言变了**（内部测试）：它原本锚定"子任务区整块替换 + 显示『子任务获取失败』"，而**这正是本版要消灭的行为** ⇒ 改锚到"非阻塞提示可见 + 行与输入框保留"。失败必须可见这层保证没丢，另加了"文案是人话"的护栏。
- **非文本字段的覆盖记录仍只在本端保存时产生**：如果你**不保存**（关掉详情、切走），不会记录（这是设计：没有发生覆盖就没有可记的东西）。
- **服务端配套需部署**：`nao-todo-server` 的 `#91`/`#92` 与服务端行为相关（缺 `iat` 的凭证不再 500、测试卫生），需按服务端流程部署；客户端本版**不依赖**它。
