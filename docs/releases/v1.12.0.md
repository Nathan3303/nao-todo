# v1.12.0（2026-09-25）

本版本新增**清单归档**（Issue #99）—— 归档 = **收起但可找回**，**绝不删数据**。web 与 desktop 行为一致，**移动端零改动**。

## 亮点

### 1. 清单归档 / 恢复闭环

- **三处入口**：清单头部操作菜单、清单**右键菜单**、侧栏底部**「已归档」**入口（直达清单管理弹窗的「已归档」页签）。
- **二次确认**：提示「该清单内 **N** 个任务将一并归档」（N = 未归档且未删除的任务数）。
- **级联归档**：清单与其任务在**同一个本地事务**内完成，且**逐任务入队同步**（离线一致、不丢改动）。
- **取消归档**：回到**最近位置**（`sortId` 保留；与活动项碰撞时自动归一）；页签内展示归档清单的任务数与归档时间。

### 2. 可见性收口 + 搜索开关

- **默认全排除**：清单视图、8 个内置视图、侧栏、日历、番茄、新建下拉、搜索**默认均不显示归档内容**。
- **唯一显式包含通道**：搜索筛选栏新增 **「包含已归档」开关**（URL 参数 `archived=1` 可分享/回填），结果行标注「已归档」。

### 3. 归档清单只读

- 归档清单内的**任务写入**与**清单自身修改/删除**均被拒绝，返回稳定错误码 **`ARCHIVED_READONLY`**；**唯一例外是「取消归档」**。
- 用户可见提示为**单条、本地化**文案（不会透出错误码）。

### 4. 单任务「取消归档」

- 若其清单**仍在归档** ⇒ 任务**移入收集箱**并给出可见提醒（「已移入收集箱 / 原清单仍处于归档状态」）；若清单**已恢复** ⇒ 回到原清单。

### 5. 服务端对齐（跨仓 `nao-todo-server`）

- 列表查询**默认排除归档**（**任务与清单两面**）：「未传 `isArchived`」与「显式 `false`」**同语义**。
- 修复 `sort` 参数**无白名单**的注入面（非法字段/方向 ⇒ 回落默认排序，不再拼接 SQL）。
- **「/sync/pull」照常返回归档内容**（镜像完整，不因默认排除而丢失本地镜像）。

## ⚠️ 行为变更（请知悉）

1. **移动端将不再显示已归档内容**（任务与清单两面均被服务端默认排除；**移动端代码零改动**）。
    - **取决于服务端部署**：本版客户端发布**不会**使该行为生效 —— 需要服务端发布/部署 `nao-todo-server` 对应变更（已合并至该仓活动主干）。
2. 归档清单内的写入会被拒绝并给出本地化提示（`ARCHIVED_READONLY`）。

## 修复

- **归档曾误删数据**：`archive()/unarchive()` 曾被错误地走「删除」路径（`deletedAt` 被置位）⇒ 已改为**委托仓储的归档/取消归档**，绝不写删除标记。（`DEF-36`）
- **服务端归档过滤空操作** + **`sort` 注入面**（`DEF-12`）。
- **脱归档变更同步不到服务端**（静默）：单任务取消归档后写入的本地「收集箱」归属，在推送时会被服务端拒绝（字面量 `inbox` 非合法 ID）⇒ 队列长期退避、**永不出队**、且无提示。已修：**推送侧**将本地 `inbox` 归一为「无清单」发送、**拉取侧**将服务端归一后的 `userId` 回填为本地 `inbox`（**同批**修复，往返闭环）。（`DEF-37`）

## 已知未做（已登记）

- **移动端同源残留**（`DEF-38`）：移动端按字面 `inbox` 过滤收集箱 ⇒ 服务端归一后的值不命中（**本版不动移动端**，需单独授权后修）。
- **通知静默为「约定式」**：归档只读提示的抑制依赖「通知入口逐处登记」（清单见 ADR）⇒ 建议后续收拢为**唯一通知包装**，并加静态守卫。
- 归档确认文案的 **N 口径微差**：N 不含「已放弃」与「子任务」，而级联会归档二者 ⇒ N 可能略小于实际归档数（既定取舍）。
