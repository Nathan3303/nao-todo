# v1.20.0 —— 每一次修改都能查到谁、改了什么

## 一句话

任务详情里多了一块「**变更历史**」：一条任务被谁、什么时候、改了哪个字段、从什么改成了什么，都能翻到。它是**旁路记录** —— 不参与同步判胜负，也不会上报服务器，只存在你自己的设备上。

## ✨ 更好用了

- **每条任务都有"变更历史"**：打开任务详情就能展开，默认折叠、不挤占名称/描述区。每条 = 时间 · 来源 · 字段中文名 + 旧值 → 新值。
- **来源看得懂**：四种来源都是中文 ——「本机修改」「同步自云端」「已合并云端修改」「恢复了我的修改」。你不用再猜"这条到底是我改的还是同步带下来的"。
- **能翻更早**：默认显示最近几条，点「更早的记录」继续翻；跨天时按今天 / 昨天 / 更早分组。
- **老任务不报错**：升级前就存在、从没改过的任务，历史区显示「暂无变更记录」，不会出现「加载失败」。

## 🐛 修好了

- **改了什么都查不到**（本版的主要能力）：以前只存"当前值"，改了就覆盖，连"谁改的"都无从追溯；冲突面板只覆盖"冲突败方"且最多留 200 条、会被挤掉。现在每次修改都留一条字段级记录。
- **删/归档/恢复也留痕**：这些动作以前在历史里什么都不留。

## ⚠️ 请留意

- **只记录本机与同步到本机的变更**：历史存在本机，**不上报服务器**；所以它不能回答"另一台设备上的谁改的"，只能区分"本机改的"和"云端同步下来的"。（要跨端显示操作者，需要改服务端协议，另立项目）
- **有保留上限**：每台设备最多保留 **1000 条 / 90 天**，更早的会被自动清理；单条内容过长会截断（会标记已截断）。
- **升级前的历史补不回来**：本版只对**今后**的修改生效。
- **只覆盖任务**：清单、子任务、评论、标签、番茄钟暂不记录（后续批次逐步接入）。
- **首次进入可能轻微顿一次**：如果本地积累了很多超期记录（例如长期不用后首启），后台清理会一次性搬走一部分（每次最多 400 条、分块进行）——属一次性成本，清完即恢复。若你觉得明显卡顿，告诉我，我可以把每批调小。

## 📦 更小更快

- **没有网络开销**：审计只写本机，同步往返次数不变。
- **保存路径无感**：审计写入 p95 ≈ **1ms**（端到端保存 p95 ≈ 2.1ms）；清理是异步的、不在保存路径上。
