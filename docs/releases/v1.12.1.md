# v1.12.1（2026-09-28）

本版本为**同步冲突客户端侧修复**（`T325` / `T326` / `T329`）—— 消除 desktop「频繁修改后有概率出现同步冲突」的客户端根因，并**关闭一条无提示静默覆盖本地改动的窗口**。web 与 desktop 行为一致，**移动端零改动**。

- **Tag**：`v1.12.1`
- **版本**：root `1.12.0 → 1.12.1` · `apps/web` `1.12.0 → 1.12.1` · `apps/desktop` `1.12.0 → 1.12.1` · `packages/infrastructure` `0.8.0 → 0.8.1`（本批唯一有源码改动的内部包；`apps/mobile` / `packages/presentation-react` 零改动，不动）
- **前置**：需与服务端（含 OCC 与派生行回传）配套；服务端已部署 `nao-todo-server` `5cb30c5`

## 亮点

### 1. 客户端修复（对应 `RC-2` / `RC-3` / `RC-5` · `RC-1` 客户端半边）

- **服务端时间校准接线修复**（`RC-2`）：push/pull 读取 `serverTime` 时**少读一层**（服务端实际放在 `body.data.serverTime`）⇒ `getServerTimeOffset()` **恒为 0**，本地写时间基准退回**裸客户端时钟**。修复后本地写随服务端时钟校准，消除时钟偏斜导致的**伪 `noop` / `stale`**（用户看到的「十几毫秒差异冲突」的客户端根因之一）。
- **pull「本地胜」回写 base**（`RC-3`）：本地有未推改动、且本地时间更新时，原实现**整段跳过且不回写 base** ⇒ OCC 下下一次推送**必然 `stale`**。现把 base 收敛到服务端当前版本（仅改 base，不动业务字段、不出队）。
- **写库与入队同事务**（`RC-5` / `DEF-50`）：本地业务行写入与同步入队原为**两次独立 await** ⇒ 拉取/偏好对账可在「行已写、队列尚未入队」的窗口内**无提示覆盖**本地改动。现收进**同一 Dexie `rw` 事务**，入队失败**整体回滚**：
    - 覆盖 `tasks` / `projects` / check-items / comments（前批）；
    - 补齐 `tags` / `pomodoros` / `pomodoroRecords` / **冲突「以我的版本重试」** / **偏好队列（含对账覆盖侧事务内再确认）**（本批）。
    - ⇒ **「无 journal 静默覆盖」窗口归零**；用户点「以我的版本重试」时不再可能丢改动。
- **同毫秒出队竞态**（`AC-T325-8`）：推送在飞时、同毫秒的新写原会被误判「未变」而误删队列项 ⇒ 改用入队**修订号**（`revision`）比较，新写保留、下轮重推。
- **消费服务端派生行回执**（`RC-1` 客户端半边）：读取 `/sync/push` 的 `data.derivedUpdates[]`（`{table,id,updatedAt}`；**缺省 / 未知表 / 空值 ⇒ 完全 no-op**，兼容旧服务端），把被计数联动改写的父任务 / 清单的 base 收敛到**库中最终版本**。**脏行也收敛**；**先应用 `results`、后应用 `derivedUpdates`**（后者为更晚的最终版本，覆盖前者）。
- **清单 pull 边界 `'' → null` 归一**（`DEF-42`）：项目 pull 时把服务端空串 `archivedAt` 归一为 `null`，避免「空串哨兵」误判。
- **日历名称排序固定 `zh-CN`**（`DEF-40`）：消除随运行环境 locale 变化导致的排序不一致。

### 2. 行为变更（请知悉）

1. **偏好保存失败会报错并回滚**：原偏好入队失败被**静默吞掉**（本地行仍写入，用户看不到失败）；现与业务行**同事务** ⇒ 入队失败时**返回错误并回滚**。web 端清单 / 标签偏好视图已有**可见反馈**（`NueMessage.error` toast）。
2. **`stale` 冲突更「可见」**：服务端部署 OCC 后，基于陈旧 base 的推送会得到**可见冲突条目**（而非静默覆盖）⇒ **可见冲突数可能上升**（设计使然，**非缺陷**；「可见化」取代「静默覆盖」更安全）。

### 3. 前置与协同（跨仓 `nao-todo-server`）

- **需与服务端配套**（OCC + 派生行回传，已部署 `5cb30c5`）：客户端 A / B① / B③ 修复**独立生效**；`derivedUpdates` 消费端在**旧服务端**下自动 no-op（行为逐字不变）。
- **旧客户端在新服务端下**：陈旧 base 会得到可见 `stale`（不再静默覆盖），属预期且更安全。

### 4. 已知未做（已登记）

- `deletions` 不参与 OCC（`R-15b`，既有局限）。
