# v1.18.2 —— 你保存时吃掉的云端那份，现在会留下记录

## 一句话

在一台设备上编辑某条任务时，另一台设备改了同一个字段，而你随后保存把云端那版覆盖掉 —— 现在界面会**明确告诉你这件事**，把「云端当时的版本」和「我的当前版本」摆在一起，并且可以**一键复制**云端那份留底。

## ✨ 更好用了

- **覆盖不再无声无息**：以前这种情况是「悄悄吃掉」，面板里什么都没有，事后也无法查。现在冲突面板会出现一条「**我的修改已覆盖云端**」，能看清云端当时是什么、我改成了什么。
- **一键复制云端那份**：这类记录上有「复制」按钮，点一下就把「云端当时的版本」复制到剪贴板，方便粘回去或留档；按钮会短暂显示「已复制」。
- **不再有会误导的按钮**：这类记录上不再出现「用云端的」——这个动作对它只会把记录清掉，拿不回云端内容。

## 🐛 修好了

- **保存时「吃掉」另一台设备的修改却毫无提示**（数据同步止血批留下的最后一个盲区）：现在会记录、会显示、可复制。这是本版的主要修复。
- **本不会产生记录的场景一律不打扰你**：连续改两次、只改了格式、另一端改的是**别的**字段、你改回原值（远端没动该字段）、你的值恰好等于云端值 —— 都不会新增记录。
- **记账失败不影响保存**：即使记录写不进去，保存照样成功、不回滚，只在内部日志里留一条严重级别的痕迹（方便我们追查），界面上不会出现报错。

## ⚠️ 请留意

- **「两端各改一个字段」现在仍然会整条冲突**：你只能在「我的版本」和「云端版本」之间**二选一**，不会逐字段合并。这是下一步（字段级合并）要解决的问题，**本版没有改变它**；看到这类冲突属已知范围，不是本版引入。
- **只对「名称 / 描述」记录覆盖**：优先级、状态、星标、标签、父任务、日期这些字段被覆盖时暂时不产生记录（它们的「编辑起点」目前拿不到；已登记为后续项）。
- **记录只保留最近一版**：同一条任务反复发生覆盖时，冲突面板里保留的是**最新一次**的云端版本，更早的中间版本我们从未存下来。

## 📦 更小更快

- 无体积与首屏变化；同步的网络往返次数**没有增加**（记录只写在本机，不上报服务端）。

## 技术细节（可略过）

- 判据：`F = keys(载荷) ∩ keys(编辑基准)`，逐字段 `(R_f ≠ O_f) 且 (L_f ≠ R_f)` 才记录；比较一律走既有 `valuesEqual`（空值哨兵归一）。
- 记录复用既有 `kind = 'pull-local-wins'` + `appendConflict`：**零新 kind、零新文案键、零新裁决路径**；快照只存差异字段 + 身份字段、>512 截断带 `truncated`、上限 200 不变。
- 记账在保存事务**之后**（journal 走 `navigator.locks` + 另一次 `meta` 写，不能进 Dexie 事务）；失败走 `logStructured('error', 'sync.journal.record-failed', {table, entityId, reason})`，不含业务值。
- 编辑基准为**可选**入参（`TaskUpdateOrigin`，定义在 domain 值对象层、application 转出）；不传 = 行为逐字不变（`persistence-go` 签名跟随但不消费、`batchUpdate` 与其余调用点不传）。
- 抽共享「挑差异字段」helper（`pickChangedFields`），A1 拉取侧改为调用；忽略字段统一 `SYNC_COMPARE_IGNORED_FIELDS`（删掉 `sync-service` 内重复表），并有「新旧实现同输入同产物」等价用例守门。
- 冲突面板：「保留服务端版本」按 kind 收口（仅 `pull-local-wins` 不渲染），该 kind 的动作行新增「复制」（复用既有 `copyLoser`/`copyLoserLabel`）。
