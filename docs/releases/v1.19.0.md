# v1.19.0 —— 两台各改一个字段，不再互相覆盖

## 一句话

以前两台设备各改一个字段（一台改标题、另一台改描述），保存后必然整条冲突、只能二选一，选哪边都丢另一边的改动。现在**按字段自动合并**：两边都保住，冲突面板也不会多出一条。

## ✨ 更好用了

- **各改各的，不再是冲突**：一台改标题、另一台改描述或优先级 —— 保存后两端都是最新，谁也不吃谁。
- **真冲突时能看清"冲突在哪一项"**：同一条任务两端都改描述才会冲突；面板现在多一行「字段」，用中文标出冲突项（如「名称」「优先级」），不再是两整行对着看。
- **标签不会被对方吞掉**：一台加 `#工作`、另一台加 `#紧急`，合并后两个都在。
- **提醒设置不会被拼成怪组合**：提醒的时间 / 重复 / 时刻 / 星期属一个整体，两端分别改时按整组取一边，不会出现"我的时刻配对方的重复"。
- **删除优先**：一台删除、另一台同时改字段，结果是删除生效，而且**不会**多出一条"我的修改覆盖了云端"的假记录。

## 🐛 修好了

- **两端改不同字段仍会冲突、只能二选一**（你 2026-11-09 走查报的那一条）：这是整行裁决的老问题 —— 版本粒度是"整条任务"，而你实际编辑的是"某个字段"。本版把裁决改成按字段。
- **冲突面板的对比可能显示"没有差异"**：修了上一条的连带问题 —— 合并后本地保留了自己的字段，若对比还取本地行就会得出"两边一样"，面板空白。现在对比取云端当前版本，标签与内容一致。
- **并发保存时可能把远端异字段整行覆盖**：合并期间若本地又改了同一任务，会放弃本轮合并、下一轮重来，而不是拿着一个从未上传过的值去顶掉云端。

## ⚠️ 请留意

- **行为变了**：以前会冲突的场景，现在多数会自动合并、不再弹冲突。这是本版的目的，但你的习惯可能需要调整 —— **真正需要你选一边的，只剩"同一字段两端都改"**。
- **已经丢掉的改动找不回来**：本版只对**今后**的同步生效；此前被覆盖的历史内容没有留存，无法回溯。
- **只对任务生效**：清单、子任务、评论、标签、番茄钟等其它数据仍按原方式同步（后续批次逐步接入）。
- **只对"名称 / 描述"保留保存侧覆盖记录**：优先级、状态、标签、父任务、日期这些字段被覆盖时仍不产生记录（已登记为后续项）。
- **两台设备都要升级**：未升级的旧端仍按整行推送，可能覆盖新端已合并的字段 → 两端都升级后才会稳定。

## 📦 更小更快

- **没有增加网络请求**：合并全部在本机完成，同步往返次数不变。
- **一次性成本**：两端都升级后首次同步会重建一次字段基准，属正常。

## 技术细节（可略过）

- 路线：**客户端三方字段合并，服务端零改动**（ADR `2026-11-10-field-level-merge.md`）。否决服务端字段级 OCC（需跨仓同发布，且对老客户端会**增加**冲突）。
- 基准 `B` = 写时捕获的**字段级基准**（队列项 `fieldBase`，只含我改过的字段；任务文本字段在**实体层**捕获 —— 落库为 `plain:` 与同步边界不同形状）。零 Dexie 版本、零迁移。
- 唯一实现 = 纯函数 `persistence-sync/field-merge.ts`（无 IO / 无加解密 / 无 `async`）；三个接入边界 = pull 远端胜 / pull 本地胜 / push `stale`，均显式传 `lwwWinner`。
- 判据：`R==B ⇒ L` · `L==B ⇒ R` · `R==L ⇒ 任取` · 三者两两不等 ⇒ 冲突；比较统一 `valuesEqual`。
- 落库守卫：`fields` = 完整合并域 · 过滤 `merged` 的 `undefined` · `{...localRecord, ...merged}` + base 单独推进 + `deletedAt` 从本地保留。
- 并发守卫：回执在飞期间本地 `revision` 变 ⇒ 放弃本轮（不记账 / 不写回 base / 不出队）。
- 记账：**零新 kind**；`conflictFields` 为 additive 可选字段（缺省不落键，老条目向后兼容）；提醒组冲突时 `conflictFields` 与 `loser` 均为整组四字段。
- 可观测：`syncStatus.fieldMergeCount` + 结构化事件 `sync.field-merge.applied`（只含表名与冲突计数，无业务值）。
- **生产回滚说明**：控制台执行 `localStorage['nao-todo:field-merge-mode'] = 'lww'` 即回到本版之前的整行裁决；`removeItem` 恢复。**下一次 pull/push 生效**，无需重启 / 重登 / 迁移；不回滚已合并数据。
