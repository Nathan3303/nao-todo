# 2026-09-10 TASK-01：子任务创建继承父任务字段（清单 + 时间窗快照）

- **评审对象**：子任务创建需继承父任务部分数据（术语：**清单 = project**，含内建「收集箱」）
- **结论**：✅ **有条件可行**（约束 C-T1…C-T8；需拍板 D7-a）

- **范围**：子任务创建的**参数默认值**（继承 = 创建时快照）；不改同步协议/表结构/游标/后端 API

## 2. D7 裁决：落点 = **A（presentation 组装）**，附三补丁 + 显式升级判据

### 2.1 定性：继承是"创建参数的默认值"，**不是领域不变量**

- 任何"子任务与父任务清单/时间窗不同"的组合都**不构成非法状态**：领域/服务端均接受，用户可立即修改；D2（创建时快照）进一步说明父子之间**无持续约束**。
- 因此领域层**不应**为此新增守卫（无不变式可守 ⇒ 属投机代码，违反简单性优先）；本裁决与 SHELL-03 附录 A-4 同源（**不新增 domain 端口 / 副作用放装配层**）。

### 2.2 结论：**方案 A**（改 2 处），但必须带三个补丁

| 补丁                                        | 内容                                                                                                                                                                      | 理由                                                                                                                                                                             |
| :------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **P1 单一拷贝函数**                         | 拷贝逻辑写成**一个导出的纯函数**（如 `resolveSubTaskDraft(parent, name)`），放在 presentation 内可测位置；`createSubTask` 只做"取父 VO → 调函数 → create → 入列"          | 可单测（§7）、可复用（未来第二入口直接调）、避免逻辑散落                                                                                                                         |
| **P2 同步修移动端同源实现**（或登记漂移债） | `compose-task-usecase.ts:129-131` 调整为同一规则（同样 5 行）                                                                                                             | **同一产品规则已存在第 2 份实现**（§1 发现 1）；不同步修 ⇒ 移动端子任务不继承，跨端语义分叉。若 PM 判定本单不覆盖移动端，**必须在 PRD/ADR 显式登记为已知不一致**（禁止默认放过） |
| **P3 精确落点**                             | 改 `use-subtasks.ts`（签名接收父 VO ref + 拷贝逻辑）与 `task-details.ts:103`（把已存在的 `task` ref 传入）；**不得**从 `taskDetailsStore.taskDetails` 读父任务（§1 陷阱） | 最小改动、零新依赖边、零 API 变更                                                                                                                                                |

## 3. 继承规则（**以 `endAt` 为锚**的窗口拷贝）

| 父任务状态                                           | 子任务继承结果                                                                                      | 依据                                                                             |
| :--------------------------------------------------- | :-------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------- |
| `startAt` 与 `endAt` 均有效且 `startAt ≤ endAt`      | **原样拷贝两者**（值快照，不做时区/粒度转换）                                                       | D1「时间窗自洽」；消费侧 `monthly-layout` 双端闭区间语义                         |
| 仅 `endAt` 有效                                      | 拷贝 `endAt`；`startAt = null`（由 `fillStartAt()` 派生）                                           | 与"仅截止（endAt-only）"任务的既有创建路径行为一致（`create-task.ts:107-124`）   |
| 仅 `startAt` / 两者皆无 / 无效值 / `startAt > endAt` | **两者皆 null**（= 未安排）                                                                         | 本域"没有 endAt ⇒ 未安排"（§1 发现 2）；避免"有开始但被视作未安排"的半窗口矛盾态 |
| `projectId`（`string \| null`，`''`=收集箱）         | **原样拷贝**；`''/null` 均表收集箱（由既有 converter `projectId \|\| ''` 承接，`converters.ts:97`） | D5「清单缺失 ⇒ 收集箱」＝不特殊处理，沿既有语义                                  |
| 其余字段                                             | **保持现状默认**（`state:'todo'`/`priority:'low'`/`tags:[]`/`description:''`/提醒默认）             | 用户规则（D1 只列三项）                                                          |

**硬约束（实现坑）**：传给 `create` 的 `startAt`/`endAt` **必须显式 `null`，严禁省略为 `undefined`** —— 实测 `dayjs(undefined).isAfter(...)` 为 `true` ⇒ 未来 `startAt` + 省略 `endAt` 会误报 `START_AFTER_END`（§1 发现 3）。

## 4. D2 快照语义与"禁级联"约束（Q3 结论）

- **必须新增约束（C-T5）**：**任何路径不得把父任务字段回写到已存在子任务**——父任务的时间窗/清单/名称/删除/归档/放弃/恢复等变更，**一律不触达子任务字段**。
- **可写的父子关系仅两处**：① 创建时写 `parentTaskId`；② `detachSubTask`（`parentTaskId → ''`，`use-subtasks.ts:118-124`，已由领域守卫校验）。即：**"父子关系"可写，"父的字段"不可写**。
- **禁止把"未安排"实现为"父变更时的同步"**（例如"父改时间窗 → 批量更新子任务"）：那会破坏快照语义并引入批量写风暴。
- **落地形态**：拷贝为**值拷贝**（字符串/基础类型）⇒ 天然解耦；因此 C-T5 是**防未来级联的纪律 + 回归断言**（§7 冒烟 4），而非需要额外代码。

## 5. R2 行为变更的影响面（Q2 结论）

**变更**：父任务未排期时，子任务由"今天"（`endAt=now`）改为**未安排**（both null）。

| 能力                  | 影响                                    | 证据/结论                                                                                                                                                                      |
| :-------------------- | :-------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 日历月/周视图         | **无影响**                              | 子任务写入 `taskDetailsStore`（`tasks-view.ts:65`），日历/任务视图读 `tasksStore` ⇒ **结构性不出现**；且 `仅 startAt/无日期 ⇒ 不占格子`                                        |
| 未安排桶（B7）        | **无影响、不会因本单增长**              | 桶数据源 = `tasksStore` 快照 + 谓词 `!endAt`（`use-calendar-monthly.ts:169`）⇒ 子任务不进桶（解 PM 的"桶失控"疑问）                                                            |
| 批量安排 / 拖拽改期   | 无影响                                  | `reschedule.ts:8-11` 已定义"未安排（endAt 空）"分支；且该表面只覆盖顶层任务                                                                                                    |
| 逾期判定              | 无影响                                  | `!task.endAt ⇒ false`（`use-calendar-monthly.ts:30-34`）⇒ 未安排子任务不会误报逾期                                                                                             |
| 子任务行展示          | **出现正向可见变化**                    | `subtasks.vue:38-50 metaText` 会显示继承到的时间窗（既有逻辑，未改代码）——与 D6「不做继承提示 UI」不冲突（这是既有字段展示，不是新提示）                                       |
| 存量数据（D3 不回填） | **新旧语义并存**                        | 同一父任务下：旧子任务仍带"今天"的 `endAt`，新子任务可能"未安排" ⇒ 无日历/逾期副作用，但 **QA 需知情**（不得当缺陷报）                                                         |
| 子任务日期编辑        | **本单不新增 UI**；未安排子任务仍可编辑 | 子任务行无日期控件（`subtasks.vue` 只有状态/名称）；但 `switchTaskDetails` 可进入该子任务详情页设置日期（非死路）⇒ **不得**为"补救未安排"在本单加 UI（防范围蔓延，如需另立单） |

## 8. 约束清单（可勾选验收）

- [ ] **C-T1 继承范围**：仅 `projectId` + `startAt` + `endAt`；其余字段保持现状默认（禁顺手扩字段）
- [ ] **C-T2 值快照**：拷贝必须**原样使用父值**，禁任何时区/粒度/格式重算（仅允许"缺失 ⇒ null"）
- [ ] **C-T3 显式 null**：`startAt`/`endAt` 必须以 `null` 显式传入，**禁 `undefined`**
- [ ] **C-T4 兜底不抛错**：父 VO 不可得 ⇒ 按"未安排 + 清单缺失"创建，返回成功，不阻塞快速输入
- [ ] **C-T5 禁级联**：任何路径不得把父任务字段回写到已存在子任务（父子关系除外）
- [ ] **C-T6 单一实现**：拷贝逻辑为**一个导出纯函数**并附单测；第二入口（React/Lynx）同规则或**显式登记不一致**
- [ ] **C-T7 父 VO 来源**：只允许 `task-details.ts` 的 `task` ref（**禁** `taskDetailsStore.taskDetails`）
- [ ] **C-T8 零 API/契约变更**：不改后端、不改同步协议/表结构/游标、不新增埋点（D4）
