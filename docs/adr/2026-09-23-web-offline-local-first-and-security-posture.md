## 3. 约束（C-46…C-62）

> 编号接续 SHELL-06 的 C-45；**C-46…C-62 为本 ADR 新增**（未占用任何既有编号）。

### 3.1 明文落盘与姿态

- [ ] **C-46 明文落盘（两端同一姿态）**：业务数据（`tasks`/`taskComments`/`taskCheckItems`/`projects`/`tags`/偏好/番茄）**明文**存 IndexedDB；`cryptoService` **保留为 passthrough 接缝**（`encrypt/decrypt` 直通、`isUnlocked` 语义**必须显式定义**——见 C-62）。**禁止**整体移除 `cryptoService`（迁移窗口内必须保留真解密能力）。**禁止**「半明文」（部分字段加密/部分明文）——与"弱化 KEK"同源，制造虚假安全感。
- [ ] **C-47 `meta` 迁移完成标记**：迁移**全库成功后**才写 `meta` 完成标记；标记存在时**不再走迁移路径**（幂等短路）。**禁止**在部分成功时写标记。

### 3.2 迁移红线（四条，**P0**）

- [ ] **C-48 迁移禁走 `repo.update()`**：迁移**必须直写表**（照 `applyPullBatch` 的 `entityToRecord` + `table.put` 写法），**不得**经仓储写路径 ⇒ 否则整库 `markDirty` ⇒ **推送风暴 + 服务端 LWW 被本地伪修改覆盖**。
- [ ] **C-49 迁移期禁同步**：迁移期间**必须**阻止 `syncService` 的 pull/push（否则 pull 把明文覆盖回密文 ⇒ **永不收敛**）。实现方式与解锁顺序一并设计，**不得**依赖"迁移很快"的时序假设。
- [ ] **C-50 幂等可续跑**：迁移必须可在任意中断点续跑（逐表/逐批进度可判定）；**不得**依赖"一次跑完"。中断后重启**不得**出现混合格式读失败。
- [ ] **C-51 双格式双向读取兜底（P0）**：读取侧必须**同时接受** `plain:<原文>` 与历史密文；`cryptoService.decrypt` **对明文输入不得抛错**（现状 `cipher.split(':')` 会抛"密文格式无效" ⇒ **必须修**）。**`key-bundle` 的删除是唯一不可逆开关**：仅在 C-47 标记写入后允许，**且必须长期保留密码入口**（本仓无遥测）。

### 3.3 登出清库

- [ ] **C-52 按键删除黑白名单（P0）**：登出清库**禁止** `localStorage.clear()`，必须按**键白名单/黑名单**逐键 `removeItem`。**白名单（必留）**：`nao.deviceId`（P2-Z7 实测：误清 ⇒ 设备漂移 + 服务端"同设备覆盖旧会话"失效 ⇒ 会话行膨胀）。**建议保留**（设备级偏好）：`THEME_MODE_KEY` / `LANGUAGE_KEY` / `CALENDAR_WEEK_START_KEY`。**黑名单（必清）**：`USER_JWT_LOCALSTORAGE_KEY`、`USER_PROFILE_CACHE_KEY`、`POMODORO_TIMER_SNAPSHOT_KEY` / `POMODORO_FOCUS_SNAPSHOT_KEY` / `POMODORO_SETTINGS_KEY`、`'USER_CONFIRM_UNRESTORE'`、`getStorageKey(tableId)`/`storageKey` 类（键名完备性见探针 **Z13**）。IndexedDB 侧清 11 业务表 + `meta` + `deletionSchedules` + `syncQueue` + `syncCursor`（复用 `deletionService` 既有事务原语）。
- [ ] **C-53 清库可重入（P0）**：清库前置 `meta.pendingWipe = <userId>`（**单事务**内与清库同提交），启动时若存在该标记则**补清**；清库完成后删除标记。⇒ 崩溃/强杀/掉电后重启**必然收敛**（"登出"是唯一清理触发点 ⇒ **登出的可靠性即安全边界**）。
- [ ] **C-54 脏队列阻塞确认（P0）**：登出前判定"是否有未回传写入"**必须直接调 `syncTracker.countDirty(userId)`**；**禁止**读 `syncStatus.pendingCount`（**DEF-13**：仅在 `endRun()` 刷新 ⇒ 滞后）。`>0` ⇒ **阻塞确认**（显示 N + 「先同步」）；离线且 `>0` ⇒ 二次确认并明示不可恢复。**绝不静默清**。

### 3.4 身份与隔离

- [ ] **C-55 `userId` 硬失败（P0，DEF-9）**：`getCurrentUserId() ?? ''` 兜底**必须移除**；`userId` 为 `null`/空时**拒绝一切库操作**（硬失败 + 可见错误），**不得**退化为"空用户"读写。明文姿态下这是**准入条件**（否则跨用户读到明文）。启动时须从 JWT 重建 `localSession`（web 现无重建点）。
- [ ] **C-62 离线进入判据替换（P0，DEF-16 / K9）**：删除 C-23 条件④；新判据 = **`offlineEntryGranted && JWT 可解析 && localSession.getCurrentUserId() === jwtUserId && 本地镜像存在`**（**两处实现同步改**：`routes.ts` 真守卫 + `offline-prerequisites.ts`）。**必须补正向单测**（现有测试只覆盖 `isUnlocked === false` 的**拒绝**路径 ⇒ 删除后无守护）。若改走"passthrough 仍置位 `isUnlocked`"的备选方案 ⇒ **必须在本 ADR 变更记录中显式声明**，否则离线进入静默失效。

### 3.5 启动门与调用点

- [ ] **C-56 启动门内迁移（P0）**：迁移**必须**在主界面挂载前、**启动门内**完成（冷启动进入"感觉即时"）；**批量事务**（5k 条 0.3–1.5s 量级），**禁止逐条事务**（数秒~十几秒）。
- [ ] **C-61 门退役顺序硬约束（P0，DEF-10）**：`checkAndCleanExpired` **必须**迁往**单一收敛点** `bootstrapLocalData(userId?)`（`userId ??= resolveUserIdFromStoredJwt()` → `localSession.setCurrentUserId(userId)` → `await deletionService.checkAndCleanExpired(userId)`），且**必须早于 `syncService.start()`**（`start()` 读 `deletionSchedules` 决定跳过启动同步）。调用点覆盖：**① desktop 冷启动（AppRoot，替代 `unlock-gate.vue:75`）② web 阶段一门 B 通过后的等价收敛点（必须）③ 常驻跨 7 天（挂既有 `registerBackfillTriggers` 前台恢复/`online` 触发源）**。**顺序：先加新调用点 + 单测 → 再删旧门**；新调用点**必须自带单测**（现有守护随门消失）。可验收判据 = 一条**顺序断言**（探针 **Z14** 预期无此断言，需补）。

### 3.6 护栏

- [ ] **C-57 desktop 单实例锁（P0）**：启用 `requestSingleInstanceLock`（实测**当前未启用**）。理由：`(user_id, device_id)` 会话 upsert、pull 游标 RMW、`syncQueue` 单写者、迁移竞态**都假设单写者**。
- [ ] **C-58 CSP 必须（P0，DEF-8）**：两端**均须有生效 CSP**。**desktop**：生产走 `win.loadFile`（`file://`，**无 HTTP 响应头**）⇒ CSP **只能**落 `<meta http-equiv="Content-Security-Policy">`。**web**：SPA **不由 `nao-todo-server` 托管**（服务端无 Static/NoRoute）⇒ CSP 必须落**静态托管侧**（**不在本仓可验收**，见 §9.3-AC12）。明文姿态下 CSP 从"建议"升为**准入条件**。
- [ ] **C-58b DB 改名暂缓**：保留 `nao-todo-desktop`（`local-database.ts:264`）。**改名 = 新库 ⇒ 存量数据被孤立**；**迁移完成前不得改名**。
- [ ] **C-59 阶段一不得产生 `markDirty`（P0）**：阶段一为**只读**；**任何**写路径都不得入队。**desktop 现状能写**（本地仓储 + `markDirty`）⇒ 阶段一**必须在 UI 层统一禁写**（**不要逐个改仓储**，会漏），并以 **P1 探针 §3.3 的 24 项清单为唯一真源**。若产生脏队列 ⇒ **C-1（登出丢未同步写入）与 LWW 立即变必需**（阶段一豁免失效）。

## 4. 威胁模型 + 残余风险接受

### 4.1 安全边界搬迁（一句话）

**从「设备上的本地密码」搬到「浏览器/系统账号 + 设备持有本身」= 「设备即凭据」。**

### 4.2 暴露窗口（量化）

| 端          | 窗口 = 从 → 到                        | 实际长度                                                                                                                                                                                                         |
| :---------- | :------------------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **desktop** | 登录（建库/落明文）→ **用户主动登出** | **无上界**：应用常驻、**当前未启用单实例锁**；JWT 失效（10041）时 `clearAuthData()` **只清 localStorage、不清 Dexie** ⇒ **明文在 JWT 失效后仍留磁盘**，直到用户登出 ⇒ 以 **C-53（可重入清库）** 作为唯一收敛保证 |
| **web**     | 同上 + 浏览器驱逐                     | 有**随机上界**（**不申请 `persist()`**，作为事实上的过期机制）                                                                                                                                                   |

**关键推论**：**明文数据的存在时间 > JWT 有效期（48h）** ⇒ **真正的边界是「登出」这个动作的可靠性**（崩溃/强杀/掉电未执行完 = 明文长期残留）。⇒ C-53 为**承重约束**。

### 4.3 「无密码」的硬上限（不可绕过）

| 闸                  | 值                                | 说明                                                                          |
| :------------------ | :-------------------------------- | :---------------------------------------------------------------------------- |
| 单次 JWT            | **48h**                           | `ExpOffset` 全仓无赋值点 ⇒ 默认值；**客户端完全不校验 `exp`**，仅响应 10041   |
| 会话（`ExpiredAt`） | **7 天，绝对，不滚动**            | `sessionRepoImpl.go:47` 仅创建时写入；`UpdateToken` 换发**不动** `expired_at` |
| 触发点              | **仅冷启动**（`check-in.vue:37`） | 无周期性 ⇒ **常驻 >48h 必被踢回登录页**（DEF-15）                             |

⇒ **「不弹密码框」的现状硬上限 = 连续 7 天**（前提：每 48h 内至少一次联网冷启动）；**7 天后连 checkin 都失败 ⇒ 只能 `signIn`（需密码）**。⇒ **读法乙（永不弹密码框）在现状服务端语义下不可能达成**；要达成必须改服务端会话模型（滚动续期 / refresh token / 长期会话）⇒ **D-6 明确不做**（K8 已确认）。

### 4.4 明确接受的残余风险（**逐项显式接受，不是遗漏**）

| #    | 残余风险                                                             | 实测/依据                                                                                                                                                                                         | 接受理由与代偿                                                                            |
| :--- | :------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------------------- |
| RS-1 | **共享设备**：任何能打开该设备/浏览器 profile 的人可直接读到全量明文 | A1 威胁 delta：**web 侧已明文存 bearer JWT 且全仓零 CSP ⇒ 恶意扩展/同源页面增量≈0**；明文**明确增量仅"共享设备"与"物理取盘"**                                                                     | 用户已拍板（无密码优先）；代偿 = 登出清库（C-52/C-53）+ 文案提示                          |
| RS-2 | **物理取盘**：磁盘上无保护                                           | 同上                                                                                                                                                                                              | 同上；**若后续需要，可加"可选锁定"（A1 档位④）作为增强，不改默认姿态**                    |
| RS-3 | **`file://` 跨目录共享（实测确证）**                                 | Electron 43 实测：同目录与**不同目录**页面均读到 localStorage 与 IndexedDB；`location.origin === "file://"` ⇒ **同 profile 下任何本地 HTML 都能读本应用数据**                                     | **机密性边界在 desktop 侧失效** ⇒ 以 C-58（`<meta>` CSP）+ 限缩 renderer 加载面代偿       |
| RS-4 | **web 驱逐（不申请 `persist()`）**                                   | desktop 实测 `navigator.storage.persisted() === true`（**不受驱逐**，修正早期推断）；web Chromium best-effort；**Safari/WebKit ITP：7 天无交互即删全部脚本可写存储** ⇒ **web 驱逐风险 100% 暴露** | 作为**事实上的过期机制**被接受（与"离线能看"存在张力 ⇒ 由 C-60 的"尚未同步完成"文案兜底） |
| RS-5 | **登出后离线 = 死路**                                                | 登出即废除 JWT（与"JWT 长期有效"语义互斥）                                                                                                                                                        | 接受 + **文案明示**（「登出将清除本地数据，需联网重新登录」）                             |
| RS-6 | **被顶号 / 10041 离线不可知**                                        | 联网后第一请求即清认证；用户会感到"离线改的突然全没了"                                                                                                                                            | 接受（**K4 未决**：10041 是否视同登出并清本地数据 ⇒ **待用户拍板**，PM 倾向**不清**）     |

### 4.5 上线前必须完成的残余风险记录

- 回滚演练**或**用户书面接受不可逆（D-5 已签 ⇒ **记录签署时点**）。
- RS-3 / RS-4 的**用户可见声明**（设置页 + 首次迁移提示）。

## 5. 迁移设计（最小充分集）

### 5.1 最小充分集（不丢存量数据）

① `meta` 的 `key-bundle` 记录**不删不覆盖** ② crypto **真解密实现保留** ③ 由 `hasKeyBundle` 驱动的**密码入口保留** ④ **迁移完成标记**（C-47）。
⚠️ **真数据丢失风险（必须写进实现说明）**：升级后**迁移完成前从未输入过旧密码** ⇒ 密文**永久不可解**（DEK 无第二把钥匙）⇒ ③ 必须**长期保留**（本仓无遥测，无法确认"全部用户已迁移"）。

### 5.2 迁移器写法（正确性）

- **直写表**（`entityToRecord` + `table.put`），**不 `markDirty`**（C-48）。
- **幂等可续跑** + **双格式双向读取**（C-50/C-51）。
- **禁用**逐条事务（C-56）。

### 5.3 门退役与调用点迁移（顺序硬约束）

| 步骤 | 动作                                                                                | 顺序要求                         |
| :--- | :---------------------------------------------------------------------------------- | :------------------------------- |
| 1    | 加 `bootstrapLocalData()`（含 `checkAndCleanExpired`）+ **单测**                    | **必须先于步骤 3**               |
| 2    | 接入 `AppRoot`（desktop）+ web 阶段一收敛点；**保证早于 `InitialSyncGate.start()`** | 同上（**C-61**）                 |
| 3    | 删除 `unlock-gate.vue`（解锁门退役）                                                | **最后**；违反即 DEF-10 静默回归 |
| 4    | 替换离线进入判据（C-62）+ 补**正向**单测（DEF-16）                                  | 与步骤 3 同批                    |
| 5    | 删 C-23 条件④ / 改 B-2 论证（§2.1）                                                 | 与步骤 3 同批                    |
