## 2. 机制与断点（读码，链上三处）

**首段·防误读**：本项**不是** DEF-STORE-01 的"双 Map 分歧"。此处两副本**彼此一致**（`diff=[]`）却**整体陈旧于本地 DB** ⇒ 属**写后失效 / 订阅**缺口；**合并双副本 / 单一权威源重构修不好本项** —— 单一 Map 同样需要"落库后有人通知它重取"的失效通路。两者可同时存在、**互不替代**。

## 3. 决策

| 要素                   | 决策                                                                                                                                                                          | 理由                                                                                                                           |
| :--------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------- |
| 失效架构               | **应用级单入口**：`nao-todo:data-changed` → 失效中心（store 失效与"某视图是否挂载"解耦）                                                                                      | 与 SHELL-02「宿主 = 元素注册表」同风格；视图域订阅导致失效能力随路由漂移                                                       |
| 详情 store 失效粒度    | **整体失效"当前打开任务的子任务"**（等价现状 `initialize()` 语义）                                                                                                            | 最小改动、可证、回归面最小；定向失效需 store 知道"当前可见 id 集合" ⇒ 引入**视图态耦合**，更复杂（留给与单一权威源合并时评估） |
| `read-after-pull` 语义 | **只文档化，不新增 `await refresh` API**：**事件驱动** —— 下次 `nao-todo:data-changed`/`RefreshData`（或重载/重开面板）后收敛；**不承诺定时收敛**、**不承诺 pull 返回即已新** | 加 await 点须定超时/失败语义，并会把 DEF-SYNC-05 §7 的重复通知收敛拖入本单；§7 为独立观察项且 QA 实测抖动**阴性**              |
| 单子边界               | **不得**与 DEF-STORE-01"单一权威源"混做                                                                                                                                       | 避免单子抖大、回归面爆炸                                                                                                       |

## 4. 被否方案

| 方案                                   | 否决理由                                                                                         |
| :------------------------------------- | :----------------------------------------------------------------------------------------------- |
| **定时收敛**（轮询 store 与 DB 差异）  | 无触发源时"过一会儿就新"是**幻觉式承诺**；引入常驻定时器与抖动风险，且与"事件驱动"架构相悖       |
| **按 id 定向失效**                     | 详情 store 需知道"当前可见 id 集合" ⇒ 视图态耦合进 store；本项症状只需"打开任务整体重取"即可消除 |
| **新增 `await refresh` API**           | 需定超时/失败语义；且会把 §7（回拉窗口重复通知）收敛拉进本单，扩大范围                           |
| **与 DEF-STORE-01 单一权威源一并重构** | 机制不同（去重 ≠ 失效），合并会使回归面覆盖两套不变量，且**并不能**修复本项                      |

## 5. 修复范围与必需性

- **方向 1（失效订阅移出视图域为应用级）：必需。** 依据两条（均与"B 路径作用域疑点"无关）：
    1. **A 路径已实证 P1**：`TaskDetailsStore` 无任何 `RefreshData` 订阅者（§2 B3）⇒ 详情副本只靠 `initialize()`；
    2. **视图域订阅存在"静默丢事件"**：`loadAndReplace()` 以 `if (states.disabled) return` 开头（`packages/presentation/task/hooks/use-task-loader.ts:88-89`；`disabled` 在加载在飞期间为 true，见 `:79/:97` + `delay` 默认 `0`）⇒ **刷新事件在加载在飞时被无声丢弃**，不置脏、不重跑。故"失效依赖视图域订阅"**本身不可靠**。
- **方向 2（`TaskDetailsStore` 补失效通路）：必需**（A 路径已证：该 store 无订阅者）。
- **方向 3（`read-after-pull` 文档化）：必需**（避免把"最终一致"误读为定时收敛）。
- **方向 4（新增，硬要求）：失效事件不得静默丢弃** —— 应用级失效中心必须提供**不丢的合并语义**（在飞中到达的刷新置 **pending/dirty** 标志、在完成后**重跑一次**），**禁止**用 `if (loading) return` 之类静默丢弃。否则"移出视图域"仍会丢事件。
- **B 路径（顶层行 `TasksStore`）判定：作用域假象成立（静态判定）⇒ 不立 `DEF-STORE-07`。**
    - **订阅者确实重新加载（静态可证）**：`useTableViewAdapter` 于 `onMounted` 订阅 `RefreshData → taskLoader.loadAndReplace`（`use-table-view-adapter.ts:44`，卸载时 `:50` 反订阅）；`loadAndReplace()` → `load()` 以**当前分页**请求（`getOptions.page = states.pagination.page`、`limit = states.pagination.limit`，`use-task-loader.ts:44-48`）→ `TaskUseCase.list()` 把**页内**任务写入 store（`taskStore.addTasks(taskViewObjects)`，`task.ts:104-108`），而 store 写入是 `map.set(id, item)` **覆盖式**（`use-mapper-store-base.ts` `addItem`/`addItems`）⇒ **页内实体必被覆盖为新值**。
    - **该实体根本不在页数据集内**：主列表/表格/看板加载器**不传 `parentTaskId`**，仓库层默认**只查顶层任务**（`packages/infrastructure/src/persistence-local/repos/task-repo-impl.ts:288-291`，注释明写"未传 `parentTaskId` 时默认只查顶层任务；子任务仅在任务详情面板按 `parentTaskId` 查询"）⇒ **子任务永不进入表格页数据集**；`store.list` 中该实体属**历史残留**（如详情页 `get()` 落库），是"**未被覆盖**"而非"失效通路断"。（旁证：`task-details.ts:52` 注释"主列表仅含顶层任务"。）
    - **判定前提**：B 路径被测实体须与 A 路径**同为子任务 S**；若改用**顶层任务 id**，需重判（届时须补"该顶层任务是否在当前页"的证据）。
    - **不可静态排除的分支**：`loadAndReplace()` 的 `if (states.disabled) return`（`use-task-loader.ts:88-89`）可在加载在飞时**静默丢弃**刷新 —— 本轮**无在飞证据**，故不作现场依据；该分支已由**方向 4** 覆盖。
    - 附：三值采集（`taskLoader.states.*`）因 `states` 为**组件局部 reactive、未挂全局/Pinia**，页面侧不可达（QA 试 3 路径均未命中）⇒ 该路作废，改以本条静态判定为准。

## 6. 不变量与回归门

1. **不得引入重复重拉风暴**：应用级订阅只注册一次、卸载时清理；
2. **BC-3a/b/c 与 `syncStatus` 记账不得受影响**（同步失败路径不变）；
3. **视图域订阅行为不得回退**（list/table/kanban/calendar/search）；
4. **重载自愈路径不得回归**（重载后行文案仍应为新值）；
5. **详情 store 的 `initialize()` 语义保持**（路由 param 变更仍触发重取）。
6. **失效事件不丢失**：在飞中到达的刷新必须**置脏 + 完成后重跑**（可验证：加载在飞时触发一次 `RefreshData`，完成后 store 必须终值为新）。
